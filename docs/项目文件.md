# 项目文件

项目文件是一份 M3E Canvas 项目的全部内容：编辑器“保存到文件”“保存到文件夹”“下载项目文件”写出的就是它，打开文件、拖进编辑器的也是它。其他工具（MCP 服务器、脚本、手工编辑）读写的也是同一种文件。

格式的读写都在 `lib/core/projectFile.ts`：纯 TypeScript，不依赖 DOM 和 Node API，浏览器和 Node 里都能运行。**写文件请调用它**，不要自己拼 JSON：同一份文档总是写出完全相同的字节，读回来再写一遍也一样，git 里才不会出现无意义的改动。

## 外层

```json
{
  "format": "m3e-project",
  "version": 2,
  "document": {
    ...
  }
}
```

- `format` 固定为 `m3e-project`，`version` 是格式版本（现在是 2），`document` 是文档本身（`lib/tokens.ts` 的 `Doc`）。
- 读的时候走 `lib/project.ts` 的 `loadDocument`（`openProject` 是它的简写）：拆开外层，按版本运行迁移（见下面的[版本和迁移](#版本和迁移)），再校验结构、清理行为数据。别的格式、结构不对的文档一律拒绝；更高版本写的文档能打开，但只读（见[更新版本写的文档](#更新版本写的文档)）。没有外层、直接就是文档的 JSON 也能读（手写文件、旧的分享链接），按版本 2 读。
- 文档里不认识的字段，在每一层都原样保留，见[不认识的字段](#不认识的字段)。

## 版本和迁移

文档一进来就走同一个入口 `loadDocument`，不管它从哪里来：打开的项目文件或文件夹、绑定的文件被外面改过后重新读入、分享链接、浏览器里保存的项目（IndexedDB，以及没有 IndexedDB 时用的 `localStorage`）、关闭页面前没保存完的那一版、MCP 服务器的文件模式、AI 起草的设计。所以一份文档在哪里都是同样地迁移、同样地校验。

- **步骤**：`lib/migrations.ts` 的 `MIGRATIONS` 是按版本排好的一串步骤，每一步把版本 N−1 的文档变成版本 N。版本 0、1、2 的文档本身是同一种写法（1 是别的工具写的外层，2 在外层加过 `packs`），所以第一步从 3 开始；**版本 3 留给第一个真正的格式变化**（整块组件退役拆成原子，或绑定、条件、读行、转场的收敛）。现在 `MIGRATIONS` 是空的，格式仍是 2。
- **每一步必须**：是纯函数，不改传进来的对象；不认识的字段原样留下；**幂等**——已经是新写法的文档再跑一遍不变。最后这条是因为有些文档不带版本（手写的、旧的分享链接、更早的浏览器记录），只能按版本 2 读，而它们其实可能已经是新写法。
- **没写版本的文档**按 2 读（`BARE_VERSION`，永远是 2）。从现在起写出去的东西都带版本：项目文件的外层、浏览器里每个项目的记录（`docs` 和 `befores` 里的 `version`）、没保存完的记录（`m3e:project:<id>:unsaved` 里的 `version`）、`localStorage` 里的旧式文档（旁边的 `m3e:doc:version`）、分享链接（链接里放的是带外层的文档）。
- **加一个步骤**：在 `MIGRATIONS` 末尾加一项（`to` 是新版本号，`name` 一句话说改了什么），把 `PROJECT_VERSION` 改成同一个号；`lib/migrations.test.ts` 会自动对它跑契约测试（不改输入、保留未知字段、幂等、对每个旧文件都得到合法文档），并检查 `lib/fixtures/history/` 里的旧项目文件迁移后在预览里的行为和写出它们的版本一样（`behaviour.json` 记的是当时的预览规则 `lib/interact.ts` 对每份文件算出的结果：开始时显示什么、每个点击去哪、怎么过去、效果留下什么）。测试里有三个不发布的示例步骤（改名并改形状、补默认值、把一个组件拆成几个），写真正的步骤时可以照着写。
- **旧文件**：`lib/fixtures/history/` 里的文件是用 git 历史中各个版本自己的代码、从它们自己的测试数据生成的（bf2463d、65278cb、79ec9e7、55ab801、cf3fa45）。a8b123f 之前用旧 Kind 写的文档（如 72e234c 的那份）从“按全新项目处理”起就不再能打开，现在仍然拒绝。

## 更新版本写的文档

版本号比这个版本高的文档（别人用新版编辑器保存的文件、新版生成的分享链接，或者新版在同一个浏览器里存过的项目），**只读打开**，保证不丢东西：

- 按这个版本能理解的样子显示出来；它不认识的内容照样留在文档里，但看不到也改不了。
- 编辑器上出现说明框：这个项目由更新的版本保存（写出格式号），为了不丢失内容只能查看，请用新版本打开编辑；可以去“所有项目”换一个。这时文档的任何修改（包括 AI 和 MCP 的）都会被拒绝，编辑器也不往浏览器存储和绑定的文件里写，打开文件时勾了“继续保存到这个文件”也不会绑定；“撤销”回不到打开它之前。
- 把它作为新项目打开时，浏览器里存的是**原样的文件内容和它的版本号**，而不是这个版本理解后的样子；新版本再打开这个项目，什么都没少。
- MCP 服务器的文件模式能读、能截图，任何会写文件的调用都被拒绝，并说明原因；`connection_status` 里有 `newerFormat`。

## 不认识的字段

一个字段这个版本不认识（更新的版本加的、别的工具写的、手写的），读文件和保存时**在每一层都原样保留**：文档、屏幕、组件组、组件、组件的 props、点击和它的效果、条件、动效和触发方式、调用的乐观更新、变量和变量集合及其模式、数据集合、可复用组件和它的属性、变体集合、组件组的 kit 和 repeat、约束、外观的每一层（填充、渐变色标、描边、阴影、文字、纹理、滤镜、变换）、主题、文档自己的风格、数据源、屏幕参数、表单、区域、接口的每个对象、模拟库的每个对象。

- 做法是每个清理函数只检查自己认识的字段，认识但写错了的丢掉（这是清理本来要做的），其余原样放回（`lib/keep.ts` 的 `withUnknown`）。放回的字段排在认识的字段后面；在要按作者顺序写的 `api` 里也一样，所以读回再写一遍字节不变。
- 不认识的**效果**（`do` 是这个版本没有的）整个保留，预览、导出的网页、手机、小程序运行时遇到它都跳过。
- 编辑器的 store 也保留：打开、载入、撤销重做、保存都带着文档顶层和每一层里不认识的字段；浏览器存储把大图片拿出去单独存、读回时放回，范围是整个文档。分享链接和 MCP 文件模式同样保留。
- 画出来和导出时只读认识的字段：外观、动效、触发方式在画和打印前只取认识的部分，不认识的内容不会进样式和导出的代码。
- 例外（按设计只保留认识的）：自定义配色 `customPalette` 只能有颜色（每一个都会被画出来）；主题里的 `recipes`、`ux` 和文档风格内部的结构由风格系统读（`lib/styles`），只保留认识的；实例的替身组件由组件定义画出来，替身自己的字段保留，里面的 props 和外观跟着定义走。键是名字而不是字段的对象（props 的值、`bind`、`overrides`、表达式参数、变量在各模式下的值、响应码、登录可接受的值……）里加的是一条“记录”，要符合记录的规则。

普通文档（没有不认识字段的）读进来再写出去，项目文件、浏览器记录和分享内容都和以前逐字节相同。

## 校验和引用

- **同一条规则**：条件、绑定、表达式这几个字段，读文件和操作（`lib/core/ops`）用的是同一份规则（`lib/rules.ts`）：读文件时丢掉不合规则的值，操作时拒绝它，说法相同。两边仍然不同的地方是有意的：操作还会检查值指向的东西存在（变量、组件、接口），文件不会因为一个过期的引用被拒绝，运行时它什么都不做；操作要求表达式能解析，文件里解析不了的表达式保留下来，留给作者在面板里看到并改。
  - 条件 `{ "var": "row.<字段>", ... }`（重复的行里读这一行的字段，AI 指南里这样写）现在操作也接受了，以前只有读文件接受。
  - 绑定到 `=表达式` 的属性，表达式的长度上限和其他表达式一样（4000 个字符），以前读文件时没有上限。
- **引用维护**：点击里的引用由 `lib/refs.ts` 统一找：去的屏幕、显示隐藏打开关闭设置的组件、滚动到的组件、条件问的组件、提交的表单，在 `else` 里、在调用的 `then` 和 `catch` 里（多深都找），以及表单自己的 `then` 和 `catch` 里。复制组件时它们跟着复制品走（以前漏了滚动目标、调用的回答、提交的表单），删除屏幕时去那里的嵌套分支改成留在原地（以前只处理最外层和 `else`）。
  - 还没做：表达式里按名字读的东西（变量名、文字里的 `{{data.x}}`、屏幕参数）改名时的更新。这要等变量有稳定的 key、绑定都变成表达式之后一起做（整改计划第四批，阶段 5 的模型收敛），那时引用索引会加上这几类。

## 排版

为了让 git 的差异有意义，文本的写法是固定的：

1. **键排序**：外层按 `format`、`version`、`document` 的顺序；`document` 里面所有对象的键都按码位排序（`"a" < "b" < "z"`，大写在小写前）。值为 `undefined` 的键不写，和 `JSON.stringify` 一样。
2. **缩进两个空格**，换行符是 `\n`，文件以换行结尾。
3. **一行一个节点**：
   - 外层、`document`、`document` 下的对象（`theme`、`customPalette`……）和数组（`frames`、`groups`、`vars`、`styles`、`promptOptions`……）展开，每个成员一行。
   - 这些数组的每个元素写在一行里（紧凑 JSON，没有空格）：一个屏幕、一个组件组（通常就是一个组件）、一个变量、一个风格各占一行。改一个组件的属性或位置，差异就是一行。
   - 例外：`components`（可复用组件的定义）和 `collections`（数据集合）的元素本身展开，它们里面的数组再展开一层：定义的 `groups` 一个组一行，集合的 `rows` 一行数据一行，`fields` 一个字段一行。
   - 空数组、空对象写成 `[]`、`{}`。

```json
{
  "format": "m3e-project",
  "version": 2,
  "document": {
    "brief": "",
    "collections": [
      {
        "fields": [
          "name",
          "price"
        ],
        "id": "fruit",
        "name": "Fruit",
        "rows": [
          ["Apple","1"],
          ["Pear","2"]
        ]
      }
    ],
    "frame": "phone",
    "frames": [
      {"id":"home","name":"Home","x":0,"y":0}
    ],
    "groups": [
      {"axis":"y","id":"g1","items":[{"component":"button","icon":null,"id":"b1","kind":"component","label":"Button","props":{"label":"Buy"},"variant":"filled"}],"x":16,"y":120}
    ],
    "paletteKey": "purple",
    "theme": {
      "dark": false,
      ...
    },
    "title": "Shop"
  }
}
```

只要按这些规则写，任何语言都能写出相同的字节；在 TypeScript 里直接用 `formatProject`。

## 文档自己的图标

`document.icons` 是文档自己的图标（可以没有）：一个对象，键是编号（用短横线连起来的小写词，如 `leaf`、`coffee-cup`），值是这个图标的 SVG 标记。组件在接受图标名的地方写 `svg:<编号>` 来用它。按上面的排版，`icons` 展开，一个图标一行：

```json
    "icons": {
      "leaf": "<svg xmlns=\"http://www.w3.org/2000/svg\" viewBox=\"0 0 24 24\" fill=\"currentColor\"><path d=\"M4 20C4 9 11 4 20 4c0 9-5 16-16 16z\"/></svg>"
    },
```

- 读的时候（`openProject`）每个图标都经过矢量原子的 SVG 清理：只留下形状、组、渐变、裁剪和蒙版，脚本、事件、外部地址、文字、滤镜、样式都去掉，再按固定写法写出；编号不合格的、清理后什么都不剩的、超过 200 个的丢掉。手写时用 `currentColor` 上色，图标就随组件的颜色变。
- 图标是文本，不放进 `m3e-assets/`。格式版本仍是 2：没有这个字段的文件照旧。

## 接口

`document.api` 是文档的接口（可以没有）：数据模型、HTTP 接口、鉴权、实时通道和服务器地址，格式见 [接口](接口.md)。它的排版和文档的其他部分有两点不同：

- **键保持原来的顺序**，不排序：模型的字段顺序就是表单的顺序，路径、响应码的顺序也是作者的。`api` 自己在 `document` 里仍按码位排序（在 `brief` 之前）。同一份文档写出的字节仍然固定：操作和读入都把 `api` 整理成同一种形状（`cleanApi`），读回再写一遍不变。
- **一项一行**：`api` 展开，它下面的列表和对象（`models`、`endpoints`、`channels`、`servers`、`tags`、`info`、`auth`、`extra`）也展开，每个模型、接口、通道、服务器各占一行。

```json
    "api": {
      "info": {
        "title": "Shop"
      },
      "models": [
        {"name":"Product","schema":{"type":"object","properties":{"name":{"type":"string"},"price":{"type":"number"}},"required":["name"]}}
      ],
      "endpoints": [
        {"operationId":"listProducts","method":"get","path":"/products","responses":{"200":{"description":"OK"}}}
      ]
    },
```

读的时候（`openProject`）经过 `cleanApi`：形状不对的项丢掉，数量、深度和字符串长度有上限，重复的 operationId 加后缀；内容上的问题（引用不存在、路径参数对不上）保留，编辑器里列出来。数据集合的 `model` 字段（关联的模型名）一样原样读写。格式版本仍是 2：没有它的文件照旧，写出的字节和以前完全一样；`api` 里每个对象不认识的字段都保留（排在认识的字段后面）。

## 模拟库

`document.mocks` 是文档的模拟库设置（可以没有），格式见 [模拟库](模拟库.md)。它下面的列表（`models`、`scenarios`、`files`、`realtime`、`routes`）和对象（`auth`、`latency`）展开，每个模型设置、场景、文件、脚本各占一行；键和文档的其他部分一样按码位排序。

```json
    "mocks": {
      "locale": "zh",
      "models": [
        {"count":24,"hints":{"email":{"kind":"email"},"name":{"kind":"personName"}},"name":"User"}
      ],
      "scenario": "new-user",
      "scenarios": [
        {"all":{"empty":true},"description":"刚注册，还没有任何数据：列表都是空的","id":"new-user","name":"新用户"}
      ],
      "seed": 1
    },
```

读的时候（`openProject`）经过 `cleanMocks`：形状不对的丢掉，数字收进范围，数量有上限；文件（`files[].data`）必须是 data URL。存成文件夹时，文件库里够大的文件放进 `m3e-assets/`（`m3e-file:` 引用，读的时候换回 data URL）：模拟库能生成的每一种格式都算（`lib/mocks/formats/table.ts`：图片、PDF、DOCX、XLSX、PPTX、CSV、TSV、JSON、XML、YAML、文本、ZIP、音频、视频、GLB、glTF、OBJ、STL……），条件和图片一样——data URL 的类型正好是模拟库生成这种格式时用的那个（`data:<类型>;base64,<内容>`，不带参数，base64 是标准写法），不到 2048 个字符的留在文本里。同一格式的别名（如 `application/x-zip-compressed`）、模拟库不认识的类型，都留在文本里，因为按扩展名读回来得不到逐字相同的 data URL。文件名是内容的哈希加这种格式的扩展名（`xlsx`、`glb`、`csv`……）。文档其他地方的非图片 data URL 不受影响。格式版本仍是 2：没有它的文件照旧，`mocks` 里每个对象不认识的字段都保留；早先版本把 XLSX、CSV 等留在文本里的项目照常打开，下次存成文件夹时才放进 `m3e-assets/`；文件库里只有图片、PDF、WAV、MP3、OGG、M4A、MP4、WebM、二进制文件（或者没有文件库）的项目，写出的字节和以前完全一样。

## 图片

图片（`image` 组件的 `src`、屏幕的描图、AI 画的场景……）在文档里是 data URL。有两种存法：

| 方式 | 何时 | 图片在哪 |
| --- | --- | --- |
| 单文件 | “保存到文件”、下载、`serializeProject(doc)` | 留在文本里，原样的 data URL |
| 文件夹 | “保存到文件夹”、`serializeProject(doc, { assets: "files" })` | 放在项目文件旁边的 `m3e-assets/`，文档里写引用 |

文件夹的结构：

```text
<文件夹>/
  m3e-project.json        项目文件
  m3e-assets/
    k3j9x0w2q1a.png       一张图片一个文件
```

- 文档里的引用是 `m3e-file:` 加上相对项目文件的路径，例如 `"src":"m3e-file:m3e-assets/k3j9x0w2q1a.png"`。
- 只有能原样写回的图片才放进文件：`data:image/<png|jpeg|webp|gif|avif|svg+xml>;base64,<内容>`，且 base64 是标准写法（解码再编码不变）。不到 2048 个字符的小图、带其他参数的、非 base64 的，都留在文本里。
- 文件名由内容决定：base64 文本的 cyrb53 哈希（36 进制）加扩展名（`png`、`jpg`、`webp`、`gif`、`avif`、`svg`；模拟库的文件用它那种格式的扩展名，见上一节），所以同一张图只存一份，名字不随保存而变。读回时按扩展名还原 MIME 类型，得到的 data URL 和原来逐字相同。
- 读的时候只解析形如 `m3e-assets/<小写字母和数字>.<扩展名>` 的路径，别的路径（包括 `..`）一律当作缺失；缺失的图片变成空图片，不会出错。
- 保存文件夹分三步，顺序保证磁盘上任何时候都有一个完整的版本：
  1. 先写新版本引用的每个文件，写完读回来核对字节；已经有同名文件的，核对内容（编辑器记得自己写过或核对过的文件的大小和修改时间，没变的不再读），内容不对（损坏的副本）就重写。任何一个写不成、`m3e-assets/` 建不了，这次保存就停在这里，项目文件不动。
  2. 再用一次原子写入替换 `m3e-project.json`。这一步失败，磁盘上仍是上一个版本和它的全部图片。
  3. 最后才清理：删掉新版本不再引用、而且能证明是编辑器自己的文件——编辑器自己写的、之后没被改过的；或者名字正好是内容的哈希、而且不是一分钟内刚写的（可能是别的程序正在进行的保存）。手工放进去的文件（如 `logo.png`）、名字像哈希但内容对不上的，都不碰。清理失败不影响保存，留到下次。

  中途崩溃最多留下没人引用的新文件，不会出现项目文件引用的图片已经被删掉的情况。MCP 服务器写文件夹按同样的规则清理。

## 在 Node 里读写

```ts
import { readFile, writeFile, rename, mkdir } from "node:fs/promises";
import { join } from "node:path";
import { readProjectText, serializeProject, isAssetPath } from "./lib/core/projectFile";

const dir = "design";
const text = await readFile(join(dir, "m3e-project.json"), "utf8");
const doc = await readProjectText(text, async (path) => (isAssetPath(path) ? new Uint8Array(await readFile(join(dir, path))) : null));
if (!doc) throw new Error("不是 M3E Canvas 项目");

// ……用文档核心（lib/core）的操作修改 doc……

const out = serializeProject(doc, { assets: "files" });
await mkdir(join(dir, "m3e-assets"), { recursive: true });
for (const f of out.files) await writeFile(join(dir, f.path), f.bytes);
await writeFile(join(dir, "m3e-project.json.tmp"), out.text);
await rename(join(dir, "m3e-project.json.tmp"), join(dir, "m3e-project.json")); // 原子替换
```

| 函数 | 说明 |
| --- | --- |
| `serializeProject(doc, { assets })` | 文档写成项目文件的文本；`assets: "files"` 时同时给出要放进 `m3e-assets/` 的图片（`path`、`mime`、`bytes`） |
| `parseProject(text)` | 读出文档（经过 `loadDocument`：迁移、校验、清理）和它引用的图片路径；不是项目时为 `null` |
| `attachFiles(doc, files)` | 把 `m3e-file:` 引用换回 data URL |
| `readProjectText(text, load)` | 上面两步合起来，`load(path)` 读图片的字节 |
| `formatProject(file)` | 只做排版：任意 `{ format, version, document }` 按上面的规则写成文本 |
| `projectNameFromFile(name)` | 文件名对应的项目名（去掉扩展名和 `m3e-canvas ` 前缀） |
| `isAssetPath(path)` | 路径是不是项目旁边的图片，用来拒绝越界路径 |

文档里的图片如果还是浏览器内部的引用（`m3e-asset:`，见下一节），要先换回 data URL 再写；编辑器写文件时会自动这样做。

## 编辑器怎样保存

- **项目在浏览器里**：每个项目存在 IndexedDB 的 `m3e-projects` 数据库，大图片单独存一份（按内容命名，多个项目共用），文档里只留 `m3e-asset:` 引用；记录里同时写上格式版本（`version`）。这是浏览器内部的存法，不是文件格式。读回时和打开文件一样经过 `loadDocument`：按记录的版本迁移、校验、清理（形状不对、打不开的旧记录不丢，原样交给编辑器，画得出来的照常显示）。
- **保存到文件 / 文件夹**（Chromium 的 File System Access API）：选好位置后项目就和它绑定，之后每次修改都在停顿约 0.7 秒后（连续修改最多等 3 秒）写一次。写入用 `createWritable`，先写到临时位置再整体替换，文件不会只写一半。
- **重新连接**：浏览器重新加载后通常要再次授权，工具栏的项目名旁会出现“重新连接文件”。授权前的修改照常存在浏览器里，授权后一次写进文件。
- **文件在外面被改了**：编辑器记得自己上次写出的大小、修改时间和内容哈希。下次要写之前（以及重新打开项目时）发现文件变了、又不是它要写的内容，就不写，并询问：载入文件里的版本（可以撤销），还是用当前版本覆盖文件。所以 MCP 服务器或 git 在编辑器打开时改了文件，也不会被悄悄覆盖。
- **不支持的浏览器**（Firefox、Safari）：只能“下载项目文件”和“打开文件”，不能自动保存。
- **打开文件**（菜单、项目主页或直接拖进编辑器）：默认作为新项目打开，也可以替换当前画布（一步撤销）；在 Chromium 里可以选择之后继续保存到这个文件。文件夹同样可以打开或拖入。

### 保存失败时

- 每次交给存储的文档都有一个序号；编辑器记得最新的、正在写的和最后保存成功的是哪一个。浏览器拒绝写入时，这一版留着等下一次写，不会丢；写的过程中又来了更新的一版，旧的那版再失败、再重试也不会顶替新的。失败后过 2 秒、5 秒、15 秒……（最长每分钟一次）自动再试。
- 工具栏的项目名旁会出现红色的“未保存”，点开可以看到浏览器里的副本和文件的副本各自的状态，并且可以“再试一次”或“下载副本”。原因分成几种分别说明：浏览器存储空间已满、浏览器关闭了项目存储（例如另一个标签页正在升级它，编辑器会自动重新打开一次）、这里不允许保存、另一个标签页保存了这个项目、其他写入错误。
- **切换项目**之前，编辑器先把手上的内容写完（浏览器里的和文件的），再看结果：都保存好了才离开；有没保存的，就留在原项目，说明哪一份没保存，可以再试一次、下载副本、仍然离开或留下。只是文件还没写（等待重新连接、在外面被改了）而浏览器里已经保存时，也会说明，下次打开这个项目时再写进文件。

### 两个标签页和关闭页面

- 同一个项目同一时间只有一个标签页能编辑（Web Lock）。浏览器没有 Web Lock（不安全的来源、旧版 WebKit）或者申请失败时，两个标签页都能编辑，但每次写入都会在同一个事务里核对：项目还是不是这个标签页上次读到或写入的版本（文档记录里的写入标记）。不是，就说明另一个标签页已经保存过——这次不写，这个标签页停止保存并变成只读，提示可以把自己的版本下载成副本；绑定的文件也不再由它写。所以两个标签页不会互相覆盖。
- 页面隐藏（切到别的标签页、手机切到后台）和关闭（`pagehide`）时，编辑器立即写入还在等待的内容，文件也不再等停顿。浏览器不会等这些写入完成，所以同时把还没保存成功的最新版本同步记到 `localStorage`（`m3e:project:<id>:unsaved`），这一版保存成功后就删掉。下次打开这个项目时，如果这份记录和保存的内容不一样，会询问是否恢复（恢复是一步撤销，也可以丢弃；直接关掉对话框则下次再问）。这是尽力而为：浏览器没有提供关闭页面时的事务保证，`localStorage` 满了也记不下。

### 分享链接

分享链接把文档放在地址的 `#docz=`（压缩）或 `#doc=` 后面，连同外层（`format`、`version`、`document`），所以读链接的版本知道它是哪个版本写的（以前的链接里只有文档，按版本 2 读）。片段不会发给服务器，但拿到链接的人和打开它的页面都能读到内容，**不是加密**。

- **分享范围**：复制链接之前先选范围——“仅外观”（屏幕、组件、可复用组件、风格、变量和屏幕上显示的数据集合）、“含示例数据”（再加接口的数据模型和模拟库）、“完整契约”（再加接口、实时通道、登录方式、服务器地址）。对话框列出这个范围包含的每一项和数量（每个数据集合、接口的各部分、接口里的示例、每个模型的固定记录、模拟文件、模拟登录接受的值……），每项都可以关掉；排除一个数据集合只去掉它的行、保留字段，引用它的列表不会断；接口还在时数据模型不能单独排除（接口引用它们）。可以预览链接里实际的内容和长度。从电脑选的图片和 AI 改写的历史从不放进链接。
- **上限**：打开链接时，地址不超过 2,000,000 个字符，压缩数据不超过 1.5 MB，解压出来不超过 8 MB（边解压边计数，超过就取消，不会先分配整块内存），嵌套不超过 128 层，值不超过 400,000 个。超过上限的链接不打开，提示向对方要项目文件；编辑器照常使用。生成的链接超过长度上限时，对话框提示改用项目文件。
