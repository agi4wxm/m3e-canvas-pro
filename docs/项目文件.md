# 项目文件

项目文件是一份 M3E Canvas 项目的全部内容：编辑器“保存到文件”“保存到文件夹”“下载项目文件”写出的就是它，打开文件、拖进编辑器的也是它。其他工具（MCP 服务器、脚本、手工编辑）读写的也是同一种文件。

格式的读写都在 `lib/core/projectFile.ts`：纯 TypeScript，不依赖 DOM 和 Node API，浏览器和 Node 里都能运行。**写文件请调用它**，不要自己拼 JSON：同一份文档总是写出完全相同的字节，读回来再写一遍也一样，git 里才不会出现无意义的改动。

## 外层

```json
{
  "format": "m3e-project",
  "version": 2,
  "document": {
    ...
  }
}
```

- `format` 固定为 `m3e-project`，`version` 是格式版本（现在是 2），`document` 是文档本身（`lib/tokens.ts` 的 `Doc`）。
- 读的时候走 `lib/project.ts` 的 `openProject`：拆开外层，按版本运行 `MIGRATIONS`，再校验结构、清理行为数据。别的格式、更高的版本、结构不对的文档一律拒绝。没有外层、直接就是文档的 JSON 也能读（分享链接、手写文件）。
- 文档里不认识的字段原样保留。

## 排版

为了让 git 的差异有意义，文本的写法是固定的：

1. **键排序**：外层按 `format`、`version`、`document` 的顺序；`document` 里面所有对象的键都按码位排序（`"a" < "b" < "z"`，大写在小写前）。值为 `undefined` 的键不写，和 `JSON.stringify` 一样。
2. **缩进两个空格**，换行符是 `\n`，文件以换行结尾。
3. **一行一个节点**：
   - 外层、`document`、`document` 下的对象（`theme`、`customPalette`……）和数组（`frames`、`groups`、`vars`、`styles`、`promptOptions`……）展开，每个成员一行。
   - 这些数组的每个元素写在一行里（紧凑 JSON，没有空格）：一个屏幕、一个组件组（通常就是一个组件）、一个变量、一个风格各占一行。改一个组件的属性或位置，差异就是一行。
   - 例外：`components`（可复用组件的定义）和 `collections`（数据集合）的元素本身展开，它们里面的数组再展开一层：定义的 `groups` 一个组一行，集合的 `rows` 一行数据一行，`fields` 一个字段一行。
   - 空数组、空对象写成 `[]`、`{}`。

```json
{
  "format": "m3e-project",
  "version": 2,
  "document": {
    "brief": "",
    "collections": [
      {
        "fields": [
          "name",
          "price"
        ],
        "id": "fruit",
        "name": "Fruit",
        "rows": [
          ["Apple","1"],
          ["Pear","2"]
        ]
      }
    ],
    "frame": "phone",
    "frames": [
      {"id":"home","name":"Home","x":0,"y":0}
    ],
    "groups": [
      {"axis":"y","id":"g1","items":[{"component":"button","icon":null,"id":"b1","kind":"component","label":"Button","props":{"label":"Buy"},"variant":"filled"}],"x":16,"y":120}
    ],
    "paletteKey": "purple",
    "theme": {
      "dark": false,
      ...
    },
    "title": "Shop"
  }
}
```

只要按这些规则写，任何语言都能写出相同的字节；在 TypeScript 里直接用 `formatProject`。

## 文档自己的图标

`document.icons` 是文档自己的图标（可以没有）：一个对象，键是编号（用短横线连起来的小写词，如 `leaf`、`coffee-cup`），值是这个图标的 SVG 标记。组件在接受图标名的地方写 `svg:<编号>` 来用它。按上面的排版，`icons` 展开，一个图标一行：

```json
    "icons": {
      "leaf": "<svg xmlns=\"http://www.w3.org/2000/svg\" viewBox=\"0 0 24 24\" fill=\"currentColor\"><path d=\"M4 20C4 9 11 4 20 4c0 9-5 16-16 16z\"/></svg>"
    },
```

- 读的时候（`openProject`）每个图标都经过矢量原子的 SVG 清理：只留下形状、组、渐变、裁剪和蒙版，脚本、事件、外部地址、文字、滤镜、样式都去掉，再按固定写法写出；编号不合格的、清理后什么都不剩的、超过 200 个的丢掉。手写时用 `currentColor` 上色，图标就随组件的颜色变。
- 图标是文本，不放进 `m3e-assets/`。格式版本仍是 2：旧版本读到这个字段会原样保留，没有这个字段的文件照旧。

## 图片

图片（`image` 组件的 `src`、屏幕的描图、AI 画的场景……）在文档里是 data URL。有两种存法：

| 方式 | 何时 | 图片在哪 |
| --- | --- | --- |
| 单文件 | “保存到文件”、下载、`serializeProject(doc)` | 留在文本里，原样的 data URL |
| 文件夹 | “保存到文件夹”、`serializeProject(doc, { assets: "files" })` | 放在项目文件旁边的 `m3e-assets/`，文档里写引用 |

文件夹的结构：

```text
<文件夹>/
  m3e-project.json        项目文件
  m3e-assets/
    k3j9x0w2q1a.png       一张图片一个文件
```

- 文档里的引用是 `m3e-file:` 加上相对项目文件的路径，例如 `"src":"m3e-file:m3e-assets/k3j9x0w2q1a.png"`。
- 只有能原样写回的图片才放进文件：`data:image/<png|jpeg|webp|gif|avif|svg+xml>;base64,<内容>`，且 base64 是标准写法（解码再编码不变）。不到 2048 个字符的小图、带其他参数的、非 base64 的，都留在文本里。
- 文件名由内容决定：base64 文本的 cyrb53 哈希（36 进制）加扩展名（`png`、`jpg`、`webp`、`gif`、`avif`、`svg`），所以同一张图只存一份，名字不随保存而变。读回时按扩展名还原 MIME 类型，得到的 data URL 和原来逐字相同。
- 读的时候只解析形如 `m3e-assets/<小写字母和数字>.<扩展名>` 的路径，别的路径（包括 `..`）一律当作缺失；缺失的图片变成空图片，不会出错。
- 编辑器保存文件夹时会删掉 `m3e-assets/` 里不再被引用、且名字符合上面格式的文件，其他文件不碰。MCP 服务器写文件夹时更谨慎：只删它自己写的，或者名字和内容的哈希对得上的；别的程序一分钟内刚写的先不删。

## 在 Node 里读写

```ts
import { readFile, writeFile, rename, mkdir } from "node:fs/promises";
import { join } from "node:path";
import { readProjectText, serializeProject, isAssetPath } from "./lib/core/projectFile";

const dir = "design";
const text = await readFile(join(dir, "m3e-project.json"), "utf8");
const doc = await readProjectText(text, async (path) => (isAssetPath(path) ? new Uint8Array(await readFile(join(dir, path))) : null));
if (!doc) throw new Error("不是 M3E Canvas 项目");

// ……用文档核心（lib/core）的操作修改 doc……

const out = serializeProject(doc, { assets: "files" });
await mkdir(join(dir, "m3e-assets"), { recursive: true });
for (const f of out.files) await writeFile(join(dir, f.path), f.bytes);
await writeFile(join(dir, "m3e-project.json.tmp"), out.text);
await rename(join(dir, "m3e-project.json.tmp"), join(dir, "m3e-project.json")); // 原子替换
```

| 函数 | 说明 |
| --- | --- |
| `serializeProject(doc, { assets })` | 文档写成项目文件的文本；`assets: "files"` 时同时给出要放进 `m3e-assets/` 的图片（`path`、`mime`、`bytes`） |
| `parseProject(text)` | 读出文档（经过 `openProject`）和它引用的图片路径；不是项目时为 `null` |
| `attachFiles(doc, files)` | 把 `m3e-file:` 引用换回 data URL |
| `readProjectText(text, load)` | 上面两步合起来，`load(path)` 读图片的字节 |
| `formatProject(file)` | 只做排版：任意 `{ format, version, document }` 按上面的规则写成文本 |
| `projectNameFromFile(name)` | 文件名对应的项目名（去掉扩展名和 `m3e-canvas ` 前缀） |
| `isAssetPath(path)` | 路径是不是项目旁边的图片，用来拒绝越界路径 |

文档里的图片如果还是浏览器内部的引用（`m3e-asset:`，见下一节），要先换回 data URL 再写；编辑器写文件时会自动这样做。

## 编辑器怎样保存

- **项目在浏览器里**：每个项目存在 IndexedDB 的 `m3e-projects` 数据库，大图片单独存一份（按内容命名，多个项目共用），文档里只留 `m3e-asset:` 引用。这是浏览器内部的存法，不是文件格式。
- **保存到文件 / 文件夹**（Chromium 的 File System Access API）：选好位置后项目就和它绑定，之后每次修改都在停顿约 0.7 秒后（连续修改最多等 3 秒）写一次。写入用 `createWritable`，先写到临时位置再整体替换，文件不会只写一半。
- **重新连接**：浏览器重新加载后通常要再次授权，工具栏的项目名旁会出现“重新连接文件”。授权前的修改照常存在浏览器里，授权后一次写进文件。
- **文件在外面被改了**：编辑器记得自己上次写出的大小、修改时间和内容哈希。下次要写之前（以及重新打开项目时）发现文件变了、又不是它要写的内容，就不写，并询问：载入文件里的版本（可以撤销），还是用当前版本覆盖文件。所以 MCP 服务器或 git 在编辑器打开时改了文件，也不会被悄悄覆盖。
- **不支持的浏览器**（Firefox、Safari）：只能“下载项目文件”和“打开文件”，不能自动保存。
- **打开文件**（菜单、项目主页或直接拖进编辑器）：默认作为新项目打开，也可以替换当前画布（一步撤销）；在 Chromium 里可以选择之后继续保存到这个文件。文件夹同样可以打开或拖入。
