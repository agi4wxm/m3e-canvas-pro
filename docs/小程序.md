# 小程序

完整产品（monorepo，见 [导出](导出.md)）里的 `apps/miniapp` 是一个 Taro 应用：同一份代码构建成**微信小程序**（weapp）、**抖音小程序**（tt）和 **H5** 网页，和 Web 应用、手机应用一样来自同一份设计，跑在同一个前端运行时（`packages/app-runtime`）上，用同一个接口客户端（`packages/api`）和同一个模拟库（`packages/mocks`）。

| 部分 | 在哪里 | 做什么 |
| --- | --- | --- |
| 组件套件 | `miniapp-kit/src/kit`（导出时原样复制进 `apps/miniapp/src/kit`） | 用 Taro 组件画出编辑器里的组件：布局、文字、图标、按钮、输入、选择器、栏、列表、卡片、弹窗……，外加主题、导航和屏幕的运行时 |
| 打印器 | `lib/export/miniapp/` | 把设计的屏幕写成页面：组件、布局、点击、绑定（数据源、表达式、重复、区域、表单、调用、参数、登录） |
| 导出目标 | `lib/export/targets/miniapp.ts` | 生成 `apps/miniapp` 工作区：Taro 配置、页面、主题、图标、运行时、模拟库的接法、自定义代码的位置、`project.config.json` |
| 测试台 | `miniapp-kit/`（独立的 Taro 项目） | 组件画廊和打印器的样例页面，类型检查、ESLint、单元测试、三个平台的构建 |


### 在开发者工具里打开

- **微信**：微信开发者工具里“导入项目”，目录选 `apps/miniapp`（`project.config.json` 让它读 `dist/weapp`），先跑 `npm run dev:weapp`。
- **抖音**：抖音开发者工具打开 `apps/miniapp/dist/tt`（Taro 构建时把 `project.tt.json` 复制成那里的 `project.config.json`），先跑 `npm run dev:tt`。
- **AppID**：`project.config.json` 和 `project.tt.json` 是自定义文件（导出只写一次），把 `touristappid` / `testappid` 换成真实的 AppID。没有 AppID 时开发者工具可以用测试号，但不能真机预览和上传。
- **请求域名**：小程序只能请求在管理后台“开发管理 → 开发设置 → 服务器域名”里登记过的 **https** 域名（`request 合法域名`；上传文件还要 `uploadFile 合法域名`）。开发时在开发者工具的“详情 → 本地设置”里勾选“不校验合法域名……”就能请求本机的后端；导出的 `project.config.json` 已经把 `urlCheck` 设为 `false`。

### 接口和模拟库

- 接口地址是构建时的 `TARO_APP_API_BASE_URL`（例：`TARO_APP_API_BASE_URL=https://api.example.com npm run build:weapp`）。不设时，小程序请求本机的后端 `http://127.0.0.1:3001`，H5 请求同站的 `/api`：`dev:h5` 把它转发给 `API_TARGET`（默认同一个后端），生产的 H5 构建也要由托管它的服务器转发 `/api`，和 Web 应用一样。
- 开发构建（`dev:*`）的接口默认由模拟库回答，和编辑器预览同一个模拟库、同样的数据和场景，会话按场景的 `signedIn` 开始（`startsSignedIn`）。`TARO_APP_API_MOCKS=off` 改为请求真实后端；`TARO_APP_MOCK_SCENARIO=new-user` 选场景，H5 也可以在地址里加 `?scenario=new-user`，或在控制台 `m3eMocks.start("network-error")`。
- 生产构建（`build:*`）里没有模拟库：`runtime.ts` 里的 `process.env.NODE_ENV !== "production"` 分支连同它 `require` 的模块一起被去掉（`scripts/check-product.ts` 检查三个平台的产物）。

### 平台能力

设计里调用的平台能力（支付、第三方登录、定位、扫码……）由套件的屏幕运行时交给生成的注册表 `src/generated/capabilities.ts`：先用 `src/custom/capabilities.ts` 里写的适配，再用小程序的默认适配（剪贴板 `Taro.setClipboardData`；打开链接是复制链接并提示，小程序打不开外部网页；选文件 `Taro.chooseImage` / `chooseMessageFile`），否则回答 `not-implemented`，开发构建在控制台提示去哪里写。地图、相机、通话画面在 `src/custom/slots/<名字>.tsx` 的插槽里用 Taro 的 `<Map>`、`<Camera>` 或服务商的插件画。世界视口（`world-view`）也是插槽：
引擎（Cocos 小游戏、`<Canvas>` 循环）接在那里，拿到世界状态、输入动作的通道（屏幕运行时的 `s.world(名字)`）和 `onEvent`；接上之前画套件的替身
`WorldStandIn`（`src/kit/world.tsx`，列出听到的输入），示例引擎在 `src/generated/exampleWorld.tsx`，测试床 `src/printed/world` 就接了它。导出不带 SDK、AppID 以外的密钥和权限声明（`app.config.ts` 的 `permission`、`requiredPrivateInfos` 要自己加）。见[平台能力](平台能力.md)。

## 屏幕怎样变成页面

- **一个屏幕一个页面**：`app.config.ts` 的 `pages` 按屏幕顺序，流程起点（没有就是第一个屏幕）在最前。页面名和组件名来自屏幕名（字母数字），同一份设计每次导出逐字节相同。
- **参数**：屏幕参数（`Frame.params`）放在页面的查询串里（`/pages/product/index?productId=…`，编码过），页面按声明的类型读，没给的用示例值，没声明的不读。
- **跳转**：`navigateTo` 压栈；要替换当前页（离开登录页、登录后回去）或页面栈快满（小程序最多 10 层）时用 `redirectTo`；底部导航栏的页面用 `switchTab`；失败时 `reLaunch`。返回是 `navigateBack`，第一页上返回回到起点。
- **浮层**（`overlay`）：画在当前页面上面（压暗、点外面关闭），不是新页面，没有地址。
- **导航栏**：每个页面 `navigationStyle: custom`，由设计里的应用栏自己画：顶上留出状态栏，右边让开胶囊按钮（“… ◎”，位置从 `getMenuButtonBoundingClientRect` 读）；H5 没有这两样。
- **底部导航栏**：几个屏幕共用同一个导航栏时，小程序用自定义 tabBar（`src/custom-tab-bar`，`tabBar.custom: true`，切换用 `switchTab`），H5 把它画在页面底部。
- **底部浮动的东西**：加载数据的屏幕上，底部的栏、悬浮按钮和站在屏幕下半部的按钮固定在屏幕底部（按钮是 `<Pin edge="floatingBottom" x bottom>`，离底部的距离按设计，再加上底部安全区），页面末尾多出一段空白（`Screen` 的 `room`，同样加上安全区），滚到最后时最后一行停在它们上方（`lib/foot.ts`，和预览、Web、手机应用同一个规则）。
- **深浅色**：和 Web 应用一样按设计：设计是浅色或深色（风格自己是深色的，比如 Spotify，选它时就是深色）就一直是那一种，窗口背景、导航栏文字、下拉刷新的圆点也跟着；设计“两种模式都画”（`bothModes`）时跟随系统（微信要 `darkmode: true`，这时导出才写；H5 是 `prefers-color-scheme`）。

## 绑定

和 Web 应用一样（[数据绑定](数据绑定.md)），绑定写成调用共用运行时的代码，表达式作为字符串交给运行时求值（从不 `eval`）：

| 设计里 | 小程序里 |
| --- | --- |
| 数据源 | `useDataSource({ key, operation, list, paging, pageSize, args, load })`，`load` 经 `CALLS["listProducts"]` 调类型化客户端；参数是表达式读出的值 |
| 表达式、`{{表达式}}` | `$.text("item.name")`、`$.fill(…)`、`$.num(…)`、`$.bool(…)`、`$.pick(…)` |
| 按数据重复 | `$.list("data.products.items").map((item, index) => …)`，`key` 是元素的 `id` |
| 区域 | `regionOf(products, { load: "enter" })` 选出 `ready`、`loading`、`empty`、`error`、`forbidden` 之一，每个状态的设计一个分支 |
| 表单 | `useForm({ id, fields, send, then, catch, status })`：字段规则来自契约，输入框是 Taro 的 `Input` / `Textarea`，下拉选择是 Taro 的 `Picker`（日期、时间也是 `Picker` 的 `date` / `time` 模式），滑块和评分按数字（评分 `value`/`onChange`，表单之外由屏幕的运行时保存，绑定的变量跟着写），选择器和表单类组件按输入的种类（图标选择、调色板按选中项的文字，数字选择器、数量加减器按数字，标签输入按标签列表、运行时和变量里一行一项，其余按文字），出错时描边变红、下面一行显示错误；服务器的 `errors[].pointer` 落到字段上；按 `id` 保存，中途去登录页再回来内容还在 |
| 文件字段 | `Taro.chooseImage`（图片）或 `Taro.chooseMessageFile`（其他文件）选出临时文件，提交时由 `Taro.uploadFile` 上传，进度交给 `onUploadProgress`；开发时模拟库收到的是读成 data URL 的文件 |
| 点击的效果 | `call`、`invoke`、`refresh`、`loadMore`、`submit`、`signOut`、设变量、显示和隐藏（作用于部件所在的整组，一开始可见的部件也能被隐藏）、打开和关闭（下拉菜单关上只关弹出层，按钮留下）、提示（`Taro.showToast`）；点击写成数据（`const A1: Action = …`），由屏幕的运行时交给每个宿主都跑的解释器 `lib/actions`（[交互规则](交互规则.md)）：每一步读那时的变量和表单，跳转参数在所有效果之后读，表单的 `then`/`catch` 也由它运行（`useScreenForm`），迟到的回答按规则处理。外链经能力注册表的 `link.open`（没有适配时 H5 打开、小程序复制），文件上传经 `file.pick`（没有适配时用平台的选择器） |
| 下拉刷新 | 有 `pullToRefresh` 数据源的页面在页面配置里打开 `enablePullDownRefresh`，`usePullDownRefresh` 重新加载，完成后 `stopPullDownRefresh` |
| 滚到底翻页 | `paging: scroll` 的数据源在 `onReachBottom`（`useReachBottom`）时加载下一页；页面本身滚动（不是页面里的某个盒子），所以平台的下拉刷新和触底都能收到 |
| 登录 | `auth: required` 的页面没有会话时记住自己（`rememberReturn`），`redirectTo` 登录页；登录表单成功后回到记住的页面（`takeReturn`），没有才走表单自己的跳转。401（刷新一次也不行）由 `runtime.whenUnauthorized` 结束会话、记住当前页、去登录页 |
| 会话 | 令牌经 `Taro.setStorage` 存（`TokenStorage`：`getStorage` / `setStorage` / `removeStorage`），H5 上就是 `localStorage` |
| 外部链接 | 小程序不能直接打开外部网页（要配置 web-view 业务域名），所以复制地址并提示；H5 直接打开 |

传输层是 `src/kit/app/transport.ts` 的 `createTaroTransport`：JSON 走 `Taro.request`，带文件的请求体走 `Taro.uploadFile`（一次一个文件，是平台的限制；其他字段作为 `formData`，内容类型由平台写）。`Taro.request` 用 `responseType: "arraybuffer"` 拿回答的原始字节（`dataType` 不让平台自己解析），再按和 Web、React Native 一样的规则读：JSON 解析，文本是字符串，PDF、图片这类文件是 `{ name, type, dataUrl, size }`（见 [导出](导出.md#回答怎样读)）；小程序没有 `btoa`、`TextDecoder` 时用纯 JS 实现。`Taro.uploadFile` 的回答只能是文本，按 JSON 或文本读。没有 `AbortController`：被取代的请求的回答由运行时丢掉。

| 滚轮选择器 | 点一项转到它，不能拖动 |

| 签名板 | 手指在板上画（触摸事件，`catchMove`），笔画画成路径图片 |
| 复制行 | 不直接调用剪贴板：复制交给 `onCopy`（应用的 `clipboard.write` 能力，打印器还没接） |
| 数字键盘的 `submit`、标签输入的 `add`/`remove` | 组件的 `onSubmit`、`onAdd`、`onRemove` 回调，导出的小程序运行接在上面的动作 |
| 纹理（`look.texture`） | 不画（编辑器自己画的图案），记一条 `look` |
| 毛玻璃（`backdrop-filter`） | 新的 WebView 照画；旧的 Android WebView 只剩填充色 |
| 指针移入 | 当作点击，记一条 `trigger` |
| 延迟触发 | 屏幕显示后自己运行（`useAfter`）；数据重复里的当作点击，记一条 `trigger` |
| 滚动到某个组件 | 不做，记一条 `scroll` |
| 文档里的图片 | 写成 `src/assets/` 下的文件；PNG、JPEG、GIF、WebP、SVG 以外的格式不写，记一条 `image` |
| 外部链接 | 复制地址（见上），记一条 `link` |
| Skyline 渲染引擎 | 不支持：页面按默认的 WebView 渲染 |
| 分体按钮、上下文菜单、级联菜单打开的菜单 | 平台的操作表，最多 6 项（多的不显示）；上下文菜单长按打开；级联菜单的子菜单是第二个操作表，第一个最多 5 项加打开子菜单的一行 |
| 悬浮菜单 | 项目画在悬浮按钮上方，点别处关闭（不压暗屏幕） |
| 方向轮盘 | 手指拖动（`catchMove`），交出方向和松手（`onValueChange`、`onRelease`）；没有读屏的方向动作 |
| 抽奖、技能按钮、棋盘、登录或支付按钮 | 只发请求，按属性显示结果、冷却和棋盘（抽奖落定时 `onSettled`），没有演示；登录或支付按钮说出它要的能力（`onAsk`），不判断成功 |
| 停靠面板的标签页 | 开了自动布局的停靠面板，每个标签页的内容都打印进去（`DockPane`），点标签显示那一页；没开自动布局的只打印选中的那页 |
| 工具提示、弹出框、悬停卡片、导航菜单 | 占着画布上展开时的大小，点一下（工具提示长按）在触发按钮旁边打开，不是平台的浮层 |
| 侧面板 | 旁边的窗口内容只画空白（画布上的示意文字不画），窗口最宽是屏幕宽度减 32 |
| 模态的侧边导航 | 展开时盖在旁边的内容上，没有遮罩 |
| 图表（图表、散点图、仪表、迷你趋势图） | 照画布的画法画成 SVG 图片（`<Image>` 的 data URL，颜色按当时的深浅色算好），轴上的名字是图片上的文字；直角坐标的图表拉伸到所在的宽度（线宽不变），环形和雷达保持比例；没有悬停时的数值提示 |
| 以表格为数据的组件 | 按列结构画；绑定到数据时仍显示设计的行，记一条 `binding` |
| 数据表格、日程、看板、可排序列表、左滑行的操作 | 草稿加回调属性（`onSearch`、`onSort`、`onPage`、`onSelect`、`onMonth`、`onDay`、`onOpen`、`onMove`、`onAdd`、`onReorder`、`onChange`），导出的小程序运行接在这些事件上的动作，可排序列表的行和左滑行的开合写回绑定的变量或表单字段；卡片、文件、行由数据决定，删除按钮只发出请求 |
| 拖动和左滑的替代 | 看板打开卡片后用箭头移动（没有拖动）；可排序列表点一行出现上移、下移按钮；左滑行长按展开收起 |
| 菜单栏 | 点菜单后用平台的操作表（`showActionSheet`）列出项目，最多 6 项 |
| 代码块 | 复制按钮用平台的剪贴板（`setClipboardData`） |
| 日程 | 月份和星期名用英文（画布按页面语言） |
| 视频、音频、网页、动画 | 画布没有文件时的替身：不用 Taro 的 `<Video>`、音频上下文和 `<WebView>`，不播放、不加载；音频的进度条停在 `position` 给的位置 |
| 相机、地图、视频通话 | 套件画的替身，导出时作为插槽（`src/custom/slots/<名字>.tsx`）的 `children`；地图替身不能拖动缩放 |
| 轮播的左右箭头 | 和手机应用一样画成“第几张/共几张”；横向翻页不挡页面上下滚动，竖向翻页用 `catchMove` |
| 二维码的复制 | `Taro.setClipboardData`，复制成功后才显示“已复制” |
| 问卷自己说的话 | 英文（“Question 1 of 2”“Next”），套件没有词表 |
| 组件事件（`play`、`markerTap`、`crop`……） | `on<事件>` 回调属性，导出的小程序把接在 `on:<事件>` 上的动作接上运行；槽位族（`tab:*`）对没有自己动作的每一项运行；能力视图的插槽用 `onEvent` 发出事件 |
| 减少动态效果 | 小程序没有这个设置：跑马灯、闪烁文字、数字滚动照常动，只有 H5 按系统设置停下 |

## 主题和尺寸

- **主题**：设计的风格（27 套风格都可以，测试台的画廊用 Material、iOS、微信和一套深色的 Spotify 核对）先在导出时算好颜色、字阶、圆角、按钮造型，组件套件读 `src/generated/theme.ts`；颜色同时写成 CSS 变量（`theme.css`：`.m3e-theme { --md-sys-color-primary: …; … }`，深色在 `.m3e-theme.m3e-dark`）。只用类选择器，WXSS、TTSS 和 CSS 都能读。图标和 SVG 按当时的颜色画成 SVG 的 data URL 放进 `<Image>`（小程序的 `<Image>` 不认 `currentColor`）。
- **尺寸用 px，不用 rpx**：设计按点（pt）画，一个点就是一个 CSS px，所以关掉了 Taro 的 px→rpx 换算（`pxtransform`）。这样和画布、Web 应用、手机应用的尺寸一致，字号不会随屏幕宽度缩放，H5 也一样；代价是更宽的屏幕上不会等比放大。自由摆放的组件按设计的坐标放，栏、自动布局和“填满宽度”的组件随屏幕宽度伸缩。

## React 的版本

Taro 4 只支持 React 18，而 Web 应用、手机应用和 `packages/app-runtime` 用的是 React 19。导出这样把两者分开：

- 根目录的 `package.json` 固定 `react`、`react-dom`、`@types/react`、`@types/react-dom` 为 19 的版本（`root.ts` 的 `ROOT_REACT`），npm 就把它们留在根目录，`apps/miniapp` 的 React 18 装在 `apps/miniapp/node_modules`。
- Taro 的配置把 `react`、`react-dom`、`@tarojs/router` 指向应用自己的那一份（`require.resolve(…, { paths: [__dirname] })`），并且先在应用自己的 `node_modules` 里找包，所以 `packages/app-runtime`（React 只是 peer 依赖）在小程序里用的也是 React 18，整个页面只有一份 React。`tsconfig.json` 的 `paths` 让类型检查也读 React 18 的类型。
- Taro 的 React 插件声明了可选的 peer 依赖 `vite@^4`，所以 npm 不把 Web 应用用的 Vite 放在根目录，而是放进每个用它的工作区：在根目录直接运行 `npx vite` 不行，用 `npm run dev -w <工作区>`。

```bash

cd miniapp-kit && npm ci && npm run check   # 类型检查、ESLint、单元测试、weapp / tt / h5 三个构建
```

- **测试台**（`miniapp-kit/`）：`src/pages/gallery` 是组件画廊（`?style=wechat&dark=1&part=button`），`src/printed/` 是打印器把样例文档（全部点击方式的 proof 文档、各个组件组合）写成的页面，和导出的应用一样被类型检查、lint 和构建。`miniapp-kit/scripts/shots.cjs` 把画廊的 H5 和编辑器的风格画廊并排截图。`test/table/` 是交互一致性表（[交互规则](交互规则.md)）的每一行按导出的小程序印出的代码（屏幕、`calls.ts`、`spec.ts`，类型化客户端和运行时用替身），由 `bun run gen:miniapp` 写出；`test/table.test.ts` 在假的 Taro 页面栈上逐行运行，也会点某个位置、发出组件事件；第四批起小程序没有已知分歧。
- **`check:product … shop`**：导出绑定了接口的商店（`boundShopDoc`），`npm run build` 构建三个平台，读产物：`app.json` 里每个屏幕一个页面，每页有脚本、配置和 WXML / TTML，没有 `eval`、`new Function`、`XMLHttpRequest`、`fetch`、`localStorage` 等小程序不能用的东西，也没有模拟库。然后在 Chromium 里驱动 H5（`scripts/check-miniapp-app.ts`）：在模拟库上（`taro build --type h5 --watch`）列表有数据、触底翻页、滚到最后时最后一行在底部的按钮上方、`new-user` 和 `network-error` 场景、点一行进详情（参数在查询串里）、直接打开详情的地址、从详情进上传图片的表单（参数带过去）、用平台的选图（H5 上是浏览器的文件选择）选一张图片上传并带着提示回到详情、表单按 Schema 拒绝、`name-taken` 的错误落到名称上、未登录时先去登录页再回来、登录后打开要会话的订单页；在真实后端上（生产构建，`/api` 转发给检查启动的后端）开始是空的、要先登录、422 落到名称上、加好的商品出现在列表里并能打开、过期令牌的 401 去登录页再回来、后端停掉后显示出错的设计。截图在 `<文件夹>/shots-shop/miniapp-*.png`，和 Web 应用的 `mocks-*.png`、`server-*.png` 放在一起可以对照。

## 已知限制

- **没有在真的微信或抖音开发者工具、真机里运行过**：检查只能读构建产物、在 Chromium 里跑 H5。小程序特有的部分（胶囊的位置、`switchTab`、`Taro.uploadFile`、`getStorage`、自定义 tabBar、真机上的下拉刷新）由类型、单元测试（假的 Taro API）和 Taro 自己保证，第一次发布前请在开发者工具和真机上走一遍。
- H5 上的下拉刷新是 Taro 的触摸手势，Chromium 里没有驱动它；触底翻页驱动了。
- 一个请求只能上传一个文件（`Taro.uploadFile` 的限制）；同一个字段的多个文件只发第一个。没有文件的 `multipart/form-data` 请求按 JSON 发送。
- 请求不能中途取消；被取代的请求的回答由运行时丢掉。
- 浮层没有地址；实时通道（AsyncAPI）还没有绑定到屏幕。
- 页面切换用平台自己的动画（`navigateTo`、`navigateBack` 都不能选动画），不按设计的过渡；返回动作自己的 `motion` 交到套件的 `goBack(spec, o)` 为止（`lastMove()` 读得到），不改变返回的动画。
- 访客用平台的返回或切换标签离开不算“离开”（只有应用自己的跳转和浮层计数）；分栏的 `resize`、地图替身的 `regionChange`、音频播放器的 `ended` 组件不发出，接在上面的动作不运行（导出报告列出）。
- 只有已退役的 `resizable` 是占位块（见上）；画成原子的组件里，拆出的树没有显示的位置（比如通知栏第二条）的点击不保留，并记一条 `slot`。

## 依赖的安全问题（已知，暂不处理）

`npm audit` 对导出的小程序报出 21 个问题，其中 6 个严重，都来自 Taro 4 自己的依赖：`@tarojs/components` 带的 swiper（原型污染）、lodash-es，以及开发服务器用的 webpack-dev-server。npm 给的唯一修法是降回 Taro 3，而 Taro 3 只支持更旧的 React，要重做组件套件和 React 的隔离，所以暂时保留 Taro 4，等 Taro 4 升级这些依赖后再跟进（导出时用 `bun scripts/gen-versions.ts --registry` 看有没有新版本）。

降低风险的现状：

- 组件套件和打印器都**不用** Taro 的 `Swiper`（轮播是套件自己用触摸翻页画的），导出的页面不会走到 swiper 的代码。
- webpack-dev-server 只在 `npm run dev:*` 时运行，不进构建产物；只在自己电脑上用它，不要把开发服务器暴露到公网。
- 发布前在导出的工程里运行 `npm audit --omit=dev -w <作用域>/miniapp`，看生产依赖里还剩什么。
