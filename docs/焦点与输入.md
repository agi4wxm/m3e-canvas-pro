# 焦点与输入（键盘和手柄）

游戏的局外界面（大厅、商城、背包、暂停菜单）、电视和电脑上的应用要能只用键盘或手柄操作。M3E 把“焦点怎样移动”
当作设计里的数据：哪些部件能获得焦点、每一屏焦点从哪里开始、上下左右各去哪里、确认和取消做什么。规则只写一份，
在 `lib/focus/`，不依赖任何平台：预览和导出的网页应用直接运行它，手机端、小程序和以后的引擎（第九批 P8：Godot 的
focus neighbour 和 InputMap）拿到同一份数据。

本文是游戏阶段整改计划第六批 H5 的前一半。输入动作到按键的映射表（`Doc.inputs`）不在这里：它要建在第五批 K2
声明的、有类型的输入动作（`move: vec2`、`skill1: bool`）之上，K2 合并后再做；本文的按键表 `UI_BINDINGS` 就是为它留的位置。

## 模型

| 东西 | 在哪里 | 是什么 |
| --- | --- | --- |
| 能获得焦点的部件 | 自动 | 点了会做事的部件：有自己的点击动作（不是“指针移入”或“延迟”开始的），某个位置有点击动作（标签栏的一项），自己会选中的位置（标签页），输入框、开关、滑块，带触发按钮的菜单 |
| `Item.focus.focusable` | 部件 | `false`：有点击也不获得焦点；`true`：现在还没有点击也获得焦点（游戏以后再接的按钮） |
| `Item.focus.next` | 部件 | `{up, down, left, right}`：这个方向去哪个部件（同一屏的部件 id），盖过按布局算出的；`"none"` 表示这个方向不动 |
| `Frame.focus.first` | 屏幕 | 屏幕出现时焦点在哪个部件；没有时是阅读顺序（从上到下、同一行从左到右）的第一个 |
| `Frame.focus.cancel` | 屏幕 | 在这一屏按取消时先运行哪个部件的点击（战斗、大厅里的暂停或菜单按钮）；没有时就关掉打开的东西或返回 |
| `Frame.focus.wrap` | 屏幕 | 某个方向没有部件时绕到另一边（短菜单适用） |

**方向怎样算。** 从当前部件出发，只看中心在那个方向上的部件；沿方向的距离算一次，偏离那条线的距离算两次（所以“同一行
的下一个”先于“下一行的”）。部件自己的 `next` 优先；它指的部件不在这一层上时仍按布局算。数据重复出来的副本（`列表#2/行`）
读它来源部件的设置。

**确认** 就是那个部件的点击（和指针点一下完全一样，经 `lib/actions` 的解释器运行）；输入框获得键盘输入，开关切换。
**取消** 依次是：屏幕的 `cancel` 部件在这一层上就运行它的点击；否则关掉打开的菜单或对话框，否则关掉叠在上面的屏幕，
否则返回上一屏。

**浮层留住焦点。** 叠在上面的屏幕（`overlay: true` 打开的）、打开的菜单和对话框是新的一层：焦点只在最上面一层里移动，
下面的部件拿不到；它关掉时焦点回到下面那一层**离开时的位置**（不是打开它的按钮，而是当时焦点所在的部件）。返回上一屏
也一样，回到那一屏时焦点在原来的位置；重新打开的屏幕从 `first` 开始。这和宿主契约（`docs/世界宿主契约.md`，第五批 K2）
的“浮层打开时释放输入、关闭后恢复”是同一件事的界面一侧。

## 按键和设备

| 动作 | 键盘 | 手柄（标准布局） |
| --- | --- | --- |
| 上下左右 | 方向键 | 十字键、左摇杆（推过 0.5 算按下，回到 0.35 以下算松开；按住 0.4 秒后每 0.12 秒重复） |
| 确认 | Enter、空格 | 下方的面键（Xbox 的 A，PlayStation 的 ✕） |
| 取消 | Escape、Backspace | 右侧的面键（B，○） |

**当前设备。** 页面记住访客正在用什么：键盘、手柄或触摸（鼠标也算触摸）。用指针时不画焦点框，按键照旧；按一下方向键或
手柄的任意键，焦点框出现在焦点该在的地方（第一下只显示，不移动）。点一下鼠标，焦点框又消失。

**按键提示。** 表达式多了一个根 `input`：`input.device`（`keyboard`、`gamepad`、`touch`），`input.keyboard`、`input.gamepad`、
`input.touch`，`input.pad`（手柄的家族：`xbox`、`playstation`、`nintendo`、`generic`），`input.hint.<动作>`（当前设备上这个
动作的键：Enter、A、✕；触摸时是空字符串）。文字里写 `{{input.hint.confirm}} 选择`，部件的显示条件写 `input.gamepad`，
设备一换就跟着变。没有这个根的宿主读到的是空。

**焦点框** 按 M3 的焦点指示：3 像素宽，离部件 2 像素，用风格的 secondary 颜色，圆角跟着部件自己的形状。

## 各宿主

| 宿主 | 做到什么 |
| --- | --- |
| 预览 | 全部：键盘、手柄（Gamepad API）、焦点框、按键提示。用指针时 ← 仍是返回、Escape 仍是关掉浮层或关掉预览；用键盘时方向键只移动焦点，Escape 是取消，在第一屏上没有可取消的时关掉预览 |
| 原型 Web、产品 Web | 文档写了焦点（任何一屏的 `focus` 或任何部件的 `focus`）时全部做到：导出的 `src/runtime.tsx` 带上驱动（`src/lib/focus/`，编辑器自己的文件原样复制），屏幕和部件的焦点设置按应用里的名字印成 `FOCUS_SCREENS`、`FOCUS_PARTS`，部件标上 `data-focus`。没写焦点的文档导出和以前逐字节相同 |
| 手机端（RN） | 平台移动焦点的地方（Android TV 的方向键、外接键盘、网页）由平台自己找下一个部件，套件给获得焦点的部件画同样的焦点框（`Surface`）；设计里的 `first`、`cancel`、`next` 写在 `src/generated/focus.json`，给产品自己的电视或键盘适配用（RN 的 `nextFocus*` 要原生视图句柄，套件还没接）。导出报告里有一条 `focus` |
| 小程序 | 微信、抖音小程序没有键盘和手柄事件，也不在页面上移动焦点：不画焦点框；设计的焦点写在 `src/generated/focus.json`，导出报告里有一条 `focus` |
| 引擎（第九批） | 读 `focus.json` 的同一份数据生成 Godot 的 focus neighbour；`UI_BINDINGS` 对应 `ui_up`、`ui_accept`、`ui_cancel` |

`focus.json` 的格式：`{version: 1, screens: [{screen, name, first, cancel?, wrap?, parts: [{id, label, box, next}]}]}`，部件按
阅读顺序，`box` 是部件在屏幕上的位置（屏幕自己的像素），`next` 是按上面规则算好的四个方向。

## 设计时怎样用

- 编辑操作 `set_focus {screen, first, cancel, wrap, parts: {部件 id: {focusable, next}}}`，读取工具 `describe_focus {screen}`
  （应用内 AI 和 MCP 都有）；`null` 清掉一项。
- 模板 `game-menu-flow`（游戏局外菜单流程）：大厅的焦点从“开始游戏”开始，菜单按钮是大厅的取消（Escape 或 B 打开叠在上面
  的暂停菜单），商城和背包取消就返回，暂停菜单留住焦点、上下绕圈，底下的提示按设备显示键名。
- 文件里的焦点在读入时清理（`lib/focus/clean.ts`）：类型不对的字段去掉，id 只是长度正常的字符串；复制部件时 `next` 跟着副本走。
  这些字段都是可选的新字段，没有格式版本的迁移。

## 测试

- `lib/focus/*.test.ts`：方向、覆盖和 `none`、起点、取消、层的留住与恢复、手柄的按下与重复、设计里的焦点图、文件清理、
  导出的网页应用带上驱动并通过类型检查、手机端和小程序拿到 `focus.json`。
- `e2e/focus.e2e.ts`：在预览里只用键盘走完大厅 → 商城 → 背包 → 暂停菜单（返回后焦点回到原处、暂停菜单里绕圈且出不去、
  提示显示 Enter 和 Esc），再用模拟的手柄（Gamepad API）做同样的事，提示显示 A 和 B。
- `rn/__tests__/focus.test.tsx`：获得平台焦点的部件画焦点框。
- 一致性表现在还表达不了焦点：表里的设计没有布局，预览、手机端和小程序的测试床（`tinyReact`、RNTL、小程序替身）都不排版，
  方向算不出来；要加表行，得先给表加“按键”这一步和每个宿主的布局。确认就是点击、取消就是返回，这两条已经由表里的点击和
  `overlay-back-closes`、`go-and-back` 守住。
