# 导出

一份设计可以导出成两种项目：

| 导出 | 是什么 | 代码 |
| --- | --- | --- |
| **原型项目** | 一个 React 应用：屏幕和点击后的行为，和预览一样运行。下载为 zip，可以只导出一个屏幕 | `lib/exportProject.ts` |
| **完整产品（monorepo）** | 一个 npm workspaces 单仓库：Web 应用、接口契约和客户端、模拟库、后端骨架、契约测试。可以写进电脑上的文件夹，之后再导出到同一个文件夹，不会删掉自定义代码 | `lib/export/` |

在编辑器里，两种都在“问 AI”对话框（以及提示词面板的“代码”页）的下载区：先选“原型项目”或“完整产品（monorepo）”。原型项目的导出和以前完全一样，字节不变（`lib/export/product.test.ts` 用摘要守着）。

## 完整产品的结构

```text
package.json          npm workspaces；脚本 dev、build、typecheck、lint、test、format
tsconfig.base.json    各工作区共用的 TypeScript 设置
eslint.config.js      ESLint（flat config），lint 不允许有警告
.prettierrc.json      Prettier，只格式化自定义代码
.prettierignore       列出全部生成的文件（Prettier 改过的生成文件会被当成手改，下次导出报冲突）
README.md             中文说明，后面附简短英文
AGENTS.md             给 Codex、Claude Code 等 AI 编程助手的规则：哪里能写、哪里不能写
CLAUDE.md             （自定义）引用 AGENTS.md，可以加自己的说明
.m3e/manifest.json    导出清单：每个文件、它是生成的还是自定义的、它的哈希
apps/web              Web 应用（React + Vite + Tailwind）
  src/main.tsx                入口：开发时先接上模拟库，再运行自定义的 setup，再画应用
  src/generated/              由设计生成：App.tsx、runtime.tsx、theme.tsx、index.css、
                              screens/（每个屏幕一个文件）、routes.ts 和 router.ts（每个屏幕一个地址，
                              浏览器的前进后退）、api.ts（接口客户端）、mocks.ts（只在开发时）
  src/components、src/lib、src/hooks、src/styles   从编辑器复制的组件，只复制屏幕用到的
  src/custom/setup.ts         （自定义）应用画出来之前运行：接 SDK、读令牌、换传输层
  src/custom/Providers.tsx    （自定义）包住整个应用：第三方 SDK 的 Provider
packages/api          接口契约和客户端，Web、移动端、小程序共用
  openapi.yaml、asyncapi.yaml  OpenAPI 3.1 和 AsyncAPI 3.0 契约
  src/transport.ts            Transport 接口：不依赖 DOM，也不假设有全局 fetch
  src/client.ts、src/fetch.ts  ApiError、send()、基于 fetch 的默认传输层
  src/generated/              types.ts（契约里的类型）、operations.ts（createApi：每个接口一个函数）、
                              contract.ts（契约数据）
packages/mocks        模拟库，只在开发时使用，生产构建里没有
  src/index.ts                createMockTransport()：传输层模拟，哪里都能用（含小程序和编辑器预览）
  src/msw.ts、browser.ts、node.ts  同一套路由的 MSW handler、浏览器 Service Worker、Node 测试
  src/generated/              fixtures.ts（每个接口默认的回答）、scenarios.ts（命名场景）
server                后端骨架（Node + TypeScript + Fastify）
  src/main.ts、src/app.ts      启动、组装（先自定义 setup，再注册契约里的全部路由）
  src/generated/              routes.ts、handlers.ts（每个接口的处理函数类型）、validation.ts、errors.ts
  src/handlers/<接口>.ts       （自定义）每个接口一个文件，先返回 501 Not Implemented
  src/custom/setup.ts         （自定义）插件、钩子、数据库、契约外的路由
  build.mjs                   esbuild 打包成 dist/main.js
contract-tests        契约测试：后端是否符合契约
apps/mobile           移动应用（React Native、Expo）的位置，后续生成
apps/miniapp          小程序（Taro）的位置，后续生成
```

导出的产品里：

```bash
npm install
npm run dev        # 同时启动后端（3001）和 Web 应用；开发时 Web 应用的接口由模拟库回答
npm run typecheck  # 每个工作区 tsc
npm run lint       # ESLint 不允许警告，Prettier 检查自定义代码
npm test           # 每个工作区的 Vitest
npm run build      # Web 应用（vite build）和后端（esbuild）
```

开发时 `VITE_API_MOCKS=off` 让 Web 应用请求本地后端（开发服务器把 `/api` 转发到 `http://127.0.0.1:3001`，`API_TARGET` 可改），`VITE_API_MOCKS=msw` 改用 MSW 的 Service Worker 提供模拟数据（浏览器网络面板里能看到）。生产构建由 `import.meta.env.DEV` 把模拟库整段去掉，`scripts/check-product.ts` 会检查构建产物里没有它。`CONTRACT_BASE_URL=http://127.0.0.1:3001 npm test -w contract-tests` 对运行中的后端跑契约测试。

## 生成的文件和自定义代码

每个文件只有两种：

- **生成的**（`generated`）：导出拥有它，每次导出都会重写。清单里记着导出写下的内容的哈希。要改屏幕、导航、文字、接口，就改设计再导出。
- **自定义的**（`seeded`，自定义代码，人或 AI 写）：导出只在它不存在时写一次初始内容，之后不再碰它，无论里面写了什么。位置：`server/src/handlers/*`、`server/src/custom/*`、`apps/web/src/custom/*`、`CLAUDE.md`。

一个自定义文件导出出来的内容（它导出的名字和签名）就是固定的约定：以后要加新的扩展点，就加新的自定义文件，而不是改旧的。生成的代码只引用自定义文件里这些固定的导出，所以无论自定义代码写成什么样，重新导出都能接上。新加的接口会多出一个 `server/src/handlers/<接口>.ts`；契约里去掉的接口，它的处理函数文件留在原处（不再被引用）。

`.m3e/manifest.json`：

```json
{
  "format": "m3e-product-manifest",
  "version": 1,
  "generator": "M3E Canvas Pro",
  "product": "shop",
  "files": {
    "apps/web/src/generated/App.tsx": { "kind": "generated", "sha256": "…" },
    "apps/web/package.json": { "kind": "generated", "sha256": "…", "keys": ["name", "dependencies.react", "…"] },
    "server/src/handlers/getProduct.ts": { "kind": "seeded", "sha256": "…" }
  },
  "pending": { "apps/web/src/generated/routes.ts.m3e-new": "…" }
}
```

同一份设计导出两次，清单和每个文件都逐字节相同（没有时间戳），所以再导出一次什么都不写。

## 重新导出

导出到一个已经有产品的文件夹时（`lib/export/merge.ts` 的 `planExport`，纯函数，单元测试覆盖每条规则）：

| 文件 | 磁盘上 | 做什么 |
| --- | --- | --- |
| 生成的 | 没有 | 写入 |
| 生成的 | 和这次导出的一样 | 不动（未变） |
| 生成的 | 和上次导出写下的一样 | 重写 |
| 生成的 | 上次导出之后被改过，或者不是导出写的同名文件 | **冲突**：不覆盖，新版本写在旁边的 `<文件>.m3e-new`，在报告里列出 |
| `package.json` | 被加过依赖或脚本 | **合并**：导出写的键用导出的值（依赖按固定版本），上次导出写过、这次不再写的键去掉，别人加的保留 |
| 自定义的 | 没有 | 写入初始内容 |
| 自定义的 | 有 | 不动，无论内容 |
| 这次不再生成的文件 | 和上次导出写下的一样 | 删除（变空的文件夹一起删） |
| 这次不再生成的文件 | 被改过 | 留在原处，报告里列出 |
| 上次的 `.m3e-new` | 冲突已解决，内容没被改过 | 删除 |

解决冲突：把改动移到自定义代码里，再用 `.m3e-new` 替换原文件（或者把两个都删掉再导出一次）。冲突在解决之前每次导出都会报。给某个工作区加依赖用 `npm install <包> -w <工作区>`，重新导出会保留。清单丢了或读不懂时当作没有导出过：只会多报冲突，不会覆盖任何改动。清单写在最后，导出中途停下也一样。

文件夹里有别的东西、又没有清单时，导出会先拒绝（编辑器里要再按一次，命令行和 MCP 要加 `--force` / `force: true`）；即使这样，同名的文件也只会得到 `.m3e-new`，不会被覆盖。

## 在编辑器里导出到文件夹

在 Chromium 里选“完整产品（monorepo）”后，“导出到文件夹…”用 File System Access 选一个文件夹，写入后显示报告：写入、未变、保留的自定义代码、删除、冲突（列出每个文件）和合并的 `package.json`。编辑器按项目记住这个文件夹（IndexedDB 的 `export-dir:<项目>`，和绑定文件一样保存句柄），下次直接“再次导出到 <文件夹>”；浏览器要求时会再问一次写入权限。不能选文件夹的浏览器下载 zip（zip 里带清单，解压后的文件夹也能再导出进去）。

## 命令行和 MCP

```bash
bun scripts/export.ts <项目文件或文件夹> <输出文件夹> [--lang zh] [--force]
```

命令行读取编辑器保存的项目文件（单个 `.json` 或带 `m3e-project.json` 的文件夹），打印报告。MCP 服务器在文件模式下多一个工具 `export_product {dir, force?}`（相对路径从项目文件所在的文件夹算起，只读会话没有它，配对了编辑器标签页时请在编辑器里导出），返回写入、冲突、保留的自定义代码等。发布的 MCP 服务器把导出要复制的编辑器源文件打包在自己里面（`mcp/build.ts`，清单在 `lib/export/sourceList.ts`，和 `lib/exportSources.ts` 由测试对齐），不需要源码仓库。

## 版本

生成的每个 `package.json` 都写精确版本，来自 `lib/versions.generated.ts` 的 `PRODUCT_VERSIONS`：和原型项目共用的包按本仓库 `bun.lock` 的版本；本仓库不用的包（ESLint、Prettier、Fastify、MSW、esbuild、tsx、Vitest、普通的 Vite 等）写在 `lib/exportPackages.ts` 的 `PRODUCT_PINS`，查过 npm 仓库。`bun scripts/gen-versions.ts --registry` 再查一遍并列出有新版本的包，改了之后 `bun run gen:versions`。TypeScript 固定在 6.0（typescript-eslint 只支持到 6.0，编辑器自己用的 7.x 没有它要的 JavaScript 接口），复制来的组件在 6.0 下也能通过类型检查。

## 后续目标怎样接入

产品由一组目标（`ProductTarget`，`lib/export/types.ts`）组成，按 `lib/export/targets/index.ts` 的 `PRODUCT_TARGETS` 顺序生成：

```ts
interface ProductTarget {
  id: string;
  build(ctx: ProductContext): Promise<Workspace | null> | Workspace | null;
}
```

`ProductContext` 带着文档、测量的宽度、语言、产品名和 npm 作用域、接口模型（`ctx.api`）、固定版本（`ctx.version(pkg)`）、读取编辑器源文件的函数和警告列表；`Workspace` 是一个文件夹（`dir`）、它的包名、它参与哪些根脚本、它的文件（每个标明 `generated` 或 `seeded`）和 README 里的一行说明。根目录（`lib/export/targets/root.ts`）最后按这些工作区生成。

| 后续工作 | 接在哪里 |
| --- | --- |
| 接口模型（Doc.api） | 已接上：`buildProduct` 自己从 `doc.api` 读（`contractOf`：`openApiObject`、有实时通道时 `asyncApiObject`、不带注释的 `schemaToTs`，见 [接口](接口.md)），`apiModelOf` 读出接口列表；`{ api }` 选项仍可以用别的契约代替它 |
| 屏幕绑定接口 | `webTarget`（`lib/export/targets/web.ts`）：屏幕通过 `src/generated/api.ts` 的 `api` 调接口，数据钩子写到 `packages/api/src/generated/hooks.ts` |
| 模拟库 | `mocksTarget`：生成 `src/generated/fixtures.ts`（每个接口的数据）和 `scenarios.ts`（命名场景），延迟和错误在 `MockAnswer` 里 |
| 后端校验 | `serverTarget`：`src/generated/validation.ts` 按接口给出 Fastify 的 JSON Schema，路由已经把它传给 Fastify |
| React Native | 替换 `mobileTarget`（现在只写 `apps/mobile/README.md`）：返回 `apps/mobile` 工作区，用 `packages/api` 和 `packages/mocks`（`createMockTransport`，或 msw/native） |
| 小程序（Taro） | 替换 `miniappTarget`：在 `packages/api` 旁加一个基于 `Taro.request` 的 `Transport` |
| 契约测试 | `contractTestsTarget`：现在检查每个接口都有路由，`CONTRACT_BASE_URL` 时检查运行中的后端 |

新目标的检查加进 `scripts/check-product.ts`（它导出一个带契约的示例产品，真的安装、检查、构建、测试、启动后端跑契约测试、在 Chromium 里打开应用，再导出一次验证合并规则）。

## 安全

文档和契约里的文字进入生成代码时只以转义后的字符串、JSON 数据或只含字母数字的标识符出现，不进注释；进入路径时只经过 `safeSegment`、`npmSlug`、`identifierOf` 这类只留字母数字的函数。所有路径在写入前检查（`lib/export/paths.ts`）：不能有 `..`、绝对路径、盘符、反斜杠、控制字符、Windows 设备名，也不能有两个只差大小写的路径；Node 的写入器还拒绝经过符号链接写到文件夹外面。`lib/exportInjection.test.ts` 用带敌意文字的文档和契约走完整导出，检查生成的代码都能解析、标记不会变成代码里的名字、路径和包名都是安全的、YAML 里的文字只在引号里。

## 检查

```bash
bun run check:product <空文件夹>
```

它要联网（`npm install`），需要装好 Playwright（和端到端测试一样），不在 `bun run test` 里；CI 里是单独的一项。`… systems` 和 `… parts` 换成原型和变量的文档、全部组件的文档（这两个不开浏览器）；`… shop` 是带自己接口的文档（`doc.api` 是商店的 OpenAPI 加聊天的 AsyncAPI，`lib/api/fixtures`），检查导出从文档读出的契约照样安装、构建、测试并通过契约测试。改了 `lib/export/` 或导出用到的组件后要跑。

## 已知限制

- 文档没有接口（`Doc.api`）时，契约是空的：客户端只有 `request`，后端没有路由，模拟库没有数据。客户端只为 JSON 的请求体和响应生成类型，`multipart/form-data` 的上传和引用可复用响应（`components.responses`）的错误还是 `unknown`。
- Web 应用的屏幕还是原型的屏幕，还没有绑定接口；路由只有屏幕，没有参数（比如 `/products/:id`），浮层没有地址。
- 生成的应用代码（`apps/web/src/generated`）在 ESLint 里关掉了几条只关乎写法的规则（未用的变量、React Compiler 的几条），由导出自己的测试保证；自定义代码用全部规则。
- 后端还没有按契约校验请求（`validation.ts` 是空的），也没有数据库。
- `apps/mobile`、`apps/miniapp` 只是占位。
