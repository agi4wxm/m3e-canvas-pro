# 导出

一份设计可以导出成两种项目：

| 导出 | 是什么 | 代码 |
| --- | --- | --- |
| **原型项目** | 一个 React 应用：屏幕和点击后的行为，和预览一样运行。下载为 zip，可以只导出一个屏幕 | `lib/exportProject.ts` |
| **完整产品（monorepo）** | 一个 npm workspaces 单仓库：Web 应用、手机应用（Expo）、小程序（微信、抖音、H5）、接口契约和客户端、模拟库、后端骨架、契约测试。可以写进电脑上的文件夹，之后再导出到同一个文件夹，不会删掉自定义代码 | `lib/export/` |

在编辑器里，两种都在“问 AI”对话框（以及提示词面板的“代码”页）的下载区：先选“原型项目”或“完整产品（monorepo）”。原型项目的导出只在有意改变时变（`lib/export/product.test.ts` 用摘要守着；第四批起点击打印成 Action 数据、由解释器运行，有点击的文档摘要因此变过一次）。

**点击是数据。** 两种 Web 导出都把每一屏的点击打印成 `lib/actions` 的 Action 数据（屏幕文件顶上的 `homeScreenActions`），只把编辑器的 id 换成应用里的名字（屏幕、部件、变量的 key），由 `src/runtime.tsx` 的 `useActions` 交给编辑器自己的解释器（`lib/actions/run.ts`，复制进项目）运行——和预览守同一份[交互规则](交互规则.md)：每一步读上一步留下的状态，调用的参数在那一步读，跳转参数在所有效果之后读，迟到的回答按同一条规则处理。原型没有接口：调用、刷新、提交、退出登录照样打印成数据，运行时不发出、在浏览器控制台说一次，导出的 README 的“Not in this prototype”里列出来；平台能力按预览的方式由模拟库回答（`lib/capabilities/mock.ts`，`AppProvider` 的 `capabilities` 可以换成自己的）。

导出的产品里：

```bash
npm install
npm run dev        # 同时启动后端（3001）和 Web 应用；开发时 Web 应用的接口由模拟库回答
npm run typecheck  # 每个工作区 tsc
npm run lint       # ESLint 不允许警告，Prettier 检查自定义代码
npm test           # 每个工作区的 Vitest
npm run build      # Web 应用（vite build）、小程序（weapp、tt、h5 三个构建）和后端（esbuild）
npm run start -w apps/mobile          # 手机应用（Expo）：Expo Go、模拟器或网页；开发时接口由模拟库回答
npm run export:android -w apps/mobile # Metro 打包 Android
npm run dev:weapp -w apps/miniapp     # 小程序：构建到 dist/weapp，用微信开发者工具打开（dev:tt、dev:h5 同理）
```

`npm run typecheck`、`npm run lint`、`npm test` 都包括手机应用（tsc、根目录的 ESLint、Jest）；`npm run build` 不打包手机应用（用 `expo export`）。手机应用的接口地址是构建时的 `EXPO_PUBLIC_API_BASE_URL`（默认 `app.json` 的 `extra.apiBaseUrl`），`EXPO_PUBLIC_API_MOCKS=off` 让开发版也请求真实后端；开发菜单切换模拟库的场景，生产构建里没有模拟库。

开发时 `VITE_API_MOCKS=off` 让 Web 应用请求本地后端（开发服务器把 `/api` 转发到 `http://127.0.0.1:3001`，`API_TARGET` 可改），`VITE_API_MOCKS=msw` 改用 MSW 的 Service Worker 提供模拟数据（浏览器网络面板里能看到）。两种方式都是编辑器预览用的同一个模拟库：同样的种子、同样的数据、同样的场景；要换场景，在 `src/custom/setup.ts` 里 `setTransport(createMockTransport({ scenario: "new-user" }))`。生产构建由 `import.meta.env.DEV` 把模拟库整段去掉，`scripts/check-product.ts` 会检查构建产物里没有它（`createMockTransport`、`setupWorker`、引擎的标记 `m3e-mock-engine`、Service Worker 文件），并确认开发服务器上 MSW 回答的是按 Schema 生成的数据。`npm run contract -w contract-tests` 对后端跑契约测试（自己启动后端，或 `--base-url` 指定运行中的；`--strict` 时未实现也算失败），见 [后端](后端.md)。

## 前端共用的运行时（packages/app-runtime）

导出的每个前端（`apps/web`、`apps/mobile`、`apps/miniapp`）都跑在同一个运行时上。它是编辑器自己的代码，像模拟库的引擎一样原样复制进 `packages/app-runtime/src/engine/`（`lib/export/targets/appRuntime.ts` 的 `APP_RUNTIME_FILES`），所以导出的应用和编辑器的预览是**同一份实现**：

| 编辑器里的文件 | 做什么 | 预览也用它 |
| --- | --- | --- |
| `lib/bindings/expr.ts`、`format.ts`、`messages.ts` | 表达式（读成语法树求值，从不 `eval`）、按语言格式化、应用自己的文字（中英日韩） | 是 |
| `lib/bindings/rules.ts` | 字段按 Schema 校验（`fieldError`）、按类型转换（`typedValue`）、Problem（`problemOf`）、`errors[].pointer` → 字段（`problemFieldErrors`）、给人看的失败说明（`problemMessage`） | 是 |
| `lib/bindings/sources.ts` | 数据源的状态（加载、分页参数、各页合并、`hasMore`、总数、没有列表时的错误、乐观修改）、`data.<名字>` 读到的样子（`sourceView`）、区域显示哪个状态（`regionOf`，和预览的 `regionState` 同一规则）、屏幕参数（`screenParams`） | 是 |
| `lib/bindings/form.ts` | 表单的请求体、校验结果和 `form.` 读到的样子 | 是 |
| `lib/api/types.ts`、`transport.ts` | 契约的类型、`Transport` 接口 | 是 |
| `lib/api/body.ts` | 传输层怎样读回答（`readBody`），小程序的传输层从这里用；`packages/api` 里是同一个文件 | 模拟库给出同样的形状 |
| `lib/app/*.ts` | 运行时本身和 React hooks（不依赖 DOM、React Native、Taro、`fetch`） | 单元测试 `lib/app/app.test.ts` |

它只依赖 React（`peerDependencies`，用应用自己的那一份）。平台相关的都由调用方传进来：传输层（`fetch`、模拟库、`Taro.request`）、令牌存在哪里（`TokenStorage`：Web 的 `sessionStorage`、RN 的 `SecureStore`、小程序的 `Taro.setStorage`）、401 之后去哪里（`onUnauthorized`）、上传进度（`TransportRequest.onUploadProgress`，平台能报告时由传输层调用）。

### API

```ts
import { createRuntime, RuntimeProvider, useDataSource, useForm, useBindings, useSession, useRegion, useRequireAuth, useCall, useInvoke, sourceKey } from "@<作用域>/app-runtime"

const runtime = createRuntime({
  transport,                 // Transport：基础传输层，以后可以 runtime.setTransport(next, { presumed }) 换掉
  auth: AUTH,                // AuthConfig：由契约生成（见下）
  storage,                   // TokenStorage：{ get, set, remove }，可以是异步的；不给就只在内存里
  storageKey: "shop:session",
  presumed: true,            // 模拟库的会话一开始就算已登录（场景的 signedIn）；真实后端为 false
  lang: "zh",                // zh / en / ja / ko，runtime.setLang() 可改
  capabilities: registry,    // CapabilityHost：平台能力的注册表（用到能力的产品生成在 src/generated/capabilities.ts）；不给时都回答 not-implemented
})
const api = createApi(runtime.transport)   // packages/api 的类型化客户端，建在带会话的传输层上
runtime.onUnauthorized = (request) => { /* 去登录页，记住回来的地方：runtime.rememberReturn(…) */ }

<RuntimeProvider runtime={runtime}>…</RuntimeProvider>
```

**`Runtime`**（`createRuntime` 的返回值）

| 成员 | 说明 |
| --- | --- |
| `transport` | 带会话的传输层：按每个接口的 `security` 加令牌（`AuthConfig.security`）；登录接口 2XX 时记下令牌开始会话，刷新接口更新令牌，登出接口结束会话；401 时用刷新令牌换一次新令牌并重试，还是 401 就结束会话并调用 `onUnauthorized`（登录接口自己的 401 不算） |
| `setTransport(next, { presumed })`、`restart(presumed)` | 换后端或模拟库开始新会话（切换场景）：数据缓存、会话清空，`epoch` 加一，屏幕上的数据源重新加载；之前发出的请求作废 |
| `session` | `SessionStore`：`get()` 得到 `{ session, presumed, restored }`，`signedIn`、`token`、`signIn()`、`update()`、`signOut()`、`ready`（读完存储） |
| `sources` | `SourceCache`：按 `key` 缓存（`sourceKey(operationId, 参数)`），`load(spec, { more, force })`、`enter(spec)`（有数据时在后台重新加载）、`refresh`、`loadMore`、`optimistic(key, row, { remove } \| { patch })`（返回撤销函数）、`clear()`。同一个 key 的新加载会取消旧的（有 `AbortController` 的平台中止请求，没有的也丢掉旧回答） |
| `call(fn, { optimistic, then, catch, status, key })` | 点击发出的调用：先做乐观修改，2XX 运行 `then(response, status, { here })`，失败时撤销乐观修改并运行 `catch(problem, status, { here })`；把应用送去登录页的 401 不运行 `catch`。迟到的回答按[交互规则](交互规则.md)的同一条规则：运行时重来之后、或同一类（`key`，`callKey(屏幕, 部件, 接口)`）有更新的调用之后到达的回答什么都不运行、不撤销，返回 `dropped`；`here` 说访客是否还在点击留下的地方（`moved()` 计数，点击自己的跳转不算），不在时应用只做数据效果、不跳转。返回 `CallResult`，从不抛错 |
| `invoke(name, args, { then, catch, key })`、`setCapabilities(host)` | 点击调用的平台能力（[平台能力](平台能力.md)）：经注册表交给适配，完成时运行 `then(result, { here })`，没做到时运行 `catch(error, { here })`（`error.type` 是 `cancelled`、`failed`、`unavailable`、`not-implemented`、`denied`、`timeout`）；没有注册表时回答 `not-implemented`；运行时重来之前发出的回答作废。返回 `InvokeOutcome`，从不抛错。`setCapabilities` 换注册表（比如开发时换成模拟结果） |
| `signOut()` | 结束会话；契约有登出接口时顺便告诉它（带着令牌，不等回答） |
| `errorOf(e)`、`isUnauthorized(e)` | 客户端抛出的 `ApiError`（`status`、`body`）读成 Problem；其他异常是 status 0（无法连接服务器） |
| `rememberReturn(to)`、`takeReturn()` | 登录后回到哪里（守卫或 401 记下，登录页取一次） |
| `moved()`、`moves` | 访客每移动一次（打开、返回、叠上或关掉屏幕）应用告诉运行时一次；迟到的回答拿它比较 |
| `whenUnauthorized(go)` | 登记 401（刷新也不行）之后去哪里（通常是去登录页），返回取消登记的函数，正好用作 effect 的清理；`onUnauthorized` 属性是同一个东西 |
| `form(id, fields, initial)` | 按 `id` 保存的表单（`FormController`）：屏幕离开又回来（比如中间去了登录页）时填的内容还在，运行时重来时清空 |
| `ctx()`、`lang`、`setLang()`、`language`、`epoch` | 表达式求值的语言、时间、币种；语言和重来次数是可订阅的 `Store` |

**`AuthConfig`**（导出从契约生成）：`{ login?: operationId, refresh?: { operationId, method, path }, logout?: { … }, tokenField?, refreshTokenField?, security: { [operationId]: { header, prefix } | { query } | null }, fallback? }`。

**React hooks**

| hook | 返回 |
| --- | --- |
| `useDataSource(spec, { load: "enter" \| "demand" })` | `SourceHandle`：`data.<名字>` 读到的全部（`value`、`items`、`status`、`loading`、`loadingMore`、`hasMore`、`error`、`empty`、`ready`、`total`），加 `refresh()`、`loadMore()`、`remove(row)`、`patch(row, fields)`。进入屏幕时加载，参数（key）变了或运行时重来时再加载 |
| `SourceSpec` | `{ key, operation, load: ({ page, signal }) => api.xxx({ query: { ...参数, ...page } }, { signal }), list: { field }, paging, pageSize, args }`——`page` 是分页约定要加的参数（游标、偏移、每页条数） |
| `useForm({ id, fields, initial, send, extra, then, catch, status })` | `FormHandle`（给了 `id` 就是运行时按它保存的那个表单，见 `form()`）：`view`（`form.` 读到的样子）、`value(f)`、`text(f)`、`error(f)`、`set(f, v)`、`submitting`、`submit()`（运行时重来之后到达的回答不运行 `then` / `catch`）、`send()`（只发送，返回结果，交给解释器运行设计里的 `then` / `catch`）、`reset()`。`fields` 是每个字段的规则（`{ kind, required, schema }`，由契约生成）；提交时先校验，有错不发送，之后随输入更新；服务器的 `errors[].pointer` 落到字段上，改了那个字段就消失；有文件时 `send(body, { onUploadProgress })` 把进度交给传输层 |
| `useBindings(scope)` | `Bindings`：屏幕的表达式。`ev(expr)` 原值、`text(expr)` 文字、`fill("共 {{len(x)}} 件")` 模板、`num(expr, 设计值, min, max)`、`bool(expr, 设计值)`、`pick(expr, 选项, 设计值)`、`holds(expr)` 条件、`list(expr)` 重复的列表、`arg(expr)`/`path(expr)` 调用参数；`with({ item, index })`、`with({ form })`、`with({ response, status })`、`with({ error })` 得到内层作用域。自动加上 `auth`（`signedIn`、`user`）和 `now` |
| `useRegion(source, { load, emptyWhen })` | 区域此刻显示的状态：`ready`、`loading`、`empty`、`error`、`forbidden`（`regionOf`） |
| `useSession()` | `{ signedIn, user, token, restored, signOut }` |
| `useRequireAuth(required, onMissing)` | `auth: required` 的屏幕：读完存储后仍未登录就调用 `onMissing`（去登录页并记住回来） |
| `useCall()` | `runtime.call` |
| `useInvoke()` | `runtime.invoke` |
| `useRuntime()`、`useEpoch()`、`useLang()`、`useAuthScope()` | 运行时本身、重来次数、语言、`auth` 作用域 |

解释器也从这里转出（`run`、`startOf`、`chooseBranch`，类型 `Action`、`Host`、`Tap`……），加上宿主要用的几样：`outcomeOf(callResult)`、`formOutcomeOf(...)` 把运行时的结果读成解释器的 `Outcome`，`isFilled(v)` 是“已填写”的判断，`pathArg`、`queryArg`、`headerArg`、`bodyOf` 按契约放置解释器读出的调用参数。

另外导出 `keyOf(item, index)`（重复的 key：元素的 `id`，没有就用位置）、`regionOf`、`sourceView`、`screenParams`（屏幕参数按声明的类型读，没给的用示例值）、`problemMessage`、`problemOf`（只是状态码名字的标题，比如 `Unprocessable Content`，换成按状态说的话）、`statusMessage`、`fieldError`、`formatDate`、`formatNumber`、`appMessage` 和 `Transport`、`PageValue`（分页参数的值，`load({ page })` 的 `page` 可以直接放进客户端的 `query`）等类型。

### 各平台怎么接

- **Web**（`apps/web`）：`storage` 是包着 `sessionStorage` 的 `TokenStorage`；传输层是 `packages/api` 的 `createFetchTransport`（开发时换成模拟库）；上传用 `XMLHttpRequest` 报告进度。
- **React Native**（`apps/mobile`，已接上）：`storage` 用 `expo-secure-store`（`getItemAsync`/`setItemAsync`/`deleteItemAsync` 正好是异步的 `TokenStorage`；网页上没有它，用 `sessionStorage`）；传输层是 `createFetchTransport({ baseUrl })`，`multipart/form-data` 的上传另用 `XMLHttpRequest` 发送并报告进度；开发时 `runtime.setTransport(createMockTransport({ scenario }), { presumed })`，`presumed` 跟随场景的 `signedIn`。React 只有一份：Metro 让 `react`、`react-native` 无论谁要都解析到应用自己的那一份。屏幕读 `useDataSource`、`useForm`、`useBindings`（`src/generated/bind.ts` 包了一层），点击里属于接口的效果由 `src/generated/effects.ts` 用 `runtime.call` 运行，登录和 401 的回跳用 `rememberReturn`/`takeReturn`。
- **小程序**（`apps/miniapp`，Taro）：`storage` 是包着 `Taro.getStorage`/`setStorage`/`removeStorage` 的 `taroStorage`；传输层是组件套件的 `createTaroTransport`（JSON 走 `Taro.request`，带文件的请求体走 `Taro.uploadFile`，用它的上传进度调 `onUploadProgress`）；没有 `AbortController` 也可以（旧回答照样丢掉）；开发时 `setTransport(createMockTransport(…), { presumed: startsSignedIn(scenario) })`；401 和登录守卫用 `whenUnauthorized`、`rememberReturn` / `takeReturn` 在页面间 `redirectTo`。Taro 4 要 React 18：根目录固定 React 19，npm 把 React 18 装进 `apps/miniapp/node_modules`，Taro 的配置让整个小程序（包括 `packages/app-runtime`）只用这一份，见 [小程序](小程序.md)。

### 回答怎样读

三端的传输层（`packages/api` 的 `createFetchTransport`，Web 和 React Native 的上传用的 `XMLHttpRequest`，小程序的 `Taro.request`）都先拿到回答的原始字节（`arrayBuffer()`、`responseType: "arraybuffer"`），再用同一个 `readBody`（`lib/api/body.ts`，复制进 `packages/api/src/body.ts` 和 `packages/app-runtime`）决定 `TransportResponse.body`：

| 回答 | `body` |
| --- | --- |
| `HEAD`、204、304、没有内容 | `undefined` |
| `Content-Disposition` 是 `attachment` 或带文件名；或者类型不是文本（PDF、图片、XLSX、ZIP、音视频、3D 模型、字体……；图片、音视频、模型、字体无论语法如何都算文件，SVG、glTF 也是） | 文件 `TransportFile`：`{ name, type, dataUrl, size }`，名字取 `Content-Disposition`（先 `filename*` 的 UTF-8 / Latin-1，再 `filename`，去掉路径），没有就取请求路径的最后一段，缺扩展名时按类型补（`/orders/42/receipt` 的 PDF 是 `receipt.pdf`） |
| JSON：`application/json`、`text/json`、任何 `+json`（如 `application/problem+json`） | 解析后的值；不是合法 JSON 时是原文 |
| 文本：`text/*`、XML、YAML、CSV、JavaScript、NDJSON、`+xml`、`+yaml`…… | 字符串（UTF-8） |
| 没有 `Content-Type` | 是 UTF-8 文本就是字符串，否则是文件（`application/octet-stream`） |

模拟库回答下载时给的就是这个形状（文件带 `Content-Type` 和 `Content-Disposition`），所以同一个下载在编辑器预览、开发时的模拟库（直接或经 MSW）和真实后端上读到的一样（`lib/export/transports.test.ts` 逐一核对）。`data URL` 的 base64 在有 `btoa` 的平台用它，没有的（小程序、部分 Hermes）用纯 JS 实现；UTF-8 解码同理（`TextDecoder`），都不用 Node 的 `Buffer`。`Taro.uploadFile` 只能把回答作为文本交回（平台限制），上传的回答按 JSON 或文本读。`scripts/check-product.ts` 的商店在开发服务器上经 MSW 下载订单收据（PDF），核对字节完整。

## Web 应用：绑定接口的屏幕

`apps/web` 的屏幕把[数据绑定](数据绑定.md)写成代码，用的是上面的共用运行时和 `packages/api` 的类型化客户端，行为和预览一致（打印在 `lib/printBindings.ts`，`lib/printBehaviour.ts` 和 `lib/codegen.ts` 调用它；Web 自己的文件在 `lib/export/targets/webSources.ts`）。以商店为例：

```tsx
// src/generated/screens/ProductsScreen.data.ts：每个数据源一个 hook，以数据源命名
/** `data.products`: listProducts, a cursor-paged list, 20 at a time, the next page on scroll, pull to refresh */
export function useProducts() {
  return useDataSource({
    key: sourceKey("listProducts"),
    operation: "listProducts",
    list: { field: "items" },
    paging: { style: "cursor", items: "items", cursorParam: "cursor", nextField: "nextCursor", limitParam: "limit" },
    pageSize: 20,
    load: ({ page, signal }) => api.listProducts({ query: page }, { signal }),
  })
}

// src/generated/screens/ProductsScreen.tsx（节选）
const productsScreenActions = {
  row: { to: "product", transition: "slide", params: { productId: "item.id" } },
} satisfies Record<string, Action>
…
const products = useProducts()
const $ = scope.with({ data: { products } })
const productsState = useRegion(products)
const act = useActions("products", { scope: $.scope, sources: { products } })
…
{productsState === "ready" && $.list("data.products.items").map((item, index) => {
  const row = $.with({ item, index })
  return (
    <Fragment key={keyOf(item, index)}>
      <Pressable onPress={() => act(productsScreenActions.row, { part: "row", item, index })}>
        … {row.text("item.name")} … {row.text("currency(item.price)")} …
```

| 设计里 | 代码里 |
| --- | --- |
| 数据源（`Frame.data`） | `<屏幕>.data.ts` 里以数据源命名的 hook（`useProducts`），参数是表达式读出的值，路径参数没给时读屏幕的同名参数；缓存按参数、旧请求取消、再进入屏幕时在后台重新加载；`load: demand` 只在刷新时加载 |
| 绑定的属性 `=表达式`、文字里的 `{{表达式}}` | `$.text("item.name")`、`$.fill("共 {{len(data.cart.items)}} 件")`、`$.num(…)`、`$.bool(…)`、`$.pick(…)`（选项只取表达式里写到的值）；表达式原样作为字符串交给编辑器自己的求值器（从不 `eval`），读不到就是空、数字和选项保持设计值 |
| 条件 `{expr}`（`showWhen`、`when`） | `$form.holds("form.error") && (…)`、`if ($.holds(…))`：真的求值，不再按“成立”处理 |
| 按数据重复 | `$.list("data.products.items").map((item, index) => …)`，`key` 是元素的 `id`（没有就用位置），行里读 `row` |
| 区域（`Group.states`） | `useRegion(products)` 选出状态（和预览的 `regionState` 同一规则），每个状态的设计是一个分支：`productsState === "loading" && (…)` |
| 表单（`Group.form`） | `useForm({ id, fields, send, then, catch, status })`，字段规则来自契约的 Schema（`<屏幕>.data.ts` 的 `CREATE_PRODUCT_FIELDS`）；输入框受控（`value` / `onChange`），出错时 `aria-invalid`，提交中按钮禁用；`date` 字段是浏览器的日期选择器（`type="date"`），`date-time` 是 `datetime-local`（按 ISO 8601 写回）；文件字段走 `XMLHttpRequest` 上传并报告进度；Problem 的 `errors[].pointer` 落到字段上；表单的内容在屏幕离开又回来时还在（运行时按 `id` 保存） |
| 点击（`Item.action`、位置的动作） | 屏幕顶上的 Action 数据（`productsScreenActions.row`），处理函数是 `act(productsScreenActions.row, { part: "row", item, index })`：解释器在点击的那一屏、那一行、那个表单上运行它（`useActions`，见上） |
| 点击的效果 `call`、`refresh`、`loadMore`、`submit`、`signOut` | 数据里的效果原样保留（`{ do: "call", operationId: "deleteProduct", args: { productId: "item.id" } }`）；屏幕交给 `useActions` 的是它自己的部分：`calls` 里每个接口经客户端怎样发出（`(a) => api.deleteProduct({ params: { productId: pathArg(a.args.productId) } })`，`a` 是解释器在那一步读出的参数），`sources` 里的数据源（刷新、翻页、乐观修改），`forms` 里的表单和它的 `then` / `catch`（同样是数据），`filled` 里表单字段的“已填写” |
| 调用平台能力 `invoke` | `{ do: "invoke", capability: "payment.pay", args: { orderId: "response.id" }, then: {…} }`：解释器在它那一步读参数，经 `runtime.invoke` 交给注册表；`then` / `catch` 读 `result` / `error`（嵌在调用的回答里时外层的 `response` 照样读得到） |
| 打开链接、组件自己的复制按钮 | 打开链接的动作走平台能力 `link.open`；组件里的复制（代码块、复制行、二维码）走 `clipboard.write`：运行时把注册表交给组件（`parts/widgets/host.ts` 的 `invoke`），应用可以换掉适配。原型和编辑器的预览没有注册表，由浏览器自己做 |
| 能力视图（地图、相机、视频通话） | 屏幕画 `<StoreMap center={…} markers={[…]} width={380} height={240}>{替身}</StoreMap>`：组件来自生成的 `slots.ts`，实现在只写一次的 `src/custom/slots/StoreMap.tsx`，写好之前画设计的替身（[平台能力](平台能力.md)的“导出”） |
| 屏幕参数（`Frame.params`） | 地址的一段：`/product/:productId`，直接打开地址（深链接）也能用；`navigate("product", { productId: … })` 带参数跳转；屏幕里 `useScreenParams()` 按声明的类型读，没给的用示例值 |
| 登录（`Frame.auth`） | `auth: required` 的屏幕：没有会话时先去登录页，登录后再去它；401（刷新一次也不行）结束会话、去登录页，登录后回到原处；登录表单成功后 `afterSignIn()` 回去，没有要回去的地方才走表单自己的跳转 |
| 下拉刷新、滚到底翻页 | 加载数据的屏幕正文是 `DataScroll`：在顶部往下拉（手指、鼠标拖、滚轮）重新加载 `pullToRefresh` 的数据源并显示转圈，滚到底（或者正文不够长时）加载 `paging: scroll` 的下一页 |
| 底部的栏和按钮 | 加载数据的屏幕上，底部的栏、悬浮按钮和站在屏幕下半部的按钮放在 `DataScroll` 外面，固定在屏幕上；正文的每一块末尾有一段不可点的空白（`top-full` 的 `span`），最后一行能滚到它们上方（`lib/foot.ts`，和预览、手机应用、小程序同一个规则） |

**模拟库和真实后端**：开发时（`npm run dev`）接口默认由模拟库的传输层回答，`auth.signedIn` 跟着模拟库的会话（场景的 `signedIn`，默认已登录）。场景由地址里的 `?scenario=new-user` 选，没有时看 `VITE_MOCK_SCENARIO`，再没有就用设计自己的；屏幕左下角有一个只在开发时出现的切换框，换场景时数据和会话从头开始。`VITE_API_MOCKS=msw` 改用 Service Worker（换场景会重新载入页面），`VITE_API_MOCKS=off` 请求真实后端。生产构建只请求 `VITE_API_BASE_URL`（默认同站的 `/api`）；`vite preview` 和开发服务器一样把 `/api` 转发到 `API_TARGET`（默认 `http://127.0.0.1:3001`）。生产构建里没有模拟库（`scripts/check-product.ts` 检查）。

**代码检查**：生成的屏幕、数据 hook、客户端、路由和其余文件都通过和自定义代码同样的 ESLint 规则；只有原型导出自己的 `App.tsx` 和 `runtime.tsx` 关掉了几条关于 React 写法的规则。

## 小程序：同一份设计的页面

`apps/miniapp` 用同一个运行时、同一个客户端和同一个模拟库，把每个屏幕写成一个 Taro 页面（打印在 `lib/export/miniapp/`，目标是 `lib/export/targets/miniapp.ts`）：数据源、表达式、重复、区域、表单（Taro 的 `Input`、`Textarea`、`Picker`）、文件（`Taro.chooseImage` 选、`Taro.uploadFile` 传）、调用、下拉刷新（`enablePullDownRefresh`）和触底翻页（`onReachBottom`）、参数（页面的查询串）、登录守卫和登录后回去（`redirectTo`）。组件套件在编辑器的 `miniapp-kit/` 里（独立的 Taro 项目，带画廊和测试），导出时原样复制。微信和抖音开发者工具、AppID、请求域名白名单、尺寸用 px 的原因、组件覆盖和画不出来的效果见 [小程序](小程序.md)。

## 和设计不一样的地方

手机应用和小程序的组件套件没有画出全部组件：没有原生组件的画成它拆成的原子或一个写着组件名的占位块，有些点击方式、效果和绑定只能近似（[手机端](手机端.md)、[小程序](小程序.md)的“组件覆盖”）。Web 应用画得和设计一样，但三个应用都可能依赖还不存在的东西（见[边界与契约](边界与契约.md)）。这些都会报告，不悄悄丢掉：

| 种类 | 哪些应用 | 是什么 |
| --- | --- | --- |
| `demo` | 三端 | 依赖原型演示的组件：它在原型里自己演“已领取”“已发送”、随机奖品，产品里从不演，没绑定它接管的属性、动作里也没调用接口时只发请求、等结果 |
| `event` | 手机应用、小程序 | 组件事件（`on:<名字>`）和槽位族（`tab:*`）上的动作，三端都运行（Web 经组件的 `onEvent` 和 `Pressable` 的位置）；只列组件不发出的事件（由手机端和小程序的打印器报告） |
| `interface` | 三端 | 屏幕调用、加载或提交的接口，契约里没有 |
| `capability` | 三端 | 要写适配或插槽的平台能力（[平台能力](平台能力.md)）：能力视图（地图、相机、视频通话，插槽还是设计的替身）；这一端没有默认适配、要在 `src/custom/capabilities.ts` 里写的调用；目录和产品都没声明的能力；没有调用 `auth.oauth` / `payment.pay` 的登录或支付按钮 |
| `custom` | 三端 | 设计标成产品自己画的部件（`slot`）：由只写一次的 `src/custom/slots/<名字>.tsx` 画，写好之前画设计的部件 |
| `unknown`、`binding` | Web | 这个版本不认识的组件（打印成一行注释）；绑定到表达式的列表、表格属性（Web 显示设计的行） |
| `input` | 手机应用、小程序 | 声明了输入的自带组件（评分、数量加减、数字键盘）绑定了变量或放在表单里：套件的组件还不交出值；分栏视图要记住访客拖出的比例（`persist`）时，手机应用只在运行期间记住（小程序用 `Taro.setStorage`，Web 用 `localStorage`） |
| `style` | 手机应用、小程序 | 风格带不过去的部分：两端组件不按它画的配方、屏幕底纹、自定义风格继承的内置 CSS 和它的每条 `rules`（见下） |
| `placeholder`、`atoms`、`binding`、`trigger`、`look`…… | 手机应用、小程序 | 打印器自己报告的近似（见各自的文档） |

每个应用把这些写在自己的 `src/generated/warnings.json`（`{ kind, screen, screens, part, detail }`，部件按名字记，同一份设计每次导出相同；Web 的在 `apps/web/src/generated/warnings.json`），导出报告按应用和种类计数：编辑器里导出后显示“和设计不一样、或依赖还没有的东西的地方：Web 应用 N 处（依赖原型演示的组件 1、组件事件 2……）；手机应用……”，可以逐条查看；命令行打印 `web: …`、`mobile: …`；MCP 的 `export_product` 返回 `differences: [{app, count, kinds, file}]`。`Product.differences`（`lib/export/types.ts` 的 `DesignDifference`，`app` 是 `web`、`mobile` 或 `miniapp`）是它们的来源，三端共有的种类由 `lib/export/boundary.ts` 收集，`lib/export/differences.ts` 计数。

原型项目（单个 React 应用）是原型：没被接管的演示组件在里面照常演示（打印成 `<Coupon … demo />`）；完整产品的 Web 应用从不打印 `demo`。声明了输入的自带组件（评分、数量加减、数字键盘）在两者里都接到绑定的变量上：`value={vars.score} onValueChange={(value) => setVar("score", …)}`。分栏视图在 Web 端打印成 `SplitView`（react-resizable-panels），两个栏各是一个面板，栏里是该栏自己的弹性布局；访客拖出的比例是界面状态，每次从设计稿的 `split` 开始，`persist` 时存在浏览器的 `localStorage`（键 `m3e-split:<组件 id>`），见[组件规范](组件规范.md)“分栏视图”。

风格：两端只带风格的结构化部分（颜色、`tokens`、字号、圆角、间距、配方名），CSS 一律不带。带不过去的记成 `style` 种类，写明依赖什么（伪元素、状态选择器、渐变……）、为什么这一端做不到、改用哪个扩展点，并在 `screens` 里列出涉及的屏幕（只有一个时也写在 `screen`）。Web 全部带过去，不报告。对照表见[风格清单](风格清单.md)的“导出到各端时带过去什么”。

## 生成的文件和自定义代码

每个文件只有两种：

- **生成的**（`generated`）：导出拥有它，每次导出都会重写。清单里记着导出写下的内容的哈希。要改屏幕、导航、文字、接口，就改设计再导出。
- **自定义的**（`seeded`，自定义代码，人或 AI 写）：导出只在它不存在时写一次初始内容，之后不再碰它，无论里面写了什么。位置：`server/src/handlers/*`（含 `channels/`）、`server/src/custom/*`、`apps/web/src/custom/*`、`apps/mobile/src/custom/*`、`apps/miniapp/src/custom/*`（包括用到平台能力时的 `capabilities.ts`、能力视图和标了插槽的部件的 `slots/<名字>.tsx`）、`apps/miniapp/project.config.json` 和 `project.tt.json`（填 AppID）、`CLAUDE.md`。

一个自定义文件导出出来的内容（它导出的名字和签名）就是固定的约定：以后要加新的扩展点，就加新的自定义文件，而不是改旧的。生成的代码只引用自定义文件里这些固定的导出，所以无论自定义代码写成什么样，重新导出都能接上。新加的接口会多出一个 `server/src/handlers/<接口>.ts`；契约里去掉的接口，它的处理函数文件留在原处（不再被引用，仍能通过类型检查），导出报告把它列为孤儿，直到有人删掉它。

`.m3e/manifest.json`：

```json
{
  "format": "m3e-product-manifest",
  "version": 1,
  "generator": "M3E Canvas Pro",
  "product": "shop",
  "files": {
    "apps/web/src/generated/App.tsx": { "kind": "generated", "sha256": "…" },
    "apps/web/package.json": { "kind": "generated", "sha256": "…", "keys": ["name", "dependencies.react", "…"] },
    "server/src/handlers/getProduct.ts": { "kind": "seeded", "sha256": "…" }
  },
  "pending": { "apps/web/src/generated/routes.ts.m3e-new": "…" }
}
```

同一份设计导出两次，清单和每个文件都逐字节相同（没有时间戳），所以再导出一次什么都不写。

### 屏幕的名字和地址

三端用同一个规则给屏幕起名（`lib/export/ir/names.ts`），所以 Web 的路由（`/product-details`）、手机应用的 Expo Router 路径（`src/app/product-details.tsx`）和小程序的页面（`pages/productDetails/index`）是同一个名字，代码里的屏幕键（`productDetails`、手机端 `ProductDetails`）也一样：

1. 屏幕名里有 ASCII 单词（并且不以数字开头）：用这些单词，`Product details` 就是 `productDetails`。
2. 没有（中文、日文、韩文的名字）：用编辑器模板给这个名字的英文（`lib/export/ir/screenWords.ts`，模板里所有中日韩屏幕名都在表里，测试守着），`首页` 是 `home`，`商品详情` 是 `product`，`我的` 是 `me`；名字末尾的数字保留（新建屏幕的默认名 `屏幕 2` 是 `screen2`）。这张表只加不改：地址可能被收藏、被分享出去。
3. 模板里也没有：用屏幕的 id（文档一直保存它，改名也不变），`合计`（id `k3j2h1g5`）是 `screenK3j2h1g5`、`/screen-k3j2h1g5`。

从不按屏幕的先后顺序起名：在前面加一个屏幕、删掉一个屏幕，别的屏幕的地址都不动。两个屏幕起出同一个名字时，后一个加数字（`home2`），按文档里的顺序。想要好读的地址，就给屏幕起一个英文名。第四批之前，没有 ASCII 单词的屏幕按顺序叫 `screen1`、`screen2`……，第一次用新版本重新导出时这些屏幕的地址会变一次。

## 重新导出

导出到一个已经有产品的文件夹时（`lib/export/merge.ts` 的 `planExport`，纯函数，单元测试覆盖每条规则）：

| 文件 | 磁盘上 | 做什么 |
| --- | --- | --- |
| 生成的 | 没有 | 写入 |
| 生成的 | 和这次导出的一样 | 不动（未变） |
| 生成的 | 和上次导出写下的一样 | 重写 |
| 生成的 | 上次导出之后被改过，或者不是导出写的同名文件 | **冲突**：不覆盖，新版本写在旁边的 `<文件>.m3e-new`，在报告里列出 |
| `package.json` | 被加过依赖或脚本 | **合并**：导出写的键用导出的值（依赖按固定版本），上次导出写过、这次不再写的键去掉，别人加的保留 |
| 自定义的 | 没有 | 写入初始内容 |
| 自定义的 | 有 | 不动，无论内容 |
| 这次不再有的自定义文件（比如去掉的接口的处理函数） | 有 | 不动，报告里列为孤儿（`customOrphans`），清单里仍记着它，所以每次导出都报，直到删掉；接口回来时接上原来的文件 |
| 这次不再生成的文件 | 和上次导出写下的一样 | 删除（变空的文件夹一起删） |
| 这次不再生成的文件 | 被改过 | 留在原处，报告里列出 |
| 上次的 `.m3e-new` | 冲突已解决，内容没被改过 | 删除 |

解决冲突：把改动移到自定义代码里，再用 `.m3e-new` 替换原文件（或者把两个都删掉再导出一次）。冲突在解决之前每次导出都会报。给某个工作区加依赖用 `npm install <包> -w <工作区>`，重新导出会保留。清单丢了或读不懂时当作没有导出过：只会多报冲突，不会覆盖任何改动。清单写在最后，导出中途停下也一样。

文件夹里有别的东西、又没有清单时，导出会先拒绝（编辑器里要再按一次，命令行和 MCP 要加 `--force` / `force: true`）；即使这样，同名的文件也只会得到 `.m3e-new`，不会被覆盖。命令行和 MCP 从不导出到磁盘的根目录、主目录或包含主目录的文件夹，加了 `force` 也一样（MCP 客户端可以给任意路径，读到的网页里的一句话不该让几百个文件落进主目录）。

## 在编辑器里导出到文件夹

在 Chromium 里选“完整产品（monorepo）”后，“导出到文件夹…”用 File System Access 选一个文件夹，写入后显示报告：写入、未变、保留的自定义代码、删除、冲突（列出每个文件）、合并的 `package.json` 和设计里已经没有的东西的自定义代码（孤儿）。编辑器按项目记住这个文件夹（IndexedDB 的 `export-dir:<项目>`，和绑定文件一样保存句柄），下次直接“再次导出到 <文件夹>”；浏览器要求时会再问一次写入权限。不能选文件夹的浏览器下载 zip（zip 里带清单，解压后的文件夹也能再导出进去）。

## 命令行和 MCP

```bash
bun scripts/export.ts <项目文件或文件夹> <输出文件夹> [--lang zh] [--force]
```

命令行读取编辑器保存的项目文件（单个 `.json` 或带 `m3e-project.json` 的文件夹），打印报告。MCP 服务器在文件模式下多一个工具 `export_product {dir, force?}`（相对路径从项目文件所在的文件夹算起，只读会话没有它，配对了编辑器标签页时请在编辑器里导出），返回写入、冲突、保留的自定义代码、孤儿（`customOrphans`）等。发布的 MCP 服务器把导出要复制的编辑器源文件打包在自己里面（`mcp/build.ts`，清单在 `lib/export/sourceList.ts`，和 `lib/exportSources.ts` 由测试对齐），不需要源码仓库。

## 版本

生成的每个 `package.json` 都写精确版本，来自 `lib/versions.generated.ts` 的 `PRODUCT_VERSIONS`：和原型项目共用的包按本仓库 `bun.lock` 的版本；本仓库不用的包（ESLint、Prettier、Fastify、MSW、esbuild、tsx、Vitest、普通的 Vite 等）写在 `lib/exportPackages.ts` 的 `PRODUCT_PINS`，查过 npm 仓库。`bun scripts/gen-versions.ts --registry` 再查一遍并列出有新版本的包，改了之后 `bun run gen:versions`。TypeScript 固定在 6.0（typescript-eslint 只支持到 6.0，编辑器自己用的 7.x 没有它要的 JavaScript 接口），复制来的组件在 6.0 下也能通过类型检查。

## 目标怎样接入

产品由一组目标（`ProductTarget`，`lib/export/types.ts`）组成，按 `lib/export/targets/index.ts` 的 `PRODUCT_TARGETS` 顺序生成：

```ts
interface ProductTarget {
  id: string;
  build(ctx: ProductContext): Promise<Workspace | null> | Workspace | null;
}
```

`ProductContext` 带着文档、测量的宽度、语言、产品名和 npm 作用域、接口模型（`ctx.api`）、固定版本（`ctx.version(pkg)`）、读取编辑器源文件的函数和警告列表；`Workspace` 是一个文件夹（`dir`）、它的包名、它参与哪些根脚本、它的文件（每个标明 `generated` 或 `seeded`）和 README 里的一行说明。根目录（`lib/export/targets/root.ts`）最后按这些工作区生成。

| 部分 | 接在哪里 |
| --- | --- |
| 接口模型（Doc.api） | 已接上：`buildProduct` 自己从 `doc.api` 读（`contractOf`：`openApiObject`、有实时通道时 `asyncApiObject`、不带注释的 `schemaToTs`，见 [接口](接口.md)），`apiModelOf` 读出接口列表；`{ api }` 选项仍可以用别的契约代替它 |
| 屏幕绑定接口 | 已接上（Web、手机应用、小程序）：`webTarget`（`lib/export/targets/web.ts`）把 `binds` 交给 `buildProject`，`lib/printBindings.ts` 把数据源、表达式、重复、区域、表单、调用、参数和登录写成代码，数据 hook 在每个屏幕旁边的 `<屏幕>.data.ts`，见上面“Web 应用：绑定接口的屏幕”；手机应用和小程序的打印器（`lib/export/rn/print.ts`、`lib/export/miniapp/print.ts`）写同样的绑定。三者和平台无关的部分在 `lib/export/bindCode.ts`：参数放在哪里、列表和分页、页大小、成功状态码、表单字段的规则、区域的状态、绑定属性怎样读、条件和模板、重复的列表、哪些效果属于接口、类型化客户端的调用形状（没有输入的接口，比如 `GET /me`，只传 `init`）、部件在报告里的名字 |
| 前端共用的运行时 | 已接上：`appRuntimeTarget`（`lib/export/targets/appRuntime.ts`）把 `lib/app` 和 `lib/bindings` 的纯函数部分复制进 `packages/app-runtime`，见上面“前端共用的运行时” |
| 模拟库 | 已接上：`mocksTarget` 把 `lib/mocks` 的引擎（`MOCK_ENGINE_FILES`）复制进 `src/engine/`，`Doc.mocks` 写成 `src/generated/` 里的数据，文件写进 `files/`（见 [模拟库](模拟库.md)）；`src/engine/` 和复制的组件一样不过 ESLint（在编辑器里检查过），类型检查照常 |
| 后端 | 已接上：`serverTarget`（`lib/export/targets/server.ts`，读契约的是 `lib/export/server/`）：路由、ajv 校验（JSON Schema 2020-12）、类型、problem+json、鉴权钩子、分页、上传、实时通道，见 [后端](后端.md)；工作区可以带自己的 `AGENTS.md` 一节（`Workspace.agents`） |
| React Native | 已接上：`mobileTarget`（`lib/export/targets/mobile.ts`）：Expo Router 应用，屏幕由 `lib/export/rn/print.ts` 打印（带绑定），套件从 `rn/src/kit` 复制（文件清单 `lib/export/rn/kitFiles.generated.ts`，`bun run gen:rn` 写），契约的数据由 `lib/export/rn/contract.ts` 生成；版本按 `rn/package.json` 和 `MOBILE_PINS`，见 [手机端](手机端.md) |
| 小程序（Taro） | 已接上：`miniappTarget`（`lib/export/targets/miniapp.ts`）生成 `apps/miniapp`：打印器 `lib/export/miniapp/`，组件套件 `miniapp-kit/src/kit`（`MINIAPP_KIT_FILES`，原样复制），传输层和令牌存储在套件的 `app/transport.ts`，见 [小程序](小程序.md) |
| 契约测试 | 已接上：`contractTestsTarget`（`lib/export/targets/contractTests.ts`）：每个接口的示例请求经生成的客户端发出，检查状态码和响应体；示例值由模拟库的生成器（`lib/mocks`）生成，契约自己的示例优先（`lib/export/server/examples.ts`） |

新目标的检查加进 `scripts/check-product.ts`（它导出一个带契约的示例产品，真的安装、检查、构建、测试、启动后端跑契约测试、在 Chromium 里打开应用，再导出一次验证合并规则）。

## 安全

文档和契约里的文字进入生成代码时只以转义后的字符串、JSON 数据（含 `__proto__` 键时用 `JSON.parse` 读字符串）或只含字母数字的标识符出现；参数名、字段名、消息名在类型里是带引号的键。唯一的例外是后端处理函数桩里给 AI 助手看的契约说明：它们只进 `//` 行注释，换行（`\n`、`\r`、U+2028、U+2029）、其他控制字符和双向文本控制符（Trojan Source）先去掉，每行以导出自己的标签开头，所以既跳不出注释，也不会被读成 `@ts-nocheck`、`eslint-disable` 这类指令（`lib/export/server/comments.ts`）。进入路径时只经过 `safeSegment`、`npmSlug`、`identifierOf` 这类只留字母数字的函数。所有路径在写入前检查（`lib/export/paths.ts`）：不能有 `..`、绝对路径、盘符、反斜杠、控制字符、Windows 设备名，也不能有两个只差大小写的路径；Node 的写入器还拒绝经过符号链接写到文件夹外面。`lib/exportInjection.test.ts` 用带敌意文字的文档和契约（接口、路径参数、模型和字段、安全方案、实时通道和消息、带指令字样的说明）走完整导出，检查生成的代码都能解析、标记不会变成代码里的名字、后端和契约测试里的每个标记都只在字符串或注释里、带契约文字的注释都是行注释且不是指令、路径和包名都是安全的、YAML 里的文字只在引号里。

它要联网（`npm install`），需要装好 Playwright（和端到端测试一样），不在 `bun run test` 里；CI 里是单独的一项（跑 `proof` 和 `shop`）。`… systems` 和 `… parts` 换成原型和变量的文档、全部组件的文档（这两个不开浏览器）；`… shop` 是带自己接口的文档（`doc.api` 是商店的 OpenAPI 加聊天的 AsyncAPI，`lib/api/fixtures`），检查导出从文档读出的契约照样安装、构建、测试，后端的 501、400、401、契约测试（全部 pending、`--strict` 失败），写好两个处理函数后 `--strict` 通过，再导出不动它们，契约加接口只多一个桩、去掉接口留下孤儿（[后端](后端.md)）。商店的屏幕绑定了这份契约（`boundShopDoc`：分页的商品列表、按 id 的详情、要登录才能用的新商品表单、登录页），`scripts/check-shop-app.ts` 在 Chromium 里驱动它的 Web 应用：在模拟库上（开发服务器）列表有数据、滚到底翻页、最后一行停在底部的按钮上方、下拉重新加载，`new-user` 和 `network-error` 场景分别显示空和出错的设计，点一行打开详情、直接打开详情的地址也能看到同一个商品，表单按 Schema 拒绝空字段和不合格的金额、`name-taken` 场景里服务器的错误落到名称上，未登录时先去登录页再回来；在真实后端上（构建好的应用，`vite preview` 把 `/api` 转发给检查启动的后端，再写好登录和取单个商品两个处理函数）开始是空的，要先登录才能加商品，处理函数的 422 落到名称上，加好的商品出现在列表里并能打开、重新载入详情地址也能打开，过期的令牌得到 401 后去登录页、登录后回到表单把它发出去，后端停掉后列表显示出错的设计。每个画面的截图在 `<文件夹>/shots-shop/`（`mocks-*.png`、`server-*.png`），编辑器预览里同样画面的截图由端到端测试写在 `e2e/.out/preview-shop-*.png`，可以并排看。手机应用由 `scripts/check-mobile.ts` 检查（同一个 `boundShopDoc`，它还有要登录的订单页——同时加载当前用户 `getMe`，一个没有输入的接口——和给商品上传图片的表单）：`expo export --platform android` 打包且包里没有模拟库、有文档里的图片（登录页的商标，写成文件打包）；开发版网页构建（`expo export --dev`）在 Chromium 里对模拟库走一遍（列表有数据、滚到最后时最后一行在底部的按钮上方，`new-user`、`network-error` 场景的空和出错设计，点一行按 id 打开详情，选一张图片上传并带着提示条返回，表单按 Schema 拒绝空字段、`name-taken` 场景里服务器的错误落到名称上，提交成功后跳转并弹提示条，未登录时订单页去登录页、登录页从打包的文件画出商标、密码错误被拒、登录后回到订单页）；再给后端多写一个订单的处理函数（登录和取单个商品用上面 Web 应用写好的那两个，原样不动），用生产版网页构建（`EXPO_PUBLIC_API_BASE_URL` 指向检查启动的后端）对真实后端走一遍（空列表、列表、详情、太短的密码按 Schema 拦下不发送、登录后回到订单、处理函数的 422 落到名称、加好的商品出现在列表里、后端停掉后出错）。手机应用的截图在同一个文件夹（`mobile-*.png`，列表滚到最后的是 `mobile-list-end.png`），和 Web 应用同一画面并排的在 `compare-*.png`。小程序的三个构建也被读一遍（每个屏幕一个页面、没有小程序不能用的 API、没有模拟库），它的 H5 用 `scripts/check-miniapp-app.ts` 在模拟库和真实后端上走同样的流程（[小程序](小程序.md)），截图是同一个文件夹的 `miniapp-mocks-*.png`、`miniapp-server-*.png`。改了 `lib/export/`、`lib/printBindings.ts`、`lib/app/`、`lib/bindings/` 或导出用到的组件后要跑。

## 已知限制

- 文档没有接口（`Doc.api`）时，契约是空的：客户端只有 `request`，后端没有路由，模拟库没有数据（导出时给了别的契约的，模拟库按它读回的接口回答）。客户端只为 JSON 的请求体和响应生成类型；`multipart/form-data` 的请求体是 `Record<string, unknown>`，引用可复用响应（`components.responses`）的错误还是 `unknown`。
- 浮层没有地址；浮层打开时带的参数不传给它。实时通道（AsyncAPI）还没有绑定到屏幕。
- 原型导出的 `App.tsx` 和 `runtime.tsx` 在 ESLint 里关掉了几条关于 React 写法的规则（由导出自己的测试保证）；其余生成的代码和自定义代码一样用全部规则。
- 后端不带数据库（`server/src/custom/db.ts` 只有内存表），其余限制见 [后端](后端.md)。
- 手机应用的限制见 [手机端](手机端.md)。
- 小程序没有在真的微信、抖音开发者工具和真机里运行过：检查只读三个平台的构建产物、在 Chromium 里驱动 H5，见 [小程序](小程序.md)。
