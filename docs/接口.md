# 接口

文档的 `api` 是产品前端和后端之间的约定：数据模型、HTTP 接口、鉴权、实时通道和服务器地址。它按标准格式存放，能原样导出成 **OpenAPI 3.1**（HTTP）、**AsyncAPI 3.0**（WebSocket / SSE）和 **JSON Schema 2020-12**（数据模型），也能导入别人写好的规范文件。编辑器左侧的“接口”标签页、应用内的 AI 和 MCP 客户端都通过文档核心的同一组操作改它。

代码在 `lib/api/`（纯 TypeScript，不依赖 DOM 和 Node，浏览器、MCP 服务器和导出器里都能用），操作在 `lib/core/ops/api.ts`，读取工具在 `lib/tools/apiRead.ts`，编辑器面板在 `components/ApiPanel.tsx`，界面文字在 `lib/i18n/api.ts`。

```text
lib/api/
  types.ts       模型的类型（lib/tokens.ts 原样转出）
  clean.ts       读入时的形状检查和上限（cleanApi）
  validate.ts    问题列表（apiProblems）：引用、路径参数、重复的 operationId……
  schema.ts      JSON Schema 的遍历、引用改名、编辑器的字段表
  defaults.ts    默认值：状态码文字、RFC 9457 错误模型、分页参数、路径参数
  openapi.ts     toOpenApi / openApiObject / fromOpenApi
  asyncapi.ts    toAsyncApi / asyncApiObject / fromAsyncApi
  merge.ts       导入的文件和已有的接口合并（mergeApi）
  typescript.ts  schemaToTs / schemaTypeTs：模型写成 TypeScript 类型
  outline.ts     给模型看的大纲、单个接口和模型的详情
  yaml.ts        YAML 的读写（无依赖，有上限）
  fixtures/      测试用的真实规范：商店（OpenAPI）、聊天（AsyncAPI + OpenAPI）
```

## 模型

容器是带 id 的列表（项目文件里一项一行、顺序由作者决定），里面装的就是标准对象本身：Schema、Parameter、Request Body、Response 写进 openapi.yaml 时一字不改。标准里有、模型没用到的字段放在 `extra`，导出时原样写回。

| 字段 | 类型 | 对应标准 |
| --- | --- | --- |
| `info` | `{ title?, version?, description?, extra? }` | OpenAPI `info`（`contact`、`license` 等在 `extra`） |
| `servers` | `ApiServer[]`：`{ env, url, description?, realtime?, extra? }` | OpenAPI `servers`（`x-m3e-env`、`x-m3e-realtime`）；有 `realtime` 的写成 AsyncAPI `servers.<env>` |
| `models` | `ApiModel[]`：`{ name, schema }` | `components.schemas.<name>`（两种规范共用） |
| `endpoints` | `ApiEndpoint[]` | `paths.<path>.<method>`：OpenAPI Operation |
| `tags` | `{ name, description?, extra? }[]` | OpenAPI 顶层 `tags` |
| `auth` | `ApiAuth`：`{ schemes, security?, login?, refresh?, logout?, tokenField?, refreshTokenField? }` | `components.securitySchemes`、顶层 `security`、`x-m3e-auth` |
| `channels` | `ApiChannel[]` | AsyncAPI `channels` 和 `operations` |
| `extra` | `{ openapi?, asyncapi? }` | 导入时模型放不下的东西：`webhooks`、`externalDocs`、顶层 `x-` 字段、`components` 里 schemas 和 securitySchemes 以外的可复用对象（responses、parameters、requestBodies、headers、examples、links、callbacks、pathItems，接口可以 `$ref` 它们），以及路径项自己的字段（`paths.<path>` 的 summary、description、servers） |

**数据模型**（`ApiModel`）：`name` 是标识符（字母开头，字母、数字、下划线，最长 64），就是 TypeScript 类型名；`schema` 是 JSON Schema 2020-12（通常是对象）。认识并校验的关键字：`$ref`、`type`（可以是数组，`"null"` 表示可为空）、`properties`、`required`、`additionalProperties`、`items`、`prefixItems`、`enum`、`const`、`format`、`default`、`examples`（OpenAPI 的 `example` 也保留）、数值和长度的上下限、`pattern`、`oneOf`/`anyOf`/`allOf`/`not`、`discriminator`、`readOnly`/`writeOnly`/`deprecated`、`contentMediaType`/`contentEncoding`。其他关键字原样保留。常用的 `format`：`date-time`、`date`、`uuid`、`email`、`uri`、`binary`（文件：上传时放在 `multipart/form-data` 里）。

**引用**：一律写 `{"$ref": "#/components/schemas/<名字>"}`，HTTP 和实时两边一样。可空的引用写成 `{"anyOf": [{"$ref": …}, {"type": "null"}]}`。

**接口**（`ApiEndpoint`）：`operationId`（全文档唯一，是生成的客户端函数名和服务器处理函数名）、`method`、`path`（`/users/{id}`，从服务器的基础地址算起）、`summary`、`description`、`tags`（第一个用来分组）、`deprecated`、`parameters`（OpenAPI Parameter 或 `$ref`）、`requestBody`、`responses`（按状态码 `"200"`、`"4XX"` 或 `"default"`）、`security`（`[]` 表示任何人可调用，不写表示用接口的默认值）、`pagination`、`extra`。

**分页**（`x-m3e-pagination`）：

| 写法 | 意思 | 省略时的名字 |
| --- | --- | --- |
| `{ "style": "cursor", "items": "items" }` | 响应的 `items` 字段是这一页的列表，`nextField` 是下一页的游标（最后一页为空或 null），请求时用 `cursorParam` 传游标、`limitParam` 传页大小 | `cursorParam: "cursor"`、`nextField: "nextCursor"`、`limitParam: "limit"` |
| `{ "style": "offset", "items": "data", "totalField": "count" }` | 跳过 `offsetParam` 条，取 `limitParam` 条，`totalField` 是总数 | `offsetParam: "offset"`、`limitParam: "limit"`、`totalField: "total"` |

`paginationOf(p)` 补上省略的名字。

**鉴权**（`ApiAuth`）：`schemes` 是 OpenAPI 的 Security Scheme：Bearer JWT `{type: "http", scheme: "bearer", bearerFormat: "JWT"}`、API 密钥 `{type: "apiKey", in: "header", name: "X-API-Key"}`、OAuth2 授权码 `{type: "oauth2", flows: {authorizationCode: {authorizationUrl, tokenUrl, refreshUrl, scopes}}}`、OpenID Connect。`security` 是每个接口默认要的（`[{"bearerAuth": []}]`）。`login`、`refresh`、`logout` 是登录、刷新令牌、退出的接口的 operationId，`tokenField`、`refreshTokenField` 是登录响应里放令牌的字段（默认 `accessToken`、`refreshToken`，`authFields(auth)` 补上）。它们写在 OpenAPI 顶层的 `x-m3e-auth`。

**错误**：新加的接口默认带 `default` 响应：`application/problem+json`，结构是 `Problem` 模型（RFC 9457：`type`、`title`、`status`、`detail`、`instance`，加扩展成员 `errors: [{pointer, detail}]` 逐个字段说明请求哪里不对，供表单显示校验错误）。文档里没有 `Problem` 时自动建一个。

**实时通道**（`ApiChannel`）：`id`（AsyncAPI `channels` 的键）、`address`（`/rooms/{roomId}`）、`title`/`summary`/`description`、`transport`（`x-m3e-transport`：`websocket` 默认，或 `sse` 只由服务器推送）、`parameters`（地址里每个 `{参数}` 一项）、`messages`（`{name, title?, summary?, description?, contentType?, payload?, headers?, examples?, extra?}`）、`operations`（`{id, action, messages?, summary?, description?, extra?}`）。

> **send / receive 的方向**：AsyncAPI 文档描述的是**后端**，和 OpenAPI 一样。`action: "send"` 是服务器发给应用的消息（新消息推到房间里），`action: "receive"` 是服务器从应用收的消息（用户发出的一句话）。前端订阅 `send`，发出 `receive`。操作不写 `messages` 时表示通道的全部消息。

**服务器**（`ApiServer`）：`env` 是环境名（`dev`、`staging`、`prod` 或自定义），`url` 是 HTTP 基础地址（也可以是相对的 `/api`），`realtime` 是实时通道的基础地址（`wss://…`；SSE 通道用 `url`）。

**数据集合关联模型**：`Doc.collections` 的每个集合可以带 `model`（模型名），说明这些行是哪个模型的示例，模拟库据此按 Schema 生成数据。数据标签页的集合卡片里可以选，`add_collection` / `update_collection` 的 `model` 参数也可以设，`rename_model` 时跟着改名，`remove_model` 时解除。

### 我们自己的扩展

| 位置 | 扩展 | 内容 |
| --- | --- | --- |
| OpenAPI Operation | `x-m3e-pagination` | 分页约定，见上 |
| OpenAPI 顶层 | `x-m3e-auth` | `{login, refresh, logout, tokenField, refreshTokenField}` |
| OpenAPI Server | `x-m3e-env`、`x-m3e-realtime` | 环境名、实时地址 |
| AsyncAPI Channel | `x-m3e-transport` | `websocket` 或 `sse` |

别人的规范文件里没有这些时：环境名按服务器的说明和地址猜（production → `prod`、staging → `staging`、local/development/localhost → `dev`，否则 `server1`…），其余留空。

## 校验

`apiProblems(api, { collections })` 列出问题，错误在前、警告在后，每条是 `{ level, at, message }`（`at` 如 `endpoints.getUser.parameters[0]`、`models.Post/properties/author`）。

- **错误**：引用指向不存在的模型或可复用对象；引用文档外部（`other.yaml#/X`：请导入合并成一个文件的规范）；路径里的 `{参数}` 没有对应的 path 参数，或 path 参数不在路径里、不是 `required: true`；路径的花括号不配对；两个接口同一个 operationId 或同一条路由；关键字类型不对（`type` 不是七种之一、`items` 是数组、`required` 不是字符串数组、`pattern` 不是正则、`minLength` 不是非负整数、3.0 写法的布尔 `exclusiveMinimum`……）；响应没有 `description`；`security` 引用不存在的方案；`login`/`refresh`/`logout` 指向不存在的接口；服务器地址不是 URL；通道地址的参数对不上；通道操作引用不存在的消息；重复的模型名、通道 id、操作 id、环境名。
- **警告**：`required` 列了 `properties` 里没有的字段；`nullable`（3.0 写法）；GET/HEAD/DELETE 带请求体；没有 2XX 响应；分页接口的成功响应里没有 `items` 字段、没有列出分页参数；参数没有 schema；SSE 通道有 `receive`；集合关联了不存在的模型。

**每个操作都不能增加错误**：操作算出新的接口后先清理（`cleanApi`，和读入时一样的形状），再比较前后的错误，多出来的一律拒绝（`invalid_value`，说明哪里会错、怎么改），不管是编辑器、AI 还是 MCP 调用。已经有错误的文档照样打开，也照样能改（只是不能更糟），面板顶上显示问题数，点开列出全部。

**读入时**（`openProject`、`loadInto`，所以文件、分享链接、撤销、MCP 都一样）经过 `cleanApi`：形状不对的项丢掉（没有路径或方法的接口、没有名字的模型），重复的 operationId、通道 id、环境名加后缀区分，模型重名保留第一个；所有标准对象按 JSON 复制，有上限：

| 上限（`API_LIMITS`） | 值 |
| --- | --- |
| 模型 / 接口 / 通道 / 服务器 / 标签 / 鉴权方案 | 1000 / 2000 / 500 / 20 / 500 / 50 |
| 每个接口的参数 / 响应 | 100 / 60 |
| 每个通道的消息 / 操作 | 200 / 200 |
| 整个 `api` 的 JSON 值个数 | 400000 |
| 嵌套深度 | 64（Schema 的遍历另限 40 层） |
| 单个字符串 | 200000 字符 |

引用可以成环（`A` 引用 `B`、`B` 引用 `A`，或者递归的树）：生成 TypeScript 时只写类型名，从不展开；`followRef` 顺着引用走到不是引用为止，遇到环就停。`lib/hostileDocs.test.ts` 和 `lib/api/api.test.ts` 用几千层的 Schema、成环的模型、上万个重复的接口检查打开、校验、导出都在有限时间内完成。

## 操作和工具

都在 `OPS` 里，所以自动成为应用内 AI 和 MCP 的工具（分组 `data`，工具集 `api`），每个一步撤销（改的是文档字段，按整份文档留一步）。

| 操作 | 做什么 |
| --- | --- |
| `add_model {name, schema?, description?}` | 加一个模型；没给 schema 时是空对象 |
| `update_model {name, schema?, properties?, required?, description?}` | 换掉整个 schema，或按名字改字段（`null` 删除字段，新字段放最后，改过的留在原位） |
| `rename_model {name, to}` | 改名，所有引用、判别器映射和关联的数据集合跟着改 |
| `remove_model {name, force?}` | 删除；还被引用时拒绝并列出在哪，`force` 时引用变成空 Schema、集合解除关联（破坏性） |
| `add_endpoint {operationId, method, path, …}` | 加一个接口：路径里的 `{参数}` 自动成为必填的 path 参数；`body`、`contentType`、`returns`、`status` 是请求体和成功响应的简写；分页时自动加分页参数；默认带 problem+json 的 `default` 响应（`problem: false` 不要）；成功状态默认 POST 201、无返回的 DELETE 204、其余 200 |
| `update_endpoint {operationId, rename?, …}` | 改任何字段；改路径时 path 参数跟着变；`responses` 按状态码合并（`null` 删除）；`rename` 时鉴权的 login/refresh/logout 跟着改 |
| `remove_endpoint {operationId}` | 删除，鉴权不再指向它（破坏性） |
| `set_auth {schemes?, security?, login?, refresh?, logout?, tokenField?, refreshTokenField?}` | 设鉴权；方案按名字合并（`null` 删除） |
| `add_channel {id, address, …}` / `update_channel {id, rename?, …}` / `remove_channel {id}` | 实时通道；地址的参数自动补齐；消息和操作整表替换 |
| `set_servers {servers}` | 整表设置环境 |
| `set_api_info {title?, version?, description?, tags?}` | 标题、版本、说明和标签 |
| `import_openapi {text, mode?}` / `import_asyncapi {text, mode?}` | 导入（见下）；返回 `{models, endpoints, channels, converted, kept, dropped, problems}` |
| `add_collection` / `update_collection` 的 `model` | 数据集合关联模型（`null` 解除） |

读取工具（只读）：`get_api`（一段紧凑的大纲：服务器、鉴权、每个模型和字段、按标签分组的接口、通道、问题）、`describe_endpoint {operationId}`（完整的操作、解析后的参数、实际生效的 security、补全的分页、用到的模型的 Schema、它的问题）、`describe_model {name}`（Schema、字段表、生成的 TypeScript、在哪里用到）、`get_spec {kind: openapi | asyncapi | typescript}`（导出的文件文本）。

删除前先问（`lib/tools/removals.ts`）：`remove_model`、`remove_endpoint`、`remove_channel` 是破坏性操作；`update_model` 删掉字段、`set_servers` 少了环境、`set_auth` 去掉方案、`update_channel` 少了消息、`replace` 模式的导入拿掉模型或接口，也会被智能体的守卫和 MCP 的确认看到（改名不算删除）。

工具集 `api` 的触发说法（`lib/agent/toolsets.ts`）：英文的 API、endpoint、OpenAPI、schema、data model、pagination、WebSocket、JWT……；中文的接口、后端、数据模型、请求体、响应、状态码、分页、鉴权、令牌、实时消息……；日文的 エンドポイント、バックエンド、スキーマ、レスポンス、トークン、リアルタイム……；韩文的 엔드포인트、백엔드、스키마、응답、토큰、실시간……。

## 导入和导出

```ts
import { toOpenApi, toAsyncApi, schemaToTs, fromOpenApi, fromAsyncApi, mergeApi } from "./lib/api";

toOpenApi(doc: { api?: ApiSpec; title?: string }): string          // openapi.yaml（OpenAPI 3.1）
openApiObject(doc): Record<string, unknown>                        // 同上，未序列化的对象
toAsyncApi(doc: { api?: ApiSpec; title?: string }): string         // asyncapi.yaml（AsyncAPI 3.0）
asyncApiObject(doc): Record<string, unknown>
schemaToTs(api: ApiSpec | undefined, o?: { binary?: string; maxDepth?: number }): string   // 每个模型一个 export type
schemaTypeTs(schema: JsonSchema, o?): string                       // 一个 Schema 的类型表达式（内联的请求体、参数用）
fromOpenApi(input: string | object): { api: ApiSpec; report: ImportReport }
fromAsyncApi(input: string | object): { api: ApiSpec; report: ImportReport }
mergeApi(current: ApiSpec | undefined, incoming: ApiSpec, format: "openapi" | "asyncapi", mode: "merge" | "replace"): ApiSpec | undefined
toYaml(value): string / parseYaml(text, limits?): unknown / parseSpecText(text): unknown   // JSON 也能读
```

- **写出是纯函数**：同一份文档总是写出相同的文本。顺序：`openapi`、`info`、`servers`、`security`、`tags`、`paths`（路径按它第一个接口出现的顺序，方法按接口的顺序）、`webhooks`、`components`（`schemas` 是全部模型、可复用对象、`securitySchemes`）、`x-m3e-auth`、其余保留的字段。Schema 里的键保持存放的顺序（字段顺序就是表单的顺序）。YAML 用块格式、两个空格缩进，字符串只在会被读成别的东西时加引号（包括 YAML 1.1 的 `yes`/`no`/`on` 和日期，所以 PyYAML、js-yaml 读回来也一样）。没有 `info.title` 时用文档标题，没有版本时 `1.0.0`。
- **模型能表示的都原样往返**：`fromOpenApi(toOpenApi(x))` 的接口和 `x` 完全相同，再写一遍文本也相同（`lib/api/roundtrip.test.ts` 用商店和聊天两份真实规范检查；导出结果另外用 openapi-spec-validator 和 AsyncAPI 3.0 官方 JSON Schema 验证过）。
- **导入时转换的**（报告的 `converted`）：OpenAPI 3.0 读成 3.1（`nullable` 变成 `"null"` 类型，可空引用变成 `anyOf`，布尔的 `exclusiveMinimum/Maximum` 变成数值）；路径级的 `parameters` 放到它的每个操作上；没有或不合格的 operationId 按方法和路径生成（`GET /users/{id}` → `getUsersById`），重复的加后缀；不是标识符的模型名改成标识符（`user-profile` → `UserProfile`），引用跟着改；AsyncAPI 里通道引用的 `components.messages` 写进通道；带 `schemaFormat` 的 payload 按里面的 schema 读。
- **原样保留、导出时写回的**（报告的 `kept`）：`webhooks`、`externalDocs`、`jsonSchemaDialect`、顶层和对象上的 `x-` 字段、`info` 的 `contact`/`license`、可复用的 `components.responses/parameters/requestBodies/headers/examples/links/callbacks/pathItems`（接口里的 `$ref` 保持指向它们）、路径项自己的 `summary`/`description`/`servers`、操作的 `servers`/`callbacks`/`externalDocs`、服务器的 `variables`、AsyncAPI 的 `defaultContentType` 和其他 components、通道和操作的 `bindings`/`servers`/`reply`/`security` 等。
- **不支持、明确拒绝或丢掉的**（报告的 `dropped`，或报错）：Swagger 2.0 和 AsyncAPI 2.x（先用工具转换）；引用其他文件的 `$ref`（要先合并成一个文件；导入后作为问题列出）；路径项本身是 `$ref`；不以 `/` 开头的路径；操作引用了不存在的通道；AsyncAPI 服务器除地址外的字段（`bindings`、`security`、`variables`）。复杂映射键（`? `）、多文档 YAML 报错并说明行号。
- **合并方式**：`merge`（默认）同名的替换、新的加在后面、其余保留；`replace` 时 OpenAPI 文件替换 HTTP 一半（接口、模型、鉴权、标签、各环境的 HTTP 地址），AsyncAPI 文件替换实时一半（通道、各环境的实时地址）；另一半仍然引用的模型保留，不会留下指向空处的引用。导入不能让已有的内容出错（文件自己的问题照常报告）。
- **YAML 读取的上限**：800 万字符、嵌套 200 层、100 万个值（别名展开后计数，所以“十亿笑声”式的别名炸弹几毫秒内被拒绝）。`__proto__` 只是普通的键。

## 编辑器

左侧“接口”标签页（随第一次打开加载），顶上四个分页：

- **模型**：每个模型一行（名字和字段），点开后可以改名（引用跟着改）、写说明、删除（被引用时先确认）；字段表一行一个字段：名字、类型（文本、数字、整数、布尔、对象、列表，文件、日期时间、日期、时间、邮箱、链接、UUID，或某个模型）、必填，“更多”里是格式、可为空、可选值、说明、示例、列表的元素类型和删除。文件、日期时间这些类型就是带格式的文本（`format: binary`、`date-time`、`date`、`time`、`email`、`uri`、`uuid`），面板直接叫出它们的名字；文件没有可选值和示例；列表的元素也可以是文件（多个文件）。
- **接口**：按第一个标签分组，每行是方法、路径和“公开”“分页”标记；点开后编辑方法、路径（path 参数跟着变）、operationId、摘要、标签、谁能调用（接口默认、任何人、某个鉴权方案）、分页（不分页、游标、偏移和列表字段）、参数（path 参数只读，可加查询参数）、请求体（无、某个模型、模型列表、在这里写字段——字段的类型选“文件”，JSON 的请求体自动改成 multipart/form-data）、响应（每个状态码一行：无内容、模型、模型列表、问题详情）。
- **实时**：通道的 id、方式（WebSocket / SSE）、地址、消息（名字和内容）、收发（服务器发 / 服务器收，以及哪条消息）。
- **设置**：接口的名称和版本；服务器（一键加 dev、staging、prod，每个环境的基础地址和实时地址）；鉴权（一键加 Bearer JWT、API 密钥、OAuth2，默认需要什么，登录、刷新令牌、退出接口）；导入（粘贴或打开文件，合并或替换，自动识别 OpenAPI 还是 AsyncAPI，显示导入报告）；导出（下载 `openapi.yaml`、`asyncapi.yaml`、`api-types.ts`）。

面板只显示它能显示的：`oneOf`、引用可复用响应这类复杂结构显示为“自定义结构（用 AI 修改）”并写出它的类型，不会被面板改坏。每次修改都是一个操作、一步撤销；操作拒绝时提示条说明原因。

## 其他部分怎样用它

- **绑定**：屏幕的数据源用 `operationId` 指向接口；列表取分页约定里的 `items` 字段（`paginationOf` 补全名字）；表单对应 `requestBody` 的 Schema，校验来自 `required`、`format`、`minLength`/`maxLength`、`minimum`/`maximum`、`pattern`、`enum`；错误分支读 `Problem`（`errors[].pointer` 对应字段）。`followRef`、`fieldRows`、`endpointParams`、`bodyOf`、`successOf` 是现成的读取函数。
- **模拟库**：已完成，见 [模拟库](模拟库.md)。按模型的 Schema 生成数据（`format`、`enum`、`minimum`…），集合的 `model` 告诉它哪些行是哪个模型的示例；登录接口返回 `authFields(auth)` 指定的令牌字段；实时脚本按通道操作的 `send` 推送消息；成环的引用限制了深度。
- **后端骨架**：已完成，见 [后端](后端.md)。它把导出的 OpenAPI / AsyncAPI 读回模型（`fromOpenApi`、`fromAsyncApi`），用 `endpointParams`、`successOf`、`paginationOf` 读接口，`schemaToTs`（`binary: "UploadedFile"`）写类型；处理函数以 `operationId` 命名；错误响应用 `application/problem+json`；`security` 为 `[]` 的接口不需要令牌。
- **导出**：完整产品的导出（`lib/export/product.ts` 的 `buildProduct`）自己读 `doc.api`（`contractOf`），`packages/api` 的 openapi.yaml、asyncapi.yaml、类型和客户端，后端的路由和处理函数桩，契约测试都来自它；`bun run check:product <空文件夹> shop` 用商店和聊天的规范真的安装、构建、测试、跑契约测试。

## 已知限制

- 编辑器的字段表只编辑对象模型的一层字段；嵌套对象、`oneOf`/`allOf`、元组、条件 Schema 用 AI 或 `update_model` 改。
- 参数只编辑名字、位置、类型和必填；`style`/`explode`、参数的 `content` 写法原样保留但面板不显示。
- 外部文件的 `$ref` 不解析；AsyncAPI 的鉴权（`securitySchemes`、操作的 `security`）原样保留，没有进入模型的 `auth`。
- AsyncAPI 的动态地址（`address: null`）读成空地址。
- 每个通道操作在面板里只能选“全部消息”或一条消息（多条用 `update_channel`）。
