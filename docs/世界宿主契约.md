# 世界宿主契约

世界视口（`world-view`）里的画面、物理、镜头和规则归引擎；M3E 负责屏幕上的其余部分、访客的输入怎样送到世界、世界的事件
发生后设计做什么（[边界与契约](边界与契约.md)“实时玩法”）。这份文档写明两边之间的约定，和平台无关：M3E 的应用做宿主、世界是
一个视口（Web、H5 页面）时这样，以后引擎做宿主、M3E 的界面叠在它上面（Cocos 小游戏、Godot 电脑端，游戏阶段第六到第十批）时
也这样。机器可读的部分在仓库里：

| 文件 | 是什么 |
| --- | --- |
| `lib/world/types.ts` | 引擎实现的 `World` 接口，宿主交给它的通道 `WorldChannel`、插槽拿到的 `WorldSlotProps`，世界的时钟 `WorldClock` |
| `lib/world/contract.ts` | 一个世界的契约 `WorldContract`：输入动作（名字和类型）、快照和每个事件负载的 JSON Schema、时钟；示例引擎的契约 `EXAMPLE_WORLD_CONTRACT` |
| `lib/world/hostContract.ts` | 宿主的契约 `WorldHostContract` 和今天所有宿主遵守的 `WORLD_HOST_CONTRACT`：生命周期、输入优先级、遮挡、浮层、暂停、时钟 |
| `lib/world/channel.ts` | 每个视口一条通道（`createWorlds`）：送输入、读按住的输入、浮层打开时全部松开（`release`） |
| `lib/world/example.ts` | M3E 的示例引擎：只经 `World` 和宿主说话，第八批用它验证 Cocos 宿主 |

这些文件随 `app-runtime` 复制进导出的应用（`src/engine/world/`），导出时再按契约生成类型（`src/generated/worldContract.ts`：
快照、事件负载、输入动作的 TypeScript 类型，以后同样可以生成 GDScript）。

## 契约归谁

世界的契约（输入动作、快照、事件、拒绝的原因、时钟）由世界一方写：没有接玩法契约时是示例引擎的；文档接了外部玩法循环模块
写的玩法契约（[玩法契约](玩法契约.md)，`document.game`）时就是它的：走输入的命令是输入动作，快照、事件、时钟照搬
（`lib/game/map.ts` 的 `worldContractOf`），导出的 `src/generated/worldContract.ts` 按它生成。M3E 不拥有其中的规则，只按它检查设计、生成类型：世界视口的 `inputs` 列出设计要发的输入动作，编辑操作
检查每个 `move`、`press`、`release` 发给的输入在不在里面、类型对不对（[交互规则](交互规则.md)“输入动作”）。

## 只传 JSON

跨过两边的东西都是可序列化的：数字、文字、`Vec2`（`{x, y}`）、id，以及由它们组成的对象和列表。`World` 的方法里只有回调本身
（`subscribe`、`on`）是函数；`view()` 的快照和事件的负载都由契约里的 JSON Schema 描述。`mount(host, size)` 的 `host` 由宿主
定义，世界不能假定它是 DOM 节点：Web 上是一个 canvas 元素，手机上是原生视图的句柄，Cocos 里是一个节点；没有自己画面的引擎
（示例引擎）不用它，宿主自己按 `view()` 画。

## 生命周期

`create`（宿主用引擎自己的方式造出世界）→ `mount(host, size)`（世界开始自己的循环）→ connect（`connectWorld(world, channel, onEvent)`：
先补上通道里正按住的输入，之后每个输入到达就交给 `world.input`，世界的每个事件交给设计）→ 运行、暂停 → `unmount()`（循环停下，
宿主断开通道和事件）。视口的尺寸变了、设计给的初始状态变了，宿主卸载后重新创建。

## 输入

- **输入动作有名字和类型，在文档里声明一次。** 世界视口的 `inputs`：`"move: vec2, attack: bool"`。`vec2` 是方向（x、y 在 -1 到 1），
  `bool` 是按住与否。方向轮盘、技能按钮、按钮、按键都只是把访客做的事接到这些名字上（`on:move` → `move`，点击 → `press` / `release`
  `attack`），以后键盘和手柄映射到同样的名字，不挂在触摸事件上。
- **按时间戳送到。** 每个输入带上应用时钟上的时刻（`input(action, value, at)`），同步送到，不经网络和应用状态。
- **优先级：HUD 先。** 落在屏幕控件上的触摸归控件；落在世界上、不在任何控件上的才交给世界（`pointer`）。一次触摸从哪里开始就
  一直归那里，直到结束（捕获）。
- **遮挡。** 宿主量出叠在世界上的 HUD 控件的区域（视口自己的像素），布局一变就告诉世界（`occlude(rects)`），世界把要紧的东西
  放在外面。
- **浮层打开时松开。** 对话框、底部面板、菜单、叠上来的屏幕打开时，宿主把世界按住的输入全部松开（方向回到中间、按键松开：
  `Worlds.release`），关上之前不再送新的输入。

## 暂停

宿主在应用进入后台时请世界暂停（`requestPause(true)`），回来时继续；浮层打开时是否暂停由宿主契约的 `overlay.pause` 决定（今天不暂停）。
和别人一起玩的世界可以拒绝（`accepted: false`）：宿主照常显示它在运行，不等它。

## 时钟

世界有自己的时间：`clock()` 给出世界时间（毫秒）、是否暂停、相对应用时钟的倍率。世界时间跑在应用的领域时钟上（传输层给的 `now`：
后端的时钟，预览里是模拟库的时钟，可以暂停、调倍率，见[模拟库](模拟库.md)），从不读设备的墙钟；HUD 上属于世界的冷却和倒计时
按 `clock()` 算。示例引擎造出来时拿到应用的时钟（预览和产品网页是 `domainNow`，两个套件是 `kitNow`），预览里暂停模拟库的时钟，
世界也停下。
