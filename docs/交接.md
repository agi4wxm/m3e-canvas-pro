## 三、第三批后半：手机端零占位（已完成）

开始时：RN 原生 63 / 原子树 49 / 占位 104；小程序原生 56 / 原子树 49 / 占位 111。完成后两端都是原生 166 / 原子树 49 / 占位 1。

| 包 | 类别 | 套件里的文件（两端同名） |
| --- | --- | --- |
| D1 | 媒体、社交、AI、反馈 | `composites/media.tsx`、`composites/live.tsx` |
| D2 | 数据与图表、列表、桌面 | `composites/data.tsx`、`composites/desk.tsx` |
| D3 | 选择器、表单 | `composites/pickers.tsx`、`composites/entry.tsx` |
| D4 | 游戏、操作、菜单与搜索 | `composites/games.tsx`、`composites/actions.tsx` |
| D5 | 布局、导航、浮层 | `composites/layouts.tsx`、`composites/navs.tsx`、`composites/floating.tsx` |

做法：受控（值从属性来、变化从回调出；没给回调时是从属性开始、属性变了就重来的草稿）；组件里不决定领域结果（抽奖类只按给它的
结果停下，套件里没有演示和随机数；登录、支付按钮只发出按下和要调用的能力）；地图、相机、视频通话走 C5 的能力视图插槽，插槽的
`children` 现在是套件的替身（`MapStandIn`、`CameraStandIn`、`CallStandIn`）；导出端暂不运行的事件都以 `on<事件>` 回调暴露。

打印器的改动：D3 按输入声明的种类把新输入接上变量和表单字段（选择、数字、词表、文字）；D5 的停靠面板（开了自动布局）把每个
标签页都打印进去（`lib/export/panes.ts`）；表格里叫 `icon` 的列的图标也打包进应用。测试床新增 `play`、`layouts`、`inputs`、
`data`、`media` 五份文档，打印进 `rn/src/printed/` 和 `miniapp-kit/src/printed/`，两端的类型检查、lint 和渲染测试覆盖它们。

各组件和画布的差异写在 [手机端](手机端.md)“组件覆盖”之后的说明和 [小程序](小程序.md)的差异表里。主要的：

- 视频、音频、网页、动画只画替身，不播放、不加载；地图替身不能拖动缩放，不发 `regionChange`。
- RN 的二维码复制只通过 `onCopy`（手机端没有剪贴板包）；小程序用 `Taro.setClipboardData`。复制行（`copy-row`）两端都只发 `onCopy`。
- 小程序的操作表最多 6 行：级联菜单、菜单栏超出时分两层。
- 看板没有拖动（打开卡片用箭头移动）；可排序列表 RN 拖把手，小程序点行出上下按钮。
- 组合框在小程序用平台 `Picker`，不能边输边筛；滚轮选择器点选项转到它，不能拖动转动。
- 富文本的格式只是外观，值仍是纯文字；颜色选择只能输入十六进制。
- 工具提示、弹出框、悬停卡片、导航菜单占着画布上展开时的大小，点一下在触发按钮旁打开，不是平台浮层；抽屉、侧面板按设计画成打开的。
- 两个套件自带的文字（问卷、日程的月份和星期、默认的读屏名称）是英文，套件没有词表。

转入第四批（导出端接线）：

- 新组件的回调大多还没被打印器接上：`onSettled`、`onSelect`、`onReorder`、`onCopy`、`onMarkerTap`、`onCrop`、`onSubmit` 等。
- 日历、滚轮选择器、原生选择器、组合框、手机号输入、一次性验证码、字段在部件定义里没有声明输入，值留在组件里（组件已接受
  `value` 和回调）；可排序列表、左滑操作行的值到不了变量和表单（打印器报告 `input`）。
- 条形列表、文件列表、树跟随 `selected` 并调用 `onSelect`，但导出的应用不写回，点了高亮不动。
- Web 端未命名地图的默认插槽名 `MapView` 和 Web 组件同名，生成的屏幕会导入两个 `MapView`（D1 发现，未修）。
- RN 已有的 `Scene` 只画一层压暗、忽略热区；小程序新的 `Scene` 两者都画（D1 发现，未修）。
- 合并后要连跑两次 `bun run gen:miniapp`（第一次写 `parts.generated.ts` 时打印器还在用旧的默认值）。
- 小程序测试里对 `@tarojs/taro` 的替身必须列出套件用到的全部导出：bun 在一次运行里共享被替换的模块，少列会让别的测试文件加载失败。

- 评测：代理只跑和改动相关的子集（`--only`）；每批整合时全量跑一次，和 CI 同时进行；基线在开 PR 前提交，不额外触发 CI。
- 流水线：一个包交回就合进集成分支，下一个不依赖它的包立刻开工，保持 3–4 个代理在跑；整合时不在本机重跑全套，以 PR 的 CI 全绿加全量评测为合并条件；每批完成合进 main。
- 代理的共同说明模板见各批的 BRIEF（工作目录外，`/home/user/wt/BRIEF9.md` 是最新版）；交给新会话时把其中的规则照搬进代理的提示。

### 多代理协作（前三批的做法）

- 协调者在集成分支上合并，每个工作包一个代理、一个分支、一个独立工作目录，按文件归属划分（新组件放各自的新文件，共享清单在末尾加一块），避免互相冲突。
- 代理交回前先合并最新的集成分支，再跑门禁；冲突多时让熟悉改动的代理在自己分支上解决。
- 机器内存和磁盘有限（4 核、15 GB）：代理只跑和自己相关的测试，重的步骤（E2E、check:product、打包构建）由协调者在合并后一次跑一个；check:product 的目录用完就删。
