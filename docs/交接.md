## 三、第三批后半：手机端零占位（已完成）

开始时：RN 原生 63 / 原子树 49 / 占位 104；小程序原生 56 / 原子树 49 / 占位 111。完成后两端都是原生 166 / 原子树 49 / 占位 1。

| 包 | 类别 | 套件里的文件（两端同名） |
| --- | --- | --- |
| D1 | 媒体、社交、AI、反馈 | `composites/media.tsx`、`composites/live.tsx` |
| D2 | 数据与图表、列表、桌面 | `composites/data.tsx`、`composites/desk.tsx` |
| D3 | 选择器、表单 | `composites/pickers.tsx`、`composites/entry.tsx` |
| D4 | 游戏、操作、菜单与搜索 | `composites/games.tsx`、`composites/actions.tsx` |
| D5 | 布局、导航、浮层 | `composites/layouts.tsx`、`composites/navs.tsx`、`composites/floating.tsx` |

做法：受控（值从属性来、变化从回调出；没给回调时是从属性开始、属性变了就重来的草稿）；组件里不决定领域结果（抽奖类只按给它的
结果停下，套件里没有演示和随机数；登录、支付按钮只发出按下和要调用的能力）；地图、相机、视频通话走 C5 的能力视图插槽，插槽的
`children` 现在是套件的替身（`MapStandIn`、`CameraStandIn`、`CallStandIn`）；导出端暂不运行的事件都以 `on<事件>` 回调暴露。

打印器的改动：D3 按输入声明的种类把新输入接上变量和表单字段（选择、数字、词表、文字）；D5 的停靠面板（开了自动布局）把每个
标签页都打印进去（`lib/export/panes.ts`）；表格里叫 `icon` 的列的图标也打包进应用。测试床新增 `play`、`layouts`、`inputs`、
`data`、`media` 五份文档，打印进 `rn/src/printed/` 和 `miniapp-kit/src/printed/`，两端的类型检查、lint 和渲染测试覆盖它们。

各组件和画布的差异写在 [手机端](手机端.md)“组件覆盖”之后的说明和 [小程序](小程序.md)的差异表里。主要的：

- 视频、音频、网页、动画只画替身，不播放、不加载；地图替身不能拖动缩放，不发 `regionChange`。
- RN 的二维码复制只通过 `onCopy`（手机端没有剪贴板包）；小程序用 `Taro.setClipboardData`。复制行（`copy-row`）两端都只发 `onCopy`。
- 小程序的操作表最多 6 行：级联菜单、菜单栏超出时分两层。
- 看板没有拖动（打开卡片用箭头移动）；可排序列表 RN 拖把手，小程序点行出上下按钮。
- 组合框在小程序用平台 `Picker`，不能边输边筛；滚轮选择器点选项转到它，不能拖动转动。
- 富文本的格式只是外观，值仍是纯文字；颜色选择只能输入十六进制。
- 工具提示、弹出框、悬停卡片、导航菜单占着画布上展开时的大小，点一下在触发按钮旁打开，不是平台浮层；抽屉、侧面板按设计画成打开的。
- 两个套件自带的文字（问卷、日程的月份和星期、默认的读屏名称）是英文，套件没有词表。

转入第四批（导出端接线）：

- 新组件的回调大多还没被打印器接上：`onSettled`、`onSelect`、`onReorder`、`onCopy`、`onMarkerTap`、`onCrop`、`onSubmit` 等。
- 日历、滚轮选择器、原生选择器、组合框、手机号输入、一次性验证码、字段在部件定义里没有声明输入，值留在组件里（组件已接受
  `value` 和回调）；可排序列表、左滑操作行的值到不了变量和表单（打印器报告 `input`）。
- 条形列表、文件列表、树跟随 `selected` 并调用 `onSelect`，但导出的应用不写回，点了高亮不动。
- Web 端未命名地图的默认插槽名 `MapView` 和 Web 组件同名，生成的屏幕会导入两个 `MapView`（D1 发现，未修）。
- RN 已有的 `Scene` 只画一层压暗、忽略热区；小程序新的 `Scene` 两者都画（D1 发现，未修）。
- 合并后要连跑两次 `bun run gen:miniapp`（第一次写 `parts.generated.ts` 时打印器还在用旧的默认值）。
- 小程序测试里对 `@tarojs/taro` 的替身必须列出套件用到的全部导出：bun 在一次运行里共享被替换的模块，少列会让别的测试文件加载失败。

## 七、各批留下的零散问题（按领域）

### 组件与组件设置

- 弹出层、悬停卡、折叠、手风琴、标签页、滚动区、宽高比还不能放组件（开合状态在组件内部，预览分开画放进去的组件；需要第四批运行时）；
  抽屉、侧面板、卡片也还不是容器。动作面板还不是真正的浮层（改了会改变旧文档外观）。
- 需要第五批行模型：菜单栏每个菜单单独的槽位；按钮组、筛选芯片预选多项。
- 组合组件添加后改变体；分裂按钮的禁用和加载（M3E 组件本身没有）；尺寸预设和行命名（优先级低）。
- C1 部件里的图片替代文字：动态卡片、个人主页头、角色卡、裁图、视频通话；看图组件的对话框角色。
- 文件上传还没有输入声明（文件不在属性里）；RN 的 FileUpload 仍用 `chosen`/`onPress` 而不是值加回调。
- 导出端绑定数据的表格仍显示设计里的行（已报告差异）。
- 退役组件：风格包为这几个组件写的专门样式，不再作用到模板里改成原子的部分（默认风格外观不变，已写进已知限制）；模板里的行是静态原子，没有绑定数据集合。
- 分栏视图：窄屏只有“堆叠”或“保持布局”两种；手机应用只在运行期间记住拖动比例；导出的应用还不触发 `on:resize`。

### 平台能力

- `push.opened` 在设计里还没有写法。
- 导出的开发版不会自动使用能力的模拟结果（有意的：未实现时明确提示）。

### 风格

- 还走旧的同步风格路径的地方：核心操作里的套件重组、切换语言、文档加载（`lib/core/state.ts`）；打印器内部（`printRnScreens`、
  `buildScreens`、`buildCode`、`buildPrompt`）；编辑器 hooks 和回调；画廊和截图页各一处渲染时设置；评测检查器。
- 自定义风格继承 iOS、WeChat、Spotify 时拿不到这几个内置风格的手机端专门设置（已在导出差异里报告）。
- 截图页无论风格的图标族都画 Rounded 图标。
- 25/27 个内置风格在可访问性检查里有未达标项（`lib/styles/__snapshots__/styles.test.ts.snap`），属设计取舍，按需逐个调。

### 编辑器

- 根组件仍整体订阅 store；面板（约 330 个组件卡片）随根组件重渲染；选中时剩下的时间主要是浏览器绘制和图层合成（[编辑器性能](编辑器性能.md)）。
- 手势中的逐帧写入（拖动、缩放手柄、手势）、跟随每次修改的布局计算、启动加载路径，还没走统一操作入口。

### 存储

- 浏览器存储（IndexedDB）里 `text/*`、`model/*` 类型的模拟文件仍内嵌（文件夹项目已改为资源文件）。

### 测试与 CI

- 有时间上限的测试在机器很忙时会超时：第三批后半五个代理同时跑时，`parts/contract.test.ts` 的 “draws whatever a saved prop holds”
  几次超时（负载约 12，单独跑 23/23 通过、约 13 秒）。新仓库 CI 上若再出现，先确认是否机器负载，再找根因，不要跳过测试。
- RN 工程自己的 jest 与 Android 打包、小程序抖音/H5 构建由 CI 的 rn、miniapp、product 任务覆盖；本地只在动到时跑。

## 八、开发约定（换会话后照此执行）

### 门禁（每一步都必须过，脚本里用 `set -e`）

```bash
bun install
bun run typecheck
bun run lint            # 不允许警告
bun run check:icons
bun run check:icon-sets
bun run check:versions
bun run check:rn
bun run check:miniapp
bun run test
bun run build
bun run mcp:build
bun run test:e2e
```

动到导出、模拟库、绑定或接口时，再跑 `bun run check:product <空目录> shop`（约 15 分钟，用完删掉目录，很占磁盘）。
动到手机端或小程序套件时，再在 `rn/`、`miniapp-kit/` 里 `npm ci` 后跑 `npm run check`。

### 生成文件

- 改依赖后 `bun run gen:versions`；新增图标名后 `bun run gen:icon-sets` 和 `bun scripts/gen-tool-icons.ts`。
- 改到 RN / 小程序打印或一致性表后 `bun run gen:rn`、`bun run gen:miniapp`（新组件第一次进小程序套件时 `gen:miniapp` 跑两次）；改工具后 `bun run mcp:docs`（`gen:agent`）。
- 导出产物只在有意改变时变化；变了就更新 `lib/export/product.test.ts` 和 `lib/exportPrototype.test.ts` 里的摘要并说明原因。

### 评测

- 改到 AI 行为后用真实模型跑 `bun run eval -- --record <目录>`，与 `evals/baselines/` 里最新的基线比较；通过的结果把 `summary.md`
  和 `results.json` 存成新基线。最新基线：`2026-11-08-batch2`（31/31）、`2026-11-08-stage3`（边界任务 8/8）。

### 写代码和提交

- 每项修复都要有在旧代码上失败的测试；旧文档照常打开、外观不变。
- 新的界面文字放在 `lib/i18n/<模块>.ts`（中、日、英、韩四种）；代码注释用英文、写原因；用户文档用中文。
- 浏览器检查用 Playwright（`require('playwright')`、`chromium.launch()`）。
- 依赖版本查注册表，锁定精确版本。
- 提交说明用中文；每一批完成、CI 全绿后合并到 `main`。

### 多代理协作（前三批的做法，可沿用）

- 协调者在集成分支上合并，每个工作包一个代理、一个分支、一个独立工作目录，按文件归属划分（新组件放各自的新文件，共享清单在末尾加一块），避免互相冲突。
- 代理交回前先合并最新的集成分支，再跑门禁；冲突多时让熟悉改动的代理在自己分支上解决。
- 机器内存和磁盘有限（4 核、15 GB）：代理只跑和自己相关的测试，重的步骤（E2E、check:product、打包构建）由协调者在合并后一次跑一个；check:product 的目录用完就删。
