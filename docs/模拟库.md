# 模拟库

模拟库让设计中的产品**不需要后端**也能完整运行：文档的接口（`Doc.api`，见 [接口](接口.md)）由模拟库回答，数据按数据模型的 JSON Schema 生成，看起来像真的（人名、头像、邮箱、地址、价格、日期……中英日韩四种语言），同一个种子总是同样的数据。要文件的地方给真实可解析的文件：图片（PNG、JPEG、WebP、GIF、SVG……）、PDF、Excel / Word / PowerPoint、CSV、JSON、YAML、压缩包、音视频、3D 模型（GLB、glTF、OBJ、STL）等四十多种格式，内容取自它所属的记录或列表的行（见[文件](#文件)）。预览、导出的 Web 应用、手机应用和小程序的开发版、它们的测试，用的都是同一个模拟库。

它的设置存在文档的 `mocks` 字段（`Doc.mocks`）里，全部可以不写：有接口、没有任何模拟设置的文档，照样得到按 Schema 生成的数据（种子 1、编辑器的语言）。作者（或 AI）只写自己想改的：种子和语言、某个字段怎样生成、每个模型几条记录、手工固定的记录、命名场景、文件库、实时脚本、登录方式。

代码在 `lib/mocks/`（纯 TypeScript，不依赖 DOM、`fetch`、`atob`、`TextEncoder` 和 Node，所以在编辑器、MCP 服务器、导出的工程和小程序里都能跑），操作在 `lib/core/ops/mocks.ts`，读取工具在 `lib/tools/mocksRead.ts`，编辑器面板在 `components/MocksPanel.tsx`，预览里的场景切换和请求记录在 `components/MockPreview.tsx`，界面文字在 `lib/i18n/mocks.ts`。

```text
lib/mocks/
  types.ts      Doc.mocks 的类型（MockSpec 等），没有别的依赖
  rng.ts        确定的随机数：每个值有自己的键（种子、模型、第几条、字段路径）
  bytes.ts      手写的 base64、UTF-8、data URL（小程序没有 atob 和 TextEncoder）
  locales.ts    中英日韩的姓名（带拉丁拼写）、城市街道和地址写法、电话、公司、商品、句子……
  hints.ts      从字段名、format、enum 推断“这个字段是什么”（inferHint）
  pattern.ts    按简单正则生成字符串
  shape.ts      模型的形状：合并 allOf、识别记录的 id 字段、接口返回哪个模型的记录
  generate.ts   生成器：JSON Schema + 提示 → 值
  data.ts       每个模型的记录：固定的在前，数据集合的行，再生成到数量；记录之间互相引用
  files.ts      文件的种类、扩展名、下载的头（Content-Type、Content-Disposition）和基本的占位文件（SVG、PDF、WAV、MP4、二进制）
  formats/      各种文件格式，纯 TypeScript 的字节（见“文件”）：

    index.ts      各格式的生成器：mockFile、makeBytes、placeholderFile（随引擎加载）
    content.ts    文件的内容：记录、列表的行或按种子生成的小表格
    deflate.ts    手写的 DEFLATE / zlib / gzip、CRC-32、Adler-32
    zip.ts        ZIP 和 tar
    raster.ts     图片的像素：和 SVG 占位图同样的渐变、圆和标题（5×7 点阵字体）
    codecs.ts     PNG、JPEG（基线）、WebP（无损 VP8L）、GIF（LZW）、BMP、ICO、TIFF
    huffman.ts    限长的 Huffman 码（JPEG、WebP 用）
    svg.ts        SVG 图片和头像
    pdf.ts        多页 PDF：标题、字段、表格、段落、页码
    office.ts     XLSX、DOCX、PPTX（最小的合法 OOXML）
    text.ts       CSV、TSV、JSON、NDJSON、XML、YAML、TXT、Markdown、HTML、RTF、iCalendar、vCard、GeoJSON、GPX、KML
    mesh.ts       3D：按种子选的网格，GLB、glTF、OBJ、STL、PLY
    media.ts      WAV 提示音和 MP4 短片
    clips.ts      MP3、Ogg、WebM、M4A、AVIF 的短片（用 ffmpeg 从测试信号做一次，base64 存在这里）
  routes.ts     接口 → 路由：按 REST 习惯推断每个接口对数据做什么
  check.ts      请求校验：按 Schema 逐字段报错，带 JSON Pointer
  clock.ts      时钟：真实的，和测试用的假时钟
  realtime.ts   实时通道的脚本
  transport.ts  createMockTransport：模拟的 Transport
  fill.ts       “按接口填充模拟库”和默认场景
  clean.ts      读入时的形状检查和上限（只在编辑器里用）
  outline.ts    给模型看的大纲（get_mocks）
```

## 模型

| 字段 | 类型 | 意思 |
| --- | --- | --- |
| `seed` | 整数 | 种子，默认 1。同样的种子、同样的接口，得到逐字节相同的数据 |
| `locale` | `zh` / `en` / `ja` / `ko` | 数据的语言；不写时跟随编辑器 |
| `scenario` | 场景 id | 预览从哪个场景开始；不写是“正常” |
| `latency` | `{min, max}` 毫秒 | 每个回答等多久，默认 150–450 |
| `errorRate` | 0–1 | 随机有多少比例的请求返回 500 |
| `models` | `MockModelConfig[]` | 每个模型：`name`、`count`（记录数，含固定的，默认 24，最多 5000）、`seed`（“重新生成”把它加一，只换这个模型的数据）、`hints`（按字段路径的生成提示）、`fixtures`（手工固定的记录） |
| `scenarios` | `MockScenario[]` | 命名场景，见下 |
| `files` | `MockFile[]` | 文件库：`{id, name, type, data, tags?}`，`data` 是 data URL |
| `realtime` | `MockRealtimeScript[]` | 实时脚本；不写时每个通道按默认方式推送，写成空列表表示一个都不推 |
| `auth` | `MockAuth` | `signedIn`（默认 true）、`accept`（接受的账号，不写时任何账号都行）、`tokenTtl`（秒，默认 3600）、`refreshTtl`（默认 30 天） |
| `routes` | `{operationId, kind?, model?}[]` | 某个接口不按 REST 习惯推断时，指定它做什么、给哪个模型的记录 |

### 生成提示（hints）

字段路径从模型开始写：`name`、`price.amount`、`images[]`、`items[].quantity`。提示是 `{kind, …}`：

- `kind`：`auto`（按名字推断）、`id`、`uuid`、`personName`、`firstName`、`lastName`、`username`、`avatar`、`email`、`phone`、`address`、`street`、`city`、`region`、`country`、`postcode`、`latitude`、`longitude`、`company`、`jobTitle`、`productName`、`category`、`tag`、`price`、`currency`、`quantity`、`rating`、`percent`、`age`、`title`、`sentence`、`paragraph`、`word`、`slug`、`code`、`color`、`url`、`image`、`file`、`audio`、`video`、`fileName`（带扩展名的文件名）、`mimeType`（媒体类型）、`date`、`dateTime`、`time`、`boolean`、`number`、`integer`、`enum`、`status`、`token`、`password`、`ip`、`version`、`constant`。
- 数字：`min`、`max`（也是列表长度的范围）；日期：`from`、`to`（ISO 日期，或相对现在：`-30d`、`+7d`、`-2h`、`now`）；枚举和状态：`weights`（值 → 权重）；`values`（从这些词里挑）；`constant` 的 `value`；`image`/`file`/`audio`/`video` 的 `files`（文件库里的 id）和 `type`（文件的格式：媒体类型或扩展名，`text/csv`、`xlsx`、`model/gltf-binary`、`png`）；`nullRate`（可选或可为空的字段留空的比例）。

没写提示的字段按名字、`format`、`contentMediaType` 和 `enum` 推断（`lib/mocks/hints.ts`）：有 `contentMediaType` 的字符串是那种文件，`reportCsv`、`exportXlsx`、`modelGlb`、`logoPng` 这样名字里带格式的文件字段是那种格式（`{kind: "file", type: "text/csv"}`），`fileName`/`filename` 是文件名，`mimeType`/`contentType`/`mediaType` 是媒体类型，`fileSize`/`bytes` 是字节数；`email` 是 example 域名下的邮箱，`avatar` 是头像，`name` 在 User 里是人名、在 Product 里是商品名、在 Store 里是公司名，`createdAt` 是过去半年里的时间、`expiresAt` 是将来的，`price`/`amount` 是这种货币的价格，`status` 的第一个值最常见，`productId` 是某个商品的 id……“按接口填充”把推断出的提示写下来，作者可以逐个改。

### 场景

`{id, name, description?, all?, ops?, latency?, errorRate?, counts?, signedIn?}`：

- `all`：每个接口怎样回答；`ops`：按 operationId 单独设置（盖过 `all`）。一条规则是 `{status?, body?, latencyMs?, network?, empty?, fixtures?, sequence?}`：
  - `status` + `body`：用这个状态码回答（注入错误：401、404、500……），`body` 不写时是 problem+json；
  - `network: true`：网络失败，没有回答（`status` 0）；
  - `empty: true`：这个接口的模型从空的开始（列表为空，详情 404，新建的照样能看到）；
  - `fixtures: "all" | [id…]`：只有固定的记录；
  - `latencyMs`：这个接口等多久；
  - `sequence: [步骤…]`：第 1 次调用用第 1 步、第 2 次用第 2 步……最后一步一直重复，用来试重试（先网络失败、再 503、再成功）。
- `latency`：所有回答等多久；`errorRate`：随机失败；`counts`：记录数（`"*"` 是所有模型）；`signedIn: false`：以未登录开始。

“按接口填充”加的五个场景：**新用户**（`all: {empty: true}`）、**大量数据**（`counts: {"*": 240}`）、**网络错误**（`all: {network: true}`）、**慢网**（2–3.2 秒）、**未登录**（`signedIn: false`），名字按数据的语言写。

### 文件库

图片、PDF、Office 文件、表格、数据、压缩包、音频、视频、3D 模型和任意二进制文件，都是 data URL。和项目的图片一样保存：浏览器里大文件单独存进 IndexedDB、文档里留 `m3e-asset:` 引用（`lib/assets.ts`，现在也收音频、视频和 `application/*`）；存成文件夹时，模拟库能生成的每一种格式（PDF、XLSX、CSV、GLB、音频、视频……）都和图片一起放进 `m3e-assets/`（只限 `mocks.files` 里的，类型是模拟库生成它时用的那个；别名和不认识的类型留在项目文件里，见 [项目文件](项目文件.md#模拟库)）。单个最多约 12 MB，最多 200 个。

字段用文件库里对应种类的文件：头像和图片字段用图片（`tags` 里有 `avatar`、`product` 时按标签挑），文件字段用 PDF、文档、表格、数据、压缩包、3D 模型和二进制，音频、视频字段用音频、视频；字段说了格式（提示的 `type`、Schema 的 `contentMediaType`）时只用这种格式的文件；提示的 `files` 可以指定用哪几个。文件库里没有合适的就按下面“文件”一节生成。

### 文件

文件库里没有合适的文件时，模拟库自己做一个**真实可解析**的文件：同一个种子同样的字节；能放内容的格式，内容取自它所属的记录（发票的 PDF 写着发票的字段）或列表的行（订单列表的 CSV、XLSX 就是那些订单）；没有记录时是按种子生成的小表格（品名、数量、价格、日期）。全部是纯 TypeScript 写出的字节（`lib/mocks/formats/`），不用 DOM、canvas、Node 的 Buffer 或 `fetch`，在编辑器、导出的 Web / React Native / 小程序里都一样。

| 类别 | 格式（扩展名） | 怎么做的 |
| --- | --- | --- |
| 图片 | PNG、JPEG、WebP、GIF、SVG、BMP、ICO、TIFF、AVIF | 和 SVG 占位图同样的图：种子的两种颜色的渐变、三个半透明的圆、白色的标题（点阵字体，只有大写拉丁字母、数字和常用符号；其他文字只写进文件的元数据：PNG 的 iTXt、JPEG 的注释）；头像是圆形渐变加姓名首字母，非拉丁名字画头和肩的剪影，外面透明（JPEG、BMP 铺白底）。PNG 逐行选滤波再压缩，JPEG 是基线 4:4:4、按图做的 Huffman 表，WebP 是无损 VP8L（一个预测器），GIF 是这张图自己的调色板加 LZW，ICO 里面是 PNG，TIFF 不压缩。AVIF 是一张固定的小图 |
| PDF | PDF | A4，至少两页：带颜色的标题栏和标题，记录的字段（标签和值），列表的表格（每页重复表头），段落，页脚“第几页 / 共几页”。页面上用标准 Helvetica（WinAnsi），所以只显示拉丁文字；任何语言的标题都写进文档属性（`/Title`） |
| 文档 | DOCX、RTF | 标题、副标题、记录的字段表（或列表的表格）、段落 |
| 表格 | XLSX、CSV、TSV | 一张工作表：表头加粗并冻结、自动筛选、数字是数字、布尔是布尔；嵌套对象展开成 `customer.name` 这样的列；CSV 按 RFC 4180 加引号（逗号、引号、换行），CRLF，UTF-8 不带 BOM |
| 演示 | PPTX | 一张种子颜色的标题页，每条记录一页（字段做成要点），最多 20 页 |
| 数据 | JSON、NDJSON、XML、YAML、GeoJSON、GPX、KML、iCalendar（ICS）、vCard（VCF） | 列表是数组、记录是对象；YAML 读回来和 JSON 一样；GeoJSON / GPX / KML 用记录自己的经纬度（`lat`/`lng`、`location.lat`……），没有时在数据语言的城市附近；ICS 每条记录一个事件（时间取 `start`、`date`、`placedAt` 这类字段）；VCF 每个人一张名片（姓名、邮箱、电话、公司） |
| 文本 | TXT、Markdown、HTML | 标题、段落和表格 |
| 压缩包 | ZIP、gzip、tar | ZIP / tar 里是 `README.txt`、`data.json`、`data.csv`、`picture.png`；`.gz` 是 JSON 压缩 |
| 音频 | WAV、MP3、Ogg（Opus）、WebM（Opus）、M4A（AAC） | WAV 是种子选的一个音的提示音；其余是固定的 0.9 秒提示音 |
| 视频 | MP4（H.264）、WebM（VP9） | 两秒的渐变短片（96×54） |
| 3D | GLB、glTF（缓冲区内嵌为 data URL）、OBJ、STL（二进制）、PLY | 种子选的形状（立方体、球、圆环、圆柱、宝石），种子颜色的材质，法线朝外，没有零面积的三角形 |
| 其他 | 二进制 | 一行说明加种子生成的字节 |

MP3、Ogg、WebM、M4A、MP4、AVIF 的编码器比整个模拟库还大，所以各是一段用 ffmpeg 从测试信号（正弦音、渐变）做一次的很短的片段，base64 存在 `formats/clips.ts`、`formats/media.ts`（合计约 13 KB，自己生成，没有版权问题），同一类型的文件都一样。

**格式怎么选**（从先到后）：

1. 接口的回答：OpenAPI 回答的 `content` 键（`text/csv`、`application/pdf`、`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`、`model/gltf-binary`……）；一个接口给出好几种时按请求的 `Accept` 选（RFC 9110 的 q 值，见下）。
2. 字段：提示的 `type`，Schema 2020-12 的 `contentMediaType`。`contentEncoding: base64`（或 OpenAPI 3.0 的 `format: byte`）的字段给 base64 字符串；文本类的 `contentMediaType`（`text/csv`、`application/json`……）没有编码时给文本本身；其余给地址（data URL，或 `fileUrl` 给的地址）。
3. 记录：同一条记录里的文件名（`fileName`、`filename` 的扩展名，固定记录里的也算）和媒体类型（`mimeType`、`contentType`）。下载 `application/octet-stream` 时也看所属记录的这两个字段，再看接口名里的词（`exportCsv`）。
4. 都没有时：图片字段是 SVG 占位图（和以前一样），文件字段是 PDF，音频是 WAV，视频是 MP4，下载是二进制。不认识的类型给同一类里最接近的（`image/heic` → PNG，`video/quicktime` → MP4，`model/fbx` → GLB，`application/vnd.x+json` → JSON），文件的 `type` 写它真正的类型。

**互相对得上**：生成的记录里，文件名的扩展名、媒体类型字段和 `size`/`fileSize`/`bytes` 字段跟着做出来的文件改（作者写死的值不改）；附件模型 `{fileName, mimeType, size, file}` 读起来像一个真文件。

**大小**：Schema 给了 `maxLength`（data URL 或 base64 的字符数、文本的长度；下载回答的二进制是字节数）时，图片缩小、表格少几行、PDF 少几页，直到放得下；data URL 怎样都放不下时给一个短地址（`https://files.example.com/名字`）。

### 实时脚本

`{id, channel, trigger?, steps, repeat?}`：`steps` 是 `{at: 毫秒, message: 通道的消息名, payload?}`，`payload` 不写时按消息的 Schema 生成，写了对象就盖在生成的上面。`trigger`：`{on: "connect"}`（默认，连上就开始）、`{on: "call", operationId}`（应用调用了这个接口之后，比如发帖后推一条通知）、`{on: "message", message}`（应用发了这条消息之后，自动回复）。`repeat: {every, times?}` 隔多久重放，`times` 不写时一直重放到断开。

没写脚本时每个通道：连上后服务器发（`send`）的每条消息隔 1.5 秒各推一条，6 秒后再来两轮；应用发消息后，0.9 秒回一条服务器的消息。

## 生成器

`generateValue(schema, options, {key, model, path, name})`：

- **确定**：每个值的随机数来自它自己的键（种子、模型、模型的种子、第几条、字段路径），所以给模型加一个字段，其他字段的值不变；生成的顺序也不影响结果。
- **一个对象的字段是同一个人**：同一条记录的姓名、用户名、邮箱、头像首字母属于同一个人；价格按同一对象里的 `currency` 定范围（日元、韩元是整数）。
- **记录之间互相引用**：嵌套的模型（订单里的商品）取那个模型已有的记录，`productId`、`authorId` 这样的字段取对应模型某条记录的 id，所以点进详情能找到。
- **Schema 覆盖**：`type`（含 `"null"` 和多类型）、`enum`、`const`、`default`、`format`（email、uuid、date-time、date、time、uri/url、ipv4/ipv6、binary/byte、password、phone）、`minimum`/`maximum`/`exclusive*`/`multipleOf`、`minLength`/`maxLength`、`pattern`（字面量、`\d\w\s`、字符类、`.`、分组和 `|`、`? * + {n,m}`；看不懂的放弃，换别的值；重复里又有重复的模式（`^(\w+\s?)*$`）只按模式本身生成，不拿别的词去试，因为差一点匹配的字符串会让正则引擎花指数时间）、`items`/`prefixItems`/`minItems`/`maxItems`/`uniqueItems`、`properties`/`required`/`additionalProperties`、`allOf`（合并）、`oneOf`/`anyOf`（选一支，`discriminator` 写上对应的名字）、`readOnly`（请求里不生成）/`writeOnly`（回答里不生成，比如密码）、`$ref`。生成的值一定通过自己 Schema 的校验（测试逐个格式检查）。
- **有界**：同一个模型在自己里面最多再出现一次（成环的引用到此为止：可为空的给 null，可选的不写）；嵌套最多 10 层；每次生成最多 5000 个值；`minItems` 最多当 100、`minLength` 最多 2000。几十亿的 `minItems`、一千层的引用链、灾难性的正则，都在一瞬间答完。
- 邮箱只用 `example.com`、`example.net`、`example.org`；英文电话用为虚构保留的 555-01xx；姓名是常见的姓和名随机组合，不是真人的数据；不联网。

## 模拟传输层

```ts
import { createMockTransport } from "./lib/mocks";

const transport = createMockTransport({ api: doc.api, mocks: doc.mocks, collections: doc.collections }, {
  scenario: "new-user",   // 不写时用文档选的场景，"" 表示正常
  seed: 1,                // 不写时用文档的
  locale: "zh",
  now: Date.UTC(2026, 0, 1),     // 日期围绕的时刻；不写时是今天零点（UTC）
  clock: fakeClock(),            // 测试用的假时钟
  latency: false,                // false 不等待；数字或 {min, max}；不写时用文档的
  onLog: (entry) => {},          // 每个请求回答后告诉它
  fileUrl: (file) => file.data,  // 回答里的文件写成什么地址，默认 data URL
});
await transport.request({ method: "GET", path: "/products", query: { limit: 20 } });
```

它就是 `lib/api/transport.ts` 的 `Transport`，另外有：`scenario`、`setScenario(id)`（换场景并重开会话）、`reset()`、`log`（最近 200 个请求：方法、路径、operationId、状态码、耗时、场景、说明）、`records(model)`（这个会话里的记录）、`connect(地址或通道 id, onMessage)`（实时通道）、`close()`。**从不抛错**：出什么问题都是一个回答，状态码 0 表示网络失败（没有回答）。

**路由**：按方法和路径（含路径参数）匹配，固定段多的路径先试；有 operationId 时优先用它；路径对、方法不对是 405（带 `Allow`）；都不对是 404。`/__mocks/files/<id>` 下载文件库里的文件或这个会话上传的文件（`Content-Disposition: inline`）。

**每个接口做什么**（`routes.ts`，`set_mock_route` 可以改）：

| 接口 | 推断为 | 做什么 |
| --- | --- | --- |
| 鉴权的 login / refresh / logout | `login` / `refresh` / `logout` | 发令牌、换令牌、退出 |
| GET，回答不是 JSON（PDF、图片、CSV、XLSX、GLB、二进制……） | `download` | 回答一个那种格式的真实文件（见“文件”）：路径在某条记录下面时（`/invoices/{id}/pdf`、`/files/{id}/download`）用那条记录（找不到 404），在某个列表下面时（`/orders/export`）用列表的全部行（最多 1000 条）；文件库里有同类型的文件时先用它 |
| 请求体是 multipart 或二进制 | `upload` | 收下文件，回答里的地址字段填上它的地址；路径在某条记录下面时（`/products/{id}/images`）把地址加到那条记录的图片字段 |
| GET 集合路径，回答是数组或带列表字段的对象 | `list` | 这个会话的记录，过滤、搜索、排序、分页 |
| GET 集合路径/{id} | `get` | 一条记录，找不到 404 |
| POST 集合路径 | `create` | 新记录：请求里的字段，加上服务器填的（id、`createdAt`、必填却没给的、只读的、有默认值的），放在最前面；201 和 `Location` |
| PATCH 集合路径/{id} | `update` | 按 RFC 7396 合并（null 删除字段），更新 `updatedAt` |
| PUT 集合路径/{id} | `replace` | 整条换掉，保留 id、创建时间和只读字段 |
| DELETE 集合路径/{id} | `delete` | 删掉，204 |
| GET 不带参数、回答是一个模型（`/me`） | `singleton` | 一份这个会话里固定的值；登录后的 `/me` 是登录的那个用户；同路径的 PATCH/PUT 改它 |
| 其他 | `action` | 按回答的 Schema 生成 |

嵌套的集合（`/users/{userId}/posts`）按 `userId` 字段过滤，新建时填上它。

**按 Accept 回答别的格式**：一个 GET 接口的成功回答同时给了 JSON 和别的类型（比如列表也能是 `text/csv` 或 XLSX）时，请求的 `Accept` 选哪种就回答哪种：每个类型取最具体的匹配范围的 q 值，q 最高的胜出，平局按接口里写的顺序；不带 `Accept`、`*/*` 或只接受 JSON 时回答 JSON（导出的 fetch 传输层默认发 `accept: application/json`）。别的类型是从 JSON 回答做的：列表的这一页做成表格，一条记录做成它的文档。

**文件的头**：下载和别的格式的回答是一个 `TransportFile`（`{name, type, dataUrl, size}`），带 `Content-Type`（文本类加 `; charset=utf-8`）和 `Content-Disposition: attachment; filename="…"`，名字不是 ASCII 时另加 `filename*=UTF-8''…`（RFC 6266 / 8187）。回答 `text/plain` 的接口回答文本本身，`Content-Type` 是它自己的类型。回答的 Schema 把模型包在一个对象里时（`{data: Product}`），按 Schema 生成外层再放进记录。

**分页**：按接口的 `x-m3e-pagination`：游标（不透明的游标，最后一页 `nextCursor` 为 null）、偏移（`totalField` 是总数）；没写分页但有 `cursor`/`after`/`offset`/`skip`/`page` 查询参数时按参数推断。页大小来自 `limit` 参数，默认和上限按参数的 Schema（默认 20，最多 100）。`total`、`count`、`hasMore` 这样的字段也填对。

**过滤、搜索、排序**：和字段同名的查询参数按值过滤（多个值、数组字段都行），`minPrice`/`maxPrice`、`price_min` 这样的按范围；`q`/`query`/`search`/`keyword` 在所有文字里搜（每个词都要有）；`sort=-createdAt`、`sort=price:desc`、`sortBy` + `order`。

**请求校验**：路径参数、查询参数、请求头参数、请求体都按 Schema 检查（类型、必填、枚举、格式、长度、范围、正则、多余字段……），PATCH 只检查给了的字段。错误是 400 的 `application/problem+json`，`errors: [{pointer: "#/price/amount", detail: "应大于 0"}]`（查询参数是 `#/query/limit`），`detail` 按数据的语言写；接口只声明了 422、没有 400 时用 422。路径里的 id 格式不对（不是 UUID）当作找不到（404）。

**登录**：

- 默认“以已登录状态开始”：需要鉴权的接口不带令牌也能用（设计时看得到数据）。场景或设置里 `signedIn: false` 时，没有令牌一律 401（带 `WWW-Authenticate`）。
- 登录接口检查账号（`auth.accept` 里有一组字段全对上就行，不设置时任何账号都可以），回答按登录接口的 Schema 生成，令牌放在 `authFields(auth)` 指定的字段（默认 `accessToken`、`refreshToken`），有 `expiresIn` 字段时写上有效期，有 `user` 字段时是登录的用户。令牌是 JWT 的形状（`alg: none`，`exp` 是真的过期时间）。
- 带了令牌就必须有效：不认识的 401 `invalid_token`，过期的 401 加 `code: "token_expired"`；刷新接口用刷新令牌换一对新的（旧的作废，一个刷新令牌只能用一次）；退出后令牌作废，也不再算已登录。API 密钥和 Basic 有值就行。

**场景、延迟和错误**：顺序是：先等（场景或接口的延迟，`latency: false` 时不等）；网络失败返回 0；随机失败返回 500；场景规定的错误状态码；没有登录 401；请求校验 400；最后才是正常回答。请求被取消（`signal.aborted`）时也返回 0。

## 实时

```ts
const room = transport.connect("/rooms/r1", (m) => console.log(m.channel, m.message, m.payload));
room.send("chatMessage", { text: "hi" });   // 触发 trigger 为这条消息的脚本
room.close();
```

地址可以是通道 id、通道的地址（`/rooms/{roomId}` 填上参数），也可以是以它结尾的完整 URL（`wss://rt.example.com/realtime/rooms/r1`，前缀不限）。调用接口会触发 `trigger: {on: "call"}` 的脚本，推到这个通道的每个连接上。

**线上的格式和导出的后端一样**（见 [后端](后端.md)）：WebSocket 的一帧就是消息的 JSON payload 本身，没有外层包装；应用发来的一帧是哪条消息，看它符合通道里应用可发（`receive`）的哪条消息的 Schema。SSE 的事件名是消息名，`data` 是 JSON payload。每条推送的 `MockMessage` 带着 `transport`（`websocket` / `sse`）和 `frame`（线上的文字：WebSocket 是 JSON，SSE 是 `event: 名字\ndata: JSON\n\n`）；`connection.receive(frame)` 收下应用发的一帧（返回认出的消息名，认不出是 undefined），`connection.send(名字, payload)` 按名字发。

## 读入和保存

读入时（`openProject`、`loadInto`）经过 `cleanMocks`（`lib/mocks/clean.ts`）：形状不对的丢掉（种类不认识的提示、id 不合格的场景和文件、不是 data URL 的文件），数字收进范围，有上限：模型 1000、每个模型的提示 400 和固定记录 500、场景 100、每个场景的接口规则 2000、重试序列 20、文件 200（单个 1600 万字符，全部 9600 万字符）、实时脚本 500、每个脚本 200 步、整个 JSON 40 万个值。只有名字、什么都没设的模型设置去掉。生成时每条记录最多 4000 个值，一个模型的全部记录合起来最多约 100 万个值：记录很多（几千条）又很宽的模型，每条记录分到的少一些（至少 150），预览打开时不会先花半分钟生成上亿个值；常用的条数（包括“大量数据”场景的 240 条）不受影响，数据和以前一样。

## 导出

完整产品的 `packages/mocks` 就是这个模拟库（见 [导出](导出.md)）：`src/engine/` 是 `lib/mocks` 的引擎文件（含 `formats/` 下的各格式生成器）和它读的 `lib/api/types.ts`、`schema.ts`、`transport.ts` 原样复制（`MOCK_ENGINE_FILES`），所以导出的应用和编辑器预览回答得一模一样；设计里的东西作为数据放在旁边：`src/generated/contract.ts`（接口和关联模型的数据集合）、`settings.ts`、`fixtures.ts`（固定的记录）、`scenarios.ts`（场景和 `ScenarioName` 类型）、`files.ts`（文件的 data URL），文件本身另外放在 `packages/mocks/files/`。

```ts
import { createMockTransport } from "@shop/mocks";          // 传输层模拟：Web、React Native、小程序、测试
const api = createApi(createMockTransport({ scenario: "new-user" }));

import { startWorker } from "@shop/mocks/browser";          // Web 开发服务器：MSW 的 Service Worker
import { mockServer } from "@shop/mocks/node";              // Node 测试：msw/node
import { startNative } from "@shop/mocks/native";           // React Native 开发版：MSW 3 的拦截器（fetch、XMLHttpRequest）
await startNative({ baseUrl: "https://api.shop.example/v1" });
```

MSW 的处理函数和传输层用同一个会话：多部分表单的文件读成 `TransportFile`，下载回答文件的字节（带传输层给的 `Content-Type` 和 `Content-Disposition`），`text/plain` 这样的文本回答原样发出，状态码 0 变成网络错误（`HttpResponse.error()`）。实时通道也由 MSW 回答：WebSocket 通道是一个 `ws.link`，SSE 通道是一个 `sse` 处理函数（只接 `Accept: text/event-stream` 的请求），都按“URL 以通道地址结尾”匹配（开发服务器的 `/api` 代理只转发 HTTP，实时地址不经过它），帧的格式和后端一样。MSW 3 没有 `msw/native` 了，`native.ts` 用 `msw/experimental` 的 `defineNetwork` 加 `@mswjs/interceptors` 的 fetch 和 XMLHttpRequest 拦截器（即原来的 msw/native）。

**只在开发时**：Web 应用只在 `import.meta.env.DEV` 时加载模拟库，生产构建里没有它；`scripts/check-product.ts` 检查构建产物里没有 `createMockTransport`、`setupWorker`、`m3e-mock-engine`，也没有 Service Worker 文件，并在开发服务器上确认 MSW 回答的是模拟库按 Schema 生成的数据。

## 一个生成器

导出的后端和契约测试要示例值的地方（契约测试的请求体、路径和查询参数、实时消息，后端自检用的请求）也用这个生成器（`lib/export/server/examples.ts` 只是包了一层）：`preferExamples` 让契约自己的示例（`examples`、`example`、`default`）优先，`minimal` 只填必填的和有示例的字段、列表取最短、不给 null，语言固定英文，日期围绕固定时刻，所以同一份契约导出的文件逐字节不变。

## 已知限制

- 屏幕没有绑定接口时，模拟数据只在请求记录面板和“模拟”标签页的记录表格里看得到；绑定见[数据绑定](数据绑定.md)。
- `pattern` 只支持简单正则；`if`/`then`/`else`、`dependentSchemas`、`patternProperties` 不参与生成（照样能通过的值多数情况下没问题，不能保证）。
- 过滤只认和字段同名的参数和 min/max 前后缀；更复杂的查询语法（`filter[price][gt]`）照原样忽略。
- 导出的 `files.ts` 把文件写成 data URL，文件库很大时开发包也大（只在开发时加载）。
- 图片上的标题只有大写拉丁字母、数字和常用符号；PDF 的页面上只有 WinAnsi 能写的拉丁文字。其他文字只在元数据里（PNG、JPEG 的文本，PDF 的标题）。
- MP3、Ogg、WebM、M4A、MP4、AVIF 是固定的小片段，不随种子变化；HEIC、MOV 这类做不出来的类型给同类里最接近的格式。
