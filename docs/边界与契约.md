# 边界与契约

这份文档写明 M3E Canvas Pro 负责什么、不负责什么，以及它和外界之间的约定。组件、模板、AI 生成的设计和导出的产品都按这里判断；组件怎样写见[组件规范](组件规范.md)，导出时怎样报告见[导出](导出.md)。

下文的“对面”指契约的另一边：后端、玩法规则、引擎，或者平台能力的适配代码。

## 定位

> M3E Canvas Pro 负责产品里用户看得见、碰得到的那一层：把状态画出来，把用户的意图送出去，并把这一层和外界之间的约定（契约），连同执行约定的管道，生成到 Web、手机应用和小程序上。
>
> 它不决定领域权威状态怎么变、业务或玩法结果是什么。业务规则、玩法规则、数值、随机结果、权威时间、领域存档、游戏世界（2D/3D 场景、物理、镜头），以及支付、地图、相机、定位、推送、第三方登录这类平台能力的真实实现，都在契约的另一边，由后端、玩法工具、引擎或平台适配代码负责。
>
> M3E 和它们通过机器可读的契约、传输或本地宿主通道、固定扩展点相连。运行时的领域真值来自外部输入；组件可以保存表现状态和有明确提交/重置语义的 UI 草稿。M3E 做不了的东西，在画布上留占位、写说明，在导出的产品里留插槽。

## 交互闭环

```text
输入 → 意图 → [ 规则：状态怎么变、结果是什么 ] → 新状态 → 反馈
└─── M3E ───┘                                  └─── M3E ───┘
```

M3E 负责闭环的两端：捕获输入、表达意图；读取新状态、呈现反馈。中间那一步不碰。

## 三种状态

| 状态 | 是什么 | 例子 | 归谁 |
| --- | --- | --- | --- |
| 表现状态 | 只决定此刻画成什么样，丢了无所谓 | 动画进度、转盘转到哪、摇杆拖到哪、逐字出现 | 组件自己（如 `NumberTicker` 的补间，`parts/widgets/Motion.tsx`） |
| 界面状态 | 这台设备上界面走到了哪 | 当前屏幕和参数、浮层开关、选中的标签、没提交的输入、深色模式、数据是否在加载 | M3E 运行时（预览的 `PreviewState`，`lib/interact.ts`；导出的 `Runtime`，`lib/app/runtime.ts`） |
| 领域状态 | 产品里“真的是这样”的事 | 余额、背包、任务进度、签到天数、抽中了什么、棋盘局面、冷却、胜负、支付结果 | 对面。M3E 只读，只请求修改 |

判断依据是**谁有权确认事实、如何提交和协调冲突**，不是“是否持久化、是否跨端”。本地或跨端保存的输入草稿、面板比例、排序偏好仍然是界面状态；评分的编辑值、待选的座位不是已经提交的评分或已锁定的座位。订单、库存、胜负这类结果不能由组件宣布成立。草稿要讲清初值、当前值、提交、取消和外部重置。

坐标系是集成提示，不是职责的唯一分界。场景、物理、镜头和世界里的权威位置由引擎负责；引擎可以提供实体锚点和可见性，M3E 在上面画名称、血条、伤害数字。锚点投影、遮挡和输入优先级由宿主契约约定。

## 负责与不负责

**M3E 负责：**

| 方面 | 内容 | 代码 |
| --- | --- | --- |
| 外观 | 风格、主题角色、效果、图标、自动布局、设备尺寸 | `lib/styles/`、`lib/look.ts`、`lib/flow.ts` |
| 组件 | 每个组件一份定义（`PartDef`），连同它的输入、事件、槽位、演示的声明 | `parts/registry.ts`、`parts/types.ts` |
| 界面结构 | 屏幕、导航和参数、浮层、流程、转场、钉住的栏、滚动 | `lib/screenMotion.ts`、`Frame.params` |
| 界面状态 | 变量和模式、浮层、选中项、输入草稿 | `lib/interact.ts`、`lib/app/` |
| 把状态画出来 | 数据源、表达式、按数据重复、区域五种状态、按语言格式化 | `lib/bindings/` |
| 把意图送出去 | 点击、槽位、槽位族、组件事件、输入 → 效果 → 调用接口、提交表单 | `Effect`（`lib/tokens.ts`）、`lib/partContract.ts` |
| 契约在客户端的镜像 | 按 Schema 校验、错误落到字段、令牌与刷新、401 去登录页、乐观更新与回滚 | `lib/bindings/rules.ts`、`lib/app/session.ts` |
| 契约和两端的管道 | 编写接口契约；客户端；后端骨架；只在开发时用的模拟库；契约测试 | `lib/api/`、`lib/mocks/`、`lib/export/` |
| 验证和交付 | 预览与导出同一份代码；带场景的无头截图；三端导出；生成与自定义分开；导出报告列出差异 | `lib/bindings/headless.ts`、`lib/export/` |

导航和登录守卫、分页游标、表单的客户端校验、令牌刷新、“加载中/空/出错”的判断看起来像逻辑，但它们是界面自己的逻辑，归 M3E。后端骨架里的路由和校验也由 M3E 生成，那是契约的机械执行，不是业务。

**M3E 不负责：**

| 不负责 | 归谁 |
| --- | --- |
| 业务规则：领域状态怎么变 | 后端处理函数（导出产品的 `server/src/handlers/`） |
| 结果：抽中什么、掉落、胜负、伤害、得分、匹配 | 后端或玩法规则 |
| 数值和配置：价格、消耗、奖励、概率、成长曲线 | 后端或玩法工具（M3E 只读） |
| 权威时间：冷却、体力恢复、每日重置、活动截止 | 后端或玩法 |
| 领域存储和存档 | 后端（`server/src/custom/db.ts`）或玩法；编辑器文档、UI 草稿和偏好的持久化可由 M3E 负责 |
| 身份与权限的判断 | `server/src/custom/auth.ts` |
| 游戏世界：场景、精灵、物理、镜头、粒子、寻路、AI、主循环 | 引擎或玩法工具；外部锚点上的 UI 可按契约交给 M3E |
| 平台能力的真实实现：支付、内购、地图、相机、扫码、定位、推送、第三方登录、音视频通话、统计 | 各端只写一次的能力适配文件（见下文“平台能力”）；M3E 只定义接口、设计各种结果的界面、提供预览模拟 |

不负责实现，不等于不管：M3E 给这些东西留占位，用说明写清楚要什么（`Item.note`、`Frame.note`，自定义组件的“它做什么”），并通过提示词交给实现的人或 AI。

## 九条契约

1. **状态进，意图出。** 领域真值从属性进来；点击、输入值、选中项和命名事件从声明过的出口出去。允许组件持有表现状态和契约明确的 UI 草稿。
2. **受控与演示分开。** 受控值直接来自属性，变更只发意图；领域演示只在显式的原型模式里运行。产品里没接上时显示未配置或只发出请求、等待结果，不能自动进入演示并宣布成功。
3. **结果来自对面，表现可以等。** 要看结果的表现分三段：发出意图 → 等待 → 结果从属性进来后落定，并发出“表现结束”的事件。表现上的随机可以，结果上的随机不行。
4. **意图只走契约。** 可能改变领域状态的意图，一律是契约里的一个接口操作或一次能力调用，经传输层或能力层出去，不开侧门。
5. **表达式和变量不承载规则；设计里的数都是示例。** 表达式只读、确定、有上限，只做显示用的派生；变量只存界面状态和显示用的副本；价格、消耗、奖励、概率、冷却时长不写死在设计里。
6. **模拟只模拟形状和通用语义，不模拟规则。** 场景描述处境（新用户、断网、未登录、支付被取消），不描述规则；需要按规则回答的预览接外部传输层。
7. **每个状态都有设计。** 状态有没有由契约决定，长什么样由 M3E 决定，而且不能留空，包括能力调用的取消、失败、拒绝授权、不可用。
8. **一份实现到处一样；做不了的留插槽。** 行为放在契约和共用运行时里，由各端打印器生成；平台做不了的东西在画布上留占位，在导出里留只写一次的插槽文件。暂时做不到的，导出报告里写明，不悄悄丢掉。
9. **和邻居相处。** 每份契约只有一个作者；不删不认识的字段；生成的归 M3E，自定义的归别人，扩展点只增不改。

## 对外：承诺与要求

**M3E 承诺：**

- 项目文件稳定：同一份文档写出相同字节，不认识的字段保留（目前只在顶层、屏幕、组件组、组件和动作这几层做到，见[项目文件](项目文件.md)）。
- 意图只以契约操作或能力调用的形式出去。
- 读数据只用表达式和固定的根：`data`、`params`、`vars`、`item`、`index`、`form`、`auth`、`response`、`error`、`status`、`row`、`now`，以及事件动作里的 `event`、槽位族动作里的 `slot`（`lib/bindings/expr.ts`）。
- 契约里声明的每种状态和错误都有设计。
- 自定义代码永远不被覆盖，扩展点只增不改。
- 编辑器、应用内 AI、MCP 用同一套操作；可以无头截图、带场景截图，别的工具（包括玩法工具的 AI）能自动把屏幕接到契约上。
- 导出报告列出三端都还依赖、但还不存在的东西：原型演示、组件事件、契约里没有的接口、待接入的平台能力（见[导出](导出.md)“和设计的差异”）。

**M3E 要求对面：**

- 机器可读的契约：数据模型（JSON Schema）、操作（OpenAPI）、推送（AsyncAPI）、能力接口，带示例。
- 一个传输层实现：从不抛错；网络失败是状态 0；错误是 problem+json，字段错误带 `errors[].pointer`。
- 每种拒绝带稳定的 `type`（资源不足、冷却中、已领取、已售罄、支付被取消……），M3E 为每一种设计一个样子。
- 时间声明时钟域、单位、同步方式和暂停/倍率语义；可以给 `endsAt`、`readyAt`，也可以给带采样时刻的剩余时间。UI 不把自己的墙钟当成领域时钟。
- 结果、数值、配置都作为数据给出。
- 命名的处境（新用户、第 7 天、资源不足、支付失败），让预览可以一键切换。

## 灰色地带怎么判

| 情况 | M3E 可以 | 必须交给对面 |
| --- | --- | --- |
| 表单校验 | 按 Schema 先拦明显的错误 | 最终判断（422 落回字段） |
| 乐观更新 | 先画出来，失败回滚（`Optimistic`，`lib/tokens.ts`） | 真正的结果 |
| 钱不够时禁用按钮 | 按读到的数据禁用并提示 | 照样要拒绝 |
| 倒计时 | 按契约时钟与截止点/采样状态推算显示 | 权威计时、暂停/变速、到点之后能不能做 |
| 随机 | 表现上的随机 | 结果上的随机 |
| 输入 | 死区、角度、手势识别 | “往前走一格”“放技能” |
| 计算 | 显示用的派生和格式化 | 应付金额、折扣、伤害、掉落 |
| 演示行为 | 在显式原型模式，由组件的演示逻辑驱动（`PartDef.demo`） | 完整产品里的真实行为；缺绑定不能触发假成功 |
| 支付回调 | 显示“已提交”“处理中”“已取消” | “支付成功”以后端订单状态为准 |
| 定位、相机、推送授权 | 设计“请求中”“被拒绝”“不可用”的界面 | 真正的授权和取值 |
| 画面 | HUD、面板、宿主提供锚点上的 UI | 世界状态、场景模拟、镜头与投影权威 |

拿不准时问两个问题：**这件事由谁确认它成立？** 如果是对面，组件只能发请求、等结果。**丢了它会不会让产品里“真的是这样”的事变得不对？** 会，就不是界面状态，不能放进变量或组件的本地状态。

## 实时玩法（移动、攻击）的边界

实时移动和攻击整体在 M3E 之外，M3E 只管屏幕这一层：HUD、手指在 HUD 上做了什么、屏幕上的反馈、战斗前后的流程。

**判定线**是领域后果与权威归属。坐标系、更新频率、触摸落点只用来选择实现通道，不是硬性禁令；UI 动画也可以逐帧运行。拖动技能键瞄准时，按钮由 UI 绘制，瞄准结果由世界决定，地面范围圈可以由世界绘制。跨层手势由宿主协商捕获、优先级、取消和焦点，UI 不单方面占有全部输入。

**两条通道：**

- 低频走契约和传输层：开局、匹配、结算、奖励。
- 高频走一条本地通道：同步调用，不经网络，也不经 React 状态。计划中的世界视口原子 `world-view`（模板里已有一个叫 `stage` 的辅助函数，`parts/templates/game.ts`，两者不是一回事）由引擎实现下面的接口：

```ts
interface World {
  mount(host: unknown, size: { w: number; h: number }): void;
  occlude(rects: Rect[]): void;                                    // HUD 挡住的区域
  input(action: string, value: Vec2 | boolean, at: number): void;  // 输入动作，带时间
  pointer(e: WorldPointer): void;                                  // 没落在控件上的触摸
  view(): unknown;                                                 // HUD 读的小快照
  subscribe(changed: () => void): () => void;
  on(event: string, run: (payload: unknown) => void): () => void;
  clock(): { now: number; paused: boolean };                       // 世界时间
  requestPause(paused: boolean): Promise<{ accepted: boolean; reason?: string }>;
  unmount(): void;
}
```

契约由世界一方声明：输入动作、HUD 只读快照、事件和时钟域。世界快照可以进入 UI 的只读投影，但不能成为另一份可写的权威。高频输入走专用通道，UI 按世界时钟显示冷却，支持暂停和变速。浮层打开时，按宿主的输入策略释放捕获并发送必要的归零或取消；联机世界可以拒绝暂停。事件用于界面反馈和导航，不在 UI 里结算玩法。

宿主有两种选择：M3E 的应用做宿主、世界作为一个视口（适合 2D、轻中度实时、Web 和小程序）；或者引擎做宿主（3D、重度实时）。输入动作、HUD 快照、事件这三样在两种方式下一样，先定成和引擎无关的契约。世界视口和输入动作建在组件事件（下文）之上，不另起一套。

## 平台能力：只定义接口，不做实现

支付、地图、相机、扫码、定位、推送、第三方登录、内购、音视频通话、统计这些能力，和后端业务、玩法规则一样，**M3E 不做真实实现**，只做四件事：

1. 定义能力接口：输入、输出、事件、失败类型。
2. 在设计里表达“什么时候调用、结果怎么呈现”，每种结果（成功、取消、失败、拒绝授权、不可用、未实现）都有设计。
3. 在预览里用模拟结果驱动这些界面。
4. 导出类型定义和只写一次的适配文件、插槽文件，由人或 AI 接真正的 SDK。

M3E 不嵌 SDK，不放密钥，不判定结果，不请求系统权限。唯一的例外是不需要账号、没有产品逻辑的通用能力（打开链接、复制、选文件、分享），M3E 可以提供各端的默认适配，但也走同一个接口，可以被覆盖。

能力目录、`invoke` 效果、能力视图和导出的适配插槽还在计划里（[整改计划](整改计划.md)第三批）。在那之前：

- 地图、相机、视频通话、语音消息、登录和支付按钮是占位外观。导出报告把它们列为“待接入的平台能力”（`capability`）。
- 设计里用“调用接口”（`call`）表达后端那一半（创建订单、领取、登记推送令牌），用组件的说明（`note`）写清楚平台那一半要做什么、返回什么。
- 支付的“成功”只来自后端的订单状态：提交订单 → 平台支付（只代表已提交或已取消）→ 结果页按订单状态显示待支付、处理中、已支付、失败。不要从按钮直接跳到“支付成功”。

## 在代码里怎样守住

| 规则 | 落在哪里 |
| --- | --- |
| 组件声明它的出口和演示 | `PartDef` 的 `input`、`events`、`families`、`demo`、`overlay`、`nav`（`parts/types.ts`）；读它们的地方只有 `lib/partContract.ts` |
| 领域演示只在显式原型模式运行 | 组件默认是产品模式（`parts/widgets/host.ts`）；编辑器的预览和原型导出才打开演示，绑定了演示所说的属性或动作里调用了接口时就不再演示（`demoRuns`、`demoTakenOver`） |
| 意图从声明过的出口出去 | 动作存在 `Item.actions` 里：槽位（`tab:2`）、槽位族（`tab:*`，表达式读 `slot.index`）、事件（`on:submit`，表达式读 `event.*`）；严格校验只接受部件声明过的键（`lib/core/ops/validate.ts`） |
| 做不到的不悄悄丢 | Web、手机应用、小程序的导出报告都列出原型演示、组件事件、契约里没有的接口、平台能力（`lib/export/boundary.ts`） |
| AI 也守边界 | 应用内 AI 的提示词、工具指南和 MCP 的说明（`lib/agent/prompt.ts`、`lib/tools/registry.ts` 的 `BOUNDARY_GUIDE`）、`public/agent.md`；评测里的负例任务（`evals/boundaryTasks.ts`，能力 `boundary`） |
| 组件契约测试 | `parts/contract.test.ts`（声明合法、产品模式只显示给定的状态、随机结果只在演示里）、`parts/widgets/outlets.test.ts`（逐个自带组件：受控值跟随属性、对面拒绝时显示不变、没人接值时的草稿和外部重置、产品只发请求而演示自己演、数据重排后选中的行不变、自有控件不算按了整个组件）、`lib/partContract.test.ts`（出口、接管、导出不演示并报告差异）、`e2e/outlets.e2e.ts`（预览里的受控值、草稿、提交事件、演示与接管） |
