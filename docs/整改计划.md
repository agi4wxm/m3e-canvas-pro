# 整改计划

依据：《M3E Canvas Pro 审查及整改建议报告》（审查基线 `cf3fa45`，即当前 main）。本文件记录按报告重新制定的修复顺序、
每批的工作包和验收方式，并随进度更新。条目编号沿用报告：阶段 0 的十六项、第 13 章的 ED/ST/AI/MC/DS/UI 编号。

## 原则

1. **正确性先于新功能。** 数据完整性、取消和授权（报告 14.1 的 A、B 批）最先做，不等任何大重构。
2. **每项修复带上能复现问题的测试。** 纯数据和状态机进 Vitest；键盘、焦点、动效、网络策略用浏览器/E2E；
   跨进程和符号链接用真实临时目录和多进程。报告 14.2 的场景表就是验收清单。
3. **不伪造领域结果。** 组件不在内部决定胜负、支付成功、抽奖结果；平台能力（支付、地图、相机、推送……）只定义接口、
   模拟和插槽，M3E 不嵌入 SDK、密钥或权限声明（报告第 1、2 章）。
4. **同一件事只写一次。** 交互规则现在有五份实现（报告第 6 章）。新加的事件、输入声明、能力调用都建在统一解释器
   （`lib/actions`）的语义说明和一致性测试之上，不再在五个宿主各写一遍。
5. **旧文件照常打开。** 模型变化走迁移框架（版本 3），保留未知字段。

## 当前进度（截至本计划）

- 已合并：组件与风格体系（#1）、文档核心 / AI 工具 / 应用内智能体 / MCP / 项目存储（#2、#3）、
  完整产品：接口契约、绑定、模拟库、Node 后端骨架、网页 / React Native / 小程序三端导出（#4）。
- 报告审查的正是这个版本，报告列出的缺陷都还在，下面逐项安排。
- 两项暂停的工作按报告调整：
  - **模拟库 v2（各种文件和数据格式）**：与报告不冲突，作为第一批的独立工作包继续。报告要求的 `Doc.mocks.capabilities`
    和由传输层提供 `now` 分别放进阶段 3 和阶段 7。
  - **手机端组件覆盖（RN 110、小程序 118 个占位）**：暂停，改到阶段 2、3 之后做。原因是报告要求先改组件本身：
    11 个整块组件退役（拆成原子，不再移植）；地图、相机、视频通话、网页视图等改成"能力视图 + 插槽"，不在套件里接
    SDK；抽奖、游戏类组件改成受控（结果由属性传入）；组件先有 `input`、`events`、槽位族声明。先移植再改造等于做两遍。

### 第一批的结论与遗留

- 报告条目逐项核对后都属实；两处表述偏重：Web 起始路由只是导出的 `START` 常量错了，直接打开网址一直进对的屏；
  `resizable` 的初始比例本来就对，真正的问题是双击复位按像素算。
- 报告之外顺带发现并修好的：`lib/assets.ts` 同样的特殊键问题；MCP 静态服务器遇到畸形百分号地址时整个进程会崩溃；
  小程序未定类型的请求体同样绕过路径段检查；完成后的 AI 回合“撤销”也只撤最后一段；RN 和小程序里叫 Screen 的屏幕无法编译。
- 补充修复（已完成）：三端导出的请求层把二进制下载当文本读坏；MCP 文件模式同名资源只看存在不比内容；
  文件夹项目里新格式的模拟文件仍内嵌在 JSON 里。合并前 CI 还查出：组件自带的实心字形挡住了描边字形的加载，
  Iconify 可达时应用栏菜单图标空白，已修。
- 转入后续批次：react-resizable-panels 升级到 4.19（缩放下拖动偏差，第三批分栏）；预览与 `lib/app` 丢弃过期回答的规则
