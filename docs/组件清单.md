## 组合件

组合件只以原子树的形式存在：拖到画布上（或点一下加到视图中央）就是一组嵌套的自动布局盒子，里面每一块都是普通组件，可以单独改、挪、删。面板上带“原子”标记（叠层图标），表示它由原子组件拼成，点标记选变体；不选时按文档的风格挑合适的变体（比如 VS Code 风格下搜索栏是带快捷键的桌面式）。

画廊 `/gallery?kits=1` 只画组合件的每个变体，当前风格会选中的变体标 ★；加 `chosen=1` 只画被选中的那个，方便逐个风格检查。

## 可拆分的组合组件

下面这些组合组件在面板上带“可拆”标记：整体加入，选中后属性面板里有“拆分为原子组件”：在原位置换成同样外观的原子树，保留名字、宽度、填充色和点击跳转，一步撤销。

`sonner`、`alert`、`card`、`item`、`dialog`、`alert-dialog`、`navigation-bar`、`app-bar`、`tabs`、`toolbar`、`breadcrumb`、`search`、`empty`、`message`、`bubble`、`attachment`、`description-list`、`stat-card`、`title-bar`、`status-bar`、`steps`、`asset-pill`、`item-cell`、`reward-track`、`check-in`、`action-sheet`、`subscription`、`timeline`、`product-card`、`price-tag`、`coupon`、`checkout-bar`、`balance-card`、`transaction-list`、`route-card`、`profile-header`、`post-card`、`leaderboard`、`conversation-list`、`section-header`、`banner`、`notice-bar`、`review-summary`、`stat-bar`、`character-card`、`game-result`、`dialogue-box`、`side-tabs`、`function-button`

共 49 个（11 个已退役的整块组件也都能拆，见下一节）。拆出的树画出组件当前的状态：优惠券是否已领取、商品卡片已加购的数量、动态的红心和收藏、行程是否已预订、交易记录选中的筛选和每行的收支方向、签到的今天、奖励进度已领取的格子、对话框正在显示的那一句、评价汇总选中的标签。拆出的树和原组件同宽、同样的文字、图标和选中状态；画廊 `/gallery?splits=1` 把每个组件和它拆出的树并排画出来对照。已知的差别：叠在图片上的角标和头像（商品卡片的折扣角标、个人主页压在封面上的头像）在原子树里排在下面一行，所以略高一些；优惠券的虚线分隔是实线。

## 退役的组件

这 11 个整块组件把数据和行为留在自己里面（购物车自己加减、算合计，登录表单自己校验后显示“验证通过”，设置分组的开关不保存），产品没法把它们接到后端，所以退役了（[边界与契约](边界与契约.md)；审查报告 3.3、3.4）：

| 组件 | 改用 |
| --- | --- |
| `inventory` 背包 | 网格盒子，格子用 `item-cell` 或原子，按背包的数据重复；选中哪一格由屏幕决定 |
| `task-row` 任务条 | `quest-row` 组合件按任务数据重复；“领取”调用接口，已领取的状态来自回答 |
| `pull-to-refresh` 下拉刷新 | 屏幕数据源的“下拉刷新”（`pullToRefresh`），三端都是原生的下拉刷新 |
| `cart-list` 购物车 | `cart-row` 组合件按购物车数据重复，底部 `buy-bar`；勾选、加减、删除、全选各自调用接口，合计和件数来自数据 |
| `contact-list` 联系人列表 | `search-bar` 加 `contact-row` 按数据重复；搜索词进变量作为数据源参数，关注调用接口 |
| `comment-list` 评论列表 | 头像、名字、时间、内容、点赞的原子行按数据重复，加 `chat-input`；点赞、发送调用接口，回复设变量 |
| `notification-list` 通知列表 | 标题行加 `notification-row` 按数据重复；点一行打开并调用“标为已读”，“全部已读”调用接口后刷新 |
| `settings-group` 设置分组 | `settings-row`、`inset-group` 组合件；开关、复选框是真正的输入，值进变量或表单 |
| `todo-list` 待办清单 | 复选框、文字、删除按钮按数据重复；新增一行用输入框加按钮或 `make_form` |
| `auth-form` 登录注册表单 | `login-form` 组合件（加 `password-field`、`terms-row`）用 `make_form` 接到登录接口；注册单独一屏，规则来自接口的 Schema |
| `chat-composer` 消息输入栏 | `chat-input` 组合件：输入框的值进变量，发送调用接口后清空 |

- **旧文档照样打开、照样画。** 组件定义还在（`parts/defs/`），画法不变；打开文件时不做任何改写，格式版本也不变（不是迁移，见[项目文件](项目文件.md)“版本和迁移”）。
- **不再提供。** 组件面板（含以前收藏的）、AI 的组件清单（`list_parts`、`public/agent.md`）里都没有它们；在面板里按旧名字搜（如“Shopping cart”“购物车”），列出的是替代它的组合件和组件（`parts/defs/retired.ts` 的 `with`，购物车是 `cart-row`、`price-summary`、`buy-bar`）；`add_part`、`add_tree` 遇到它们会拒绝，并说明改用什么。`public/agent.md` 的“Retired”表、`describe_part` 和 `describe_node` 的 `retired` 告诉 AI 它们是什么；文档里有退役组件时，应用内 AI 每一轮的上下文里会列出它们。所有模板都已改成原子（拆分出的同一棵树，外观和以前一样）。
- **拆成原子。** 文档里有退役组件时，画布上方出现提示：有几个、是哪些，“拆成原子”一次拆完（一步撤销），“暂不”收起到下次打开。也可以选中一个，在属性面板里“拆分为原子组件”。AI 和 MCP 用 `split_retired`（不给 `ids` 时拆屏幕上所有的）或 `split_into_atoms`。拆出的树和组件同样大（`e2e/retire.e2e.ts` 在画布上量过，11 个的宽高都和组件一样）、同样的文字和图标，组件各处的点击落在显示它的原子上。
- **列表变成数据。** 一个列表的各行拆出来是同样的原子、同样的样子和点击，只有单元格的文字不同时，只留一行做模板（文字写成 `{{字段}}`），外面一个盒子按新建的数据集合重复它，集合里是组件原来的行（字段名取表格的列名，如 `name`、`price`；头像的缩写另存一列 `initials`）。画出来和不按数据重复的拆法逐个原子相同。默认的购物车、评论列表都会这样拆；各行样子不同（未读的通知、已完成和未完成的待办、开关和箭头混排的设置、按首字母分组的联系人）、各行点击去不同地方，或者只有一行时，行保持为原子，不建集合。拆开后集合可以连接口的模型，或者换成按接口数据重复（`set_repeat`、`wire_screen`）。
- **拆开后不再自己算。** 购物车的合计和“结算 (3)”的件数、待办的“1 / 3”是拆分时组件显示的文字，之后不再随勾选和加减变化，要绑定到数据；登录表单的校验提示（`badEmail` 等）和“验证通过”不拆出来，校验由接口的 Schema 和表单（`make_form`）负责。下拉刷新拆出来只是一个提示框，下拉交给它所在屏幕的数据源：屏幕加载数据时，拆分（`split_retired` 或属性面板）在这些数据源上打开“下拉刷新”（`pullToRefresh`，结果里的 `refreshes` 列出是哪些），和拆分是同一步、一起撤销；屏幕还没有数据源时，等有了再在数据源上打开。
- **导出。** 拆开后三端都是普通原子。没拆的旧文档里，Web 照旧用组件自己的代码；手机应用和小程序把它们画成拆出的原子树，组件各处的点击落在显示它的原子上。React Native 套件原来的 `AuthForm` 不保存输入、也不校验，已经删掉，登录表单在手机上和小程序一样画成原子树。

自带组件的代码在 `parts/widgets/`，其余组件直接由 `components/m3e/` 的 shadcn M3E 组件拼成。`side-tabs` 不再是自写组件，由 M3E 按钮拼成。

## 容器

能放组件的有 10 个：`box`、`container`、`stack`、`grid-view`、`dock`、`supporting-pane`、`resizable`、`window`、`custom`，以及场景图 `scene`（叠在图上的按钮、血条跟着它走）。`box` 是组合时用的通用盒子：自动布局默认打开、随内容伸缩、没有标题和虚线框；`container` 是带标题的旧式容器，模板还在用。

**没开自动布局时**按位置判断包含关系，和画板带组件的方式一样：

- 组件完全落在容器内、并且画在容器上层，就算在容器里；拖出来就不算了。
- 拖动、用方向键移动或复制容器时，里面的内容一起走；容器里的容器也一样。锁定的分组不跟着动。
- 容器放到已有组件上时会退到它们后面，不会盖住它们。

**开了自动布局时**（`box`、`container`、`dock`、`supporting-pane`、`window`、`custom` 可选横排、竖排、网格，`grid-view` 固定为网格）：

- 组件拖进去就排好，拖动可以调整顺序，拖到容器外就离开。内容超出容器也不会掉出来。
- 可设置间距、内边距、对齐、分布、换行、列数、宽高随内容；里面的组件可以占满剩余空间。容器可以嵌套。
- 多选后点“添加自动布局”，会按现在的排列方向放进一个新容器。
- `dock` 每个标签放自己的内容。

## 没有验证的

- **组合件在各风格下的样子：** 只看过上表列出的风格，其余风格只经过测试。严格遵守风格时，组合件自带的圆角和外观（光泽、厚边、玻璃）会被风格去掉，样子由盒子的表面角色、填充色和风格决定。
- **组合件放下的第一帧：** 落下时按估计尺寸排一次，画布量出真实尺寸后再排；估计偏差大的（长文字、特殊字体）第一帧可能有重叠，随后自动排好。
- **组合件和拆分在手机版编辑器里：** 手机版顶栏的 + 打开完整的组件面板（分层、分类、搜索），点一下加到当前屏幕，在 390px 宽度下实际操作过；组合件的变体菜单和拆分在手机上没有验证。
- **重新组合的边界：** 可复用组件定义里的组合件会重新组合，但定义记下的整体宽高要等下次打开编辑定义时才按新尺寸更新。栏一类的组合件（标签栏、顶栏、HUD、结算栏、聊天输入栏）的外层盒子固定在屏幕边缘（盒子的“在屏幕上”），放下就贴边，整理和风格排版也把它当成栏；拆分一个独立的栏（应用栏、导航栏、结算栏等）得到的盒子同样固定在原来的边缘。2026 年 11 月以前加入的组合件没有记下这一点，仍按正文排。深浅色切换本身不进撤销，只有它让组合件重建时才和重建合成一步。

- **图片生成：** OpenAI 的 `gpt-image-2.6-sunburst` 在页面上真实生成过竖屏 JPEG（约 24 秒；2026 年 11 月再测约 25 秒，一张是选中场景后点按钮生成，一张是 AI 生成游戏后按文档风格自动生成），浏览器直连正常，图片存进资源库后存档只剩引用，刷新后图片还在。GIF 也真实生成过一张（9 帧、512×768、约 2MB、约 30 秒），能逐帧解码；画布上定格在第一帧，开启“减少动态效果”时点按钮才播放。`gpt-image-2.6-flare`、Gemini 和 SVG 输出没有实测。GIF 的参数按官网指南摘要接入并由真实调用确认，接口参考页目前还没列出它们。默认模型可以在 AI 设置里改。

- **图片裁剪和语音、通话：** 裁剪只记录框选位置，不生成裁好的图片；语音不播放真实声音；视频通话是界面，没有真实音视频。
- **棋盘：** 棋局是对面的（`cells`、`status`），组件只发出点了哪一格。原型的演示里只有轮流落子和连成 N 个判赢（井字棋、五子棋这类），以及选择格子；2048、消消乐等规则由对面实现。

- **AI 生成：** OpenAI 的默认模型 `gpt-6.1-sol` 在页面上真实调用过：生成整个应用四次（Material 记账、iOS 严格风格读书、模型自己选了 Claude 风格的聊天、模型自己选了休闲风格的三消游戏，每次约 45–75 秒、3–4 个屏幕），组件说明和屏幕说明各一次（约 3 秒）。生成的应用能打开，点击跳转正常，文字是中文，没有“无法绘制”，严格风格下模型只写风格允许的外观（`elevation`）。写错的模型 ID、断网、截断或不是 JSON 的回复都给出中文提示，画布不变。Claude Sonnet 5.5 早先用脚本和页面调用真实接口跑通过；这次只用模拟的接口核对了请求（地址、请求头、回退参数、`max_tokens`）和正常、截断、529 过载、拒绝四种回复。模型猜错高度造成的重叠会在测量后自动推开，放不下时屏幕变长、可以滚动。选择框和下拉菜单在画布上展开着画，自动布局和推开重叠按展开的大小留位置，预览里收起后下面会空出一块。模型写的说明可能提到应用并没有实现的功能，要人看过再用。Gemini、DeepSeek 没有实际调用。
