# 资产引用

游戏和应用自己的美术（图片、图标、视频、音频、3D 模型、动画）由资产管线生产，M3E 不生产、不复制，只按 ID 引用（[游戏阶段整改计划](游戏阶段整改计划.md)第七批 J5，“外部模块的接口约定”里资产管线那一行）。做法照文档自己的图标 `svg:<编号>` 的先例：组件里写 `asset:<id>`，画的时候按资产清单查。

## 资产清单

资产清单是资产管线写的一份 JSON 文件，M3E 只读，从不写它。格式有版本号，规范是 `lib/assetManifest.schema.json`（JSON Schema 2020-12），读取的代码是 `lib/assetManifest.ts`；测试夹具里有一份最小的例子：`lib/fixtures/assets/asset-manifest.json`。

```json
{
  "format": "asset-manifest",
  "version": 1,
  "generator": "管线的名字和版本",
  "assets": {
    "ui/hero": {
      "type": "image",
      "file": "ui/hero.png",
      "width": 1200,
      "height": 600,
      "variants": {
        "web": { "file": "web/hero.webp", "width": 1200, "height": 600 },
        "wechat": { "file": "wechat/hero.jpg", "width": 600, "height": 300 }
      },
      "source": "美术组 / 某某工具",
      "license": "CC0-1.0",
      "title": "首页横幅"
    }
  }
}
```

- **ID**：稳定的资产 ID，字母和数字组成的词，用一个 `-`、`_`、`.` 或 `/` 连起来，最长 128 个字符（`ui/hero`、`coin.gold`）。
- **`type`**：`image`、`icon`、`video`、`audio`、`model`、`animation` 之一。
- **`file`**：文件，相对清单所在的文件夹，用 `/` 分隔；不能有 `..`、盘符、反斜杠，也不能从 `/` 开始。`mime` 可以不写，按扩展名推断。
- **`width`、`height`**：尺寸（像素，整数）。
- **`variants`**：各平台的变体，键是平台名（`web`、`ios`、`android`、`wechat`、`douyin`、`cocos`、`godot`……，小写），值和主文件的写法一样。变体由资产管线生成，M3E 从不自己做。
- **`source`、`license`**：来源和授权（SPDX 编号或授权的原文）。`title` 是给挑选的人（和 AI）看的说明。
- 读的时候不符合格式的条目丢掉，并说明原因（列表工具和 MCP 的状态里能看到），其余照常读；`version` 比 1 大的清单整份不读，说明它是新版本写的。

## 项目在哪里找清单

只依赖格式，不依赖位置：清单的路径是项目里的一项配置 `external.assetManifest`（相对项目文件所在文件夹的路径，不能出这个文件夹），不写就是项目文件旁边的 `asset-manifest.json`。AI 和 MCP 用 `set_asset_manifest` 改它。

```json
"external": { "assetManifest": "art/out/asset-manifest.json" }
```

- **编辑器**：项目“保存到文件夹”（绑定到文件夹，见[项目文件](项目文件.md)）以后，从那个文件夹里读清单和它列出的文件，之后每两秒看一次，清单或任何一个文件变了就重新读。只绑定到单个文件、或者没有绑定的项目没有清单。
- **MCP 服务器的文件模式**和 `bun run export`：从项目文件所在的文件夹读，和读项目的图片一样只在这个文件夹里读，不跟随链接；每次调用前看一次有没有变。
- 文档里只有 `asset:<id>` 这个引用，清单的内容不进文档，所以项目文件、浏览器存储、分享链接都不变大；`external` 是新增的可选字段，不需要升格式版本，旧文件照常打开。

## 哪里可以写 asset:&lt;id&gt;

| 属性 | 接受的类型 |
| --- | --- |
| 图片属性（`image` 的 `src`、卡片和头像的 `image`、列表行的图片……） | `image`、`icon` |
| 图标属性（`icon` 的 `name`、按钮的 `icon`、列表行的图标……） | `icon`、`image` |
| 视频的 `src` | `video` |
| 音频播放器的 `src` | `audio` |

现在还没有接受 3D 模型的组件属性，`model` 类型的资产先只在清单里列出，等有 3D 组件时再接。

## 画出来

画布、预览和无头截图（MCP 文件模式的 `screenshot`）都按清单画：图片、视频画清单里的主文件，图标把图片画在图标的位置。清单里换一张图（同名文件换内容，或者 `file` 指向另一个文件），引用它的所有组件跟着变；清单里没有的 ID、类型不对的（图片属性里放了视频），组件画它自己的占位。

## 导出

导出只写引用和一张查找表，不复制资产：

- 屏幕代码里是 `asset("<id>")`，查找表写在每个应用旁边：原型和 Web 应用是 `src/assets.ts`（产品里是 `apps/web/src/generated/assets.ts`），手机应用和小程序是 `src/generated/assets.ts`。查找表里每个用到的 ID 有它在这个平台上的文件（Web 用 `web` 变体，iOS 用 `ios`，Android 用 `android`，微信用 `wechat`，抖音用 `douyin`，没有变体时用主文件）、类型和尺寸。
- 文件本身是资产管线的：应用在资产地址下找它们，Web 是 `VITE_ASSET_BASE`（默认 `/assets/`），手机应用是 `EXPO_PUBLIC_ASSET_BASE`，小程序是 `TARO_APP_ASSET_BASE`。管线换了文件不用重新导出。
- 手机应用和小程序的套件暂时不能把资产画成图标：这样的图标留空，导出报告里列为 `asset` 一类的差异。

## 缺口

设计里引用了、清单里没有的资产（被删掉、还没交付、类型不对，或者根本没读到清单）是缺口：

- **导出报告**（`lib/export/boundary.ts`）在每个应用下列出 `asset` 一类，写明屏幕、组件和属性；
- **缺口文件** `.m3e/gaps.json` 写在导出的产品里，给中枢读。每次导出都写，没有缺口时 `gaps` 是空数组，这样中枢能分清“没有缺口”和“没检查”。格式是通用的，玩法契约的缺口（`game-*`）、链接数据过期（`data`）、契约版本和中枢的索引不一致（`contract-version`）按同样的形状加 `kind`，见[导出](导出.md)“缺口文件”。资产的一条是：

```json
{
  "format": "m3e-gaps",
  "version": 1,
  "generator": "M3E Canvas Pro",
  "product": "my-game",
  "gaps": [
    {
      "kind": "asset",
      "module": "asset-pipeline",
      "ref": "ui/hero",
      "reason": "missing",
      "detail": "asset:ui/hero is not in the asset manifest (removed, or not delivered yet)",
      "where": [{ "screen": "Home", "part": "Hero", "prop": "src" }]
    }
  ]
}
```

`reason` 是 `missing`（清单里没有）、`wrong-type`（类型不对）或 `no-manifest`（没读到清单）。

## AI 和 MCP

- `list_assets`：列出清单里的资产（ID、类型、尺寸、说明、有哪些平台变体、来源和授权）、哪些组件引用了它，以及设计里引用了但清单里没有的；可以按类型和词筛选。
- `set_asset {id, asset, prop?}`：把一个资产放到组件上，`prop` 不写时放到第一个接受这种类型的属性；清单里没有的 ID、类型不对的会被拒绝。
- `set_asset_manifest {path}`：设置清单的路径（`""` 回到默认）。
- `set_props` 等写属性的工具也接受 `asset:<id>`；手边有清单时，清单里没有的 ID 会被拒绝并列出可用的；没有清单时照样写下引用，导出时列为缺口。
