# 风格清单

一份文档选一个风格，组件、屏幕背景和场景图都跟着变。风格定义在 `lib/styles.ts`，排版规则在 `lib/styleLayout.ts`，选择面板在 `components/StylePanel.tsx`。

## 一套风格有三层

| 层 | 管什么 | 例子 |
| --- | --- | --- |
| 配色和字体 | 主色、背景、字体、图标家族 | 微信的绿和灰底；赛博朋克的红字和青色点缀 |
| 组件形状 | 按钮、卡片、标签页、开关、列表、弹窗、头像、对话框的造型 | iOS 的圆角分组列表和居中提醒框；微信的上下分栏弹窗和方头像；星露谷文字在左、立绘在右的对话框 |
| 排版 | 页边距、区块间距、同类间距、导航位置、内容聚在哪 | 微信列表通栏并贴着标题栏；VS Code 和 Discord 左侧图标栏；赛博朋克顶部标签导航；消除手游资源胶囊在顶、按钮贴底 |

选风格时三层一起换，已有屏幕会按新规则重排，一次撤销就能退回。

## 组件和风格解耦

组件库只有一套，同一个组件在不同风格下呈现不同。

- **组件**只管结构和功能，把自己的部位命名出来（`data-slot`），比如 `dialogue-portrait`、`app-bar-title`。它不知道有哪些风格。
- **风格**只给命名部位“穿衣服”，也靠颜色角色、字号阶梯和圆角这些变量起作用。它不依赖组件的内部结构。
- 不存在“iOS 开关”“微信弹窗”这样的专属组件。新增一套风格不用改组件，新增一个组件也不用改风格，它会自动吃到配色、字体、字号和圆角。

`lib/styles.test.ts` 用测试守住这条边界：组件代码里不能出现风格名或风格读取，风格规则里不能出现 `:first-child`、`h1` 这类结构定位。

## 风格是一份规范

选定风格后，文档就被约束在这套规范里。所有修改入口走同一道校验（`lib/styleRules.ts`），不靠自觉：

| 入口 | 约束 |
| --- | --- |
| 配色、形状、字体、动效面板 | 上锁，只显示当前值 |
| 部件检查器 | 颜色只能选这个风格的颜色角色；圆角、阴影、边框、玻璃、旋转这些选项不出现；位置和对齐由排版规则决定 |
| AI 生成 | 告知当前风格和规则，并固定风格；返回后再校验一遍，越界的内容直接去掉 |
| 打开文件、分享链接 | 进入编辑器时按文档主题校验 |
| 拖拽、增删、改尺寸、改文字 | 放下后按风格规则重排 |

风格规定不了的内容仍由作者决定：用哪些组件、文字内容、亮色或暗色、对比度（无障碍需要）。

- “严格遵守规范”默认打开，可以在风格面板关掉，关掉后所有设置和自由摆放都回来；重新打开等于重新应用一次这个风格。
- 从未选过风格的文档不受约束。选过“Android”后同样受约束，但配色和动效仍可调，因为 Material 3 本身允许。
- 锁定的部件不参与自动排版，可以用它保留有意摆放的位置。

排版的取舍：

- 只移动屏幕自己的部件。锁定的部件和容器里的部件不动，有意叠在一起的部件（比如贴在图片上的标签）继续叠在一起；只是边缘碰到的不算叠放，会被分开。
- 普通页面按行排：顺序看上下位置，同一高度的算一行，宽度取整行、二分之一或三分之一。
- 有场景图的屏幕不按行排。它更像游戏 HUD，部件留在放置的角落或边缘，贴齐页边距，互相不重叠。
- 放不下就把屏幕加长，下一套风格放得下就缩回去。作者自己拉长的屏幕不会被缩短。
- 剧情对话框贴在屏幕底部。作者手动选“内容贴底”时，资源胶囊和血条留在顶部。
- 宽屏上没有底部导航栏，选了底部导航的风格会改用侧边栏。
- 抖音的视频、Instagram 的图片和视频通栏无圆角。抖音整屏视频本身用场景图表现，AI 收到的排版说明也是这样写的。

每一套都对照真实产品做，只取整体视觉语言，不用对方的标志和素材。产品按 2025 到 2026 年的下载量、收入和同时在线榜单挑选。

## 已知的差距

- 纯样式做不出的部分：卷轴飘带、雕花边角、3D 光泽图标、水墨笔触。这些要靠 AI 生成的贴图，属于下一阶段。
- 排版靠规则重排，不会替你增删部件。微信的会话列表、抖音的全屏信息流这类典型页面，需要自己摆好部件或交给 AI 生成，风格只负责把它们排成该产品的样子。
- 排版说明大多对照真实截图写成，数值（边距、间距）是目测，只有微信、Ant Design、Fluent 的控件尺寸来自官方规范。
- 字体只能取相近的免费字体。SF Pro、苹方、Segoe UI 只在装了它们的设备上才生效；游戏的定制字体无法复制。中文字体：休闲游戏用站酷快乐体，科幻和射击类用站酷庆科黄油体，魂类和黑神话用思源宋体，黑神话标题用马善政毛笔体，像素风用缝合像素体（SIL 开源协议，约 600KB，从 jsDelivr 加载）。
- 字号字重：iOS 按苹果默认字号（凭记忆），微信按 WeUI，其余对照截图估算。Display 级大字只换字体，不换字号。
- 为了还原产品本身，少数按钮的文字对比度低于 4.5:1，比如微信绿底白字约 2.4:1。这些写在每套风格的 `loud` 字段里，其余文字都有测试保证可读。

## 加一套新风格

1. 在 `lib/styles.ts` 的 `STYLE_PACKS` 里加一项，`refs` 写参照产品，`basis` 如实写来源级别。
2. 控件造型从 `RECIPES` 里选。不够用时加新变体，并在 `VARIANT_LABELS` 写四种语言的名字。新变体只能用组件的命名部位，缺部位就给组件补 `data-slot`，不要写结构选择器。字号写进 `TYPE_RAMPS`。
3. 跑 `bun run test lib/styles.test.ts`，它会检查文字可读性和用到的组件插槽。
4. 跑 `bun run check:export <空文件夹> style`，确认导出后的应用也穿着这套风格。
5. `SHAPE_AND_LAYOUT` 里写它的组件形状、排版数值和排版说明。
6. 跑 `bun run gen:agent` 重新生成 `public/agent.md` 的风格表，AI 才知道它。
