# 风格清单

一份文档选一个风格，组件、屏幕背景和场景图都跟着变。风格的代码在 `lib/styles/`，排版规则在 `lib/styleLayout.ts`，选择面板在 `components/StylePanel.tsx`，每个组件在某个风格下的样子可以在 `/gallery` 里看。

## 一套风格有三层

| 层 | 管什么 | 写在哪 | 例子 |
| --- | --- | --- | --- |
| 配色、字体、图标 | 主色、背景、字号阶梯、正文和标题字体、图标家族 | `packs/<键名>.ts` 的 `light`、`dark`、`type`、`font`、`display`、`icons` | 微信的绿和灰底；Claude 的暖象牙底和衬线标题 |
| 组件形状和构成 | 每类组件怎么画、部件怎么摆：按钮、卡片、列表行有没有右箭头、返回箭头旁有没有“返回”二字、标题居中还是靠左 | `packs/<键名>.ts` 的 `recipes` 选配方，`css` 写本风格独有的规则；配方本身在 `recipes/*.ts` | iOS 的圆角分组列表、行尾灰色箭头、彩色方块图标；微信的上下分栏弹窗和方头像 |
| 排版 | 页边距、区块间距、同类间距、导航位置、内容聚在哪 | `packs/<键名>.ts` 的 `ux` 和 `layout` | 微信列表通栏并贴着标题栏；VS Code 左侧图标栏 |

选风格时三层一起换，已有屏幕会按新规则重排，一次撤销就能退回。

## 文件结构

```text
lib/styles/
  index.ts          对外接口：别处只从 lib/styles 引用，内部怎么拆不影响它们
  types.ts          风格由什么组成（StylePack），以及写配色、字号的简写
  theme.ts          从文档主题读出风格：stylePatch、recipesOf、uxOf、stylePalette……
  sheet.ts          把主题写成一张样式表：styleCss、screenBackground、hasBackdrop
  recipes/
    catalog.ts      配方清单 RECIPES，以及每类、每个变体的四语名称
    shared.ts       各配方共用的选择器：按钮、面板、卡片、菜单、顶栏、列表行、标题……
    buttons.ts      按钮、悬浮按钮、按下反馈
    surfaces.ts     面板、卡片、底部面板、提示气泡、盒子的表面角色
    tabs.ts         标签页、分段按钮
    controls.ts     开关、滑块、勾选框、标签、徽标、头像
    navigation.ts   导航栏、顶栏的底色、顶栏的构成
    fields.ts       输入框、单行输入、搜索
    lists.ts        列表、列表行、分隔线、菜单
    dialogs.ts      弹窗、剧情对话框
    gauges.ts       血条、进度条
    marks.ts        标题文字、图标处理、屏幕底纹、滚动条
  packs/
    index.ts        风格的顺序（风格面板按这个顺序显示）
    ios.ts …        每套风格一个文件
    desk.ts         电脑软件几套风格共用的写法（菜单栏、侧栏、树、命令面板、Windows 标题栏），本身不是风格
  styles.test.ts
```

## 组件和风格解耦

组件库只有一套，同一个组件在不同风格下呈现不同。

- **组件**只管结构和功能，把自己的部位命名出来（`data-slot`），它不知道有哪些风格。
- **风格**只给命名部位“穿衣服”，也靠颜色角色（`--md-sys-color-*`）、字号阶梯和圆角这些变量起作用。它不依赖组件的内部结构。
- 不存在“iOS 开关”“微信弹窗”这样的专属组件。新增一套风格不用改组件，新增一个组件也不用改风格，它会自动吃到配色、字体、字号和圆角。

`lib/styles/styles.test.ts` 用测试守住这条边界：组件代码里不能出现风格名或风格读取；风格规则里不能出现 `:first-child`、`h1`、`>` 这类结构定位；规则里提到的每个 `data-slot`、每个 `-后缀` 都必须有组件真的带着它。

### 部位的命名

`data-slot` 一律写成 `<组件>-<部位>`，部位从下面这组词里选，所以一条规则既能点名一个组件的部位，也能用后缀一次说到所有组件的同一种部位，比如 `[data-slot$="-chevron"]` 是所有行尾箭头。

| 部位 | 意思 | 例子 |
| --- | --- | --- |
| `title` `subtitle` `description` | 标题、副标题、说明文字 | `product-card-title`、`conversation-row-subtitle` |
| `value` `price` `meta` | 行尾的值、价格、时间这类附注 | `item-value`、`checkout-bar-price`、`notification-row-meta` |
| `glyph` | 行或格子开头的图标位，风格可以给它加方块或圆底 | `settings-row-glyph`、`icon-grid-glyph` |
| `chevron` | 行尾表示“还有下一层”的箭头 | `item-chevron`、`settings-row-chevron` |
| `badge` `tag` `dot` | 数字角标、文字标签、小红点 | `conversation-row-badge`、`product-card-tag` |
| `media` | 图片、封面 | `card-media`、`post-card-media` |
| `header` `footer` `actions` | 头部、底部、操作区 | `contact-list-header`、`post-card-actions` |
| `leading` `trailing` `heading` | 栏的左侧、右侧、中间标题区 | `app-bar-leading`、`app-bar-heading` |
| `row` `cell` `item` | 列表行、格子 | `transaction-row`、`inventory-cell`、`side-tabs-item` |
| `track` `fill` `bar` `rest` `gap` `stop` | 条形的轨道、填充和各段 | `progress-bar`、`progress-rest`、`reward-track-fill` |
| `indicator` `handle` | 选中指示、拖动条 | `notification-row-indicator`、`sheet-handle` |

列表行本身也有名字（`settings-row`、`conversation-row`、`contact-row`、`notification-row`、`transaction-row`、`file-row`），列表行配方会把它们和 M3 的 `item` 一起处理。

### 组合钩子

有些产品的组件比 Material 多一个部件，或者部件换了位置。这些部件已经放在组件里，默认隐藏（`hidden`），风格用 CSS 让它出现、换位置。行为不变，Material 和不提它的风格看起来和以前一样。

| 钩子 | 在哪 | 谁让它出现 |
| --- | --- | --- |
| `item-chevron` | 列表行行尾（没有开关、勾选这类控件时） | `row: chevron`（iOS）、`row: arrow`（微信） |
| `app-bar-back-label` | 顶栏返回箭头旁的“返回”二字（左侧图标是返回箭头时） | `appbar: ios` |
| `app-bar-large-title` | 小顶栏下方的大标题 | `appbar: large`（Notion、iOS 根页面） |
| `search-cancel` | 搜索框右边的“取消” | `search: cancel`（iOS） |
| `sheet-handle` | 底部面板顶上的拖动条 | `sheet: grabber`、`sheet: rim` |
| `app-bar-caret` | 小顶栏标题后的下拉箭头（标题能打开菜单，比如选模型） | ChatGPT、Claude 的 `css`（有返回箭头时不出现） |
| `message-actions` | AI 回答下方一行复制、重试、点赞、点踩的小图标 | ChatGPT、Claude 的 `css` |
| `title-bar-icon` | 标题栏和窗口标题前的应用图标 | Windows、VS Code（Windows 按钮时）、Discord、Steam |
| `title-bar-caption` | 作者选了 Mac 按钮时，备着的一组 Windows 最小化、最大化、关闭 | Windows、Discord、Steam |
| `tree-twisty` | 树形列表每行前的折叠箭头（下面有子行的朝下，空文件夹朝右） | 六套电脑软件 |
| `tabs-close` | 标签页文字后的关闭按钮 | VS Code（只在选中的标签上） |
| `steps-check` `steps-tail` | 步骤条已完成那步的对勾、每步标题后面连到下一步的线 | Ant Design |

顶栏在小尺寸时由 `appbar` 配方改成三栏网格，标题无论两边有几个图标都真正居中。

### 盒子的表面角色

原子组件“盒子”带 `data-slot="box"` 和 `data-surface`（`none`、`card`、`panel`、`field`、`bar`、`chip`、`button`、`sheet`、`overlay`、`well`）。风格按角色给它穿衣服：`card` 的盒子在 iOS 里就是 iOS 的卡片，`field` 的盒子就是这个风格的输入框，`button` 的盒子吃按钮配方。这些角色写在 `recipes/shared.ts` 的选择器组里（`PANELS`、`CARDS`、`BUTTONS`、`CHIPS`、`TOP_BARS`、输入框的 `BARE`），`well`（下凹区域）写在 `surfaces.ts` 的 `BOX_CSS`。作者自己选了强调色填充的盒子，风格不会改它的底色。

## 风格是一份规范

选定风格后，文档就被约束在这套规范里。所有修改入口走同一道校验（`lib/styleRules.ts`），不靠自觉：

| 入口 | 约束 |
| --- | --- |
| 配色、形状、字体、动效面板 | 上锁，只显示当前值 |
| 部件检查器 | 颜色只能选这个风格的颜色角色；圆角、阴影、边框、玻璃、旋转这些选项不出现；位置和对齐由排版规则决定 |
| AI 生成 | 告知当前风格和规则，并固定风格；返回后再校验一遍，越界的内容直接去掉 |
| 打开文件、分享链接 | 进入编辑器时按文档主题校验 |
| 拖拽、增删、改尺寸、改文字 | 放下后按风格规则重排 |

风格规定不了的内容仍由作者决定：用哪些组件、文字内容、亮色或暗色、对比度（无障碍需要）。

- “严格遵守规范”默认打开，可以在风格面板关掉，关掉后所有设置和自由摆放都回来；重新打开等于重新应用一次这个风格。
- 从未选过风格的文档不受约束。选过“Android”后同样受约束，但配色和动效仍可调，因为 Material 3 本身允许。
- 锁定的部件不参与自动排版，可以用它保留有意摆放的位置。

排版的取舍：

- 只移动屏幕自己的部件。锁定的部件和容器里的部件不动，有意叠在一起的部件（比如贴在图片上的标签）继续叠在一起；只是边缘碰到的不算叠放，会被分开。
- 普通页面先读出结构再排：能横着切开的地方分成一段一段，每段再竖着切成几列，层层切下去；同样的部件排成几行几列就当作网格。段与段之间用这套风格的区块间距和同类间距，段里的间距统一成最接近的间距阶梯或 4dp 网格，对齐取部件本来最接近的边、中线或文字基线。宽度取整行、二分之一或三分之一。
- 一行里有明显的大空档时两端对齐，比如标题贴左边距、右边的图标按钮贴右边距；文字和开关分在两端；铺满大半宽度的一行卡片铺满内容宽度，网格横竖用同一个间距；图片旁边的两行字仍在图片旁边。
- 有场景图的屏幕不按行排。它更像游戏 HUD，部件留在放置的角落或边缘，贴齐页边距，互相不重叠。
- 放不下就把屏幕加长，下一套风格放得下就缩回去。作者自己拉长的屏幕不会被缩短。
- 剧情对话框贴在屏幕底部。作者手动选“内容贴底”时，资源胶囊和血条留在顶部。
- 宽屏上没有底部导航栏，选了底部导航的风格会改用侧边栏。
- 抖音的视频、Instagram 的图片和视频通栏无圆角。抖音整屏视频本身用场景图表现，AI 收到的排版说明也是这样写的。

每一套都对照真实产品做，只取整体视觉语言，不用对方的标志和素材。产品按 2025 到 2026 年的下载量、收入和同时在线榜单挑选。

| `game` | Game Icons 剪影 | 同一个 | RPG、魂类 |
| `emoji` | Fluent Emoji Flat（彩色，不跟随文字颜色） | 同一个 | 休闲游戏 |

- 对照表在 `scripts/icon-tables/<家族>.ts`，逐个人工核对过：比如 iOS 的返回是 `chevron-left` 而不是箭头，设置是 `gear-alt`。`bun scripts/propose-icon-tables.ts <家族>` 会按同义词给缺的名字提建议，仍要人看过再写进表。
- 家族里没有的名字退回 Material Rounded。`emoji` 和 `game` 故意不映射箭头、关闭、菜单、更多、加号这类界面骨架，它们保持 Material，颜色跟随控件。
- 不同图标集的留白不同，生成时按实测把每套缩放到和 Material 一样的视觉大小（`SCALE`），线条粗细保持各自的风格。图标的 `<svg>` 带 `data-family`，风格可以按家族微调。
- 图标全部离线打包：`bun run gen:icon-sets` 从 `@iconify-json/*` 取出用到的字形，写到 `components/m3e/icon-sets/data`，每套按名字分片，选中某个家族才加载它的分片，主包不变大。代码里新用了图标名，跑一次这个命令（`bun run check:icon-sets` 检查是否过期）。只有谁都没打包的名字（作者自己输入的）才会联网向 Iconify 取。
- 导出的项目只带用到的字形：Material 在 `src/components/m3e/icon-data.app.ts`，风格家族的字形和对照在 `src/style-icons.ts`，断网也能显示。
- 各图标集的许可见 `NOTICE`。Game Icons 是 CC BY 3.0，用到它的应用要署名作者（Lorc、Delapouite 等，game-icons.net）。

## 风格画廊和截图

画廊把注册表里的每个组件，按画布同样的方式（`PartView`、风格的作用域、风格的屏幕底色）画在一个带标签的格子里，按分类分组。以后新增的组件自动出现；`parts/kits/*.ts` 里导出的组合件（kit）也会被找到，按放到画布上的样子排好画出来。少数组件的构成会随属性变化（返回箭头、大标题、多行设置列表、底部面板），画廊额外画几个样例，写在 `components/Gallery.tsx` 的 `SAMPLES` 里。

地址参数：

| 参数 | 意思 | 例子 |
| --- | --- | --- |
| `style` | 风格键名，不写是 Android | `style=ios` |
| `dark` | `1` 暗色、`0` 亮色，不写是风格自己的默认模式 | `dark=1` |
| `category` | 只看一个分类 | `category=Navigation` |
| `lang` | 组件里的文字用哪种语言，默认中文 | `lang=en` |
| `part` | 只看这几个组件 | `part=app-bar,item,search` |

风格面板的“在这个风格下查看全部组件”按钮会在新窗口打开当前风格的画廊。

截图（脚本不启动服务，先在另一个终端启动开发服务器）：

```bash
bun run dev -- --port 3105
```

```bash
bun scripts/style-shots.ts --base http://localhost:3105 --out shots --style ios,wechat
```

- 不写 `--style` 就是全部风格加 Android；`--dark` 只截暗色，`--both` 亮暗各一份；`--category`、`--part`、`--lang`、`--width` 和画廊参数一致。
- 输出是 `shots/<风格>[-dark]/<分类>.png` 和整页 `shots/<风格>[-dark].png`。比 1400 像素高的分类另外切成 `<分类>-1.png`、`<分类>-2.png`……整张太长时缩小后看不清，看切片（`--tile 0` 不切）。
- Playwright 从 Node 能找到的地方加载（`require("playwright")`），不是项目依赖。

检查一个风格的流程：截图 → 逐张看 → 找出“不像这个产品”的组件 → 在这个风格的 `packs/<键名>.ts` 里换配方或写 `css` → 刷新画廊确认 → 跑测试。

## 加一套新风格

1. 在 `lib/styles/packs/` 新建 `<键名>.ts`，用 `definePack` 写出配色（`roles` 简写）、字体、图标家族、`recipes`、`ux`、`layout`，`refs` 写参照产品，`basis` 如实写来源级别。字号阶梯写在 `type`。
2. 把它加进 `packs/index.ts` 的列表，位置决定风格面板里的顺序。
3. 需要新的免费字体时，在 `lib/tokens.ts` 的 `FONTS` 加一项。
4. 跑 `bun run test lib/styles`，它检查文字可读性、用到的组件部位、图标家族和每个变体的四语名称。
5. 跑 `bun run gen:agent` 重新生成 `public/agent.md` 的风格表，AI 才知道它。
6. 跑 `bun run check:export <空文件夹> style`，确认导出后的应用也穿着这套风格。
7. 打开画廊截图，逐类看一遍。

## 修一个组件在某个风格下的样子

按影响面从小到大选：

1. **只这一个风格不对**：在 `packs/<键名>.ts` 的 `css` 里写规则。只能用 `data-slot`、其他 `data-*` 属性、颜色角色变量（`--md-sys-color-*`）和风格变量（`--st-*`）；它写在作用域里、所有配方之后，所以能覆盖配方。
2. **几个风格都需要同一种做法**：在 `recipes/` 对应的模块里加一个变体，在 `catalog.ts` 的 `RECIPES` 登记、在 `VARIANT_LABELS`（或按类的 `BY_KIND`）写四种语言的名字，再让这些风格选它。
3. **组件缺部位**：给组件补 `data-slot`（按上面的命名），需要多一个部件时加一个默认隐藏的组合钩子。只加属性和隐藏元素，不改行为，不挪代码。

不要写结构选择器（`:first-child`、`> div`、`h1`），不要在组件里判断风格。部件的作者填色（强调色填充）由 `UNPAINTED` 保护，配方不覆盖。

## 已知的差距

- 纯样式做不出的部分：卷轴飘带、雕花边角、3D 光泽图标、水墨笔触。这些要靠 AI 生成的贴图或矢量原子组件。
- 排版靠规则重排，不会替你增删部件。微信的会话列表、抖音的全屏信息流这类典型页面，需要自己摆好部件或交给 AI 生成，风格只负责把它们排成该产品的样子。
- 排版说明大多对照真实截图写成，数值（边距、间距）是目测，只有微信、Ant Design、Fluent 的控件尺寸来自官方规范。
- 字体只能取相近的免费字体。SF Pro、苹方、Segoe UI 只在装了它们的设备上才生效；游戏和 Claude、Codex 的定制字体无法复制。中文字体：休闲游戏用站酷快乐体，科幻和射击类用站酷庆科黄油体，魂类和黑神话用思源宋体，黑神话标题用马善政毛笔体，像素风用缝合像素体（SIL 开源协议，约 600KB，从 jsDelivr 加载）。
- 字号字重：iOS 按苹果默认字号（凭记忆），微信按 WeUI，其余对照截图估算。
- 为了还原产品本身，少数按钮的文字对比度低于 4.5:1，比如微信绿底白字约 2.4:1、Claude 陶土橙底白字约 3.9:1。这些写在每套风格的 `loud` 字段里，其余文字都有测试保证可读。
- 进度条的粗细由组件属性写在行内，`progress` 配方改粗细时用了 `!important`；其余规则都不用。
- 画廊里的组合件按“还没测量尺寸”时的排法画，和放到画布上测量后可能差几像素。
