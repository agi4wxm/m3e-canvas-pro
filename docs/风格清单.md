# 风格清单

一份文档选一个风格，组件、屏幕背景和场景图都跟着变。风格的代码在 `lib/styles/`，排版规则在 `lib/styleLayout.ts`，选择面板在 `components/StylePanel.tsx`，每个组件在某个风格下的样子可以在 `/gallery` 里看。

## 一套风格有三层

| 层 | 管什么 | 写在哪 | 例子 |
| --- | --- | --- | --- |
| 配色、字体、图标 | 主色、背景、字号阶梯、正文和标题字体、图标家族 | `packs/<键名>.ts` 的 `light`、`dark`、`type`、`font`、`display`、`icons` | 微信的绿和灰底；Claude 的暖象牙底和衬线标题 |
| 组件形状和构成 | 每类组件怎么画、部件怎么摆：按钮、卡片、列表行有没有右箭头、返回箭头旁有没有“返回”二字、标题居中还是靠左 | `packs/<键名>.ts` 的 `recipes` 选配方，`css` 写本风格独有的规则；配方本身在 `recipes/*.ts` | iOS 的圆角分组列表、行尾灰色箭头、彩色方块图标；微信的上下分栏弹窗和方头像 |
| 排版 | 页边距、区块间距、同类间距、导航位置、内容聚在哪 | `packs/<键名>.ts` 的 `ux` 和 `layout` | 微信列表通栏并贴着标题栏；VS Code 左侧图标栏 |

选风格时三层一起换，已有屏幕会按新规则重排，一次撤销就能退回。


## 组件和风格解耦

组件库只有一套，同一个组件在不同风格下呈现不同。

- **组件**只管结构和功能，把自己的部位命名出来（`data-slot`），它不知道有哪些风格。
- **风格**只给命名部位“穿衣服”，也靠颜色角色（`--md-sys-color-*`）、字号阶梯和圆角这些变量起作用。它不依赖组件的内部结构。
- 不存在“iOS 开关”“微信弹窗”这样的专属组件。新增一套风格不用改组件，新增一个组件也不用改风格，它会自动吃到配色、字体、字号和圆角。

`lib/styles/styles.test.ts` 用测试守住这条边界：组件代码里不能出现风格名或风格读取；风格规则里不能出现 `:first-child`、`h1`、`>` 这类结构定位；规则里提到的每个 `data-slot`、每个 `-后缀` 都必须有组件真的带着它。

### 部位的命名

`data-slot` 一律写成 `<组件>-<部位>`，部位从下面这组词里选，所以一条规则既能点名一个组件的部位，也能用后缀一次说到所有组件的同一种部位，比如 `[data-slot$="-chevron"]` 是所有行尾箭头。

| 部位 | 意思 | 例子 |
| --- | --- | --- |
| `title` `subtitle` `description` | 标题、副标题、说明文字 | `product-card-title`、`conversation-row-subtitle` |
| `value` `price` `meta` | 行尾的值、价格、时间这类附注 | `item-value`、`checkout-bar-price`、`notification-row-meta` |
| `glyph` | 行或格子开头的图标位，风格可以给它加方块或圆底 | `settings-row-glyph`、`icon-grid-glyph` |
| `chevron` | 行尾表示“还有下一层”的箭头 | `item-chevron`、`settings-row-chevron` |
| `badge` `tag` `dot` | 数字角标、文字标签、小红点 | `conversation-row-badge`、`product-card-tag` |
| `media` | 图片、封面 | `card-media`、`post-card-media` |
| `header` `footer` `actions` | 头部、底部、操作区 | `contact-list-header`、`post-card-actions` |
| `leading` `trailing` `heading` | 栏的左侧、右侧、中间标题区 | `app-bar-leading`、`app-bar-heading` |
| `row` `cell` `item` | 列表行、格子 | `transaction-row`、`inventory-cell`、`side-tabs-item` |
| `track` `fill` `bar` `rest` `gap` `stop` | 条形的轨道、填充和各段 | `progress-bar`、`progress-rest`、`reward-track-fill` |
| `indicator` `handle` | 选中指示、拖动条 | `notification-row-indicator`、`sheet-handle` |

列表行本身也有名字（`settings-row`、`conversation-row`、`contact-row`、`notification-row`、`transaction-row`、`file-row`），列表行配方会把它们和 M3 的 `item` 一起处理。

### 组合钩子

有些产品的组件比 Material 多一个部件，或者部件换了位置。这些部件已经放在组件里，默认隐藏（`hidden`），风格用 CSS 让它出现、换位置。行为不变，Material 和不提它的风格看起来和以前一样。

| 钩子 | 在哪 | 谁让它出现 |
| --- | --- | --- |
| `item-chevron` | 列表行行尾（没有开关、勾选这类控件时） | `row: chevron`（iOS）、`row: arrow`（微信） |
| `app-bar-back-label` | 顶栏返回箭头旁的“返回”二字（左侧图标是返回箭头时） | `appbar: ios` |
| `app-bar-large-title` | 小顶栏下方的大标题 | `appbar: large`（Notion、iOS 根页面） |
| `search-cancel` | 搜索框右边的“取消” | `search: cancel`（iOS） |
| `sheet-handle` | 底部面板顶上的拖动条 | `sheet: grabber`、`sheet: rim` |
| `app-bar-caret` | 小顶栏标题后的下拉箭头（标题能打开菜单，比如选模型） | ChatGPT、Claude 的 `css`（有返回箭头时不出现） |
| `message-actions` | AI 回答下方一行复制、重试、点赞、点踩的小图标 | ChatGPT、Claude 的 `css` |
| `title-bar-icon` | 标题栏和窗口标题前的应用图标 | Windows、VS Code（Windows 按钮时）、Discord、Steam |
| `title-bar-caption` | 作者选了 Mac 按钮时，备着的一组 Windows 最小化、最大化、关闭 | Windows、Discord、Steam |
| `tree-twisty` | 树形列表每行前的折叠箭头（下面有子行的朝下，空文件夹朝右） | 六套电脑软件 |
| `tabs-close` | 标签页文字后的关闭按钮 | VS Code（只在选中的标签上） |
| `steps-check` `steps-tail` | 步骤条已完成那步的对勾、每步标题后面连到下一步的线 | Ant Design |
| `time-picker-wheel` | 时间选择器里转动的几列（时、分、上下午），选中的一行在中间，代替表盘 | `picker: ios`、`picker: weui`、`picker: boxed` |

顶栏在小尺寸时由 `appbar` 配方改成三栏网格，标题无论两边有几个图标都真正居中。

日历和时间选择器把每个部位都命名了，其他风格要日期时间的样子时，在 `recipes/pickers.ts` 加一个变体：

- 日历：`calendar-header`（月份和箭头那一行）、`calendar-title`、`calendar-nav`、`calendar-previous`、`calendar-next`、`calendar-weekdays`、`calendar-weekday`、`calendar-cell`（每天的格子）、`calendar-day`（能点的那一天）；格子和那一天都带 `data-today`、`data-outside`，选中的那一天带 `data-selected-single` 或 `data-range-*`。日期选择器的输入框是 `date-picker`，日历按钮是 `date-picker-trigger`，弹出的日历是 `date-picker-popup`。
- 时间选择器：`time-picker-title`、`time-picker-header`（时分两格和上下午）、`time-picker-segment`、`time-picker-separator`、`time-picker-period`、`time-picker-dial`（表盘）、`time-picker-footer`、`time-picker-mode`；滚轮是 `time-picker-wheel`、`time-picker-column`（带 `data-field`）、`time-picker-item`（带 `data-distance` 0–2 和 `data-active`）、`time-picker-indicator`（选中行的底色或细线）。

标题配方（`text`）和标题字体只落在标题上：名字以 `-price`、`-value`、`-star` 结尾的部位，按钮、键盘按键、等宽数字（`tabular-nums`）和它们里面的字，即使用了标题字号也不算标题。图表和表格（`dashboard-chart`、`dashboard-table` 等）默认画在屏幕底色上，内容放在卡片上的风格（iOS、微信、电商）给它们白卡片。

### 盒子的表面角色

原子组件“盒子”带 `data-slot="box"` 和 `data-surface`（`none`、`card`、`panel`、`field`、`bar`、`chip`、`button`、`sheet`、`overlay`、`well`）。风格按角色给它穿衣服：`card` 的盒子在 iOS 里就是 iOS 的卡片，`field` 的盒子就是这个风格的输入框，`button` 的盒子吃按钮配方。这些角色写在 `recipes/shared.ts` 的选择器组里（`PANELS`、`CARDS`、`BUTTONS`、`CHIPS`、`TOP_BARS`、输入框的 `BARE`），`well`（下凹区域）写在 `surfaces.ts` 的 `BOX_CSS`。作者自己选了强调色填充的盒子，风格不会改它的底色。

### 靠顺序取胜，不靠权重

CSS 先比选择器权重，权重相同才比先后。所以“后写的赢”只有在大家权重一样时才成立：

- `recipes/shared.ts` 里的每个选择器组（`PANELS`、`CARDS`、`BUTTONS`、`MENUS`、`ROWS`、`HEADINGS`……）放进 `:is()` 后都只有一个属性的权重，和单写一个 `[data-slot=…]` 一样。只起筛选作用的部分（“带圆角类名”“不是图标按钮”“不是作者自己填的强调色”）一律包在 `:where()` 里，不加权重。按钮加状态（`PRESSES`）、按钮加变体（`TONED`）是两个属性，这是有意的。
- 以前 `PANELS` 里“任何用容器色填充、带圆角的盒子”这一项没有包 `:where()`，有三个属性的权重，于是所有 `:is(PANELS)` 规则都比后面的卡片、底部面板、菜单配方和风格自己的 `css` 重，后写的反而输。Fluent 暗色下卡片留着一圈淡淡的细线就是这个原因；11 个游戏风格为此在规则后面加了 `:not(#_)`，借一个 id 的权重硬压过去。现在这些都去掉了。
- 改正之后，一些以前被面板规则压住、从没显示过的配方第一次生效：卡片、菜单、底部面板、分段按钮、搜索框、时间选择器的配方，以及各风格 `css` 里写在后面的规则。逐张截图对比过，大多是本来就想要的样子（Fluent 的卡片、浮层、弹窗终于用上自己的阴影）；消除休闲和冰雪策略原先选的 `framed` 卡片配方会让卡片丢掉和其他面板一致的厚边，所以去掉了，卡片仍穿面板的衣服。
- 风格的 `css` 不要再用 `:not(#_)` 之类的 id 加权。一条规则输了，先看对手是谁：对手是配方里的后代选择器或状态选择器（比如 `[data-slot=switch][data-checked]`），就把自己写得同样具体；对手是选择器组，说明那个组又变重了，修 `shared.ts`。
- `styles.test.ts` 用一个小的权重计算器守住这两点：共享选择器组不能超过一个属性的权重；所有风格、所有配方变体写出的样式表里不能有 id 权重，风格文件里不能出现 `:not(#`。

## 风格是一份规范

选定风格后，文档就被约束在这套规范里。所有修改入口走同一道校验（`lib/styleRules.ts`），不靠自觉：

| 入口 | 约束 |
| --- | --- |
| 配色、形状、字体、动效面板 | 上锁，只显示当前值 |
| 部件检查器 | 颜色只能选这个风格的颜色角色；圆角、阴影、边框、玻璃、旋转这些选项不出现；位置和对齐由排版规则决定 |
| AI 生成 | 告知当前风格和规则，并固定风格；返回后再校验一遍，越界的内容直接去掉 |
| 打开文件、分享链接 | 进入编辑器时按文档主题校验 |
| 拖拽、增删、改尺寸、改文字 | 放下后按风格规则重排 |

风格规定不了的内容仍由作者决定：用哪些组件、文字内容、亮色或暗色、对比度（无障碍需要）。

- “严格遵守规范”默认打开，可以在风格面板关掉，关掉后所有设置和自由摆放都回来；重新打开等于重新应用一次这个风格。
- 从未选过风格的文档不受约束。选过“Android”后同样受约束，但配色和动效仍可调，因为 Material 3 本身允许。
- 锁定的部件不参与自动排版，可以用它保留有意摆放的位置。

排版的取舍：

- 只移动屏幕自己的部件。锁定的部件和容器里的部件不动，有意叠在一起的部件（比如贴在图片上的标签）继续叠在一起；只是边缘碰到的不算叠放，会被分开。
- 普通页面先读出结构再排：能横着切开的地方分成一段一段，每段再竖着切成几列，层层切下去；同样的部件排成几行几列就当作网格。段与段之间用这套风格的区块间距和同类间距，段里的间距统一成最接近的间距阶梯或 4dp 网格，对齐取部件本来最接近的边、中线或文字基线。宽度取整行、二分之一或三分之一。
- 一行里有明显的大空档时两端对齐，比如标题贴左边距、右边的图标按钮贴右边距；文字和开关分在两端；铺满大半宽度的一行卡片铺满内容宽度，网格横竖用同一个间距；图片旁边的两行字仍在图片旁边。
- 有场景图的屏幕不按行排。它更像游戏 HUD，部件留在放置的角落或边缘，贴齐页边距，互相不重叠。
- 放不下就把屏幕加长，下一套风格放得下就缩回去。作者自己拉长的屏幕不会被缩短。
- 剧情对话框贴在屏幕底部。作者手动选“内容贴底”时，资源胶囊和血条留在顶部。
- 宽屏上没有底部导航栏，选了底部导航的风格会改用侧边栏。
- 抖音的视频、Instagram 的图片和视频通栏无圆角。抖音整屏视频本身用场景图表现，AI 收到的排版说明也是这样写的。

每一套都对照真实产品做，只取整体视觉语言，不用对方的标志和素材。产品按 2025 到 2026 年的下载量、收入和同时在线榜单挑选。

## 图标家族

风格也决定图标长什么样：iOS 用接近 SF Symbols 的线条图标，微信、VS Code、Windows 各用自己产品的图标，游戏用剪影或彩色图标。组件里写的仍是 Material Symbols 的名字（`home`、`arrow_back`），换家族只换画法，不用改组件。

| 键名 | 图标集 | 未选中 / 选中 | 适合 |
| --- | --- | --- | --- |
| `rounded` | Material Symbols Rounded | 线框 / 实心 | Android（默认） |
| `filled` `light` `sharp` | Material Symbols 的实心、细线、方角 | 按规则取 | Discord 式实心、细线、硬朗 |
| `pixel` | Pixelarticons，缺的用方角 | 同一个 | 像素游戏 |
| `sf` | Framework7（仿 SF Symbols） | 线框 / `-fill` | iOS |
| `fluentui` | Fluent UI System Icons 24 | regular / filled | Windows、Office |
| `codicon` | Codicons | 多数只有线框 | VS Code |
| `phosphor` | Phosphor | regular / fill | 社交、内容类 |
| `lucide` | Lucide | 只有线框，选中也一样 | ChatGPT、Notion |
| `remix` | Remix Icon | line / fill | 短视频、电商 |
| `ant` | Ant Design Icons | outlined / filled | 支付宝、钉钉 |
| `tabler` | Tabler Icons | 线框 / filled | Steam、射击游戏 |
| `mingcute` | MingCute | line / fill | 微信 |
| `game` | Game Icons 剪影 | 同一个 | RPG、魂类 |
| `emoji` | Fluent Emoji Flat（彩色，不跟随文字颜色） | 同一个 | 休闲游戏 |

- 对照表在 `scripts/icon-tables/<家族>.ts`，逐个人工核对过：比如 iOS 的返回是 `chevron-left` 而不是箭头，设置是 `gear-alt`。`bun scripts/propose-icon-tables.ts <家族>` 会按同义词给缺的名字提建议，仍要人看过再写进表。
- 家族里没有的名字退回 Material Rounded。`emoji` 和 `game` 故意不映射箭头、关闭、菜单、更多、加号这类界面骨架，它们保持 Material，颜色跟随控件。
- 不同图标集的留白不同，生成时按实测把每套缩放到和 Material 一样的视觉大小（`SCALE`），线条粗细保持各自的风格。图标的 `<svg>` 带 `data-family`，风格可以按家族微调。
- 图标全部离线打包：`bun run gen:icon-sets` 从 `@iconify-json/*` 取出用到的字形，写到 `components/m3e/icon-sets/data`，每套按名字分片，选中某个家族才加载它的分片，主包不变大。代码里新用了图标名，跑一次这个命令（`bun run check:icon-sets` 检查是否过期）。只有谁都没打包的名字（作者自己输入的）才会联网向 Iconify 取。
- 导出的项目只带用到的字形：Material 在 `src/components/m3e/icon-data.app.ts`，风格家族的字形和对照在 `src/style-icons.ts`，断网也能显示。
- 各图标集的许可见 `NOTICE`。Game Icons 是 CC BY 3.0，用到它的应用要署名作者（Lorc、Delapouite 等，game-icons.net）。

## 风格画廊和截图

画廊把注册表里的每个组件，按画布同样的方式（`PartView`、风格的作用域、风格的屏幕底色）画在一个带标签的格子里，按分类分组。以后新增的组件自动出现；`parts/kits/*.ts` 里导出的组合件（kit）也会被找到，按放到画布上的样子排好画出来。少数组件的构成会随属性变化（返回箭头、大标题、多行设置列表、底部面板），画廊额外画几个样例，写在 `components/Gallery.tsx` 的 `SAMPLES` 里。

地址参数：

| 参数 | 意思 | 例子 |
| --- | --- | --- |
| `style` | 风格键名，不写是 Android | `style=ios` |
| `dark` | `1` 暗色、`0` 亮色，不写是风格自己的默认模式 | `dark=1` |
| `category` | 只看一个分类 | `category=Navigation` |
| `lang` | 组件里的文字用哪种语言，默认中文 | `lang=en` |
| `part` | 只看这几个组件 | `part=app-bar,item,search` |

组合件（kit）每个变体都画，按当前风格的 `KitLook` 选中的变体标 ★。几个只看组合件的参数：`kits=1` 只画组合件，再加 `chosen=1` 只画每个组合件被选中的那个变体（看一个风格的组合方式最快），`splits=1` 把每个可拆分的组合组件和它拆出的原子树并排画出来。截图脚本对应 `--kits`、`--chosen`、`--splits`。

风格面板的“在这个风格下查看全部组件”按钮会在新窗口打开当前风格的画廊。

截图（脚本不启动服务，先在另一个终端启动开发服务器）：

```bash
bun run dev -- --port 3105
```

```bash
bun scripts/style-shots.ts --base http://localhost:3105 --out shots --style ios,wechat
```

- 不写 `--style` 就是全部风格加 Android；`--dark` 只截暗色，`--both` 亮暗各一份；`--category`、`--part`、`--lang`、`--width` 和画廊参数一致。
- 输出是 `shots/<风格>[-dark]/<分类>.png` 和整页 `shots/<风格>[-dark].png`。比 1400 像素高的分类另外切成 `<分类>-1.png`、`<分类>-2.png`……整张太长时缩小后看不清，看切片（`--tile 0` 不切）。
- Playwright 从 Node 能找到的地方加载（`require("playwright")`），不是项目依赖。

检查一个风格的流程：截图 → 逐张看 → 找出“不像这个产品”的组件 → 在这个风格的 `packs/<键名>.ts` 里换配方或写 `css` → 刷新画廊确认 → 跑测试。

## 加一套新风格

1. 在 `lib/styles/packs/` 新建 `<键名>.ts`，用 `definePack` 写出配色（`roles` 简写）、字体、图标家族、`recipes`、`ux`、`layout`，`refs` 写参照产品，`basis` 如实写来源级别。字号阶梯写在 `type`。
2. 把它加进 `packs/index.ts` 的列表，位置决定风格面板里的顺序。
3. 需要新的免费字体时，在 `lib/tokens.ts` 的 `FONTS` 加一项。
4. 跑 `bun run test lib/styles`，它检查文字可读性、用到的组件部位、图标家族和每个变体的四语名称。
5. 跑 `bun run gen:agent` 重新生成 `public/agent.md` 的风格表，AI 才知道它。
6. 跑 `bun run check:export <空文件夹> style`，确认导出后的应用也穿着这套风格。
7. 打开画廊截图，逐类看一遍。

## 自定义风格

内置的 27 套风格是代码；自定义风格是**数据**，存在文档里（`Doc.styles`），跟着项目文件、分享链接和导出的项目走。人可以在风格面板里做，AI 也可以直接写出来。它和内置风格用法完全一样：`theme.style` 写它的键名（`custom:` 开头），画布、预览、画廊、导出的应用、AI 的规则说明都穿着它。

### 格式

字段和内置风格包（`StylePack`）几乎一一对应，只是 CSS 写成规则数组：

| 字段 | 内容 |
| --- | --- |
| `key` | `custom:<id>`，id 只用小写字母、数字、`-`、`_` |
| `name`、`hint`、`layout` | 四种语言的文字 `{ zh, en, ja, ko }`，也可以只写一个字符串 |
| `extends` | 可选，一个内置风格的键名：它的 CSS 作为底，没写的字段都取它的 |
| `refs`、`basis`、`group` | 参照的产品、数值来源级别、分类（`app`、`desktop`、`mobileGame`、`pcGame`） |
| `seed`、`light`、`dark` | 种子色和两种模式下的 24 个颜色角色（只能是 `#RRGGBB`），`error*` 四个可选 |
| `mode` | 选中时打开的模式 |
| `shape`、`font`、`display`、`icons`、`motion` | 都取已有的选项：圆角档位、字体、标题字体、图标家族、动效 |
| `recipes` | 每类控件选一个配方变体，只能是 `RECIPES` 里有的 |
| `control`、`pill`、`compact`、`edge` | 按钮圆角、`rounded-full` 的含义、电脑软件的紧凑尺寸、硬边宽度 |
| `screen`、`screenDark` | 屏幕底纹：`#hex` 或渐变（linear/radial/conic-gradient），不能是图片 |
| `capsLabels`、`italicDisplay`、`loud`、`tokens` | 大写标签、斜体标题、为还原产品而有意保留低对比度的底色（不降低检查门槛，只标明是有意的）、没有角色的控件颜色（`#hex` 或 `var(--md-sys-color-…)`） |
| `art`、`ux`、`type` | 生成图片的画风描述、排版（`margin`、`gap`、`tight`、`nav`、`place`、`bleed`）、字号阶梯 |
| `rules` | `[{ selector, declarations }]`，写在配方和所继承风格的 CSS 之后 |

`extends` 是最常见的做法：只写想改的部分，其余照搬内置风格。比如一个粉色的 iOS：

```json
{ "key": "custom:pink", "name": "Pink", "extends": "ios", "light": { "primary": "#C2185B" }, "recipes": { "tabs": "underline" } }
```

去掉继承来的某个可选字段（标题字体、底纹、`tokens`、`type`、`loud`）写 `null`。`tokens` 写了就整组替换。

### CSS 规则只能写这些

自定义风格来自文件、链接或模型，规则在进入样式表之前逐条检查（`lib/styles/css.ts`）：

- **选择器**只能按部位的名字和状态选：`[data-*]`、`[aria-*]` 属性选择器；空格、`>`、`+`、`~` 组合；`:hover`、`:active`、`:focus`、`:focus-visible`、`:focus-within`、`:checked`、`:disabled`、`:enabled`、`:indeterminate`、`:placeholder-shown`；`:is()`、`:where()`、`:not()`、`:has()`（里面也是同样的语法）；最后可以有 `::before`、`::after`、`::placeholder`；`*` 只能跟在空格后面；单独一个 `&` 表示风格的作用域本身。不能用类名、id、元素名、`:root`、`:first-child` 这类结构伪类。每个选择器先要说是哪个部位（以 `[data-…]`、`:is(…)` 或 `*` 开头）。
- **属性**只能是白名单里的：颜色和背景（含渐变）、边框和圆角、阴影、`filter`、`backdrop-filter`、`clip-path`、`mask`、变换、内外边距和间距、尺寸、字体排印、`display`（none、flex 等，用来显示组合钩子）、`order`、flex 和 grid 的排列、`position`（不能是 `fixed`）、`top/right/bottom/left/inset`、`z-index`（-100 到 100）、`content`、SVG 的 `fill`/`stroke`、过渡和动画，以及自定义属性 `--名字`。
- **值**只能用词、数字、单位、`#hex` 和会画图的函数（`var`、`calc`、`rgb`、`color-mix`、各种渐变、`polygon`、滤镜和变换函数等）。`url()`、`image-set()` 之类会从别处取东西的函数一律不行；`!important`、反斜杠、注释和 `; { } < > @ :` 这些会结束声明或规则的字符也不行。引号里的文字只能出现在 `content`（16 字以内）和 `font-family`。

不合规的声明单独去掉，选择器不合规整条规则去掉，原因用中英文写在问题列表里。编译后每条规则一行，都在风格的作用域里，和内置风格自己的 CSS 在同一个位置，所以画布、预览、画廊和导出的应用都一样。颜色尽量写角色变量（`var(--md-sys-color-primary)`），这样亮暗两种模式都对。

### 校验

`validateCustomStyle(任何东西)` 返回 `{ style, problems }`：把能纠正的纠正（键名补前缀、数字限制在范围内、缺的颜色角色按种子色生成、不认识的字体图标换成默认），不安全或不认识的去掉，最后附上颜色可访问性检查（下一节）没通过的每一项。每条问题有位置（`light.onPrimary`、`rules[3].background`）、处理方式（去掉、替换、保留待看）和中英文说明，界面和 AI 都能据此修改。校验是幂等的，校验过的风格再校验不变。

### “能导入”和“通过可访问性检查”是两回事

一个风格能不能导入、能不能穿，只看它是否安全、完整，和颜色好不好读无关：读不清的颜色照原样保留（`fix: "kept"`），作者可以坚持自己的配色。颜色是否读得清由 `checkAccess(风格)`（`lib/styles/access.ts`）单独回答，返回 `{ pass, checks, issues }`，每一项都可定位：

- **门槛按用途分**：正文 4.5:1；大号文字 3:1（按风格自己的字号阶梯算，24px 及以上，或 18.66px 及以上且字重 700）；必要的非文字界面元素 3:1（输入框和描边控件的边线 `outline`、焦点环 `secondary`、打开的开关 `tokens.toggleOn`）；停用控件只测量、列出，不要求（WCAG 对停用控件的例外）；装饰性元素（分隔线 `outlineVariant`、`tonedLine`、描边和边框色）不检查。
- **每种状态分别查，浅色、深色各一遍**：常态（各层面板上的正文和次要文字、各种填充上的文字、主色文字在屏幕和面板上、屏幕底纹上的正文、设了 `tokens.barBg`/`onBar` 时顶栏标题）；悬停和焦点（文字颜色 8%、10% 的状态层叠在填充上之后）；选中（选中指示器上的文字、按配方确定的选中标签页和导航项文字、打开的开关）；错误（输入框下的错误提示、错误色按钮、错误容器）；停用（38% 的文字叠在 10% 的填充上）。
- **按最终看到的颜色算**：状态层先合成；半透明的 token 叠在屏幕色上；屏幕底纹（`screen`）取每个色标叠在屏幕色上之后最难读的那个。
- **`loud` 不降低任何门槛**。写在 `loud` 里的底色上，文字读不清照样是一项问题，只是标上 `loud`，说明是为了还原产品而有意保留。
- 每项问题写成：哪种模式、哪种状态、读的是什么、前景和背景各取自哪里（`light.onPrimary` 在 `light.primary` 上）、实际比值、需要的比值和字号，例如“浅色·悬停：悬停时主按钮的文字：light.onPrimary 在 light.primary 上 3.45:1，正文至少 4.5:1（label-large 14px/500）；light.primary 写在 loud 里，按风格保留，仍算可访问性问题”。

这个检查只看风格本身的颜色数据：作者手动给部件填的色、文字下面的图片、自定义 CSS 规则里写的颜色、字体实际画得比字重细，都看不到。所以“通过”只说明这套颜色在这些检查里读得清，**不等于界面符合 WCAG**。风格编辑器在问题列表上方写明“颜色可访问性检查：N 项未通过，风格仍可使用”或“全部通过（不等于符合 WCAG）”，并把读不清的颜色行标红（不管是否写在 `loud` 里）。

内置风格还原的是真实产品，很多在个别地方达不到：iOS 绿色开关在白底上约 2:1，微信绿底白字约 2.4:1，iOS 蓝色文字在灰底上约 3.6:1。每套内置风格未通过的项记在 `lib/styles/__snapshots__/styles.test.ts.snap`，颜色或检查规则一改就会在评审里看到。内置风格自己的测试仍守着一条风格底线（成对的文字低于 4.5:1 时必须写进 `loud` 且不低于 2:1），那是防止风格无声退化，不是可访问性结论。

AI 写风格（`generate_style`）用同一个检查：它自己写出的读不清的颜色（继承的内置风格原本就有的问题不算它的）发回给模型改一次，剩下的文字颜色、边线和主色文字按规则修好，`loud` 里的也修；评测里的风格检查（`evals/graders.ts` 的 `custom-style`）复用这个检查器，要求各状态下的文字都读得清，同样不代表 WCAG 合格。

文档打开（文件、链接、AI 草稿都走 `lib/project.ts` 的 `cleanBehavior`）时每个自定义风格都会重新校验；不是风格的条目去掉，同一个键名只留第一个。主题指向一个不存在的自定义风格时按 Android 处理，和不认识的内置键名一样。

### 别处怎么拿到文档的自定义风格

所有读风格的地方都通过 `styleOf(键名)`，它先找内置风格，再找“当前可用”的自定义风格（`lib/styles/book.ts`）：

- `setDocStyles(doc.styles)`：编辑器打开文档、风格改动时调用，之后 `stylePatch`、`recipesOf`、`uxOf`、调色板、`styleCss`、`screenBackground`、`kitLookOf`、严格规则、`rulesForModel` 都认得自定义键名。
- `withDocStyles(doc.styles, () => …)`：只在这次同步调用里可用，结束后恢复原样。接收整份文档的函数（导出项目、代码视图、提示词）自己会这样包一层；MCP 服务这类无界面的程序处理文件时也用它。
- `resolveStyle(键名, doc.styles)`：只查一次，不改变当前可用的风格。

### 在面板里做一个

风格面板最下面的“我的风格”：

1. 选中一个风格后点“复制当前风格”，或从“从内置风格复制…”里直接选一个。能完整放进上面语法的内置风格 CSS 会转成规则（iOS、微信、VS Code 等十套），其余的用 `extends` 继承原风格的 CSS。新风格立刻穿到文档上。
2. 编辑器：顶部是实时预览（按钮、标签页、开关、勾选、滑块、输入框）；下面是名称、浅色和深色两套颜色（成对显示底色和上面的文字，旁边是对比度，不够时标红）、“按主色生成全部颜色”、正文和标题字体、图标家族、圆角、按钮圆角、动效、默认模式、类型、每类控件的配方、导航位置和间距。最后是问题列表和“CSS 规则（高级）”，规则以 JSON 编辑，应用时逐条检查。
3. 每次改动先校验再写进文档；同一个风格连续改动合成一步撤销。改了配方或分类，没人动过的组合件会按新样子重新组合；严格模式下画面按新的间距重排。
4. “导出风格”下载 `<名称>.m3e-style.json`（`{ format: "m3e-style", version: 1, style }`）；“导入风格”读回这种文件或一个裸的风格对象，同键名的风格会被替换，导入后立即使用，校验时去掉的内容会列出来。
5. “在这个风格下查看全部组件”打开画廊：`/gallery?style=custom:…&custom=<风格 JSON>`。不带 `custom` 时画廊读本浏览器里编辑器正在打开的文档，所以 `/gallery?style=custom:…` 也能看。AI 和截图脚本可以把风格 JSON 放进 `custom` 参数（一个风格、风格数组或风格文件都行）。

### 让 AI 写一个

模型草稿里可以带 `styles`，主题写 `"theme": { "style": "custom:…" }`。草稿进文档时和文件一样逐条校验，问题会被去掉；模型的风格和文档原有的合并，同键名替换。最省事的写法是 `extends` 最接近的内置风格，只改颜色和几类配方。

## 修一个组件在某个风格下的样子

按影响面从小到大选：

1. **只这一个风格不对**：在 `packs/<键名>.ts` 的 `css` 里写规则。只能用 `data-slot`、其他 `data-*` 属性、颜色角色变量（`--md-sys-color-*`）和风格变量（`--st-*`）；它写在作用域里、所有配方之后，权重相同时就能覆盖配方（见上面“靠顺序取胜，不靠权重”，不要用 `:not(#_)` 加权）。
2. **几个风格都需要同一种做法**：在 `recipes/` 对应的模块里加一个变体，在 `catalog.ts` 的 `RECIPES` 登记、在 `VARIANT_LABELS`（或按类的 `BY_KIND`）写四种语言的名字，再让这些风格选它。
3. **组件缺部位**：给组件补 `data-slot`（按上面的命名），需要多一个部件时加一个默认隐藏的组合钩子。只加属性和隐藏元素，不改行为，不挪代码。

不要写结构选择器（`:first-child`、`> div`、`h1`），不要在组件里判断风格。部件的作者填色（强调色填充）由 `UNPAINTED` 保护，配方不覆盖。作者用反色填的按钮（比如 Codex 输入框的“写代码”，浅色页面上是黑色胶囊、深色页面上是白色胶囊）由 `NOT_INVERSE` 保护：它的文字颜色是按这个填色换过的，所以去掉按钮填色的配方（艾尔登法环的 `text`）和给所有按钮写白字的配方（`gloss`、消除休闲的糖果按钮）都不碰它，否则会变成深底深字或白底白字。

## 已知的差距

- 纯样式做不出的部分：卷轴飘带、雕花边角、3D 光泽图标、水墨笔触。这些要靠 AI 生成的贴图或矢量原子组件。
- 排版靠规则重排，不会替你增删部件。微信的会话列表、抖音的全屏信息流这类典型页面，需要自己摆好部件或交给 AI 生成，风格只负责把它们排成该产品的样子。
- 排版说明大多对照真实截图写成，数值（边距、间距）是目测，只有微信、Ant Design、Fluent 的控件尺寸来自官方规范。
- 字体只能取相近的免费字体。SF Pro、苹方、Segoe UI 只在装了它们的设备上才生效；游戏和 Claude、Codex 的定制字体无法复制。中文字体：休闲游戏用站酷快乐体，科幻和射击类用站酷庆科黄油体，魂类和黑神话用思源宋体，黑神话标题用马善政毛笔体，像素风用缝合像素体（SIL 开源协议，约 600KB，从 jsDelivr 加载）。
- 字号字重：iOS 按苹果默认字号（凭记忆），微信按 WeUI，其余对照截图估算。
- 为了还原产品本身，少数按钮的文字对比度低于 4.5:1，比如微信绿底白字约 2.4:1、Claude 陶土橙底白字约 3.9:1。这些写在每套风格的 `loud` 字段里，可访问性检查照样把它们列为问题；各风格在悬停、焦点、选中、错误状态下未通过的项见上面“‘能导入’和‘通过可访问性检查’是两回事”。
- 进度条的粗细由组件属性写在行内，`progress` 配方改粗细时用了 `!important`；其余规则都不用。
- 自定义风格只能在已有的配方变体、字体和图标家族里选，不能定义新的配方或加载新字体。内置风格里按作者填色（`[class~="bg-primary"]`）或重复声明写的规则不符合自定义风格的语法，所以复制这些风格时用 `extends` 继承它们的 CSS，而不是转成可编辑的规则。
- 可用的自定义风格是全局的一份（`book.ts`），同步代码里用 `withDocStyles` 隔开；跨 `await` 的流程要在每段同步代码里各自包一层。
- 时间选择器的滚轮只画选中值和上下各两个，点一格就选它，不能拖着转。
- 动作表的动作不知道哪一个是删除，iOS 里都画成主色。
- 画廊里的组合件和画布一样先按估计尺寸排，量出真实尺寸后再排；字体或图标晚到时会再量一次。
- 组合件落到画布上是一层平铺的原子：顶部应用栏组合件里的返回、更多按钮叠在顶栏盒子上，却不在盒子元素里面。`hud` 顶栏配方能给顶栏盒子换成深色底，却够不到这些按钮，所以在消除休闲这类顶栏是饱和色或深色的浅色风格里，它们仍是正文色（深色），在蓝色顶栏上看不清。要组合件给这些按钮指定顶栏上的文字色，风格这边做不到。
