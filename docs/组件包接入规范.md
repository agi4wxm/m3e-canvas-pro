# 组件包接入规范

把扩展组件接入应用时，按本规范操作。以下路径都相对于仓库根目录。现有组件见[组件清单](组件接入进度.md)。

## 一句话规则

**一个组件只写一份定义，放在自己的组件包目录里。不改 `Kind`，不给 `Item` 加字段，不碰编辑器和渲染器。**

## 目录结构

```text
parts/packs/
  index.ts          所有组件包的唯一注册表
  types.ts          组件包的类型定义
  load.tsx          按需加载
  contract.test.ts  契约测试，自动检查每个组件包
  <包 id>/
    index.ts        定义（纯数据，不引用 React 组件）
    parts.ts(x)     导出全部自带组件，供按需加载
    Xxx.tsx         自带组件（没有就不需要）
```

## 接入步骤

### 给现有组件包加组件

1. 在 `<包 id>/index.ts` 的 `defs` 里加一份定义。
2. 如果要用自带组件：
   - 新建组件文件；
   - 在 `parts.ts` 里导出；
   - 在 `sources` 里登记。
3. 运行类型检查和测试。

实测：新增 `dashboard/stat-card` 和 `game/quantity-stepper` 后，组件包目录外的 543 个文件改动数为 0。

### 新建组件包

1. 新建 `parts/packs/<包 id>/index.ts`，导出一个 `PartPack`。
2. 在 `parts/packs/index.ts` 的 `PACKS` 里加上它。
3. 如果组件来自 npm，把依赖加到 `package.json`。

`index.ts` 的最小写法：

```ts
import { h } from "../../node";
import type { PartPack } from "../types";

export const myPack: PartPack = {
  id: "mypack",
  version: "0.1.0",
  sources: {},
  defs: [
    {
      slug: "mypack/hello",
      name: "Hello",
      labels: { ja: "…", zh: "…", ko: "…" },
      category: "Actions",
      icon: "star",
      w: 120,
      h: 40,
      props: [{ key: "text", label: "Text", labels: { ja: "…", zh: "…", ko: "…" }, kind: "text", default: "Hello" }],
      tree: (p) => h("div", { "data-slot": "hello", className: "text-on-surface" }, p.s("text")),
    },
  ],
};
```

## 面板分类

**分类按用途，不按来源。** 组件包决定代码放在哪，`category` 决定组件在面板哪一类，两者无关。`game/` 里的数量加减器就在“选择”里。

分类固定为 12 个，在 `parts/registry.ts` 的 `CATEGORIES`：Actions、Text inputs、Selection、Navigation、Overlays、Feedback、Layout、Data、Media、Chat、Game、Ant Design。不要为一个组件包单独加分类。只有另一套设计体系才值得单独成类，而且默认折叠（`PartsPalette.tsx` 的 `FOLDED`）。

**加新组件前先看有没有重复。** 能用现有组件加属性表达的，就加属性，不再新建。

**组件 ID 可以直接改。** 这是全新项目，不保留旧 ID 的转换。合并或改名后，用旧 ID 保存的文件里，这个组件会显示“Unknown part”，整个文件照常打开。

## 必须遵守的约定

契约测试能查出的项标了“自动”，其余要靠代码评审。

| 约定 | 说明 | 检查 |
|---|---|---|
| 命名 | 组件 ID 写成 `<包 id>/<kebab-case>`，按语义取名，比如用 `quantity-stepper` 而不是 `stepper` | 自动 |
| 定义不含 React | `index.ts` 只能引用 `../../node`、`../../labels` 和类型；组件通过 `load` 按需加载 | 自动 |
| 组件来源 | 用到的组件都要能解析；`sources` 里登记的组件都要被用到，并且 `load` 真能拿到 | 自动 |
| 不抢名字 | 组件名不能和 M3、Recharts 或其他包重复 | 自动 |
| 分类 | `category` 是 `CATEGORIES` 之一，同一类里没有同名组件 | 自动 |
| 容错 | 任何属性存了错误类型的值，都不能让组件崩溃 | 自动 |
| 多语言 | 组件名和属性名要有日、中、韩翻译（可以来自公共词表） | 自动 |
| 存档 | 默认值存取后不变 | 自动 |
| 导出 | 本地组件的 `from` 写 `@/components/packs/<包 id>/<文件名>`，文件必须存在 | 自动 |
| 容器 | 能放其他组件的部件写 `holds: true`，并提供 `width`、`height` 属性。不存子项列表，包含关系按位置判断（`lib/tokens.ts` 的 `heldBy`） | 评审 |
| 运行时图标 | 运行时才确定的图标用 `parts/packs/PackIcon.tsx`，编辑器只会自动加载组件树里能看到的图标 | 评审 |
| 数据位置 | 组件数据都放进 `props`，用 `PropDef` 描述；表格数据用 `kind: "table"` | 评审 |
| 颜色 | 自带组件只用角色类（如 `bg-primary`），不写十六进制色值 | 评审 |
| 第三方主题 | 第三方组件要通过 `usePartTheme()` 读取种子色、深色和圆角，参考 `antd/parts.tsx` | 评审 |
| 第三方弹层 | 弹层要留在组件旁边，不能挂到 `<body>`，否则会跑出主题作用域 | 评审 |
| 第三方过渡 | 依赖同步测量的弹层，要在 `src/index.css` 的减少动态效果规则里加例外 | 评审 |
| 交互归属 | 组件自己管内部交互；画布上组件是惰性的，不用处理选中和拖动 | 评审 |
| 来源和许可 | 在定义文件头注明来源仓库和许可证；复制代码前先确认许可证 | 评审 |

## 文档怎样打开

文件和分享链接统一走 `lib/project.ts` 的 `openProject`：拆开 `m3e-project` 信封，按版本运行 `MIGRATIONS`，再校验结构。以后改格式时，在 `MIGRATIONS` 里加一步。

其他版本的文件、版本号更高的文件、含未知 Kind 的文件一律拒绝，不做半懂的解析。

保存的文件格式：

```json
{ "format": "m3e-project", "version": 2, "packs": { "game": "0.1.0" }, "document": {} }
```

## 提交前检查

在仓库根目录运行：

```bash
bun run typecheck
```

```bash
bun run test
```

```bash
bun run build
```

有弹层或自定义交互的组件，还要在预览模式里实际操作一遍。验证期间有多个问题是单元测试全部通过后，才在真实浏览器里发现的。

## 已知限制

- **本地组件要手动复制：** 导出的代码只提示复制文件，不会自动带上。游戏组件和复制行还依赖 `parts/packs/PackIcon.tsx`，它在画布外要改成直接用 `Icon`，图标由 `bun run gen:icons` 打包。
- **表格属性是纯文本编辑：** 单元格里的逗号会被当成分隔符。
- **第三方弹层在画布上不展开：** 展开绘制的逻辑只认 M3 的弹层组件名。
- **AntD 配色由它自己的算法生成：** 主色能跟随种子色，但部分派生色和 M3 不一致，比如下拉选中项在绿色主题下偏灰。
- **容器不自动排版：** 里面的组件要手动摆放。网格不会把内容排进格子，停靠面板切换标签不会切换内容，分栏拖动时上面的组件不会跟着变。
- **容器的内容要完全落在里面才算：** 压在边上的组件不跟着移动。把容器缩小到露出组件，同样不再带它。
- **复制容器不带内容：** 只复制容器本身。
- **导出的代码是平铺的：** 容器和里面的组件各自绝对定位，不会生成嵌套的 JSX。提示词里是嵌套的。
- **抽奖组件只是原型：** 概率是均等的，结果不会保存，可以用“固定结果”指定要演示的路径。
- **Ant 弹窗画在原地：** 真正的 Modal 会挂到 `<body>` 并盖住编辑器，所以 `antd/modal` 用卡片画成面板，导出的代码也是这个面板。
- **旧 Kind 还在：** 编辑器内部还有 37 个原版的旧 Kind 和相关迁移代码（`lib/migrate.ts`、`migrateGroups`），它们和组件定义是两套并行的模型。
- **图表默认是示例数据：** 需要用户替换。
- **媒体组件只是外观：** 视频、网页和动画组件不会真正播放或加载内容。
