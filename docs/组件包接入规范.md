# 组件包接入规范

把扩展组件接入应用时，按本规范操作。以下路径都相对于仓库根目录。接入进度见[组件接入进度](组件接入进度.md)。

## 一句话规则

**一个组件只写一份定义，放在自己的组件包目录里。不改 `Kind`，不给 `Item` 加字段，不碰编辑器和渲染器。**

## 目录结构

```text
parts/packs/
  index.ts          所有组件包的唯一注册表
  types.ts          组件包的类型定义
  load.tsx          按需加载
  legacy.ts         读取 fork 存档的工具，以及映射到现有 M3 组件的 Kind
  contract.test.ts  契约测试，自动检查每个组件包
  fork-items.test.ts 用各 fork 的真实数据检查打开和转换
  <包 id>/
    index.ts        定义（纯数据，不引用 React 组件）
    parts.ts(x)     导出全部自带组件，供按需加载
    Xxx.tsx         自带组件（没有就不需要）
```

## 接入步骤

### 给现有组件包加组件

1. 在 `<包 id>/index.ts` 的 `defs` 里加一份定义。
2. 如果要用自带组件：
   - 新建组件文件；
   - 在 `parts.ts` 里导出；
   - 在 `sources` 里登记。
3. 运行类型检查和测试。

实测：新增 `dashboard/stat-card` 和 `game/quantity-stepper` 后，组件包目录外的 543 个文件改动数为 0。

### 新建组件包

1. 新建 `parts/packs/<包 id>/index.ts`，导出一个 `PartPack`。
2. 在 `parts/packs/index.ts` 的 `PACKS` 里加上它。
3. 如果组件来自 npm，把依赖加到 `package.json`。

`index.ts` 的最小写法：

```ts
import { h } from "../../node";
import type { PartPack } from "../types";

export const myPack: PartPack = {
  id: "mypack",
  version: "0.1.0",
  sources: {},
  defs: [
    {
      slug: "mypack/hello",
      name: "Hello",
      labels: { ja: "…", zh: "…", ko: "…" },
      category: "Actions",
      icon: "star",
      w: 120,
      h: 40,
      props: [{ key: "text", label: "Text", labels: { ja: "…", zh: "…", ko: "…" }, kind: "text", default: "Hello" }],
      tree: (p) => h("div", { "data-slot": "hello", className: "text-on-surface" }, p.s("text")),
    },
  ],
};
```

## 面板分类

**分类按用途，不按来源。** 组件包决定代码放在哪，`category` 决定组件在面板哪一类，两者无关。`game/` 里的数量加减器就在“选择”里。

分类固定为 12 个，在 `parts/registry.ts` 的 `CATEGORIES`：Actions、Text inputs、Selection、Navigation、Overlays、Feedback、Layout、Data、Media、Chat、Game、Ant Design。不要为一个组件包单独加分类。只有另一套设计体系才值得单独成类，而且默认折叠（`PartsPalette.tsx` 的 `FOLDED`）。

**加新组件前先看有没有重复。** 能用现有组件加属性表达的，就加属性，不再新建。

## 合并组件

要把旧组件并入另一个组件：

1. 给留下的组件补上旧组件的功能，放宽尺寸上限。
2. 删除旧定义，在目标组件所在的包里写 `retired`：`{ 旧 ID: { slug: 新 ID, props: (旧 props) => 新 props } }`。
3. 把指向旧 ID 的 `legacyKinds` 改到新 ID。

旧文档打开时走 `lib/project.ts` 的 `currentPart`，文件和本地存档都会经过。留下的组件改了属性形状时，在 `legacy.ts` 的 `PROP_UPGRADES` 里写转换。

不该出现在面板上、但已有文件还要用的组件，写 `hidden: true`。

## 必须遵守的约定

契约测试能查出的项标了“自动”，其余要靠代码评审。

| 约定 | 说明 | 检查 |
|---|---|---|
| 命名 | 组件 ID 写成 `<包 id>/<kebab-case>`，按语义取名，比如用 `quantity-stepper` 而不是 `stepper` | 自动 |
| 定义不含 React | `index.ts` 只能引用 `../../node`、`../../labels` 和类型；组件通过 `load` 按需加载 | 自动 |
| 组件来源 | 用到的组件都要能解析；`sources` 里登记的组件都要被用到，并且 `load` 真能拿到 | 自动 |
| 不抢名字 | 组件名不能和 M3、Recharts 或其他包重复 | 自动 |
| 分类 | `category` 是 `CATEGORIES` 之一，同一类里没有同名组件 | 自动 |
| 合并 | `retired` 的旧 ID 不再存在，目标存在，只写目标有的属性 | 自动 |
| 容错 | 任何属性存了错误类型的值，都不能让组件崩溃 | 自动 |
| 多语言 | 组件名和属性名要有日、中、韩翻译（可以来自公共词表） | 自动 |
| 存档 | 默认值存取后不变 | 自动 |
| 导出 | 本地组件的 `from` 写 `@/components/packs/<包 id>/<文件名>`，文件必须存在 | 自动 |
| 容器 | 能放其他组件的部件写 `holds: true`，并提供 `width`、`height` 属性。不存子项列表，包含关系按位置判断（`lib/tokens.ts` 的 `heldBy`） | 评审 |
| 数据位置 | 组件数据都放进 `props`，用 `PropDef` 描述；表格数据用 `kind: "table"` | 评审 |
| 颜色 | 自带组件只用角色类（如 `bg-primary`），不写十六进制色值 | 评审 |
| 第三方主题 | 第三方组件要通过 `usePartTheme()` 读取种子色、深色和圆角，参考 `antd/parts.tsx` | 评审 |
| 第三方弹层 | 弹层要留在组件旁边，不能挂到 `<body>`，否则会跑出主题作用域 | 评审 |
| 第三方过渡 | 依赖同步测量的弹层，要在 `src/index.css` 的减少动态效果规则里加例外 | 评审 |
| 交互归属 | 组件自己管内部交互；画布上组件是惰性的，不用处理选中和拖动 | 评审 |
| 来源和许可 | 在定义文件头注明来源仓库和许可证；复制代码前先确认许可证 | 评审 |

## 旧文档兼容

把 fork 的 Kind 接入组件包时，在 `legacyKinds` 里声明映射，旧文档打开后就会转成新组件：

```ts
legacyKinds: {
  joystick: {
    slug: "game/joystick",
    props: (item) => ({ ...(typeof item.value === "number" ? { angle: item.value } : {}) }),
  },
},
```

已有 M3 组件能表达的 Kind，不新写组件，直接加到 `legacy.ts` 的 `CORE_LEGACY_KINDS`。

**写映射前先看真实数据。** 打开 `fixtures/fork-items.json`（由各 fork 自己的 `makeItem` 生成），不要凭字段名猜：

- `dataTable` 有 3 种存法：仪表盘的 `tabs` 是列名，GPUI 的 `tabs` 是制表符分隔的行，Tauri 把整张表存在 `supporting` 里。
- `statCard` 的 `supporting` 是数值，不是说明文字。
- `progress` 的 `value` 在 Miuix 里是 0 到 1，在 GPUI 里是 0 到 100。

**先看方言，再看名字。** 同一个名字在不同 fork 里可能完全不同，比如 `button` 在 GPUI 里用 `variant: "default"`，在 Miuix 里按 `w`、`h` 计尺寸。`legacy.ts` 的 `dialectOf` 先判断方言，查 `DIALECT_KINDS`，查不到才按通用映射处理。

方言也解决了歧义：`stepper` 在 GPUI 里是步骤条（`desktop/steps`），在游戏和 iOS 里是数量加减器（`game/quantity-stepper`）。

**仍分不清的不要映射。** 转错了比留占位更难发现。比如 `calendar` 在 GPUI 里是日期网格，在游戏分支里是每日签到（`game/check-in`），要靠方言分开；没有方言可以区分时，就保留为占位。

**不要漏出默认文案。** 目标组件的默认值可能带示例文字（比如 `item` 的 `12 new messages`、`dropdown-menu` 的 `Delete`），原数据没有这一项时要显式写空字符串，否则示例文字会被当成用户内容。

**图标名要转换。** fork 的图标名可能来自其他图标集（`sf:calendar`、`chart-pie`），也可能已被 Material Symbols 淘汰（`emoji_events` 现在叫 `trophy`）。名字不存在时不会报错，只是什么都不画，所以要经过 `legacy.ts` 的 `materialIcon`。运行时才确定的图标，用 `parts/packs/PackIcon.tsx`，因为编辑器只会自动加载组件树里能看到的图标。

`fork-items.test.ts` 会逐个检查转换后文字和列表内容是否还在。确实没有位置的内容，要明确写进 `NO_PLACE` 例外表。

## 文档怎样打开

外部文档（文件、分享链接）统一走 `lib/project.ts` 的 `openProject`：

1. **拆信封：** 支持无信封文档、`m3e-project` 信封和页面架构分支的 `web-canvas-project` 信封。Miuix 和 SwiftUI 的 `screens` 结构在这一步转成画板和分组，并保留跳转。两者靠顶层有没有 `parts` 数组区分。
2. **拒绝未来版本：** 版本号高于当前的文件直接拒绝，不做半懂的解析。
3. **迁移：** 按版本依次运行 `MIGRATIONS`。以后改格式时，在这里加一步。
4. **展开嵌套：** GPUI 的 `group.children` 和游戏分支的 `item.children` 展开到顶层，位置不变。
5. **收编未知组件：** 转换或保留为占位，详见下表。
6. **校验：** 结构不对才拒绝。

浏览器本地存档不经过 `openProject`，直接由编辑器加载，但同样会收编未知组件。AI 生成的结果仍走严格校验，不收编未知 Kind，避免把模型编造的组件当成真实内容。

| 遇到的情况 | 处理 | 原始数据 |
|---|---|---|
| 组件包能接管的 Kind | 转成对应组件 | 完整保留在 `foreign`，不能“还原” |
| 没人认识的 Kind | 显示同尺寸的虚线占位，可移动、删除、撤销 | 完整保留在 `foreign`；以后装了对应组件包会自动转换 |
| 组件包缺失的组件 | 显示占位 | `component` 和 `props` 不变 |
| 文档顶层未知字段 | 编辑器不使用 | 保存时原样写回 |
| 未知的 `platform` | 编辑器不使用 | 改存为 `foreignPlatform` |
| 版本号更高的文件 | 拒绝打开 | 不改动文件 |

`foreign` 里的本地图片（`data:` 地址）不会进入分享链接。

保存的文件格式：

```json
{ "format": "m3e-project", "version": 2, "packs": { "game": "0.1.0" }, "document": {} }
```

## 提交前检查

在仓库根目录运行：

```bash
bun run typecheck
```

```bash
bun run test
```

```bash
bun run build
```

有弹层或自定义交互的组件，还要在预览模式里实际操作一遍。验证期间有多个问题是单元测试全部通过后，才在真实浏览器里发现的。

## 已知限制

- **本地组件要手动复制：** 导出的代码只提示复制文件，不会自动带上。游戏组件和复制行还依赖 `parts/packs/PackIcon.tsx`，它在画布外要改成直接用 `Icon`，图标由 `bun run gen:icons` 打包。
- **表格属性是纯文本编辑：** 单元格里的逗号会被当成分隔符。
- **占位组件没有属性面板：** 选中后面板为空，但可以移动、删除和撤销。
- **第三方弹层在画布上不展开：** 展开绘制的逻辑只认 M3 的弹层组件名。
- **AntD 配色由它自己的算法生成：** 主色能跟随种子色，但部分派生色和 M3 不一致，比如下拉选中项在绿色主题下偏灰。
- **项目文件转换没有真实文件验证：** Miuix 和 SwiftUI 的项目文件都能打开，但转换依据的是类型定义和手写样本。
- **SwiftUI 画板显示为桌面预设：** 它的画板是 393×852，编辑器的手机预设是另一个尺寸，所以画板工具条会高亮桌面图标。尺寸和内容都是对的。
- **SwiftUI 的外观只读取强调色和深浅色：** 形状、字体和预设名强调色不起作用，原样保留在 `swiftUITheme` 里。
- **Shadcn 的映射没有样本：** 这两个目录没有许可证，只按通用字段读取，详见进度文档。
- **容器不自动排版：** 里面的组件要手动摆放。网格不会把内容排进格子，停靠面板切换标签不会切换内容，分栏拖动时上面的组件不会跟着变。
- **容器的内容要完全落在里面才算：** 压在边上的组件不跟着移动。把容器缩小到露出组件，同样不再带它。
- **复制容器不带内容：** 只复制容器本身。
- **导出的代码是平铺的：** 容器和里面的组件各自绝对定位，不会生成嵌套的 JSX。提示词里是嵌套的。
- **再存回去不是 fork 的格式：** 嵌套展开后不会还原成 `children`，只有组件自身的原始数据留在 `foreign` 里。背包格子里摆的物品目前只留在 `foreign` 里，不会显示。
- **确认框预览里不会关闭：** `confirmBox` 转成 `alert-dialog` 后，和其他没有触发按钮的弹层一样保持打开（依据 `viewOf` 的逻辑，没有单独实测点击按钮）。
- **抽奖组件只是原型：** 概率是均等的，结果不会保存，可以用“固定结果”指定要演示的路径。
- **Ant 弹窗画在原地：** 真正的 Modal 会挂到 `<body>` 并盖住编辑器，所以 `antd/modal` 用卡片画成面板，导出的代码也是这个面板。
- **fork 样本是各 Kind 的默认值：** `fork-items.json` 由 `makeItem` 生成，形状真实，但没有覆盖用户编辑后的取值。Shadcn 两个画布因依赖 `zod` 没有生成，SwiftUI 没有 `makeItem`，Ant Design 的样本没有 `component` 字段。
- **方言识别靠特征推断：** Miuix 看 `w`、`h`，GPUI 看 `variant` 取值。其他 fork 如果恰好用了相同取值，可能被认错。SwiftUI 没有特征字段，由项目文件转换时打上标记。
- **转换可能放不下全部内容：** 比如 `sideSheet` 的导航列表在 M3 侧边面板里没有对应属性，界面上看不到，但完整保留在 `foreign` 里。
- **图表值是占位：** fork 的图表都没存数据，转换后是占位数值，需要用户替换。
- **媒体组件只是外观：** 视频、网页和动画组件不会真正播放或加载内容。
