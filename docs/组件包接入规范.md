# 组件包接入规范

把扩展组件接入应用时，按本规范操作。以下路径都相对于仓库根目录。接入进度见[组件接入进度](组件接入进度.md)。

## 一句话规则

**一个组件只写一份定义，放在自己的组件包目录里。不改 `Kind`，不给 `Item` 加字段，不碰编辑器和渲染器。**

## 目录结构

```text
parts/packs/
  index.ts          所有组件包的唯一注册表
  types.ts          组件包的类型定义
  load.tsx          按需加载
  legacy.ts         读取 fork 存档的工具，以及映射到现有 M3 组件的 Kind
  contract.test.ts  契约测试，自动检查每个组件包
  fork-items.test.ts 用各 fork 的真实数据检查打开和转换
  <包 id>/
    index.ts        定义（纯数据，不引用 React 组件）
    parts.ts(x)     导出全部自带组件，供按需加载
    Xxx.tsx         自带组件（没有就不需要）
```

## 接入步骤

### 给现有组件包加组件

1. 在 `<包 id>/index.ts` 的 `defs` 里加一份定义。
2. 如果要用自带组件：
   - 新建组件文件；
   - 在 `parts.ts` 里导出；
   - 在 `sources` 里登记。
3. 运行类型检查和测试。

实测：新增 `dashboard/stat-card` 和 `game/quantity-stepper` 后，组件包目录外的 543 个文件改动数为 0。

### 新建组件包

1. 新建 `parts/packs/<包 id>/index.ts`，导出一个 `PartPack`。
2. 在 `parts/packs/index.ts` 的 `PACKS` 里加上它。
3. 如果组件来自 npm，把依赖加到 `package.json`。

`index.ts` 的最小写法：

```ts
import { h } from "../../node";
import type { PartPack } from "../types";

export const myPack: PartPack = {
  id: "mypack",
  version: "0.1.0",
  category: { key: "My pack", icon: "widgets", labels: { ja: "…", zh: "…", ko: "…" } },
  sources: {},
  defs: [
    {
      slug: "mypack/hello",
      name: "Hello",
      labels: { ja: "…", zh: "…", ko: "…" },
      category: "My pack",
      icon: "star",
      w: 120,
      h: 40,
      props: [{ key: "text", label: "Text", labels: { ja: "…", zh: "…", ko: "…" }, kind: "text", default: "Hello" }],
      tree: (p) => h("div", { "data-slot": "hello", className: "text-on-surface" }, p.s("text")),
    },
  ],
};
```

## 必须遵守的约定

契约测试能查出的项标了“自动”，其余要靠代码评审。

| 约定 | 说明 | 检查 |
|---|---|---|
| 命名 | 组件 ID 写成 `<包 id>/<kebab-case>`，按语义取名，比如用 `quantity-stepper` 而不是 `stepper` | 自动 |
| 定义不含 React | `index.ts` 只能引用 `../../node`、`../../labels` 和类型；组件通过 `load` 按需加载 | 自动 |
| 组件来源 | 用到的组件都要能解析；`sources` 里登记的组件都要被用到，并且 `load` 真能拿到 | 自动 |
| 不抢名字 | 组件名不能和 M3、Recharts 或其他包重复 | 自动 |
| 容错 | 任何属性存了错误类型的值，都不能让组件崩溃 | 自动 |
| 多语言 | 组件名和属性名要有日、中、韩翻译（可以来自公共词表） | 自动 |
| 存档 | 默认值存取后不变 | 自动 |
| 导出 | 本地组件的 `from` 写 `@/components/packs/<包 id>/<文件名>`，文件必须存在 | 自动 |
| 数据位置 | 组件数据都放进 `props`，用 `PropDef` 描述；表格数据用 `kind: "table"` | 评审 |
| 颜色 | 自带组件只用角色类（如 `bg-primary`），不写十六进制色值 | 评审 |
| 第三方主题 | 第三方组件要通过 `usePartTheme()` 读取种子色、深色和圆角，参考 `antd/parts.tsx` | 评审 |
| 第三方弹层 | 弹层要留在组件旁边，不能挂到 `<body>`，否则会跑出主题作用域 | 评审 |
| 第三方过渡 | 依赖同步测量的弹层，要在 `src/index.css` 的减少动态效果规则里加例外 | 评审 |
| 交互归属 | 组件自己管内部交互；画布上组件是惰性的，不用处理选中和拖动 | 评审 |
| 来源和许可 | 在定义文件头注明来源仓库和许可证；复制代码前先确认许可证 | 评审 |

## 旧文档兼容

把 fork 的 Kind 接入组件包时，在 `legacyKinds` 里声明映射，旧文档打开后就会转成新组件：

```ts
legacyKinds: {
  joystick: {
    slug: "game/joystick",
    props: (item) => ({ ...(typeof item.value === "number" ? { angle: item.value } : {}) }),
  },
},
```

已有 M3 组件能表达的 Kind，不新写组件，直接加到 `legacy.ts` 的 `CORE_LEGACY_KINDS`。

**写映射前先看真实数据。** 打开 `fixtures/fork-items.json`（由各 fork 自己的 `makeItem` 生成），不要凭字段名猜：

- `dataTable` 有 3 种存法：仪表盘的 `tabs` 是列名，GPUI 的 `tabs` 是制表符分隔的行，Tauri 把整张表存在 `supporting` 里。
- `statCard` 的 `supporting` 是数值，不是说明文字。
- `progress` 的 `value` 在 Miuix 里是 0 到 1，在 GPUI 里是 0 到 100。

**先看方言，再看名字。** 同一个名字在不同 fork 里可能完全不同，比如 `button` 在 GPUI 里用 `variant: "default"`，在 Miuix 里按 `w`、`h` 计尺寸。`legacy.ts` 的 `dialectOf` 先判断方言，查 `DIALECT_KINDS`，查不到才按通用映射处理。

方言也解决了歧义：`stepper` 在 GPUI 里是步骤条（`desktop/steps`），在游戏和 iOS 里是数量加减器（`game/quantity-stepper`）。

**仍分不清的不要映射。** 比如 `calendar` 去掉 GPUI 后只剩游戏分支的每日签到，它不是日期选择，目前保留为占位。转错了比留占位更难发现。

**不要漏出默认文案。** 目标组件的默认值可能带示例文字（比如 `item` 的 `12 new messages`），原数据没有这一项时要显式写空字符串，否则示例文字会被当成用户内容。

`fork-items.test.ts` 会逐个检查转换后文字和列表内容是否还在。确实没有位置的内容，要明确写进 `NO_PLACE` 例外表。

## 文档怎样打开

外部文档（文件、分享链接）统一走 `lib/project.ts` 的 `openProject`：

1. **拆信封：** 支持无信封文档、`m3e-project` 信封和页面架构分支的 `web-canvas-project` 信封。Miuix 的 `screens` 结构在这一步转成画板和分组，并保留跳转。
2. **拒绝未来版本：** 版本号高于当前的文件直接拒绝，不做半懂的解析。
3. **迁移：** 按版本依次运行 `MIGRATIONS`。以后改格式时，在这里加一步。
4. **收编未知组件：** 转换或保留为占位，详见下表。
5. **校验：** 结构不对才拒绝。

浏览器本地存档不经过 `openProject`，直接由编辑器加载，但同样会收编未知组件。AI 生成的结果仍走严格校验，不收编未知 Kind，避免把模型编造的组件当成真实内容。

| 遇到的情况 | 处理 | 原始数据 |
|---|---|---|
| 组件包能接管的 Kind | 转成对应组件 | 完整保留在 `foreign`，不能“还原” |
| 没人认识的 Kind | 显示同尺寸的虚线占位，可移动、删除、撤销 | 完整保留在 `foreign`；以后装了对应组件包会自动转换 |
| 组件包缺失的组件 | 显示占位 | `component` 和 `props` 不变 |
| 文档顶层未知字段 | 编辑器不使用 | 保存时原样写回 |
| 未知的 `platform` | 编辑器不使用 | 改存为 `foreignPlatform` |
| 版本号更高的文件 | 拒绝打开 | 不改动文件 |

`foreign` 里的本地图片（`data:` 地址）不会进入分享链接。

保存的文件格式：

```json
{ "format": "m3e-project", "version": 2, "packs": { "game": "0.1.0" }, "document": {} }
```

## 提交前检查

在仓库根目录运行：

```bash
bun run typecheck
```

```bash
bun run test
```

```bash
bun run build
```

有弹层或自定义交互的组件，还要在预览模式里实际操作一遍。验证期间有多个问题是单元测试全部通过后，才在真实浏览器里发现的。

## 已知限制

- **本地组件要手动复制：** 导出的代码只提示复制文件，不会自动带上。
- **表格属性是纯文本编辑：** 单元格里的逗号会被当成分隔符。
- **占位组件没有属性面板：** 选中后面板为空，但可以移动、删除和撤销。
- **第三方弹层在画布上不展开：** 展开绘制的逻辑只认 M3 的弹层组件名。
- **AntD 配色由它自己的算法生成：** 主色能跟随种子色，但部分派生色和 M3 不一致，比如下拉选中项在绿色主题下偏灰。
- **SwiftUI 画布的项目文件打不开：** 它的结构（`screens` 加 `parts`）和其他工程不同，还没写转换。Miuix 的项目文件已能打开，但转换依据的是它的类型定义和手写样本，没有用真实保存的文件验证过。
- **fork 样本是各 Kind 的默认值：** `fork-items.json` 由 `makeItem` 生成，形状真实，但没有覆盖用户编辑后的取值。Shadcn 两个画布因依赖 `zod` 没有生成，SwiftUI 没有 `makeItem`。
- **方言识别靠特征推断：** Miuix 看 `w`、`h`，GPUI 看 `variant` 取值。其他 fork 如果恰好用了相同取值，可能被认错。
- **转换可能放不下全部内容：** 比如 `sideSheet` 的导航列表在 M3 侧边面板里没有对应属性，界面上看不到，但完整保留在 `foreign` 里。
- **图表值是占位：** fork 的图表都没存数据，转换后是占位数值，需要用户替换。
- **媒体组件只是外观：** 视频、网页和动画组件不会真正播放或加载内容。
