# 玩法契约

玩法契约是 game-loop（外部的玩法循环模块）写给 M3E 读的一份文件：它接受哪些命令（参数、回答、拒绝码）、发出哪些事件、
快照长什么样、时钟怎么走、还接受哪些来自别的系统的“外部事实”。按[游戏阶段整改计划](游戏阶段整改计划.md)的决策 K2，契约只有
一个作者：game-loop 写，M3E 导入、只读，不复制规则、不改契约。M3E 只依赖文件的**格式**，不依赖文件放在哪里（中枢的处理方式）：
契约文件的路径是项目的配置（`document.external.gameContract`，和资产清单的 `external.assetManifest` 同一处），换地方只改这一项。

| 文件 | 内容 |
| --- | --- |
| `lib/game/m3e-game.schema.json` | 契约文件格式的 JSON Schema（2020-12）：game-loop 可以用它检查自己的输出 |
| `lib/game/format.ts` | 读契约：严格按格式读，不修补；读不了时列出每条原因 |
| `lib/game/map.ts` | 契约在文档里变成什么：`game.*` 接口操作、problem+json 的 `type`、输入动作、世界契约、模拟库场景 |
| `lib/game/link.ts` | 文档和契约的连接 `document.game`、契约路径的配置：再次导入时替换它生成的一切，并报告改了什么、坏了什么 |
| `lib/game/gaps.ts` | 设计里和契约对不上的引用（缺口）列表，以及按缺口文件（`.m3e/gaps.json`）格式给出的同一份列表 |
| `lib/game/folder.ts` | 文件夹项目打开时按路径读旁边的契约 |
| `lib/game/fixtures/example.m3e-game.json` | 最小示例契约：模板和测试都按它写，接上真正的 game-loop 之前代替它 |
| `lib/gameLoop/` | 预览接本地 game-loop（见“本地 game-loop”） |

## 文件格式

文件名以 `.m3e-game.json` 结尾，格式 `m3e-game`，版本 1：

```jsonc
{
  "format": "m3e-game",
  "version": 1,
  "namespace": "game",              // 命令变成的接口操作的前缀：game.pull
  "contractVersion": "1.0.0",       // game-loop 自己给契约的版本号，重新导入时比较
  "summary": "…",
  "problemBase": "urn:game:problem:", // 可省；拒绝的 problem type = problemBase + 拒绝码
  "clock": { "unit": "ms", "pausable": true, "rates": [0.5, 1, 2] },
  "snapshot": { /* JSON Schema：view() 给的快照 */ },
  "events": { "hit": { "summary": "…", "payload": { /* JSON Schema */ } } },
  "commands": {
    "pull": {
      "via": "api",                  // 走接口：发一次、回答一次
      "params": { /* JSON Schema，对象 */ },
      "result": { /* JSON Schema */ },
      "rejections": { "insufficient-resources": { "status": 409, "title": "Not enough gems", "summary": "…" } }
    },
    "move": { "via": "input", "input": "vec2" }   // 走世界的输入通道：每秒很多次、不回答
  },
  "facts": { "purchaseSettled": { "from": "payments", "params": { /* JSON Schema */ } } }
}
```

- 命令、事件、事实的名字：小写字母开头，后面字母和数字（`pull`、`checkIn`）；拒绝码：小写字母、数字和连字符（`cooldown`）。
- 拒绝的 `status` 是 400–499，省略时 409；`type` 省略时是 `problemBase`（省略时 `urn:<namespace>:problem:`）加拒绝码。
- 读的时候（`readGameContract`）先按格式的 JSON Schema 检查，再检查名字；有任何一处不对就整份不读，并列出原因。最多 100000 个值、
  嵌套 40 层、100 万个字符。

## 契约在文档里变成什么

- **走接口的命令**变成接口操作 `<namespace>.<命令>`（`game.pull`）：`POST /<namespace>/commands/<命令>`，参数是 JSON 请求体，
  回答是 200，每个拒绝状态是一个 `application/problem+json` 响应，其 `type` 只能是该状态下这个命令的拒绝类型；另有默认的
  `Problem` 响应。操作带 OpenAPI 扩展 `x-m3e-game`（`{namespace, contractVersion, command}`），导出的 OpenAPI 原样写出。
- **拒绝码**变成 problem+json 的 `type`，设计在 `catch` 上按它分支：

  ```json
  { "do": "call", "operationId": "game.pull", "args": { "count": "10" },
    "then": { "to": "none", "effects": [{ "do": "snackbar", "message": "{{response.pulled[0].name}}" }] },
    "catch": { "to": "none", "when": { "expr": "error.type == 'urn:game:problem:insufficient-resources'" },
               "effects": [{ "do": "setVar", "var": "summonIssue", "value": "gems" }],
               "else": { "to": "none", "effects": [{ "do": "setVar", "var": "summonIssue", "value": "failed" }] } } }
  ```

- **走输入的命令**是世界的输入动作（`move: vec2`、`attack: bool`），设计用 `move`、`press`、`release` 发（[交互规则](交互规则.md)“输入动作”），
  不经过接口。
- **快照、事件、时钟**连同输入动作就是世界的契约（[世界宿主契约](世界宿主契约.md)，`lib/world/contract.ts` 的 `WorldContract`，
  `worldContractOf`）：文档接了玩法契约时，导出写的 `src/generated/worldContract.ts` 是它的，不再是示例引擎的。示例契约的世界部分
  和示例引擎的契约完全一样（测试检查）。
- **每个拒绝**变成模拟库的一个场景，编号 `<操作>.<拒绝码>`（`game.pull.insufficient-resources`）：这个操作在该场景里回答那个
  拒绝的 problem，预览切到这个场景就能看到对应的设计。其余时候模拟库按回答的 Schema 生成数据，请求按参数的 Schema 检查。
- **外部事实**只列出来，不变成任何操作：只有别的系统（支付、运营后台）告诉 game-loop，应用从来不发。

## 只读

- `game.*` 操作是 game-loop 的：`update_endpoint`、`remove_endpoint` 拒绝改它们，`add_endpoint` 不能在契约的命名空间里加操作，
  导入作者自己的 OpenAPI（包括替换模式）也保留它们。要改只能在 game-loop 里改，再重新导入。
- 再次导入（`import_game_contract`，或文件夹项目重新打开）替换上一份契约生成的全部操作和场景（作者自己同名的操作保留、契约的
  不加），并给出报告：版本号（这次和上次）、是否和上次一样、增删改了哪些命令、拒绝、输入、事件、事实，以及**缺口**。
- 缺口（`gameGaps`）是设计里和契约对不上的引用，一处一条：`{kind, ref, reason, detail, where}`，`where` 和缺口文件的位置一样
  （`{screen?, component?, part?, prop?}`，`prop` 是槽位、`form` 或数据源）。`kind` 是 `command`（调用了契约没有的
  命令，或调用了走输入的命令）、`fact`（调用了外部事实）、`param`（给了命令不接受的参数，或没给它要的参数）、`rejection`
  （`catch` 按命令已经没有的拒绝类型分支）、`input`（向世界发它不接受的输入，或类型不对）、`event`（世界视口在契约没有的事件上
  做动作）。`reason` 是 `missing`、`not-a-call`、`not-the-apps`、`not-taken`、`needed`、`wrong-type` 之一。`gameHubGaps` 按资产引用
  定下的缺口文件格式（`lib/export/gaps.ts`）给出同一份列表：`kind` 为 `game-<种类>`，`module` 为 `game-loop`，同一个缺口的各处
  合在 `where` 里；把它写进导出报告和 `.m3e/gaps.json` 是第七批 J7 的事。

## 项目里的设置

`document.external.gameContract` 是契约文件相对项目文件夹的路径（和资产清单的路径规则一样：文件夹里的相对路径，没有 `..`、
盘符和反斜杠），省略时是项目文件旁边的 `game-contract.m3e-game.json`。`document.game` 是文档和契约的连接（可以没有）：

```json
"external": { "gameContract": "game-loop/contract.m3e-game.json" },
"game": { "hash": "…", "contract": { "format": "m3e-game", … } }
```

- **文件夹项目每次打开时**按路径读文件：内容一样什么都不变；变了就重新导入，编辑器提示有几处缺口；文件不见了或读不了，保留
  上次读到的契约并提示。没有接契约、也没有配置路径的项目不读；只接了示例契约的项目在文件夹里有契约文件时换成它，没有时不提示。
  MCP 服务器的文件模式打开项目时也一样按路径读项目旁边的契约（`mcp/src/file.ts`），结果写在日志里。
- `contract` 是上次读到的契约，只读：分享链接、浏览器里的副本没有文件夹也照样知道它。`hash` 是契约内容的哈希（和文件的空白
  无关）。`example: true` 表示这是 M3E 的示例契约（模板带来的），接上 game-loop 自己的契约之前代替它。
- 读的时候（`openProject`、编辑器的文档核心）契约按格式重新读一遍：读不了的整个连接丢掉；不合规的路径丢掉。

## 编辑器和 AI

- “项目”菜单的“导入玩法契约…”选一个 `.m3e-game.json`：一步，可以撤销；路径记为文件名（文件夹项目里即项目旁边的文件）。
- 工具：`import_game_contract {text, path?}`（只能是 game-loop 写的文件原文，不能自己写一份；`path` 写进 `external.gameContract`）、
  `remove_game_contract`（连同路径的配置一起去掉）、
  `get_game_contract`（每个命令的调用写法、每个拒绝的分支条件、输入动作、事件、快照、时钟、外部事实，和缺口）。
- 抽卡（`gacha-pull`）和签到（`daily-check-in`）模板按示例契约写：文档没有契约时带上示例契约；按钮调用 `game.pull`、
  `game.checkIn`，回答里的名字和奖励来自 game-loop，资源不足、本期结束、今天已签到、其他失败各有一个提示设计（`summonIssue`、
  `checkInIssue` 只记最后一次拒绝是哪种，是界面状态，不是钻石或天数）。
- 本地 game-loop 按同样的路径回答同样的操作、用同样的 problem type 拒绝，模板不用改（见下一节）。

## 本地 game-loop

预览栏的“由谁回答”可以选**模拟库**或**本地 game-loop（填地址）**。选了 game-loop，预览的接口调用（包括 `game.*` 操作）、实时
通道和世界视口都发给这个地址上的本地进程，不再由模拟库回答；拒绝照样落到设计按 problem type 写的分支上。地址和选择存在项目的
配置里：`document.external.gameLoop`，`{"url": "http://localhost:8787", "preview": true}`；只存地址，不能带用户名、密码、查询参数
或片段（密钥放在这些地方），带了的地址不收（读文件时整项丢掉）。“切回模拟库”一下就回去，地址留着。

| 文件 | 内容 |
| --- | --- |
| `lib/gameLoop/link.ts` | 项目里的地址（`readGameLoopUrl`、`gameLoopOf`）、game-loop 的自我介绍和检查（`checkGameLoop`） |
| `lib/gameLoop/transport.ts` | 预览的传输层：导出的 `packages/api` 同一套客户端（fetch 的传输层、`withRealtime`），指向这个地址 |
| `lib/gameLoop/world.ts` | 由 game-loop 演的世界：经 `World` 接口（[世界宿主契约](世界宿主契约.md)），快照、事件、时钟、输入走一条实时连接 |
| `lib/gameLoop/fixtures/standIn.ts`、`serve.ts` | 测试用的替身 game-loop（Bun 的 HTTP + WebSocket 服务）：按示例契约回答 `game.pull`、`game.checkIn`（成功和每个拒绝码）、一个 ticker 通道和世界的快照流；`bun lib/gameLoop/fixtures/serve.ts 8787` 可以手动起一个试预览 |
| `components/preview/gameLoop.ts`、`GameLoopSwitch.tsx` | 预览里的选择、状态和预览栏的按钮 |

game-loop 要讲的协议和导出的后端（[后端](后端.md)）一样，多一个自我介绍：

- **自我介绍** `GET <地址>/.well-known/m3e-game-loop` 回答 JSON：`{"format": "m3e-game-loop", "version": 1, "namespace": "game",
  "contractVersion": "1.0.0", "now": 1730000000000}`。`now` 是游戏的时钟（毫秒，可省），应用读到的“现在”和世界时间按它走；
  可选 `realtime`（实时前缀，默认 `/realtime`）和 `world`（世界流在实时前缀下的路径，默认 `/world`）。
- **命令和其他接口**按契约的路径和方法：`POST <地址>/game/commands/pull`，JSON 请求体，成功 200，拒绝回 `application/problem+json`，
  `type` 是契约的拒绝类型（`urn:game:problem:insufficient-resources`）。文档里别的接口也按路径发给它。
- **实时通道**在实时前缀下：`ws://<主机>/realtime/<通道地址>`，每一帧就是一条消息的 JSON payload，不加信封；SSE 通道照样
  （`event:` 是消息名）。令牌按导出的后端放在 `access_token` 里。
- **世界流** `ws://<主机>/realtime/world?view=<世界视口的 id>`，同样每帧一个 JSON，按字段区分：game-loop 发 `{"snapshot": {…}}`
  （契约的快照）、`{"event": "hit", "payload": {…}}`（契约的事件）、`{"clock": {"now", "paused", "rate"}}`（世界时间）、
  `{"pause": {"accepted", "reason"?}}`（对暂停请求的回答）；预览发 `{"input": "move", "value": {"x", "y"}, "at": 毫秒}`、
  `{"pointer": {…}}`、`{"occlude": [矩形]}`、`{"pause": true|false}`。世界视口显示快照，设计在它的事件上的动作照常运行，
  不再演示示例引擎。
- **CORS**：编辑器的页面和 game-loop 不同源，game-loop 要回 `Access-Control-Allow-Origin`（本机开发用 `*` 即可，不带 Cookie）、
  允许 `content-type`、`accept`、`authorization` 请求头并回答 `OPTIONS` 预检；编辑器在公网的 https 页面上时 Chrome 访问本机地址
  还会问 `Access-Control-Allow-Private-Network`，回 `true`。导出的后端开发时设 `CORS_ORIGINS` 即可。

预览栏写清楚它现在怎样，出错时栏里直接显示原因，并每隔几秒重试（连不上、CORS、不是 game-loop 时）：

| 状态 | 说明 |
| --- | --- |
| 连接中 | 正在问自我介绍 |
| 正常 | 写出地址、契约的命名空间和版本 |
| 连不上 | 地址上没有回应（没启动、端口不对） |
| CORS 拒绝 | 有东西在回答，但不允许这个页面读（浏览器里分辨：带 CORS 的请求失败、不带 CORS 的不透明请求成功） |
| 不是 game-loop | 没有自我介绍，或格式、版本这个 M3E 读不了 |
| 版本不对 | game-loop 的 `contractVersion` 和文档导入的契约不一样：重新导入它的契约，或启动对应版本的 game-loop |
| 别的契约 | `namespace` 不一样 |

版本不对时请求照样发出（设计和回答可能对不上，栏里一直写着）；game-loop 从出错变成正常时预览从头开始，正在显示的屏幕重新加载。
平台能力（支付、定位……）仍由模拟库回答，它们不是 game-loop 的。页面自己放了 `window.m3ePreviewTransport` 时它优先，预览栏没有
这个选择。AI 工具里还没有设置地址的操作（`set_game_loop` 只是预览栏的编辑操作）。
