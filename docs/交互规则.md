# 交互规则

一次点击（或指针移入、延迟、组件的事件）做什么：先看条件走哪一支，再按顺序执行效果，最后跳到哪里；调用接口的效果
回答到达后再运行 `then` 或 `catch`。这些规则只写一份：数据模型在 `lib/actions/model.ts`，解释器在 `lib/actions/run.ts`，
解释器向它所在的应用要的东西（宿主接口）在 `lib/actions/host.ts`。解释器是纯 TypeScript，不依赖 DOM、React 和平台，
编辑器、Node、React Native 和小程序都能直接运行；表达式用 `lib/bindings/expr.ts` 的求值器（从不 `eval`）。

预览已经接到解释器上：每一次交互都经 `lib/actions` 的 `run` 运行，宿主是 `components/preview/host.ts`，交互状态在
`components/preview/store.ts`，数据、调用、表单和会话是导出的应用也用的 `lib/app` 的 Runtime（`lib/bindings/design.ts` 从文档读出
数据源、表单和契约交给它），它也管重新开始、登录后回到原处和能力调用。手机端套件和小程序套件第四批起也打印动作数据、由 `lib/actions` 运行：手机端的记忆在 `rn/src/kit/app.tsx`，
`lib/export/targets/mobile.ts` 写出的 `effects.ts` 是解释器的宿主；小程序屏幕的运行时（`miniapp-kit/src/kit/app/screen.tsx`）就是
宿主。本文是它们
都要遵守的规则；文末的一致性表在每个宿主上各跑一遍，列出今天谁没做到。整改计划第四批把五个宿主都接到
`lib/actions` 上，再逐条消掉表里的分歧。两种 Web 导出已经接上（第四批 E2）：打印器（`lib/printBehaviour.ts`、
`lib/printBindings.ts`）只把点击打印成 Action 数据、把 id 换成应用里的名字，导出的 `src/runtime.tsx`（`lib/runtimeSource.ts`
写出）实现 `Host`，由 `useActions` 交给复制进项目的 `lib/actions` 运行；产品的接口、表单、能力经 `lib/app` 的运行时
（`outcomeOf`、`FormHandle.send`、`Runtime.invoke`）。

数据怎样读、表达式怎样写见 [数据绑定](数据绑定.md)；组件怎样声明点击位置和事件见 [组件规范](组件规范.md)。

## 模型

| 类型 | 是什么 |
| --- | --- |
| `Action` | 一次点击：`ActionBody` 加上 `when`（条件）、`else`（条件不成立时的主体）、`trigger`（不是点击时怎样开始） |
| `ActionBody` | `effects`（按顺序的效果），然后去哪：`to`（屏幕 id、`back`、`link`、`none`），`params`（给打开的屏幕的参数，每个是表达式），`overlay`（叠在上面），`url`（`link` 打开的网址），`scrollTo`，`motion`（屏幕怎样进来；没有时是默认的滑入。版本 4 起没有 `transition`，见[项目文件](项目文件.md)） |
| `Condition` | `{expr: 表达式}`、`{filled: 输入框 id}`。变量和值的比较也是表达式（`vars.count == 3`），版本 4 把旧的 `{var, op, value}` 写成了它 |
| `Answer` | 调用和能力回答后运行的主体（`then`、`catch`）：`ActionBody` 加上 `when`、`else`，条件读回答（见“回答上的条件”） |
| `Effect` | `show`、`hide`、`toggle`、`open`、`close`（`part`），`setVar`（`value` 或 `expr`），`toggleVar`，`addVar`（`by`），`setProp`，`snackbar`（`message` 里可以有 `{{表达式}}`），`call`（`operationId`、`args`、`body`、`then`、`catch`、`optimistic`），`refresh`、`loadMore`（`source`），`submit`（`form`），`signOut`，输入动作 `move`（`part`、`action`、`vector`）、`press` / `release`（`part`、`action`），见“输入动作” |
| `Trigger` | `{on: "hover"}`、`{on: "delay", ms}` |
| `Optimistic` | `{source, remove: true}` 或 `{source, patch: {字段: 表达式}}` |

`lib/tokens.ts` 原名转出这些类型，文档、操作和打印器照旧使用。`then` / `catch` 嵌套调用的上限只有一个常量
`MAX_CALL_DEPTH = 4`：读文件（`lib/project.ts`）、编辑操作（`set_action`）和解释器都按它。

## 一次点击怎样运行

1. **选分支。** 没有 `when` 就运行动作本身；有 `when` 时成立运行本身，不成立运行 `else`，没有 `else` 就什么都不做。
   选定的主体里所有文字的 `{{current.字段}}` 先换成最近点过的集合行（没有这个字段就是空）。
2. **按顺序执行效果。** 每个效果在它那一步读当时的状态：后一个效果看得到前一个写入的值（变量、显示状态、属性）。
   表达式的作用域每一步重新取（`Host.scope`）。
3. **调用不等回答。** `call` 在它那一步发出，参数在那一步读；后面的效果和这次点击的跳转不等它。要等回答的事写进 `then`。
4. **最后跳转。** 跳转的参数（`params`）在所有效果之后读，所以 `[setVar pick="p7"]` 再跳转带 `{id: "vars.pick"}`，
   打开的屏幕收到 `p7`。`back` 先关叠在上面的屏幕；`link` 只打开 http / https 网址（`linkUrlOf`），其余不打开；
   `none` 只运行效果（`scrollTo` 照样滚动）；不存在的屏幕哪儿也不去。

## 条件

| 条件 | 成立的时候 | 边界 |
| --- | --- | --- |
| `{filled}` | 输入框里有东西：非空白文字、勾上、选了一项（序号 ≥ 0）、选了文件 | 输入框不存在时不成立 |
| `{expr}` | 表达式的值为真（`truthy`：不是 null、false、0、""、NaN、空列表）。变量和值比较写成 `vars.名字 == 值`（`==` 让 `3` 和 `"3"` 相等）；集合行的字段读 `row.字段`（点击或显示所在的那一行） | **读不出来（解析不了、读到不存在的数据）当作不成立**，走 `else`；不在行里的部件读 `row` 读到的是空 |

## 每个效果

| 效果 | 做什么 | 边界 |
| --- | --- | --- |
| `show` / `hide` | 让部件出现或消失，一开始可见的部件也能隐藏 | 部件不存在时什么都不做 |
| `toggle` | 按现在的显示状态反过来 | 同上 |
| `open` | 打开浮层部件：菜单、对话框、底部面板出现并打开 | 有自己触发按钮的（下拉菜单）打开它的弹出层 |
| `close` | 关闭浮层部件 | **有自己触发按钮的（下拉菜单）只关弹出层，按钮留在屏幕上**；没有触发按钮的（对话框、面板）关上就不在屏幕上 |
| `setVar` | 写变量：`expr` 在这一步求值（优先于 `value`） | 值按变量类型转换：文字变文字，数字要能读成数，布尔按 `""`、`"false"`、`"0"` 为假；转不成或读到空就不写；表达式读到对象时写它的文字；变量不存在时什么都不做 |
| `toggleVar` | 布尔变量取反 | 不是布尔的变量写回原值（算作写过） |
| `addVar` | 数字加 `by`，结果按百万分之一取整（三次加 0.1 是 0.3） | `by` 不是有限数时什么都不做 |
| `setProp` | 改部件的一个属性 | 部件不存在时什么都不做 |
| `snackbar` | 弹提示条，文字里的 `{{表达式}}` 在这一步读 | 新的提示条换掉旧的 |
| `call` | 调用接口，见下 | 嵌套超过 4 层的不发 |
| `refresh` / `loadMore` | 重新加载点击那一屏的数据源 / 加载下一页 | 数据源不存在时什么都不做 |
| `submit` | 提交表单：`form` 给了就是那个组，否则是被点的部件所在的表单 | 见“表单” |
| `signOut` | 结束会话（有退出接口就顺便调用，不等它） | 见“会话” |
| `move` | 把一个方向作为世界的一个输入（`action`，不写是 `move`）发给世界视口 `part` | 见“输入动作”：方向在这一步读，读不出方向的不发 |
| `press` / `release` | 按下 / 松开世界视口 `part` 的一个命名输入（`action`：`attack`、`jump`） | 同上 |
| `spawn` | 用模板 `group`（一个组的 id，`Group.spawn` 说它是模板）生成一个实例 | 见“按事件生成”：实例读这一步的 `event`；组不是模板时什么都不做 |
| 不认识的效果 | 什么都不做 | 后来版本存的文件照样能运行 |

## 点击时冻结的上下文

一次点击发生时记下它在哪里（`Tap`）：哪一屏（屏幕上的或叠在上面的那一屏）、那一屏的参数、被点的部件、它所在的数据
重复的那一项（`item`、`index`）和集合行（`row`）、它所在的表单、开始它的事件带来的东西（`event`）。这次点击引起的
一切，包括它的调用回答后的 `then` 和 `catch`，都在这个位置上运行，不管那时屏幕上显示的是哪一屏。

**冻结的是“哪一个”，值每次现读**：`then` 读到的是点击那一屏的参数和那一行，但数据、变量、会话、表单的内容都是回答
到达时的值。`then` 和 `catch` 的作用域另外有 `response` / `status`（成功）或 `error` / `status`（失败）。

## 调用接口

`{do: "call", operationId, args, body}`：`args` 的每个值是表达式，在这一步读；读成空（`undefined`）的不发。宿主按契约
把参数放进路径、查询或请求头，其余放进 JSON 请求体；给了 `body` 时它就是整个请求体。

- 2XX：运行 `then`（读 `response`、`status`）。
- 其余：先把乐观修改放回，再运行 `catch`（读 `error`、`status`）。
- 因为没有会话被拒绝（401，刷新令牌也没救回来）：应用去登录页，**不运行 `catch`**。
- 登录接口成功、而应用是被守卫或 401 送来登录的：回到原处，代替 `then` 的跳转；`then` 的效果照常运行。
- **乐观修改**：`optimistic` 在发出调用前就改点击所在那一行（`remove` 去掉它，`patch` 改字段，字段的表达式读那一行作
  `item`），失败时放回。不是从数据重复里点的，没有行可改，就不改。
- **嵌套**：`then` / `catch` 里可以再调用，最多 4 层：第四层 `then` 里的调用是最后一个发出的。
- 宿主的调用抛出异常时当作失败（`status` 0）。

## 迟到的回答

回答到达时世界可能已经变了。规则只有一条，所有宿主相同：

| 回答到达前发生了什么 | then / catch | 乐观修改 |
| --- | --- | --- |
| 宿主重新开始了（换了模拟库的场景、运行时 `restart`、换了后端） | 不运行 | 不放回（那份数据已经清空） |
| 同一屏的同一个组件又调用了同一个接口 | 不运行（新的那次会回答） | 不放回（新的那次的修改在它上面；新的失败时会放回到它之前） |
| 访客已经离开（返回、换屏、叠上或关掉屏幕、滑走、点了别的跳转；平台自己的返回也算：系统返回键、滑动返回、预览控制栏的返回、平台标签栏切换） | **效果照常运行，跳转不再发生** | 失败时照常放回 |
| 都没有 | 照常运行，包括跳转 | 失败时放回 |

点击自己的跳转、以及它的 `then` / `catch` 里的跳转不算离开：`[call save, 跳到“完成”]` 的 `then` 在“完成”页上照常运行。

**为什么这样定。** `then` / `catch` 里有两类东西：让应用跟上后端的（设变量、刷新数据、提示条、再调用），和带访客去
哪里的（跳转）。后端已经做了那件事，前一类不能丢——第一批里预览“访客离开就整个丢弃”会让购物车数量、列表这些状态
和后端对不上；后一类只在访客还在原地时才有意义，访客已经走开时再跳转是把人拽走，`lib/app` 的 `Runtime.call`
现在就会这样。重新开始之后，回答属于一个已经不存在的会话，什么都不该做；同一组件对同一接口的新调用代表同一个意图，
旧回答晚到时如果还运行，会覆盖新的结果（点两次“喜欢”、回答倒序到达）。宿主只需要提供两样东西：调用的结果里标明
“重新开始后作废”（`dropped`），和一个随每次移动增加的计数（`Host.moves()`）。手机端和小程序的路由由平台掌管，
不经应用的移动也要算进去：RN 套件由应用的路由告诉它哪一屏获得焦点（`screenShown`，导出应用的 `ScreenRoute` 经
`routing.tsx` 的 `seen` 调用），不是应用要求去的那一屏就算一次移动；小程序套件读移动计数时比较页面栈，平台自己改了
页面栈（返回键、原生标签栏）就算一次（一致性表 `invoke-late-platform-back`）。

`lib/app` 的 `Runtime.call` / `invoke` 自己也守这条规则（给不经解释器、直接用它的代码）：重新开始之后到达的回答返回
`dropped`，不运行 `then` / `catch`、不撤销；给了 `key`（`callKey(屏幕, 部件, 接口)`）时同一类更新的调用之后到达的旧回答也一样；
`then` / `catch` 多收到一个 `{ here }`，应用每次移动调用 `runtime.moved()`，`here` 为假时只做数据效果、不跳转。`useForm`
的 `then` / `catch` 同样不在重新开始之后运行。

## 表单

- `submit` 找到表单后先按契约的规则检查字段：有错就在字段上显示，不发请求，也不运行 `catch`。
- 提交中再按一次不算新的提交，也不算失败（什么都不发生）。
- 表单的 `then` / `catch` 读 `form` 就是被提交的表单，提交按钮在表单外也一样；迟到的回答同上一节。

## 会话

- `signOut` 结束会话，`auth.signedIn` 之后读作 false。它自己不跳转，去哪里由这次点击的 `to` 决定。
- **需要登录的屏幕（`auth: "required"`）没有会话时不留在屏幕上**：进入它时先去登录页，登录后再到它；会话在它显示
  时结束（退出登录、401），应用也去登录页。手机端和小程序（屏幕守卫）、预览、产品 Web（宿主的 `signOut`）这样做；原型 Web 没有会话。

## 触发方式

`startOf(action, { pointer })` 给出动作怎样开始：

- 默认是点击。
- `hover`：指针移入时运行；**没有指针的平台（手机、小程序）上改为点击**，否则那个动作永远到不了。
- `delay`：屏幕进入使用后 `ms` 毫秒运行一次（0 到 600000）；每次屏幕重新进入使用（盖在上面的屏幕关掉）重新计时，
  运行的是那时部件上的动作。所有平台都应这样做；手机端和小程序在数据重复里的延迟仍变成点击（打印器的差异报告里有）。

## 事件与槽位族

部件在定义里声明自己的出口（`PartDef.events`、`PartDef.families`，见 [组件规范](组件规范.md)），`Item.actions` 的键说明
动作放在哪里（键的写法在 `lib/actions/model.ts`：`eventKey`、`familyKey`、`eventOfKey`、`familyOfKey`；按部件定义找动作
在 `lib/partContract.ts`：`slotAction`、`eventAction`、`payloadOf`）：

| 键 | 什么时候运行 | 额外读到 |
| --- | --- | --- |
| `tab:2`、`icon`…（一个位置） | 点那个位置 | — |
| `tab:*`（槽位族） | 点这一族里**没有自己动作**的任何一项；有自己动作的那一项只运行自己的 | `slot.key`（`"tab:2"`）、`slot.index`（`2`） |
| `on:submit`…（事件） | 部件发出这个事件 | `event.<字段>`：只有事件声明过的字段，按声明的类型，其余丢掉 |

宿主在这时调用 `run(action, host, { ...tap, slot })` 或 `run(action, host, { ...tap, event: payloadOf(声明, 负载) })`；解释器
把它们放进作用域（`tapScope`），之后的规则和点击完全相同：条件、顺序、调用、迟到的回答都一样。部件自己不决定结果，
事件只把访客做了什么带出来（[边界与契约](边界与契约.md)）。今天五个宿主都这样运行：预览（`components/Preview.tsx` 的 `fire` 交给 `run`）、
手机端和小程序（打印器把 `on:<名字>` 接到组件的回调上，槽位族接到 `slotTaps`，见 `lib/export/partEvents.ts`）、两种 Web 导出
（自带组件经 `onEvent` 发出事件，槽位族的动作印在设计属性里每一项的位置上，同时作为“这一族的函数”交给
`Pressable` 的 `families`，运行时由绑定数据或点击加出来的项也运行它，`lib/printBehaviour.ts`；手机端和小程序的 `slotTaps`
本来就对任何一项作答）。

## 输入动作

世界视口（`world-view`，见 [组件规范](组件规范.md)“世界视口”）的画面是引擎的，M3E 只把访客的输入送过去。送的方式是三个
效果，和别的效果一样由解释器运行，从现有的控件上接：方向轮盘的 `on:move` 事件（每推向一个新方向发一次，松开时发回中间，
负载 `{x, y}`；键盘的方向键在网页上也这样推）、`on:release`，技能按钮、普通按钮的点击，任何部件的事件。

| 效果 | 发给世界的 | 例子 |
| --- | --- | --- |
| `{do: "move", part, action?, vector}` | 一个方向：`vector` 是表达式，在这一步读，读成 `{x, y}` 或文字 `"x,y"`，x、y 在 -1 到 1，长度超过 1 的按比例缩回 1，保留两位小数；固定方向可以直接写 `"1,0"`。`action` 不写是 `move` | 方向轮盘的 `on:move` 上 `{do: "move", part: "arena", vector: "event"}` |
| `{do: "press", part, action}` | 按下一个命名输入（`true`） | 技能按钮的点击上先 `press` 再 `release`（一次点击就是按下又松开） |
| `{do: "release", part, action}` | 松开它（`false`） | |

- **宿主只转交。** 解释器调用 `Host.worldInput(part, action, value, tap)`，宿主把它交给这个世界视口自己的通道
  （`lib/world/channel.ts` 的 `createWorlds`：同步送到，不经网络，也不经应用的状态）；输入的后果（移动多远、打中没有）由引擎决定。
  没有世界视口的宿主可以不实现它，输入就哪儿也不去。
- **顺序照常。** 方向在它那一步读，后面的效果和跳转不等世界；同一次点击里先 `press` 后 `release` 就按这个顺序送到。
- **读不出方向的不发**，`action` 不是“小写字母开头、字母和数字”的不发。编辑操作还检查：`part` 必须是世界视口，`action`
  必须在它的 `inputs` 属性声明的输入里（`"move: vec2, attack: bool"`；`inputs` 为空时不限），类型要对（`move` 发给 `vec2`，`press` /
  `release` 发给 `bool`，没写类型的两样都行），`vector` 要能解析（`lib/core/ops/validate.ts`）。输入动作和世界之间的其余约定（时间戳、
  优先级、浮层打开时松开）见[世界宿主契约](世界宿主契约.md)。
- **世界的事件照常是部件事件。** 世界视口发出 `hit`、`collected`、`ended`，设计在 `on:<名字>` 上接动作（提示、跳到结算页），
  规则和别的事件一样；替身本身不发事件，导出的应用里由插槽里的引擎发出。
- **替身说出它听到的。** 世界视口的替身（画布、预览、两个套件）按到达顺序列出最近的 4 个输入：方向写成 `move 0.5,-1`（同一个
  输入的新方向替换上一行），按下写成 `attack ↓`、松开 `attack ↑`；五个宿主写同样的字，一致性表按它检查（`world-*` 几行）。

## 按事件生成

“每收到一次 `hit` 就在头顶飘一个伤害数字”：一个组标成**模板**（`Group.spawn`，编辑操作 `set_spawn`），事件上的动作用
`{do: "spawn", group}` 每次生成一个**实例**。写法对应“按数据重复”：重复按数据的每一行画一份模板，生成按每次事件画一份，份数
随时间来去。

| 模板的字段 | 意思 |
| --- | --- |
| `life` | 一个实例活多少秒（0.1–60，默认 1），按应用的时钟（领域时钟：后端的，预览里是模拟库的）算，不读设备的时间 |
| `max` | 同时最多活几个（1–50，默认 8），也是对象池的大小 |
| `at` | 表达式，生成时读：实例站在哪个实体上（`event.id`）。现在只记下来，位置仍是模板的位置；锚定到实体是 H3 的事 |
| `motion` | `float`（上浮 32 像素，最后五分之二的时间淡出：伤害数字）、`fade`（原地淡出）、`none`（不动，默认） |

- **实例读它那一步。** 解释器在 `spawn` 这一步读作用域（`event` 最要紧，还有变量、数据、`now`），交给 `Host.spawn(group, scope, tap)`；
  模板文字里的 `{{event.amount}}` 这样的表达式在生成时按它读一次，之后不跟着变。绑定（`bind`）照常按屏幕读，读不到 `event`。
- **寿命按时钟。** 实例在“现在 ≥ 生成时间 + life”时消失；时钟暂停时不老，倍率为 3 时老得快 3 倍。宿主不靠自己的计时器判断：活着的
  实例是时钟的函数（`lib/spawn.ts` 的 `live(group, now)`），画的人每帧读一次。
- **上限和对象池。** 活着的已经有 `max` 个时，新的一个顶替最老的那个，画在它腾出的位置上；没满时占编号最小的空位。宿主事先把
  模板按 `max` 份布局好（池），实例来了只是填字、显示、移动这些现成的节点，**不经过 React 状态**：预览和两种 Web 导出由
  `lib/spawnDom.ts` 每帧直接写页面上的节点（`data-spawn-of`、`data-spawn-slot`），生成不触发 React 提交。
- **画布只画模板**，预览和导出的应用一开始一个也不画。重新开始（换场景、运行时重启）时实例全部清掉。
- 一致性表 `spawn-*` 四行：每个事件一个实例、按时钟到时消失、时钟暂停时不老、到上限顶替最老的。手机端和小程序的套件还没有对象池，
  打印器照设计把模板画一次、`spawn` 什么都不做，并在导出报告里说明（已知分歧）；原型 Web 没有传输层的时钟，暂停那一行是已知分歧。

## 订阅（实时通道的消息）

屏幕可以订阅契约里的实时通道（`Frame.subscriptions`，见[数据绑定](数据绑定.md)“订阅”）。订阅的规则和点击、回答共用一份：

- **何时打开、何时关闭。** 屏幕在显示时打开它的订阅（叠在它上面的浮层不算离开），离开（换屏、返回、关掉）时关闭；地址读到的
  参数变了，就关掉旧的、重新打开新的（重新开始收）。手机端和小程序的页面栈把下面的屏幕留着：它们按“是否在显示”打开订阅
  （RN 套件读应用路由给的 `useOnShow`，小程序读平台的 `useDidShow` / `useDidHide`），所以被盖住的屏幕不收消息。
- **消息先收下，再运行动作。** 收到的消息先放进 `data.<name>`（留最新的 `keep` 条），屏幕按它重画之后，再运行订阅上的动作：
  消息名自己的 `on:<消息名>` 优先，没有就运行 `on:message`。动作是屏幕自己在消息到达时做的一次点击，读 `event`
  （`event.message`、`event.payload`、`event.at`，`at` 和 `now` 一样是 ISO 时间），条件、效果顺序、调用、迟到的回答都照点击的规则。
- **迟到的消息。** 和迟到的回答同一条规则：订阅关掉之后线上还到达的消息什么都不做；宿主重新开始（换场景、换后端）时所有订阅关掉、
  收下的消息丢掉，显示中的屏幕在新会话上重新订阅，旧连接上再到的消息什么都不做。
- **时间。** `now` 读的是传输层的时钟（`Transport.now`：后端的时钟，预览里是模拟库的时钟，可以暂停、调倍率），每一步重新读
  （解释器的 `tapScope` 每一步取宿主的 `ctx().now`），前端从不拿自己的系统时间当领域时间。

`lib/app` 的 `ChannelHub`（`runtime.channels`）和 `useChannel` / `useSubscription` 是所有宿主共用的实现；预览经
`lib/bindings/design.ts` 的 `DesignRuntime.listen` 用它，导出的三端由打印器经共用的 `lib/export/ir/channels.ts` 印成
`useSubscription(定义, 作用域, { "on:<消息>": (event) => 运行动作 })`。一致性表的 `message-*`、`clock-*` 几行检查这些。

## 回答上的条件

`then`、`catch` 是回答的主体（`Answer`）：可以像一次点击那样带 `when` 和 `else`，条件读回答——`then` 里是 `response`、
`status`，`catch` 里是 `error`、`status`，能力的是 `result`、`error`（`error.type`）。回答到达后先选分支，规则和
“选分支”一样：没有 `when` 就运行主体；条件成立运行主体，不成立运行 `else`，没有 `else` 就什么都不做；读不出来的条件
不成立。选定的分支之后照常：效果按顺序、最后跳转，迟到的回答规则（重新开始、让位、访客已离开）和嵌套上限都不变。

```json
{ "do": "call", "operationId": "pay",
  "then": { "to": "done", "when": { "expr": "response.state == 'paid'" },
            "else": { "to": "pending" } },
  "catch": { "to": "none", "when": { "expr": "status == 409" },
             "effects": [{ "do": "snackbar", "message": "已被领取" }],
             "else": { "to": "none", "effects": [{ "do": "snackbar", "message": "失败 {{status}}" }] } } }
```

`trigger` 在回答上没有意义（它在回答到达时开始），编辑操作拒绝它（`lib/core/ops/validate.ts`）；条件和 `else` 照常检查。
读文件时回答上的 `when` 按条件清理、`else` 按主体清理（`lib/project.ts`）。以前（第二批 B1 到第四批）编辑操作拒绝回答上的
条件，因为没有宿主读它；第四批解释器先支持（`lib/actions/run.ts`），再放开那条拒绝；手机端和小程序的打印器把回答上的条件原样印进动作数据，
五个宿主都照做（一致性表的 `call-then-branch`、`call-catch-branch`、`invoke-then-branch`）。

## 宿主接口

`Host`（`lib/actions/host.ts`）是解释器向应用要的东西，每个宿主各写一次：

| 方法 | 做什么 |
| --- | --- |
| `scope(tap)` | 这一步表达式读到的作用域：点击那一屏的数据、参数、变量（按名字和 id）、行、表单、会话、时间（点击所在的集合行由解释器自己加上：`row`） |
| `ctx()` | 求值的语言、时间、货币 |
| `variable(id)` / `setVar(id, v)` | 读、写变量（写入的值已按类型转换） |
| `filled(part)` | 输入框里有没有东西 |
| `shown(part)` / `setShown(part, on)` / `setOpen(part, on)` / `setProp(part, prop, v)` | 部件的状态 |
| `toast(text)` | 提示条 |
| `go(to, o)` / `back(o)` / `openLink(url)` / `scrollTo(part)` | 去哪里（`go` 的 `o.motion` 是屏幕进来的动画，没有时是默认的滑入；`back` 的 `o.motion` 是返回动作自己的动画，见下） |
| `call(op, args, tap)` | 发出调用，从不抛出；结果标明成功、失败、`unauthorized`、`dropped` |
| `optimistic(source, change, tap)` | 先改数据源，返回撤销 |
| `refresh(source, tap)` / `loadMore(source, tap)` | 数据源 |
| `form(id, tap)` / `submit(form, tap)` | 表单：找到它；检查并发送（没发出时返回 null） |
| `signOut()` / `afterSignIn(op)` | 会话；登录后回到原处 |
| `moves()` | 访客移动的次数 |
| `worldInput(part, action, value, tap)` | 输入动作：把方向（`{x, y}`）或按下 / 松开（`true` / `false`）交给世界视口的通道（可选，没有世界视口的宿主不写） |
| `spawn(group, scope, tap)` | 按事件生成：用模板 `group` 生成一个实例，`scope` 是这一步读到的（可选，没有模板的宿主不写） |

返回的动画：返回动作有自己的 `motion` 时，解释器把它交给 `back({ motion })`，宿主按它倒放，代替这一屏来时的动画；没有时
照来时的动画倒放（旧文档返回动作的 `transition` 从来没有宿主读，版本 4 把它去掉了）。叠在上面的屏幕照常先关掉。预览和两种 Web
导出照这样播放；手机端和小程序把它交给导航（套件的 `Nav.back(o)`、`goBack(spec, o)`），平台的页面栈按自己的动画返回（打开屏幕时也一样，
见[手机端](手机端.md)、[小程序](小程序.md)的已知限制）。一致性表的 `back-own-motion` 检查宿主做出或交给导航的这一步。

`run(action, host, tap)` 返回的 Promise 在这次点击引起的所有调用（以及回答又引起的调用）都结束后完成，测试可以等它。
能力调用（`invoke`，第三批）加进来时也走这里：一个效果、一个宿主方法、同样的回答规则。

## 第二批顺带发现

- 手机端：没有接口的设计不打印屏幕参数和跳转参数（打印器只在 `doc.api` 存在时打印绑定）。第四批已修：导出的应用总带运行时打印。
- 手机端：表单的 `then` / `catch` 读屏幕的作用域，里面没有 `form`，`form.values.*` 读不到（本批已修：导出的 `bind.ts` 里 `useFormFor` 把被提交的表单放进它们的作用域）。
- 手机端和小程序：“打开”只让菜单部件出现，不打开它的弹出层；“关闭”连触发按钮一起隐藏。第四批已修。
- 产品 Web 和小程序：不只是调用参数，“设为变量”的表达式和跳转参数也读屏幕渲染时的作用域。第四批已修（解释器每一步重新取作用域）。
- 小程序：一个叫 `pick`（或 `omit`、`seg`、`headers`）的接口会让 `calls.ts` 多印一个用不到的同名辅助函数（按子串判断）。第四批已修：按打印时用到的辅助函数输出。
- `lib/app` 的 `useForm`：表单的 `then` / `catch` 不检查运行时是否已重新开始（`Runtime.call` 本身检查）。第四批已修。
