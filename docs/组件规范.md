# 组件规范

所有组件都按这份规范写。下面标了“自动”的约定由 `parts/contract.test.ts` 检查，违反就测试失败。现有组件见[组件清单](组件清单.md)，每个来源的组件由谁承担见[组件盘点](组件盘点.md)。

## 一句话规则

**一个组件只写一份定义。** 面板、属性面板、画布、预览、提示词和导出代码都读这一份。

## 文件放在哪

```text
parts/
  registry.ts      所有组件的注册表，两层和 19 个分类
  defs/*.ts        组件定义：纯数据，不引用 React
  defs/atoms.ts    盒子、矢量图形、单选按钮、状态圆点这几个原子
  defs/splits.ts   组合组件拆成原子时的原子树
  atoms.ts         拼原子树用的小函数（box、hbox、vbox、text、icon……）
  svg.ts           矢量图形的图形库和粘贴代码的清理
  kits/*.ts        组合件：只以原子树存在的组合组件，每个领域一个文件
  kits/shared.ts   组合件共用的：kit()/variant() 简写、看风格的判断、分组列表、分隔线、常用词
  widgets/*.tsx    M3E 没有现成组件时，自己写的组件
  widgets/sources.ts  每个自带组件在哪个文件
  catalog.ts       给 AI 看的组件清单
lib/kits.ts        组合件和拆分落到文档里：展开、排布、落点、按风格选变体
components/m3e/    shadcn M3E 组件库
```

## 两层：原子组件和组合组件

**原子组件**不能再拆：盒子、文字、图标、矢量图形、图片、按钮、输入框、开关、头像、徽章……**组合组件**由原子组成：搜索栏、列表行、卡片、应用栏……想要的组件面板上没有时，用原子在嵌套的盒子里拼出来，就像在 Figma 里嵌套自动布局框架。

每个分类属于一层，由 `parts/registry.ts` 导出：

| 导出 | 说明 |
| --- | --- |
| `CATEGORIES` | 19 个分类，按面板顺序，原子在前 |
| `CATEGORY_TIER` | 每个分类属于 `"atom"` 还是 `"composite"` |
| `tierOf(def)` | 一个组件（或组合件）属于哪一层 |
| `categoriesOf(tier)` | 一层里的分类 |
| `CATEGORY_TEXT`、`CATEGORY_ICON`、`TIER_TEXT` | 分类和层在四种语言里的名字、图标 |

| 层 | 分类 |
| --- | --- |
| 原子 | 基础（Basics）、控件（Controls）、指示（Indicators） |
| 组合 | 操作、表单、选择器、栏与导航（Navigation）、菜单与搜索、弹出层、反馈、布局容器、列表、数据与图表、电商与支付、社交与聊天、AI 对话、媒体、游戏、桌面软件 |

其他代码只通过 registry 读分类，不自己写分类名。

### 原子的约定

- **盒子 `box`**：通用框架。能放组件（`holds`），自动布局默认打开（竖排），宽高默认随内容，没有标题和虚线框。它只画 `surface` 表面角色：`none`（默认，看不见）、`card`、`panel`、`field`（输入框的外框）、`bar`、`chip`、`button`、`sheet`、`overlay`、`well`。从面板手动加的盒子先是 `panel`，好看见、好往里放（`PartDef.seed`：手动加入时的初始属性，手动加的文字同样先随文字宽度）；模板、组合件和 AI 写的盒子没写表面就是 `none`。根节点带 `data-slot="box"` 和 `data-surface`，风格按表面角色打扮盒子，所以用盒子拼出来的组合组件跟着风格走。填充色、圆角和外观涂在根节点上。
- **矢量图形 `svg`**：图形库（丝带横幅、爆炸星、波浪、六边形、盾牌、气泡尾巴、角花、闪光、超椭圆……）、一条路径（`path` + `viewBox`），或粘贴 SVG 代码。粘贴的代码由 `parts/svg.ts` 自己解析，只留下画图的元素和属性：脚本、样式、事件、`foreignObject`、图片、外部链接和 `javascript:`、`data:` 都去掉，`href` 只能指向图里自己的部分。颜色默认跟随文字色（`currentColor`），代码里自己写了颜色的照用。
- **文字 `text`**：`fit: "auto"` 随文字宽度（放在横排里用），`fit: "fixed"`（默认）在宽度内换行，竖排拉伸时宽度由盒子给；`maxLines` 超出显示省略号。
- **输入框 `input`、多行输入 `textarea`**：`variant: "plain"` 没有边框、底色和内边距，外面的盒子就是输入框。它的 `data-slot` 是 `plain-input` / `plain-textarea`，风格对输入框的打扮落在外面的 `field` 盒子上，不落在它上面。多行输入的 `autoGrow` 随内容增高。
- **按钮**：`trailingIcon` 是文字后面的图标（模型选择的下拉箭头）；`button` 和 `icon-button` 有不带底色的 `ghost` 变体；`icon-button` 的 `iconFill` 用实心图标。
- 原子要能被组合：放进横排时不能强占固定宽度。没有宽度属性可读的原子写 `guess`，在画布量出真实尺寸前给排布一个估计。

## 加一个组合件

组合件是只以原子树存在的组合组件，放在 `parts/kits/` 里，每个领域一个文件，登记到 `parts/kits/index.ts` 的 `KITS`。

```ts
const box: KitDef = {
  slug: "prompt-box",           // 不能和任何组件重名
  name: "Prompt box",
  labels: { zh: "输入框", ja: "入力ボックス", ko: "입력창" },
  category: "AI",               // 一个组合层的分类
  icon: "chat",
  about: "a card holding a plain textarea over a row of buttons",  // 给 AI 看的一句话
  variants: [
    {
      key: "home",
      name: "Home",
      labels: { zh: "首页", ja: "ホーム", ko: "홈" },
      suits: (look) => look.group !== "desktop",   // 可选：哪些风格默认用它
      build: (look) => vbox({ surface: "card", width: 380, hugWidth: false, padX: 16, padY: 16, gap: 16 }, [
        area(say("Ask anything", "有问题，尽管问", "何でも聞いてください", "무엇이든 물어보세요")),
        hbox({ justify: "between" }, [iconButton("add", say("Add", "添加", "追加", "추가")), iconButton("arrow_upward", say("Send", "发送", "送信", "보내기"), { variant: "filled" })]),
      ]),
    },
  ],
};
```

- 只用原子组件，只有盒子能放东西（测试检查）。用 `parts/atoms.ts` 里的 `box`、`hbox`、`vbox`、`text`、`para`、`icon`、`iconButton`、`button`、`entry`、`area`……新文件里用 `parts/kits/shared.ts` 的 `kit(slug, name, [zh, ja, ko], 分类, 图标, about, 变体)` 和 `variant(key, name, [zh, ja, ko], build, { suits, span })` 简写，最外层盒子自动以组合件的名字命名。
- 每个组合件至少有一个变体适合 Material（没有 `suits`，或 `suits(MATERIAL_LOOK)` 为真），变体按顺序挑第一个适合的，所以默认的放在最前、不写 `suits`（测试检查）。
- 文字用 `say(en, zh, ja, ko)` 写四种语言，加入时按编辑器语言写入。
- 变体是同一个东西的不同组合方式。要跟风格走的写 `suits(look)`：`KitLook` 由 `lib/kits.ts` 的 `kitLookOf(theme)` 从主题算出，组合件代码里不写任何风格名。它有：风格的分组（`group`）；各类控件的配方（`field`、`bar`、`button`、`list`、`surface`、`toggle`、`nav`、`tabs`、`segmented`、`dialog`、`sheet`、`appbar`、`row`、`card`、`avatar`、`dialogue`）；窗口按钮在哪（`caption`：Mac 字体或手机产品的风格是左侧红绿灯 `lights`，Windows 字体、桌面软件、游戏和 Material 是右侧按钮 `buttons`）；是否紧凑、深浅色、边距。`shared.ts` 里有常用的判断：`isGame`、`isDesk`、`isDense`、`isIosLike`（居中提醒、分组列表、iOS 分段）、`isWeui`、`groupingOf`（分组列表是圆角卡片 `inset`、通栏 `flush` 还是不分组 `bare`）。`build(look)` 也能读它（比如分组列表的行按风格放进卡片）。跟屏幕一样宽的（顶栏、底栏）写 `span: "screen"`。
- 颜色要能跟着深浅色变：盒子用表面角色和填充角色（`surface`、`inverseSurface`……），不要按放下时的深浅色写死“反色盒子”——文档之后切换深浅色时它会变成白盒子。Codex 风格输入框就是跟着页面的面板，只有主按钮用反色。
- 一组相邻的行用 `section(rows, look, textAt)`：分组的风格里是一个 `card` 表面的盒子，行之间的分隔线从文字处（`textAt`）开始（`insetRule`），iOS 是灰底上的圆角卡片，微信是通栏白底；Material 不分组。分隔线是 1px 高的盒子（`rule`），在竖排里会被拉伸，`separator` 原子的长度是固定的。
- 竖排只有在宽度不随内容时才拉伸子项（`lib/flow.ts`）。要拉伸的子项（分隔线、进度条）放在给了宽度的竖排里，或者竖排本身被外层拉伸。
- 节点可以带 `name`、`grow`（占满剩余空间）、`fill`（填充色角色）、`textColor`、`corners`、`look`。严格遵守风格时圆角和外观会被风格去掉，所以组合件不能只靠它们好看，主要靠表面角色和组件自己的变体。产品自己画的形状（冷却弧、星星、爆炸星、丝带、红绿灯）用矢量图形原子；外观（`lib/look.ts` 的预设，如游戏按钮的厚边 `pressedLip`、稀有度的 `goldFrame`、标题的 `gameTitle`）只是锦上添花。表面会被风格当成按钮打扮的（`surface: "button"`），有的风格画成没有底色的文字按钮，上面的字不要只靠 `on-primary`；要一个实心圆时用 `fill: "primary"`。
- 盒子不能叠放：角标、压在封面上的头像只能排在相邻的一行或一列里。
- 画廊 `/gallery?kits=1` 按画布同样的方式（先按估计排、量出真实尺寸后再排，直到不动）画出每个组合件的每个变体，当前风格选中的标 ★；`chosen=1` 只画选中的；`splits=1` 把每个可拆的组件和它拆出的树并排画出来。
- 盒子的宽高会自动和外层对上：被竖排拉伸、或在横排里占满剩余空间的盒子不再随内容（`settleSizes`），不用自己写。

加入文档由 `lib/kits.ts` 完成：`kitGroups(kit, look, lang, { variant, at, screen })` 把树展开成分组（最外层盒子在前，其余用 `inFlow` 指向所在盒子），按估计尺寸排好，在手机上收窄到内容宽度；`landTree` 把它放进松手处的屏幕。编辑器里拖放和点击都是一步撤销，选中最外层盒子。

## 让组合组件可以拆分

在 `parts/defs/splits.ts` 的 `SPLITS` 里按组件 ID 加一个函数，参数是组件当前的属性，返回同样外观的原子树：

```ts
"stat-card": (p) => vbox({ surface: "panel", width: px(p), hugWidth: false, padX: 16, padY: 16, gap: 4 }, [
  text(p.s("title"), "label", { color: "muted" }),
  text(p.s("value"), "headline"),
]),
```

registry 把它挂到组件定义的 `atoms` 上，属性面板就会出现“拆分为原子组件”。拆分（`splitIntoAtoms`）在原位置、原图层顺序换成这棵树：最外层盒子沿用组件的 ID、名字、测量宽度、点击跳转和填充色、文字色、圆角、外观，所在的自动布局也不变（`inFlow` 和它在布局里的要求：`flowSize`、`flowFill`、`alignSelf`、`flowAbsolute`、`flowMin`、`flowMax`、`flowSpan`）。按位置的点击跳转（`actions`）落到现在显示那个位置的原子上：列表的行、标签页、栏上的图标按钮；变量（`bind`）落到显示那个属性的原子上，比如搜索的 `value`、`placeholder` 落到里面的输入框。树的结构说得清的写在 `SPLITS` 旁边的 `SPLIT_TAPS` 里（每个位置对应树里的哪个原子、每个属性对应哪个原子的哪个属性）；没写的，位置找说同样文字或显示同样图标的唯一一个按钮，变量找显示同样文字的唯一一个原子；找不到的不保留。测试检查每棵树只有原子、属性都合法，并且保留组件显示的文字（按下后才出现的文字、只显示第一条的轮播除外），每个位置都有原子接住（拆出的树没显示的除外）。拆出的树要和组件一样大（差几像素以内）、同样的文字、图标和选中状态：应用栏 64 高、在屏幕自己的表面上（滚动后才是栏的表面），卡片的图片贴到边，搜索视图的每行 56 高、有阴影；在画廊 `splits=1` 里并排对照。

原子要给出不随属性变的估计尺寸（`guess`），组合件落下时才排得准：没有文字的开关、复选框、单选按钮，各尺寸的头像，标签和角标都有。

## 加一个组件

1. 在 `parts/defs/` 对应的文件里加一份 `PartDef`。能用 M3E 组件拼出来的，就只写定义。
2. 需要自己管理状态时，在 `parts/widgets/` 写组件，并登记到 `index.ts` 和 `sources.ts`。
3. 运行 `bun run gen:agent`，让 AI 也知道这个组件。
4. 如果它承担了某个来源的组件，更新 `docs/组件盘点.md`。
5. 运行下面的检查。

```ts
{
  slug: "hello",
  name: "Hello",
  labels: { ja: "…", zh: "…", ko: "…" },
  category: "Media",
  icon: "star",
  w: 120,
  h: 40,
  props: [{ key: "text", label: "Text", labels: { ja: "…", zh: "…", ko: "…" }, kind: "text", default: "Hello" }],
  tree: (p) => h("div", { "data-slot": "hello", className: "text-on-surface" }, p.s("text")),
}
```

**加之前先看有没有重复。** 能用现有组件加属性表达的，就加属性，不要新建。能用原子在盒子里拼出来的，写成组合件（见下文），不要再做一个整块的组件；整块的组合组件最好同时写好拆分用的原子树。

## 必须遵守的约定

| 约定 | 说明 | 检查 |
| --- | --- | --- |
| 命名 | ID 是 kebab-case，按用途取名，不带来源前缀 | 自动 |
| 分类 | `category` 是 `CATEGORIES` 之一，每个分类属于一层、原子在前；同一类里没有同名的组件和组合件；组合件只放在组合层；每个分类都有组件 | 自动 |
| 原子 | 原子层里只有盒子能放组件；组合件和拆分出的树只由原子组成，属性都是组件有的、类型和范围合法 | 自动 |
| 定义不含 React | `parts/defs` 只能引用 `../node`、`../labels`、`../types`、`../flow`、`../atoms`、`../svg` | 自动 |
| 矢量图形 | 粘贴的 SVG 只留画图的元素和属性，没有脚本、事件和外链 | 自动 |
| 外观 | 有可见表面的组件要声明 `appearance`，填充色和圆角要真的涂到那个节点上；自带组件的根元素要接受 `className` 和 `style`（`parts/widgets/look.ts`）。没有表面的写进测试里的名单并说明原因 | 自动 |
| 按钮 | 按钮用 M3E 的 `Button`，格子、星星这类点击区域用 `Tap`，不写裸的 `<button>` | 自动 |
| 输入控件 | 不写裸的 `<input>`、`<select>`、`<textarea>`。例外只有颜色选择和文件选择 | 自动 |
| 颜色 | 只用主题色（如 `bg-primary`）。作者自己填的颜色是数据，可以原样使用；图片上的文字遮罩是唯一的例外 | 自动 |
| 组件来源 | 用到的组件都要能解析，`sources.ts` 里的每个组件都要被用到，并且能加载到 | 自动 |
| 不抢名字 | 自带组件不能和 M3E、Recharts 重名 | 自动 |
| 容错 | 任何属性存了错误类型的值，都不能让组件崩溃 | 自动 |
| 多语言 | 组件名和属性名要有日、中、韩翻译（可以来自公共词表） | 自动 |
| 存档 | 默认值存取后不变 | 自动 |
| AI 清单 | `public/agent.md` 里的组件清单和定义一致 | 自动 |
| 盘点 | `docs/组件盘点.md` 里写的组件都存在 | 自动 |
| 数据位置 | 组件数据都放进 `props`，用 `PropDef` 描述；表格数据用 `kind: "table"` | 评审 |
| 运行时图标 | 运行时才确定的图标用 `WidgetIcon`，编辑器只会自动加载组件树里能看到的图标 | 评审 |
| 容器 | 能放其他组件的写 `holds: true`，并提供 `width`、`height`。没开自动布局时，包含关系按位置判断（`lib/tokens.ts` 的 `heldBy`）。要支持自动布局就声明 `flow` 并带上 `FLOW_PROPS`；如果内容区不是根节点，给内容区加 `data-flow` | 评审 |
| 动效 | 在画布上（`[inert]` 内）不运行，并遵守“减少动态效果” | 评审 |
| 地址 | 视频、音频、网页只接受 http(s) 地址，保存的 `javascript:` 不能执行 | 评审 |
| 来源和许可 | 文件头注明思路来源和许可证；没有许可证的项目只参考结构，不复制代码 | 评审 |

## 文档怎样打开

文件和分享链接统一走 `lib/project.ts` 的 `openProject`：拆开 `m3e-project` 信封，按版本运行 `MIGRATIONS`，再校验结构。以后改格式时，在 `MIGRATIONS` 里加一步。

- 其他格式、版本号更高的文件，以及含 `component` 以外 Kind 的文件，一律拒绝，画布不变。
- 组件定义不存在的（比如改过 ID），文件照常打开，这个组件显示 “Unknown part”。这是全新项目，不保留旧 ID 的转换。

```json
{ "format": "m3e-project", "version": 2, "document": {} }
```

## 自动布局

`parts/flow.ts` 是属性定义，`lib/flow.ts` 负责排布。组件的位置仍然存在文档里，所以预览、对齐线和图层不用另外处理；开了布局的容器每次改动后重写这些位置。做法对照 Figma 的自动布局。

- 谁属于哪个容器写在 `Group.inFlow`，所以内容超出容器时也不会掉出来。放在容器里的组件、布局刚打开时已在容器里的组件，都会自动归入。
- 顺序就是文档里的顺序，只有拖放能改变它。
- 还没量过尺寸的组件不参与排布，否则会按猜测的尺寸排错。
- 导出的代码把这些内容嵌套进容器，写成真实的 flex 和 grid，子项的要求写在包住它的一层 `div` 上（`flex-1`、`self-*`、`col-span-*`、`min-w-[…]`、`absolute`）。给编码代理的提示词也逐个写出这些要求和对应的类；绝对定位的子项不列在排布顺序里，而是写在“叠在容器上”一节，带上相对容器左上角的位置。

容器的属性：

| 属性 | 说明 |
| --- | --- |
| `layout` | `free`（关闭）、`row`、`column`、`grid` |
| `gap`、`gapY` | 间距；`gapY` 是换行后行与行、网格行与行之间的距离，不写就等于 `gap` |
| `padX`、`padY` | 左右、上下内边距 |
| `padTop`、`padRight`、`padBottom`、`padLeft` | 单独一边的内边距，写了才生效，没写的边用 `padX`、`padY` |
| `align` | 横穿排布方向的对齐：`start`、`center`、`end`、`stretch`、`baseline`（文字基线，只对横排和网格有意义） |
| `justify` | 沿排布方向的分布：`start`、`center`、`end`、`between`、`around`、`evenly` |
| `wrap`、`columns` | 横排换行；网格列数 |
| `hugWidth`、`hugHeight` | 宽、高随内容 |

子项写在 `Item` 上，旧文档里没有就按原来的规则：

| 字段 | 说明 |
| --- | --- |
| `flowSize` | `{ w, h }`，每个方向 `fixed`（自己的尺寸）、`hug`（随内容，只对开了布局的容器）、`fill`（占满布局给的空间）。不写时，沿排布方向看 `flowFill`，横穿方向看容器的 `align` 是不是 `stretch` |
| `flowFill` | 旧写法：沿排布方向占满剩余空间，等于该方向的 `fill` |
| `alignSelf` | 只对这一个子项改横穿方向的对齐 |
| `flowAbsolute` | 绝对定位：不参与排布，留在放下的位置，跟着容器移动；离开所在的布局后自动取消（拖出容器、直接拖进另一个布局、粘贴到别的屏幕后按位置归入别的布局） |
| `flowMin`、`flowMax` | `{ w, h }`，布局给它定尺寸（填充、随内容）时不小于、不大于这个值 |
| `flowSpan` | 在网格里跨几列 |

- **随内容的容器里填充：** 沿排布方向没有剩余空间可分，按自己的尺寸；横穿方向按其他子项撑出的尺寸拉伸，和 Figma 的“填充容器”一样。全部子项都填充时按各自尺寸。
- **基线：** 画布量出每个组件第一行文字的位置（取字形框高度的五分之四处），没有文字的组件按底边算，和浏览器的规则一致。
- **面板：** 容器有单独的“自动布局”一节：方向、换行、3×3 对齐格、间距方式、间距、内边距（可分边）、宽高随内容。放在布局里的组件有“在自动布局中”一节：宽高各选固定、随内容、填充，自身对齐，绝对定位，最小最大值，网格里的跨列。

### 整理、整理所选和转为自动布局

三个命令共用 `lib/structure.ts` 读出的结构：

1. **XY 切分：** 能用一条水平线把一组部件分开的地方，切成上下几段；每段再用竖线切成左右几列；每块再换方向切，直到只剩一个部件。哪条直线都分不开的（风车形摆放），按“中线落在同一行、左右并排”分行。
2. **网格：** 连续几行、每行同样个数的相似部件（同一个组件，或宽高相差不到两成）合成网格，几列同样个数的相似部件也一样。最后一行可以少几个。
3. **排列：** 一组里的间距取中位数，落到间距阶梯上（风格的 `gap` 和 `tight`，相差 15% 以内取阶梯值，否则取 4dp 网格），所有间距统一。对齐看这组部件本来最接近共用哪条线：竖排比较左边、中线、右边，横排比较上边、中线、下边和文字基线；已经对齐到像素的保持，否则横排默认居中、竖排默认靠左，除非另一条线明显更接近。一行里有一个空档比最窄的空档宽三倍以上（且至少 32），就在那里分成两组，两组各贴一端，像标题和右边的操作按钮。

- **整理**（`lib/tidy.ts` 的 `tidyFrame`）：栏、FAB、弹窗、侧边栏、场景图和锁定的部件照旧按规则摆放；其余部件按上面的结构一段一段排在页边距之间。单个部件保持原来靠哪边；同一列里较窄的部件多数靠哪边（左、中、右），没有正好对齐到页边距或中线的部件就跟着靠哪边，一列不混用对齐。一行有大空档就两端对齐；跨过大半宽度的一行均匀铺满（是否跨过大半宽度按原来的和排紧后的宽度一起判断，整理后再整理结论不变）；排成一行比内容宽度还宽的，拆成上下几段。网格跨过大半宽度就铺满内容宽度，横竖用同一个间距。有意叠在一起的部件当作一个整体：大半（六成以上）压在另一个上面的（容器上的部件、图片上的文字），或小部件压在大部件的角上（图标上的角标）；只是蹭到别的部件边缘的（压在输入框边框上的开关）当作摆歪了，分开排。放不下的段留在原处，不会被推出屏幕。整理会在自己的结果上再读一遍，直到不再移动，所以对整理过的屏幕再整理什么都不动（严格遵守风格时每次改动后都整理，不会出现第二次跳动）。
- **整理所选**（`lib/align.ts` 的 `tidyUpParts`，Ctrl+Alt+T）：把选中的部件按所在的行排成一行、一列或网格，横竖各用一个间距，左上角不动。只有每行个数相同（最后一行可以少）、每列是相似部件时才排成网格；不是网格的，每行各自排匀，行与行上下排开。间距落到间距阶梯上，但不超出所选部件原来的范围（最多多出落到阶梯上的几像素）；互相压住的部件保持原样，不会被排到别的部件上。整理过的再整理什么都不动。只选了一个部件或选中的是屏幕时，Ctrl+Alt+T 整理所在的屏幕。
- **转为自动布局**（`lib/flow.ts` 的 `suggestAutoLayout`，Shift+A）：把读出的结构变成嵌套的容器：段变成竖排，行变成横排（有大空档的行用两端分布，外层其他部件至少一样宽时填满外层的宽度，否则保持自己的宽度），网格变成网格（各列等宽后会比原来宽很多的，改成上下几行），都随内容。只选一个没开布局的容器时，给它自己打开布局，内边距取内容离边缘的距离（上下、左右各自相等时写 `padX`、`padY` 并去掉以前单独设的边，否则四边分别写），以前设的行间距、分布方式和换行也去掉。屏幕面板里的“整屏转为自动布局”对屏幕上除栏、FAB、弹窗、侧边栏和场景图以外的部件做同样的事。新容器现在是不带标签、填充和边框的 `container`，组件和属性写在 `LAYOUT_BOX` 一处。

### 对齐线

拖动和拉尺寸时（`lib/guides.ts`，画在 `components/SmartGuides.tsx`）：

- 边缘和中线吸附到同一屏幕上其他部件的边缘和中线，以及屏幕的边缘、页边距和中线，画出对齐的线。
- 和相邻部件之间的距离等于它们已有的间距，或正好在两个部件中间时吸附过去，用粉色标出每段相等的间距。
- 标出到上下左右最近部件（没有就到屏幕边缘）的距离。
- 选中部件后按住 Alt 指向另一个部件，显示两者之间的距离；指向空白处显示到屏幕边缘的距离。
- 线宽始终是 1 个设备像素，标签不随缩放变大变小。拖动开始时算好所有候选线，移动时只查找，四十个屏幕的文档也不卡。按住 Ctrl（或 Cmd）不吸附；不在线上时仍落在 4dp 网格上。

## 导出项目

`lib/exportProject.ts` 把文档变成能安装运行的项目，打成 zip：每个屏幕一个文件（`lib/codegen.ts`），加上按文档生成的 `src/runtime.tsx`（`lib/runtimeSource.ts`）。组件文件不列清单，从屏幕的 import 一路走下去，走到什么就复制什么，所以组件里新增的 import 不用另外登记；走不到文件就报错，不写出坏项目。放到别处的文件要加进 `lib/exportSources.ts` 的 glob。

点击、变量、条件怎样写成代码在 `lib/printBehaviour.ts`：组件定义不用改，只读 `props` 的 `tree` 会被按不同取值各画一次，不同的地方变成表达式。

## 已知限制

- **没开自动布局的容器：** 内容要完全落在容器里才算在内，压在边上的不跟着移动。分栏（`resizable`）拖动时上面的组件不会跟着变。
- **屏幕本身不是自动布局：** 整屏要流式排布时，用屏幕面板里的“整屏转为自动布局”，或放一个全尺寸容器并打开布局，或者用“整理”。除自动布局的内容外，导出的代码仍按屏幕绝对定位，变体按窗口宽度切换，不是单一页面自适应。
- **预览里的尺寸：** 组件的测量值来自画布，预览里文字变长时，横排布局不会重新排。
- **基线是估算的：** 浏览器不直接给出文字基线，画布取第一行字形框的五分之四处，不同字体可能差一两个像素；可复用组件实例和数据重复的行没有基线，按底边对齐。
- **固定和随内容：** 普通组件的“随内容”只对开了自动布局的容器有效；文字等组件的宽度是一个数值，在布局里选“固定”就是保持这个数值。
- **转为自动布局：** 新容器用的是 `container`，还不是 `box` 原子组件；换成 `box` 时改 `lib/flow.ts` 的 `LAYOUT_BOX` 一处即可。读出的结构只看位置，不看语义，叠放的部件会当成一个整体放进布局里。
- **整理：** 只移动部件，不改尺寸（风格的宽度规则除外）；结构推断只看摆放的位置，摆得太乱时会按行来读。
- **复制的代码：** 只提示要复制哪些自带组件文件。“下载项目”会把屏幕用到的文件都带上。
- **导出项目：** 屏幕上设置的滑动切换不会导出；主题的 `emphasized` 不生效，编辑器里也一样；运行时才知道名字的图标仍然向 Iconify 请求。
- **可复用组件：** 实例的大小就是定义内容的大小，自动布局只放置它，不拉伸也不让它填充剩余空间，也没有尺寸手柄。列表行的文字和容器的属性不能覆盖。导出的代码是展开后的普通组件，不生成可复用的 React 组件。
- **数据重复：** 画布上只有第一行是真实组件，其余行是淡显的副本。
- **模板：** 面板缩略图是示意图，不是真实绘制。模板文字按插入时的语言写入，之后切换语言不跟着变（公共词表里的词除外）。
- **图层：** 只有顶层行可以重命名；文字组件在图层里都显示为“文字”。
- **手机版编辑器：** 没有模板和组件标签，完整功能在桌面宽度上。
- **模态侧边栏：** 布局只占收起时的宽度，展开后盖在内容上。复制出去的代码（不是“下载项目”）要自己用 `onDismiss` 接上关闭。
- **场景图：** 是图片或循环 GIF，不会对操作做出反应；GIF 分辨率较低；热区要在表格里填百分比，不能在画布上拖；画风靠相同的文字描述保持，不能保证同一角色每次长得一样。分享链接带不了本地生成的图片。
- **没有实物的组件：** 动画、相机和地图只是占位外观；语音消息和视频通话没有真实音视频；图片裁剪不生成新图片；抽奖概率均等，结果不保存；图表默认是示例数据。
- **平台外观：** iOS、Miuix 等平台的组件都按 M3E 外观绘制。登录和支付按钮不带品牌标志。
- **性能：** 40 个屏幕的文档拖动一帧约 30ms，能用，但达不到 60 帧。
- **盒子：** 表面角色改成 `none` 的空盒子在画布上看不见，只在选中时有框；可以在图层里找到。图层不按盒子嵌套显示。
- **组合件：** 落下时只按估计尺寸排一次，画布量出真实尺寸后再排，第一帧可能略有跳动。拖着走时不吸附对齐线。拆分时，拆出的树没有显示的位置，它的点击跳转不保留：通知栏的多条公告、剧情对话框的多句台词只拆出第一条，后面的公告和还没轮到显示的选项没有原子接住。变量绑定在没有原子单独显示的属性上（如标签页、导航栏选中第几项）时不保留。滚动时收起（`collapseOnScroll`）只对 FAB 有效，可拆的组件里没有 FAB。拆出的是 Material 的组合方式：风格重新排布组件的地方（如 iOS 应用栏的标题居中）不跟着拆，风格只按表面角色打扮拆出的盒子。叠在图片上的角标和头像在拆出的树里排在相邻的一行，所以略高。
- **图标：** 有些 Material 图标没有描边版（如 `arrow_upward`、`graphic_eq`），不带实心标记时画不出来；组合件里这类图标都用了 `iconFill`。

## 外观和效果

组件的外观写在 `Item` 上，不写进 `props`：`fill`（填充角色）、`textColor`（文字角色）、`corners`（四个圆角）和 `look`（效果）。`parts/appearance.ts` 把它们画到组件声明的 `appearance.target` 节点上，画布、预览、导出代码和提示词读的是同一棵树，所以看到的就是导出的。数据和 CSS 的换算都在 `lib/look.ts`。

| 效果 | 字段 | 怎样画 |
| --- | --- | --- |
| 填充叠层 | `fills`：纯色、线性、径向、角向，每层两个以上色标；`clearFill` 去掉组件自身的填充 | `background-image`，第一层在最上面 |
| 描边 | `stroke`：粗细、颜色、实线/虚线/点线、内侧/居中/外侧、四边分别设置 | 实线用 `box-shadow` 画，不占位置，跟着圆角走；虚线和点线用 `outline` |
| 阴影 | `shadows`：x、y、模糊、扩展、颜色、内阴影；空列表表示无阴影 | `box-shadow`，描边在最上面 |
| 高度 | `elevation`：0 到 4 | 风格的卡片造型决定每一级的样子（`--look-elev-N`），没有规定时用 M3 的高度 |
| 模糊和玻璃 | `blur`、`glass`、`glassSaturate` | `filter: blur()`、`backdrop-filter` |
| 混合、滤镜、变换 | `blend`、`opacity`、`filter`、`rotate`、`transform`、`clip` | `mix-blend-mode`、`filter`、`rotate`/`scale`/`skew`，都不占位置 |
| 文字 | `text`：颜色、字号、字重、字间距、行高、大小写、斜体、装饰线、阴影、描边、渐变 | 写在被绘制的节点和其中每个直接含文字的节点上；渐变文字给每段文字包一层 `span`，只裁切到字形，不碰组件的表面 |
| 纹理 | `texture`：噪点、纸张、圆点、网格、条纹、斜纹、棋盘格、碳纤维、扫描线、交叉线、网点 | 叠在填充上、文字下的 `background-image`；噪点和纸张是内联 SVG，只接受十六进制墨色 |

约定：

- **颜色只有两种写法。** M3 角色的 kebab-case 名称（`primary`、`on-surface`、`surface-container-high`），可带透明度（`primary/40`）；或者十六进制（`#rgb`、`#rgba`、`#rrggbb`、`#rrggbbaa`）。角色跟着风格和深浅色变，十六进制是作者自己的颜色。其他字符串（`red`、`var(...)`、`url(...)`）一律不认。
- **打开即清洗。** 文件、分享链接和 AI 的回答都经过 `cleanLook`：类型不对的字段去掉，数字收进范围，认不出的字符串丢弃，不会因为外观拒绝整个文件。绘制时再校验一次，所以浏览器里自存的副本也不会把任意字符串带进样式。
- **旧字段照旧。** `borderWidth`、`borderColor`、`shadow`、`opacity`、`glass`、`rotate`、`gradientTo`、`gradientAngle`、`font` 的绘制结果和以前完全一样（`lib/look.test.ts` 逐条对照）。同时给了新旧两种时以新的为准：`fills` 代替 `gradientTo`，`shadows` 代替 `shadow`。面板显示旧字段换算成的效果，改动后写成新字段。
- **状态层不受影响。** 外观只写内联样式，不碰 `::before`，按钮的悬停和按下仍由 M3E 的状态层负责。内联的 `box-shadow` 会盖过按钮悬停时的阴影变化。
- **严格遵守风格时**（`lib/styleRules.ts`），`look` 只保留 `opacity`、`rotate`、`transform`、`blur`、`blend` 和 `elevation`，面板也只显示这些。表面、描边、阴影和文字效果由风格决定。
- **预设**（光泽按钮、玻璃、霓虹、立体按钮、游戏标题、金色边框、纸张等）写的是普通字段，套用后仍可逐项修改。套用预设会替换效果，保留不透明度和变换。

已知限制：组件内部自己渲染、不在树里的文字（比如自带组件从属性里取的标签）拿不到渐变文字和字号，只继承颜色、阴影和描边；`elevation` 在导出项目里依赖 `src/style.css` 中的 `--look-elev-N`，复制出去的单个屏幕代码只有 M3 的默认高度；屏幕背景还不能用效果。
