# 手机端

设计导出成手机应用（Expo / React Native）：完整产品（[导出](导出.md)）里的 `apps/mobile` 是一个 Expo Router 应用，每个屏幕一个路由，屏幕用设计自己的组件套件画，绑定的接口、表单、登录和各种状态由和 Web 共用的运行时（`packages/app-runtime`）跑，开发时接口由模拟库回答。这里说组件套件、主题、代码打印器，以及导出的应用怎样组成。

## 组成

| 部分 | 在哪 | 说明 |
| --- | --- | --- |
| 组件套件 | `rn/src/kit/` | 每个组件一个 React Native 组件，属性和编辑器里的组件一样（`parts/defs`），全部可选，没写的取编辑器的默认值。导出时整份复制到应用的 `src/kit/` |
| 主题 | `lib/export/rn/theme.ts` | 把文档的主题（风格、深浅色、配色、字号、圆角、配方、图标家族）解析成套件读的 `KitTheme` |
| 代码打印器 | `lib/export/rn/print.ts`、`app.ts` | 把文档的屏幕写成用套件拼的 TSX，像 `lib/codegen.ts` 给网页写的那样；有运行时（导出的应用）时连同数据绑定一起打印 |
| 手机应用 | `lib/export/targets/mobile.ts`、`lib/export/rn/contract.ts` | 完整产品的 `apps/mobile`：路由、运行时、接口、模拟库、配置 |
| 测试台 | `rn/` | 独立的 Expo 项目（不在编辑器的构建里）：画廊、测试、网页构建和 Android 打包 |
| 生成的数据 | `bun run gen:rn` | 组件默认值、矢量图形、默认主题、画廊的主题/图标/原子树、打印器的样例输出；`bun run check:rn` 只检查 |

版本全部锁定（Expo SDK 58，`rn/package.json`）：`expo 58.0.23`、`react-native 0.88.1`、`react 19.3.0`、`react-native-web 0.21.4`、`nativewind 4.2.7`（Tailwind `3.4.19`）、`react-native-svg 15.16.0`、`expo-image 58.0.18`、`expo-linear-gradient 58.0.3`、`expo-blur 58.0.5`、`react-native-reanimated 4.7.1`、`react-native-worklets 0.13.0`、`react-native-safe-area-context 5.11.1`、`@react-native-community/datetimepicker 9.2.1`、`typescript 6.0.3`、`jest 30.5.2`、`jest-expo 58.0.14`、`@testing-library/react-native 14.1.0`、`eslint 9.39.5`、`eslint-config-expo 58.0.4`。Expo 的版本是 `npm view expo version` 查到的当前稳定版，其余按 Expo 58 的 `bundledNativeModules.json`。导出的应用用 `rnDependencies()` 拿同一份版本。

## 导出的应用里有什么

完整产品的 `apps/mobile`（`mobileTarget`）：

```text
package.json                    @<作用域>/mobile，main 是 expo-router/entry；依赖按 rn/package.json 和 MOBILE_PINS 精确锁定
app.json                        名字、scheme、Android 包名、iOS bundle id、extra.apiBaseUrl；网页用 Metro，单页
babel.config.js、metro.config.js、tailwind.config.js、global.css、nativewind-env.d.ts、tsconfig.json、jest.config.js、jest.setup.tsx
src/app/                        Expo Router 的路由（生成的代码）
  _layout.tsx                   根布局：AppRoot 包住一个 Stack（不画标题栏，设计画自己的栏）
  index.tsx                     打开第一个屏幕（第一个流程的，否则第一个屏幕）
  <屏幕>.tsx                    每个屏幕一个路由；有参数的屏幕参数是路径的一段：product/[productId].tsx
  (tabs)/                       导航栏的目的屏幕（两个以上时）放在 Tabs 里，切换时各自保持状态；Tabs 不画栏，栏是屏幕自己的
  overlay/<屏幕>.tsx            被“打开浮层”打开的屏幕：透明模态，在原屏幕上居中
src/generated/                  生成的代码
  screens/*.tsx                 每个屏幕一个组件（打印器写的）
  theme.ts、icons.ts            主题和离线图标
  root.tsx                      AppRoot：安全区、运行时、应用的记忆（变量、显示隐藏、提示条）、主题、导航、自定义 Providers、开发菜单
  routing.tsx                   屏幕 → 路由（ROUTES、hrefOf）、基于 expo-router 的导航、登录守卫、401 后去登录页并记住回来的地方
  runtime.ts                    packages/app-runtime 的运行时：令牌存在 expo-secure-store（网页上是 sessionStorage），fetch 到 API_BASE_URL
  api.ts                        packages/api 的类型化客户端，和按 operationId 调用的 call()
  contract.ts                   从契约生成的数据：每个接口的方法、路径、参数位置、分页；会话的 AuthConfig；每个表单字段的规则
  bind.ts                       屏幕的绑定：useParams、useScreenScope、useSource（数据源）、useFormFor（表单）
  effects.ts                    表达式的读取器，和点击里属于接口的效果：调用、刷新、下一页、提交、退出登录
  transport.ts、files.ts        上传：expo-image-picker / expo-document-picker 选文件，multipart 表单用 XMLHttpRequest 报告进度
  mocks.ts、DevMenu.tsx         只在开发时：模拟库的传输层和切换场景的开发菜单
  ScreenRoute.tsx               一个屏幕作为路由：读地址里的参数、记下正在显示的屏幕、要登录的屏幕的守卫
  app.test.tsx                  Jest：每个屏幕在模拟库下画得出来、数据源都加载完、表单没填就不发送
  warnings.json                 画得和设计不一样的地方（占位、拆成原子、保持设计值的绑定……），导出报告里也按种类列出
src/kit/**                      组件套件，整份复制（生成的代码，rn/src/kit 的文件，清单在 lib/export/rn/kitFiles.generated.ts）
src/custom/setup.ts             （自定义）应用启动时运行：接 SDK、runtime.setTransport(…)
src/custom/Providers.tsx        （自定义）包住整个应用：第三方 SDK 的 Provider
```

`src/app`、`src/generated` 和 `src/kit` 都是生成的代码：不要改，改设计后重新导出。设计表达不了的地方（第三方 SDK：支付、地图、推送）写在 `src/custom`。根目录的 `AGENTS.md` 有手机应用一节（`Workspace.agents`）。

```bash
npm run start -w apps/mobile          # Expo：Expo Go、模拟器或网页
npm run web -w apps/mobile
npm run typecheck -w apps/mobile      # 也在根目录的 npm run typecheck 里
npm test -w apps/mobile               # Jest，也在根目录的 npm test 里
npm run export:android -w apps/mobile # Metro 打包 Android
```

根目录的 `npm install` 一起安装手机应用（npm workspaces）。Metro 配置让 `react`、`react-native`、`react-dom`、`react-native-web` 无论谁要都解析到应用自己的那一份（共用的运行时和套件里只有一份 React）；Expo 自己找到工作区根目录和它的 `node_modules`。ESLint 用根目录的配置（`apps/mobile/src/kit/` 在编辑器的 `rn/` 里检查过，不再检查），Prettier 只格式化自定义代码。

### 接口和模拟库

- 基础地址：构建时的 `EXPO_PUBLIC_API_BASE_URL`，否则 `app.json` 的 `extra.apiBaseUrl`（默认 `http://localhost:3001`；Android 模拟器里本机是 `10.0.2.2`）。
- 开发时（`__DEV__`）接口由模拟库（`@<作用域>/mocks` 的 `createMockTransport`）回答，和编辑器预览同一个模拟库；`EXPO_PUBLIC_API_MOCKS=off` 改为请求真实后端。屏幕角落有一个小按钮（`mocks · 场景`），点开选择场景（正常、新用户、大量数据、网络错误、慢网、未登录，以及作者自己的），选中后运行时重新开始：数据和会话清空，`auth.signedIn` 按场景定。网页上 `?scenario=new-user` 从某个场景开始，`?devmenu=off` 隐藏按钮（截图用）。要用 MSW 的拦截器，在 `src/custom/setup.ts` 里调用 `@<作用域>/mocks/native` 的 `startNative({ baseUrl })`。
- 生产构建（`expo export`）里没有模拟库：`root.tsx` 只在 `if (__DEV__ && …)` 里 `require("./mocks")`，Metro 在生产构建里把这段和它引用的东西一起去掉。`scripts/check-product.ts` 检查 Android 和网页的生产包里没有模拟库的标记。

## 打印出来的屏幕

一个屏幕打印出来是这样：

```tsx
// Generated by M3E Canvas from the design. Do not edit: change the design and export again.
import { AppBar, At, Box, Button, Cell, Pin, Screen, Text, useNav } from "../../kit";

export function HomeScreen() {
  const nav = useNav();
  return (
    <Screen width={412} height={892}>
      <Pin edge="top">
        <AppBar title="Inbox" />
      </Pin>
      <At x={16} y={96}>
        <Box surface="card" layout="row" gap={12} padX={16} padY={12} align="center" hugWidth={false} width={380}>
          <Cell dir="row" grow>
            <Text text="Messages" styleVariant="title" />
          </Cell>
          <Button label="Open" variant="tonal" onPress={() => nav.go("Detail")} />
        </Box>
      </At>
    </Screen>
  );
}
```

- **组件**：每个组件就是套件里的同名组件（`app-bar` → `AppBar`，见 `rn/src/kit/coverage.ts`），只写和默认值不同的属性。React Native 自己用的名字换掉：`style` 属性写成 `styleVariant`，容器的 `fill` 属性写成 `ground`。
- **外观**：`fill`、`textColor`、`corners`、`look` 和编辑器的 `Item` 一样，`look` 先经过 `cleanLook` 再写进代码。
- **排版**：没开自动布局的部件按设计的位置放（`At`，和网页导出一样是设计稿的坐标）；钉在顶部、底部的栏用 `Pin`（贴边、在安全区内、和屏幕一样宽）；长屏幕的正文在 `ScrollView` 里滚动，栏不动。自动布局的容器（盒子、容器）把里面的部件嵌套进去，用真正的 flex 排；部件对布局的要求（占满剩余空间、横穿方向拉伸、单独对齐、最小最大尺寸、跨列、脱离布局）写在包住它的 `Cell` 上，和网页导出包一层 `div` 一样。网格（React Native 没有 CSS grid）排成一行一行，按列数和跨列分宽度。
- **点击**：只是跳转的点击写成 `nav.go("屏幕")`，浮层 `nav.go("屏幕", { overlay: true })`，返回 `nav.back()`，外链 `nav.open(地址)`（只认 http/https）；组件内某个位置的点击写在 `taps={{ "tab:1": … }}` 里。做得更多的点击（效果、条件、带参数）是设计的动作数据（`const A1: Action = {…}`），由套件的 `useAct` 运行（`rn/src/kit/app.tsx`，和预览的 `lib/interact.ts` 同样的规则）：先看条件（`when`，不成立时走 `else`），按顺序做效果，再去它说的地方。设变量（值或表达式）、切换、加减、设属性、显示、隐藏、切换显示、打开、关闭、提示条（文字里的 `{{表达式}}` 读出来）都做；调用接口、刷新、下一页、提交、退出登录交给应用（`src/generated/effects.ts`）。延迟触发写成 `useAfter(毫秒, …)`，指针移入当作点击。
- **记忆**：`AppProvider` 记着变量（`doc.vars`）、点击显示或隐藏的部件、设过的属性、条件要问的输入框内容和提示条。开始时隐藏、或会被点击显示隐藏的部件包在 `app.shown("组")` 里；`showWhen` 条件包在 `app.holds(…)`（表达式条件是 `$.holds("…")`）里；绑定变量的属性读 `app.bound("变量", 设计值)`，被设属性的读 `app.prop("部件", "属性", 设计值)`；输入框绑定了变量或被条件问到时把输入告诉 `app.input`。驱动深色模式的变量切换主题。
- **文字**：文档里的所有文字只以转义后的字符串出现在属性里，不写 JSX 文本、不写注释；屏幕、组件和变量名只取字母数字，大小写不同的名字也分开（每个都是一个文件名）。`lib/exportInjection.test.ts` 用敌意字符串走一遍网页和手机两种导出。

### 绑定接口的屏幕

文档有接口时（导出的应用），屏幕连同[数据绑定](数据绑定.md)一起打印，和预览同一套规则（`packages/app-runtime` 就是预览的代码）：

```tsx
const S1: SourceDef = { name: "products", operationId: "listProducts", pageSize: 20 };
const A1: Action = { to: "Product", params: { productId: "item.id" } };

export function ProductsScreen() {
  const $0 = useScreenScope({});                    // params、vars、auth、now
  const products = useSource(S1, $0);               // useDataSource：进入屏幕时加载、分页、缓存
  const $ = $0.with({ data: { products } });
  const r1 = regionOf(products, { load: "enter" }); // 区域显示哪个状态
  const act = useAct({ sources: { products } });
  return (
    <Screen width={412} height={892}>
      <At x={16} y={16} bottom={0}>
        <Box …>
          {r1 === "ready" ? (
            <Repeat data={$.list("data.products.items")} keyOf={keyOf} scroll
              onEndReached={() => void products.loadMore()} onRefresh={() => void products.refresh()} …>
              {(item, index) => {
                const $1 = $.with({ item, index });
                return <Box onPress={() => act(A1, { scope: $1.scope, item })}>…<Text text={$1.text("item.name")} /></Box>;
              }}
            </Repeat>
          ) : r1 === "loading" ? (…骨架屏的设计…) : r1 === "empty" ? (…) : r1 === "error" ? (…) : r1 === "forbidden" ? (…) : null}
        </Box>
      </At>
    </Screen>
  );
}
```

- **数据源**（`Frame.data`）：`useSource` 按 `operationId` 调接口（`src/generated/api.ts` 的 `call`：路径参数填进路径，其余按契约放进查询或请求头），参数是表达式；接口的路径参数数据源没给时读屏幕同名的参数。分页按契约（游标或偏移），`useDataSource` 合并各页。
- **表达式**：绑定的属性按属性的种类读：文字 `$.text`、数字 `$.num`（保持在范围里）、开关 `$.bool`、选项 `$.pick`、列表 `rowsOf`；文字里的 `{{…}}` 用 `$.fill`。表达式保持作者写的字，运行时用编辑器的求值器读，从不 `eval`。
- **底部浮动的东西**：加载数据的屏幕上，底部的栏、悬浮按钮和站在屏幕下半部的按钮固定在屏幕底部（按钮和悬浮按钮是 `<Pin edge="floatingBottom" x bottom>`，离底部的距离按设计，再加上系统的安全区），列表滚到最后多出一段空白（`Repeat` 的 `room`，同样加上安全区），最后一行停在它们上方（`lib/foot.ts`，和预览、Web、小程序同一个规则）。
- **重复**：按数据重复的容器第一个子项每个元素画一次（`Repeat`，行读 `item`、`index`，key 是元素的 `id`）。直接放在屏幕上的列表用 `FlatList`，占到屏幕底部的栏为止，自己滚动：`paging: scroll` 滚到底加载下一页（`onEndReached`，底部转圈），`pullToRefresh` 下拉刷新（`RefreshControl`）。嵌在别的布局里的列表直接排出所有行。
- **区域**（`Group.states`）：五个状态的设计都打印出来，按 `regionOf` 选一个显示（和预览的 `regionState` 同一规则）。
- **表单**（`Group.form`）：`useFormFor` 用契约生成的字段规则（`contract.ts` 的 `FORMS`）校验，提交时先校验，有错不发送；服务器的 `errors[].pointer` 落到字段上。输入按组件接上：输入框和多行输入 `value`/`onChangeText`，开关和复选框 `checked`/`onValueChange`，选择器和单选组按选中项的文字，滑块按数字；日期、日期时间字段的输入框点一下打开系统的日期、时间选择器（Android 对话框，iOS 面板，网页上套件自己的月历和时间）；文件上传用 `pickFile`（只收图片时打开相册，否则打开文件），文件按 `TransportFile`（带 `dataUrl`，模拟库也读得懂）放进请求体，`multipart/form-data` 的接口由 `transport.ts` 用 `XMLHttpRequest` 发送并报告进度（`form.progress`）。提交中带 `submit` 的按钮被禁用；输入框和提交按钮带 `testID`（`field:<字段>`、`submit:<表单>`）。
- **调用**：`call` 效果按参数名把 `args` 放进路径、查询或请求体，`optimistic` 先移除或修改被点的那一行，失败时放回；`then`/`catch` 读 `response`、`status` 或 `error`。
- **登录**：会话按契约的 `x-m3e-auth`（登录、刷新、登出接口和令牌字段）由运行时管理，令牌存在 `expo-secure-store`。`auth: required` 的屏幕没有会话时去登录页（路由的守卫），401 刷新不了也去登录页，都记住原来的屏幕和参数；登录表单（或登录接口的调用）成功后回到那里，`then` 的跳转让位，效果照常。
- **屏幕参数**（`Frame.params`）：路由的路径段（`/product/[productId]`），按声明的类型读，没给的用示例值；跳转时 `params` 的表达式在点击时读出。

## 组件覆盖

215 个组件里：**63 个原生**（32 个原子全部、容器和 30 个常用组合组件），**42 个用拆出的原子树画**（`parts/defs/splits.ts`，按文档风格组合），**110 个是占位**（画一个和组件同样大、写着组件名的虚线框，导出时列在 `warnings` 里；能放东西的占位仍然把里面的部件排进去）。74 个组合件在文档里本来就是原子树，全部可以画。

按分类（不带标记的是原生，◇ 是原子树，✕ 是占位，◆ 是组合件，也是原子树）：

| 分类 | 组件 |
| --- | --- |
| 基础 | 盒子（`box`）、矢量图形（`svg`）、标签（`label`）、分隔线（`separator`）、图标（`icon`）、形状（`shape`）、文本（`text`）、图片（`image`）、空白间隔（`spacer`） |

## 主题

`rnThemeOf(doc)` 和画布用同一套规则：颜色先按种子色生成 M3 配色（`lib/m3e/color.ts`），风格有自己的颜色时按 `lib/styles/sheet.ts` 的展开盖上去，浅色和深色各一份，跟着系统切换（`ThemeProvider` 的 `dark` 可以指定）；字号阶梯用风格自己的（`type`、桌面软件的紧凑字号），没写的用 M3；圆角按形状比例；控件圆角（胶囊或某一级）；风格的配方；图标家族；风格自己的颜色（开关开着的颜色、导航选中色、栏的底色、强调文字色）。颜色只会是十六进制，`color-mix` 和 `var(--md-sys-color-…)` 在生成时就算好。

字体：网页上用风格的字体（画廊会从 Google Fonts 取），手机上用系统字体（iOS 是苹方/SF，Android 是 Roboto）；要用自己的字体得把字体文件打包进应用（`expo-font`），套件不带字体文件。

图标：按主题的图标家族从 `components/m3e/icon-sets` 取字形（和网页一样，家族没有的退回 Material Rounded），只带屏幕和套件用到的名字，离线可用；文档自己的图标（`svg:<编号>`）也一起带上。

## 已知限制

- 没开自动布局的屏幕按设计稿的坐标放，和网页导出一样不随屏幕宽度变；栏和自动布局里的内容会跟着屏幕宽度。
- 指针移入当作点击，“滚动到”不打印；变量的模式（集合的多个模式）不跟着切换，绑定变量的设计字段（填充、圆角等）按导出时的值写死。
- 拆成原子树的组合组件，它自己的属性绑定的表达式不生效（按设计的值画），并报告。
- 嵌在别的布局里的数据列表不虚拟化、不能滚到底分页或下拉刷新（用“加载更多”按钮）；列表行里的表单没有表单的行为。
- 导航的过渡动画用 Stack 的默认动画，不按设计的过渡；浮层用透明模态打开，同一个屏幕要么总是浮层要么总是普通路由。
- 不是列表的数据屏幕（比如详情）在手机上不滚动：内容比屏幕长时下面的部分看不到（Web 和小程序会滚动）。
- 实时通道（AsyncAPI）还没有绑定到屏幕。
- 拆成原子树的组合组件，组件内部某个位置的点击（比如通知栏第二条）不保留，整个组件的点击保留。
- 动画只有加载圈和加载指示在转；画布上的动效、Lottie 之类不导出。
- 风格 CSS 里的细节只有 iOS、微信、Spotify 三套写进了 `EXTRAS`，游戏风格的厚边、切角、金边等只用配方近似（面板描边和硬阴影）。
- 字体在手机上是系统字体，要和设计一致需要自己打包字体。
