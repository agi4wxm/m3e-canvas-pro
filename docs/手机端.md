# 手机端

设计导出成手机应用（Expo / React Native）：完整产品（[导出](导出.md)）里的 `apps/mobile` 是一个 Expo Router 应用，每个屏幕一个路由，屏幕用设计自己的组件套件画，绑定的接口、表单、登录和各种状态由和 Web 共用的运行时（`packages/app-runtime`）跑，开发时接口由模拟库回答。这里说组件套件、主题、代码打印器，以及导出的应用怎样组成。

## 组成

| 部分 | 在哪 | 说明 |
| --- | --- | --- |
| 组件套件 | `rn/src/kit/` | 每个组件一个 React Native 组件，属性和编辑器里的组件一样（`parts/defs`），全部可选，没写的取编辑器的默认值。导出时整份复制到应用的 `src/kit/` |
| 主题 | `lib/export/rn/theme.ts` | 把文档的主题（风格、深浅色、配色、字号、圆角、配方、图标家族）解析成套件读的 `KitTheme` |
| 代码打印器 | `lib/export/rn/print.ts`、`app.ts` | 把文档的屏幕写成用套件拼的 TSX，像 `lib/codegen.ts` 给网页写的那样；有运行时（导出的应用）时连同数据绑定一起打印 |
| 手机应用 | `lib/export/targets/mobile.ts`、`lib/export/rn/contract.ts` | 完整产品的 `apps/mobile`：路由、运行时、接口、模拟库、配置 |
| 测试台 | `rn/` | 独立的 Expo 项目（不在编辑器的构建里）：画廊、测试、网页构建和 Android 打包 |
| 生成的数据 | `bun run gen:rn` | 组件默认值、矢量图形、默认主题、画廊的主题/图标/原子树、打印器的样例输出；`bun run check:rn` 只检查 |

版本全部锁定（Expo SDK 58）：`lib/exportPackages.ts` 的 `EXPO_PINS` 是唯一手写版本的地方（`expo`、`react-native`、`react`、`react-native-web`、`nativewind` 和 Tailwind 3、`react-native-svg`、`expo-image`、Reanimated、Worklets、Jest、`jest-expo`、ESLint 9 和 `eslint-config-expo`……，以及导出的应用另外要的 Expo Router、SecureStore、选择器），TypeScript 和产品共用 `PRODUCT_PINS` 的。`bun run gen:versions` 把它们写进 `rn/package.json`，`bun run check:versions` 在 `rn/package.json` 或它的 `package-lock.json` 落后时失败（改了版本后在 `rn/` 里 `npm install`）。Expo 的版本是 `npm view expo version` 查到的当前稳定版，其余按 Expo 58 的 `bundledNativeModules.json`。导出的应用用 `rnDependencies()` 拿同一份版本。

## 导出的应用里有什么

完整产品的 `apps/mobile`（`mobileTarget`）：

```text
package.json                    @<作用域>/mobile，main 是 expo-router/entry；依赖按 rn/package.json 和 MOBILE_PINS 精确锁定
app.json                        名字、scheme、Android 包名、iOS bundle id、extra.apiBaseUrl；网页用 Metro，单页
babel.config.js、metro.config.js、tailwind.config.js、global.css、nativewind-env.d.ts、tsconfig.json、jest.config.js、jest.setup.tsx
src/app/                        Expo Router 的路由（生成的代码）
  _layout.tsx                   根布局：AppRoot 包住一个 Stack（不画标题栏，设计画自己的栏）
  index.tsx                     打开第一个屏幕（第一个流程的，否则第一个屏幕）
  <屏幕>.tsx                    每个屏幕一个路由；有参数的屏幕参数是路径的一段：product/[productId].tsx
  (tabs)/                       导航栏的目的屏幕（两个以上时）放在 Tabs 里，切换时各自保持状态；Tabs 不画栏，栏是屏幕自己的
  overlay/<屏幕>.tsx            被“打开浮层”打开的屏幕：透明模态，在原屏幕上居中
src/generated/                  生成的代码
  screens/*.tsx                 每个屏幕一个组件（打印器写的）
  theme.ts、icons.ts            主题和离线图标
  images.ts                     文档里的图片（属性里的 data URL）：每张写成 assets/images/ 下的文件，这里逐个 require，Metro 才会打包；屏幕读 IMAGES.image1
  root.tsx                      AppRoot：安全区、运行时、应用的记忆（变量、显示隐藏、提示条）、主题、导航、自定义 Providers、开发菜单
  routing.tsx                   屏幕 → 路由（ROUTES、hrefOf）、基于 expo-router 的导航、登录守卫、401 后去登录页并记住回来的地方
  runtime.ts                    packages/app-runtime 的运行时：令牌存在 expo-secure-store（网页上是 sessionStorage），fetch 到 API_BASE_URL
  api.ts                        packages/api 的类型化客户端，和按 operationId 调用的 call()
  contract.ts                   从契约生成的数据：每个接口的方法、路径、参数位置、分页；会话的 AuthConfig；每个表单字段的规则
  bind.ts                       屏幕的绑定：useParams、useScreenScope、useSource（数据源）、useFormFor（表单）
  effects.ts                    表达式的读取器，和点击里属于接口的效果：调用、刷新、下一页、提交、退出登录
  transport.ts、files.ts        上传：expo-image-picker / expo-document-picker 选文件，multipart 表单用 XMLHttpRequest 报告进度
  mocks.ts、DevMenu.tsx         只在开发时：模拟库的传输层和切换场景的开发菜单
  ScreenRoute.tsx               一个屏幕作为路由：读地址里的参数、记下正在显示的屏幕、要登录的屏幕的守卫
  app.test.tsx                  Jest：每个屏幕在模拟库下画得出来、数据源都加载完、表单没填就不发送
  warnings.json                 画得和设计不一样的地方（占位、拆成原子、保持设计值的绑定……），导出报告里也按种类列出
src/kit/**                      组件套件，整份复制（生成的代码，rn/src/kit 的文件，清单在 lib/export/rn/kitFiles.generated.ts）
src/custom/setup.ts             （自定义）应用启动时运行：接 SDK、runtime.setTransport(…)；路由等它运行完才画（SetupGate，见[导出](导出.md)的“setup”）
src/custom/Providers.tsx        （自定义）包住整个应用：第三方 SDK 的 Provider
src/custom/capabilities.ts      （自定义，用到平台能力时）能力的适配：支付、第三方登录、定位、扫码……
src/custom/slots/<名字>.tsx      （自定义，画了能力视图时）真实的地图（react-native-maps）、相机（expo-camera）、通话画面
```

`src/app`、`src/generated` 和 `src/kit` 都是生成的代码：不要改，改设计后重新导出。设计表达不了的地方写在 `src/custom`：平台能力（支付、第三方登录、定位、推送……）的适配写在 `src/custom/capabilities.ts`，地图、相机、通话画面写在 `src/custom/slots/` 的插槽里，都只写一次、重新导出不覆盖；生成的 `src/generated/capabilities.ts` 是注册表（先用自定义的适配，再用平台默认：打开链接 `Linking`、分享 `Share`、选文件 `expo-document-picker`，否则回答 `not-implemented` 并在开发版提示）。定位、相机、扫码要权限声明，没有默认适配。见[平台能力](平台能力.md)。根目录的 `AGENTS.md` 有手机应用一节（`Workspace.agents`）。

```bash
npm run start -w apps/mobile          # Expo：Expo Go、模拟器或网页
npm run web -w apps/mobile
npm run typecheck -w apps/mobile      # 也在根目录的 npm run typecheck 里
npm test -w apps/mobile               # Jest，也在根目录的 npm test 里
npm run export:android -w apps/mobile # Metro 打包 Android
```

根目录的 `npm install` 一起安装手机应用（npm workspaces）。Metro 配置让 `react`、`react-native`、`react-dom`、`react-native-web` 无论谁要都解析到应用自己的那一份（共用的运行时和套件里只有一份 React）；Expo 自己找到工作区根目录和它的 `node_modules`。ESLint 用根目录的配置（`apps/mobile/src/kit/` 在编辑器的 `rn/` 里检查过，不再检查），Prettier 只格式化自定义代码。

### 接口和模拟库

- 基础地址：构建时的 `EXPO_PUBLIC_API_BASE_URL`，否则 `app.json` 的 `extra.apiBaseUrl`（默认 `http://localhost:3001`；Android 模拟器里本机是 `10.0.2.2`）。
- 开发时（`__DEV__`）接口由模拟库（`@<作用域>/mocks` 的 `createMockTransport`）回答，和编辑器预览同一个模拟库；`EXPO_PUBLIC_API_MOCKS=off` 改为请求真实后端。屏幕角落有一个小按钮（`mocks · 场景`），点开选择场景（正常、新用户、大量数据、网络错误、慢网、未登录，以及作者自己的），选中后运行时重新开始：数据和会话清空，`auth.signedIn` 按场景定。网页上 `?scenario=new-user` 从某个场景开始，`?devmenu=off` 隐藏按钮（截图用）。要用 MSW 的拦截器，在 `src/custom/setup.ts` 里调用 `@<作用域>/mocks/native` 的 `startNative({ baseUrl })`。
- 生产构建（`expo export`）里没有模拟库：`root.tsx` 只在 `if (__DEV__ && …)` 里 `require("./mocks")`，Metro 在生产构建里把这段和它引用的东西一起去掉。`scripts/check-product.ts` 检查 Android 和网页的生产包里没有模拟库的标记。

## 打印出来的屏幕

一个屏幕打印出来是这样：

```tsx
// Generated by M3E Canvas from the design. Do not edit: change the design and export again.
import { AppBar, At, Box, Button, Cell, Pin, Screen, Text, useNav } from "../../kit";

export function HomeScreen() {
  const nav = useNav();
  return (
    <Screen width={412} height={892}>
      <Pin edge="top">
        <AppBar title="Inbox" />
      </Pin>
      <At x={16} y={96}>
        <Box surface="card" layout="row" gap={12} padX={16} padY={12} align="center" hugWidth={false} width={380}>
          <Cell dir="row" grow>
            <Text text="Messages" styleVariant="title" />
          </Cell>
          <Button label="Open" variant="tonal" onPress={() => nav.go("Detail")} />
        </Box>
      </At>
    </Screen>
  );
}
```

- **组件**：每个组件就是套件里的同名组件（`app-bar` → `AppBar`，见 `rn/src/kit/coverage.ts`），只写和默认值不同的属性。React Native 自己用的名字换掉：`style` 属性写成 `styleVariant`，容器的 `fill` 属性写成 `ground`。
- **外观**：`fill`、`textColor`、`corners`、`look` 和编辑器的 `Item` 一样，`look` 先经过 `cleanLook` 再写进代码。
- **排版**：没开自动布局的部件按设计的位置放（`At`，和网页导出一样是设计稿的坐标）；钉在顶部、底部的栏用 `Pin`（贴边、在安全区内、和屏幕一样宽）；长屏幕的正文在 `ScrollView` 里滚动，栏不动。自动布局的容器（盒子、容器）把里面的部件嵌套进去，用真正的 flex 排；部件对布局的要求（占满剩余空间、横穿方向拉伸、单独对齐、最小最大尺寸、跨列、脱离布局）写在包住它的 `Cell` 上，和网页导出包一层 `div` 一样。网格（React Native 没有 CSS grid）排成一行一行，按列数和跨列分宽度。
- **点击**：只是跳转的点击写成 `nav.go("屏幕")`，浮层 `nav.go("屏幕", { overlay: true })`，返回 `nav.back()`；组件内某个位置的点击写在 `taps={{ "tab:1": … }}` 里，槽位族（`tab:*`）用 `slotTaps(…)`：没有自己动作的每一项都运行族的动作，读 `slot`。做得更多的点击（效果、条件、带参数、外链）是设计的动作数据（`const A1: Action = {…}`），由 `useAct` 交给导出应用的解释器：`src/generated/effects.ts` 用套件的记忆、运行时和导航组成宿主，运行每个宿主都跑的 `lib/actions`（[交互规则](交互规则.md)）：先看条件，按顺序做效果（每一步读那时的变量、表单和会话），调用不等回答，跳转参数在所有效果之后读，回答在点击那一屏运行 `then`/`catch`，迟到的回答按规则处理。外链经能力注册表的 `link.open` 打开（没有适配时用 `Linking`）。组件事件（`on:<事件>`）接到组件的回调上（`onSettled`、`onReorder`、`onSubmit`……），负载用 `eventOf` 按声明裁剪，动作读 `event`；能力视图的插槽用 `onEvent` 发出事件。延迟触发写成 `useAfter(毫秒, …)`，指针移入当作点击。没有运行时的套件测试床用套件自己的小运行器（只有本地效果）。
- **打开和关闭**：有自己触发按钮的浮层（下拉菜单、提示、弹出框）关上时只关弹出层，按钮留在屏幕上；菜单的开合由应用的记忆保管（`open`/`onOpenChange`），“打开”的效果打开它的弹出层。
- **记忆**：`AppProvider` 记着变量（`doc.vars`）、点击显示或隐藏的部件、设过的属性、条件要问的输入框内容和提示条。开始时隐藏、或会被点击显示隐藏的部件包在 `app.shown("组")` 里；`showWhen` 条件包在 `app.holds(…)`（表达式条件是 `$.holds("…")`）里；绑定变量的属性读 `app.bound("变量", 设计值)`，被设属性的读 `app.prop("部件", "属性", 设计值)`；输入框绑定了变量或被条件问到时把输入告诉 `app.input`。驱动深色模式的变量切换主题。
- **文字**：文档里的所有文字只以转义后的字符串出现在属性里，不写 JSX 文本、不写注释；屏幕、组件和变量名只取字母数字，大小写不同的名字也分开（每个都是一个文件名）。`lib/exportInjection.test.ts` 用敌意字符串走一遍网页和手机两种导出。

### 绑定接口的屏幕

文档有接口时（导出的应用），屏幕连同[数据绑定](数据绑定.md)一起打印，和预览同一套规则（`packages/app-runtime` 就是预览的代码）：

```tsx
const S1: SourceDef = { name: "products", operationId: "listProducts", pageSize: 20 };
const A1: Action = { to: "Product", params: { productId: "item.id" } };

export function ProductsScreen() {
  const $0 = useScreenScope({});                    // params、vars、auth、now
  const products = useSource(S1, $0);               // useDataSource：进入屏幕时加载、分页、缓存
  const $ = $0.with({ data: { products } });
  const r1 = regionOf(products, { load: "enter" }); // 区域显示哪个状态
  const act = useAct({ sources: { products } });
  return (
    <Screen width={412} height={892}>
      <At x={16} y={16} bottom={0}>
        <Box …>
          {r1 === "ready" ? (
            <Repeat data={$.list("data.products.items")} keyOf={keyOf} scroll
              onEndReached={() => void products.loadMore()} onRefresh={() => void products.refresh()} …>
              {(item, index) => {
                const $1 = $.with({ item, index });
                return <Box onPress={() => act(A1, { scope: $1.scope, item })}>…<Text text={$1.text("item.name")} /></Box>;
              }}
            </Repeat>
          ) : r1 === "loading" ? (…骨架屏的设计…) : r1 === "empty" ? (…) : r1 === "error" ? (…) : r1 === "forbidden" ? (…) : null}
        </Box>
      </At>
    </Screen>
  );
}
```

- **数据源**（`Frame.data`）：`useSource` 按 `operationId` 调接口（`src/generated/api.ts` 的 `call`：路径参数填进路径，其余按契约放进查询或请求头），参数是表达式；接口的路径参数数据源没给时读屏幕同名的参数。分页按契约（游标或偏移），`useDataSource` 合并各页。
- **表达式**：绑定的属性按属性的种类读：文字 `$.text`、数字 `$.num`（保持在范围里）、开关 `$.bool`、选项 `$.pick`、列表 `rowsOf`；文字里的 `{{…}}` 用 `$.fill`。表达式保持作者写的字，运行时用编辑器的求值器读，从不 `eval`。
- **底部浮动的东西**：加载数据的屏幕上，底部的栏、悬浮按钮和站在屏幕下半部的按钮固定在屏幕底部（按钮和悬浮按钮是 `<Pin edge="floatingBottom" x bottom>`，离底部的距离按设计，再加上系统的安全区），列表滚到最后多出一段空白（`Repeat` 的 `room`，同样加上安全区），最后一行停在它们上方（`lib/foot.ts`，和预览、Web、小程序同一个规则）。
- **重复**：按数据重复的容器第一个子项每个元素画一次（`Repeat`，行读 `item`、`index`，key 是元素的 `id`）。直接放在屏幕上的列表用 `FlatList`，占到屏幕底部的栏为止，自己滚动：`paging: scroll` 滚到底加载下一页（`onEndReached`，底部转圈），`pullToRefresh` 下拉刷新（`RefreshControl`）。嵌在别的布局里的列表直接排出所有行。
- **区域**（`Group.states`）：五个状态的设计都打印出来，按 `regionOf` 选一个显示（和预览的 `regionState` 同一规则）。
- **表单**（`Group.form`）：`useFormFor` 用契约生成的字段规则（`contract.ts` 的 `FORMS`）校验，提交时先校验，有错不发送；服务器的 `errors[].pointer` 落到字段上。输入按组件接上：输入框和多行输入 `value`/`onChangeText`，开关和复选框 `checked`/`onValueChange`，选择器和单选组按选中项的文字，滑块和评分按数字（评分 `value`/`onValueChange`，绑定的变量变了星星跟着变）；日期、日期时间字段的输入框点一下打开系统的日期、时间选择器（Android 对话框，iOS 面板，网页上套件自己的月历和时间）；文件上传用 `pickFile`（只收图片时打开相册，否则打开文件），文件按 `TransportFile`（带 `dataUrl`，模拟库也读得懂）放进请求体，`multipart/form-data` 的接口由 `transport.ts` 用 `XMLHttpRequest` 发送并报告进度（`form.progress`）。提交中带 `submit` 的按钮被禁用；输入框和提交按钮带 `testID`（`field:<字段>`、`submit:<表单>`）。
- **调用**：`call` 效果按参数名把 `args` 放进路径、查询或请求体（路径参数和 Web 的类型化客户端一样经 `packages/api` 的 `segment` 写成一个路径段：`/` 等被编码，`.`、`..` 直接拒绝，不会把请求和令牌发到别的地址），`optimistic` 先移除或修改被点的那一行，失败时放回；`then`/`catch` 读 `response`、`status` 或 `error`。
- **登录**：会话按契约的 `x-m3e-auth`（登录、刷新、登出接口和令牌字段）由运行时管理，令牌存在 `expo-secure-store`。`auth: required` 的屏幕没有会话时去登录页（路由的守卫），401 刷新不了也去登录页，都记住原来的屏幕和参数；登录表单（或登录接口的调用）成功后回到那里，`then` 的跳转让位，效果照常。
- **屏幕参数**（`Frame.params`）：路由的路径段（`/product/[productId]`），按声明的类型读，没给的用示例值；跳转时 `params` 的表达式在点击时读出。

## 给导出 v2 的接口

```ts
import { printRnApp, rnDependencies, rnAgentsSection } from "lib/export/rn/app";
import { readKitSources, readRnConfig } from "lib/export/rn/kitSources";

const { files, warnings, theme, screens } = await printRnApp(doc, widths, { kit: await readKitSources() });
// 导出的应用（mobileTarget）用 printRnScreens(doc, widths, { kitImport: "../../kit", runtime: { bind: "../bind" }, images: { from: "../images", name: pictures.name } })
// pictures = new RnPictures("assets/images", "../../assets/images")：文档里的图片写成文件（pictures.files），images.ts 是 pictures.module()
// files: { path: "src/generated/…" | "src/kit/…", text, kind: "generated" | "kit" }[]，路径相对 apps/mobile
// warnings: { kind, screen, screens, part, detail }[]（part 是部件的名字，不是 id；风格带不过去的部分是 kind: "style"，screens 列出涉及的屏幕），导出时写进 src/generated/warnings.json 并列在导出报告里
```

媒体、社交、AI 和反馈里原生画的组件（`composites/media.tsx`、`composites/live.tsx`）和画布的不同：视频、音频、网页和动画画的是画布没有文件时的替身，套件不播放、不加载（没有播放器和网页视图，也不加依赖），音频播放器的进度条停在 `position` 给的位置，语音消息和画布一样只是“假装”播放；相机、地图、视频通话是能力视图的替身，导出的应用把它作为插槽的 `children` 交给 `src/custom/slots/<名字>.tsx`，地图替身不能拖动缩放（不会发出 `regionChange`）；组件事件（`play`、`markerTap`、`crop`、`muted`……）是 `on<事件>` 回调属性，导出的应用把设计接在 `on:<事件>` 上的动作接到这些回调上运行（第四批，见下面“交互”）；二维码的“复制”在手机上没有剪贴板（要加包），由 `onCopy` 交给应用，没人接时不会显示“已复制”；问卷自己说的话（“Question 1 of 2”“Next”“Choose one to continue.”）是英文，套件没有词表；数字滚动的千位分隔总是逗号；表现力轮播和图片裁剪拖动之外有读屏操作（轮播每张的“下一张”“上一张”，裁剪框的放大、缩小和上下左右移动）；跑马灯、闪烁文字和数字滚动在系统要求减少动态效果时不动。

选择框、菜单在应用里点一下才打开（`Modal`），编辑器在画布上是展开画的。

选择器和表单类的原生组件（`rn/src/kit/composites/pickers.tsx`、`entry.tsx`）都是受控输入：给了回调就只显示属性给的值、改动交出去，没给时是从属性开始的草稿，属性变了从新值重来。打印器按输入声明的种类接上表单字段和变量：选择（图标选择、调色板）按选中项的文字（数字变量存第几项），文字（颜色、多选和穿梭框的“1,3”、地区路径、选座、数字键盘、签名路径、富文本的文字）`value`/`onChangeText`，数字（数字选择器、数量加减器）`value`/`onValueChange`，标签输入按标签列表（变量里一行一项）。和画布不同的地方：原生选择器和组合框点一下在屏幕上弹出选项（组合框在弹层里输入筛选）；颜色选择没有取色器和吸管，色值是输入的十六进制；滚轮选择器点一项转到它（读屏可以一步一步调），不能拖动滚轮；富文本的标记作用于整段文字（手机的输入框不能给一部分文字加样式），只是外观，值仍是纯文字；签名用手指在板上画（`react-native-svg` 画路径）；复制行没有直接调用剪贴板，复制交给 `onCopy`（应用的 `clipboard.write` 能力，打印器还没接，按下只运行点击）；数字键盘的 `submit`、标签输入的 `add`/`remove` 事件是 `onSubmit`、`onAdd`、`onRemove` 回调，导出的应用运行接在上面的动作；选座的合计、数字键盘的“已发送”、签名的“已签名”只按属性显示（演示不在产品里）。日历、滚轮、原生选择器、组合框、电话号码、验证码格子、字段和表单没有声明输入，值留在组件里（组件接受 `value` 和回调，以后接）。日期、时间选择器在手机上用系统自己的选择器（`@react-native-community/datetimepicker`：Android 是对话框，iOS 放在弹出的面板里），网页上没有系统选择器，套件自己画一个月历。对话框、底部面板按设计放在屏幕上原样画；要点一下才弹出的，把它放在单独的屏幕上，用“打开浮层”的跳转打开。

游戏类组件、动作和菜单（`rn/src/kit/composites/games.tsx`、`actions.tsx`）守组件的边界：六个抽奖组件按下只发请求（`action` 或 `egg:N` 槽位），按 `result` 和 `pending` 播放并落定，落定时调用 `onSettled`（`{ index, label }`），套件里没有演示，导出的应用不会自己抽中什么；技能按钮按 `endsAt`（加 `clockSkew`）显示冷却，按下只发请求；棋盘只显示给定的 `cells`、`status`、`picked`，不判断轮到谁、谁赢；方向轮盘拖动时交出方向（`onValueChange`，`"x,y"`），松手时 `onRelease`，读屏用上、下、左、右四个动作推一下再松开。分体按钮、上下文菜单（长按打开，读屏用它的长按动作）、级联菜单点开后是 `Modal` 里的列表；级联菜单的子菜单在同一个列表里换掉主菜单（第一行返回），不在旁边展开；悬浮菜单的项目在 `Modal` 里浮在悬浮按钮上方，点别处关闭。登录或支付按钮只交出按下（`onPress`）并说出它要的能力（`onAsk`：`auth.oauth` 或 `payment.pay`），成功与否由服务方和后端给出。命令列表、筛选栏里输入的文字和打开的筛选项是访客的草稿（`onSearch`、`onChangeText`、`onFilter`），关卡选择选中的关卡同样（`onSelect`）。落定（`onSettled`）、松手（`onRelease`）这些组件事件，导出的应用运行接在上面的动作；草稿类的回调（搜索、筛选、选关）不是事件，打印器不接。和画布的差别：转盘、技能按钮的冷却扇形用 `react-native-svg` 画（画布是锥形渐变），蛋用路径画，组件读屏的默认名字是英文（套件没有词表）。
能放部件的布局容器（网格、停靠面板、辅助面板、自定义组件）把放进去的部件按自己的自动布局排在标题下面，标题占画布留出的高度（`flow.inset`）；网格按画布的规则把高度分给每一行。停靠面板打印每个标签页的内容（`DockPane`，`lib/export/panes.ts`），点哪个标签就显示哪一页，和 Web 一样；没开自动布局的停靠面板和层叠照旧：压在上面的部件按坐标画在屏幕上，别的标签页的不打印。选中的标签、目的地、页码、引导页的页、展开收起都从属性来：给了回调（`onSelect`、`onExpandedChange`、`onOpenChange`、`onValueChange`、`onPage`）就是受控的，没给时是从属性开始的草稿，属性变了重新开始；点各处时先改自己，再运行设计接在那里的点击（`taps`）。工具提示、弹出框、悬停卡片、导航菜单占着画布上展开时的大小，触发的按钮或链接站在原处，点一下（工具提示是长按）才在旁边打开，和预览一样；抽屉、侧面板按设计展开着画，开关由屏幕的显示和隐藏决定。和画布的差异：侧面板旁边的“窗口内容”只画空白，画布上的示意文字不画；模态的侧边导航展开时盖在旁边的内容上，没有遮罩；小程序导航栏右边的胶囊只是画出来的；可折叠、滚动区、宽高比在画布上还不能放部件，套件里也只画它们自己的内容。

数据与图表、列表和桌面软件的组件（`composites/data.tsx`、`composites/desk.tsx`）和画布上的不同之处：

- **图表**用 `react-native-svg` 照 Recharts 的画法画（网格、底部的名字、并排或堆叠的柱、线、面积、环形、雷达），手机上没有指针悬停时的数值提示；散点图、热力图、仪表、迷你趋势图、漏斗图、甘特图同样照画，迷你趋势图用手指滑过读数。
- **表格**按列结构画（宽度、对齐、按类型写值，币种、百分比、日期按英文写，和画布一样）；没有列结构时的列宽按各列最长的文字分配，近似浏览器的表格布局。绑定到数据的表格（以及以表格为数据的占比条列表、数据表格、看板、日程、文件列表、漏斗图、甘特图）在导出的应用里仍显示设计的行，导出报告按“绑定”列出。
- **访客的操作只发出去**：数据表格的搜索、排序、翻页、勾选，日程的翻月和选日，看板的打开、移动、添加，可排序列表的移动，左滑行的展开收起，都是草稿（从属性开始，属性变了重新开始）加回调属性（`onSearch`、`onSort`、`onPage`、`onSelect`、`onMonth`、`onDay`、`onOpen`、`onMove`、`onAdd`、`onReorder`，可排序列表的 `onChange` 和标签输入一样交出各行的文字，左滑行的 `onValueChange`）；导出的应用把接在这些事件上的动作接到回调上运行（`on:<事件>`），可排序列表的行和左滑行的开合也写回它绑定的变量或表单字段。卡片在哪一列、有哪些文件由数据决定：看板不自己移动卡片，文件列表的删除按钮（`remove:N`）只发出请求、没接动作时什么也不做；原型里的演示（看板自己挪卡片、文件列表藏起删掉的文件）在应用里不演。
- **选中项**：占比条列表、文件列表、树形列表的选中行跟随属性 `selected`（预览里点一行会移动它），套件在点击时调用 `onSelect`，导出的应用把它写回（没有绑定的 `selected` 由应用的记忆保管），点了就换高亮。
- **手势的替代**：看板没有拖动，打开一张卡片后用它下面的左右箭头移动；可排序列表用手柄拖动（松手时落到所在的位置，拖动中其他行不让位），读屏用“上移”“下移”；左滑行读屏用“激活”展开收起。可排序列表和左滑行的值（行的顺序、是否展开）不会写进绑定的变量或表单（打印器报告 `input`）。
- **日程**的月份和星期名用英文（画布按页面语言）；**菜单栏**点一个菜单后它的项目在屏幕中间的弹层里打开（和下拉菜单一样），不是挂在菜单下面；**窗口**按画布的 36 高标题栏和自动布局摆放里面的部件。

## 主题

`rnThemeOf(doc)` 和画布用同一套规则：颜色先按种子色生成 M3 配色（`lib/m3e/color.ts`），风格有自己的颜色时按 `lib/styles/sheet.ts` 的展开盖上去，浅色和深色各一份，跟着系统切换（`ThemeProvider` 的 `dark` 可以指定）；字号阶梯用风格自己的（`type`、桌面软件的紧凑字号），没写的用 M3；圆角按形状比例；控件圆角（胶囊或某一级）；风格的配方；图标家族；风格自己的颜色（开关开着的颜色、导航选中色、栏的底色、强调文字色）。颜色只会是十六进制，`color-mix` 和 `var(--md-sys-color-…)` 在生成时就算好。

字体：网页上用风格的字体（画廊会从 Google Fonts 取），手机上用系统字体（iOS 是苹方/SF，Android 是 Roboto）；要用自己的字体得把字体文件打包进应用（`expo-font`），套件不带字体文件。

图标：按主题的图标家族从 `components/m3e/icon-sets` 取字形（和网页一样，家族没有的退回 Material Rounded），只带屏幕和套件用到的名字，离线可用；文档自己的图标（`svg:<编号>`）也一起带上。

## 已知限制

- 没开自动布局的屏幕按设计稿的坐标放，和网页导出一样不随屏幕宽度变；栏和自动布局里的内容会跟着屏幕宽度。
- 指针移入当作点击，“滚动到”不打印；数据重复里的延迟触发当作点击；访客用系统返回键离开不算“离开”（只有应用自己的跳转和关闭浮层计数）；分栏的 `resize`、地图替身的 `regionChange`、音频播放器的 `ended` 组件不发出，接在上面的动作不运行（导出报告列出）；变量的模式（集合的多个模式）不跟着切换，绑定变量的设计字段（填充、圆角等）按导出时的值写死。
- 拆成原子树的组合组件，它自己的属性绑定的表达式不生效（按设计的值画），并报告。
- 嵌在别的布局里的数据列表不虚拟化、不能滚到底分页或下拉刷新（用“加载更多”按钮）；列表行里的表单没有表单的行为。
- 导航的过渡动画用 Stack 的默认动画，不按设计的过渡（返回动作自己的 `motion` 交到 `Nav.back` 为止，也不改变返回的动画）；浮层用透明模态打开，同一个屏幕要么总是浮层要么总是普通路由。
- 不是列表的数据屏幕（比如详情）在手机上不滚动：内容比屏幕长时下面的部分看不到（Web 和小程序会滚动）。
- 实时通道（AsyncAPI）还没有绑定到屏幕。
- 拆成原子树的组合组件，组件内部各处的点击落在显示它的原子上（和编辑器里“拆分为原子组件”的规则一样，`lib/kits.ts` 的 `splitTaps`）；拆出的树没有显示的位置（比如通知栏第二条），它的点击不保留并报告（`kind: "slot"`），整个组件的点击保留。
- 动画只有加载圈和加载指示在转；画布上的动效、Lottie 之类不导出。
- 风格 CSS 里的细节只有 iOS、微信、Spotify 三套写进了 `EXTRAS`，游戏风格的厚边、切角、金边等只用配方近似（面板描边和硬阴影）。
- 字体在手机上是系统字体，要和设计一致需要自己打包字体。
