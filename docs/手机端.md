# 手机端

设计导出成手机应用（Expo / React Native）时用的组件套件、主题和代码打印器。导出的整体结构（`apps/mobile` 在 monorepo 里的位置、`package.json`、路由）由导出 v2 负责，这里提供它要放进去的东西：每个屏幕一份 React Native 代码、主题、离线图标，以及这些代码依赖的组件套件。

## 组成

| 部分 | 在哪 | 说明 |
| --- | --- | --- |
| 组件套件 | `rn/src/kit/` | 每个组件一个 React Native 组件，属性和编辑器里的组件一样（`parts/defs`），全部可选，没写的取编辑器的默认值。导出时整份复制到应用的 `src/kit/` |
| 主题 | `lib/export/rn/theme.ts` | 把文档的主题（风格、深浅色、配色、字号、圆角、配方、图标家族）解析成套件读的 `KitTheme` |
| 代码打印器 | `lib/export/rn/print.ts`、`app.ts` | 把文档的屏幕写成用套件拼的 TSX，像 `lib/codegen.ts` 给网页写的那样 |
| 测试台 | `rn/` | 独立的 Expo 项目（不在编辑器的构建里）：画廊、测试、网页构建和 Android 打包 |
| 生成的数据 | `bun run gen:rn` | 组件默认值、矢量图形、默认主题、画廊的主题/图标/原子树、打印器的样例输出；`bun run check:rn` 只检查 |

版本全部锁定（Expo SDK 58，`rn/package.json`）：`expo 58.0.23`、`react-native 0.88.1`、`react 19.3.0`、`react-native-web 0.21.4`、`nativewind 4.2.7`（Tailwind `3.4.19`）、`react-native-svg 15.16.0`、`expo-image 58.0.18`、`expo-linear-gradient 58.0.3`、`expo-blur 58.0.5`、`react-native-reanimated 4.7.1`、`react-native-worklets 0.13.0`、`react-native-safe-area-context 5.11.1`、`@react-native-community/datetimepicker 9.2.1`、`typescript 6.0.3`、`jest 30.5.2`、`jest-expo 58.0.14`、`@testing-library/react-native 14.1.0`、`eslint 9.39.5`、`eslint-config-expo 58.0.4`。Expo 的版本是 `npm view expo version` 查到的当前稳定版，其余按 Expo 58 的 `bundledNativeModules.json`。导出的应用用 `rnDependencies()` 拿同一份版本。

## 导出的应用里有什么

```text
src/generated/theme.ts          主题（生成的代码）
src/generated/icons.ts          屏幕和套件用到的图标字形，离线（生成的代码）
src/generated/screens/*.tsx     每个屏幕一个组件（生成的代码）
src/generated/screens/index.ts  屏幕表、第一个屏幕、流程起点（生成的代码）
src/generated/App.tsx           主题 + 图标 + 一个简单的导航器（生成的代码）
src/kit/**                      组件套件，整份复制（生成的代码）
src/custom/**                   自定义代码（人或 AI 写），导出从不写这里
```

`src/generated` 和 `src/kit` 都是生成的代码：不要改，改设计后重新导出。设计表达不了的地方（第三方 SDK：支付、地图、推送）写在 `src/custom`。导出 v2 写 `AGENTS.md` 时可以用 `rnAgentsSection()` 拿手机端这一节（中英文）。

一个屏幕打印出来是这样：

```tsx
// Generated by M3E Canvas from the design. Do not edit: change the design and export again.
import { AppBar, At, Box, Button, Cell, Pin, Screen, Text, useNav } from "../../kit";

export function HomeScreen() {
  const nav = useNav();
  return (
    <Screen width={412} height={892}>
      <Pin edge="top">
        <AppBar title="Inbox" />
      </Pin>
      <At x={16} y={96}>
        <Box surface="card" layout="row" gap={12} padX={16} padY={12} align="center" hugWidth={false} width={380}>
          <Cell dir="row" grow>
            <Text text="Messages" styleVariant="title" />
          </Cell>
          <Button label="Open" variant="tonal" onPress={() => nav.go("Detail")} />
        </Box>
      </At>
    </Screen>
  );
}
```

- **组件**：每个组件就是套件里的同名组件（`app-bar` → `AppBar`，见 `rn/src/kit/coverage.ts`），只写和默认值不同的属性。React Native 自己用的名字换掉：`style` 属性写成 `styleVariant`，容器的 `fill` 属性写成 `ground`。
- **外观**：`fill`、`textColor`、`corners`、`look` 和编辑器的 `Item` 一样，`look` 先经过 `cleanLook` 再写进代码。
- **排版**：没开自动布局的部件按设计的位置放（`At`，和网页导出一样是设计稿的坐标）；钉在顶部、底部的栏用 `Pin`（贴边、在安全区内、和屏幕一样宽）；长屏幕的正文在 `ScrollView` 里滚动，栏不动。自动布局的容器（盒子、容器）把里面的部件嵌套进去，用真正的 flex 排；部件对布局的要求（占满剩余空间、横穿方向拉伸、单独对齐、最小最大尺寸、跨列、脱离布局）写在包住它的 `Cell` 上，和网页导出包一层 `div` 一样。网格（React Native 没有 CSS grid）排成一行一行，按列数和跨列分宽度。
- **点击**：跳转写成 `nav.go("屏幕")`，浮层 `nav.go("屏幕", { overlay: true })`，返回 `nav.back()`，外链 `nav.open(地址)`（只认 http/https）；组件内某个位置的点击写在 `taps={{ "tab:1": … }}` 里。设变量、显示隐藏、提示条这些效果还没打印，写成 `nav.todo("effects")` 并报告。`useNav` 由 `ScreenStack`（简单的栈式导航）或导出 v2 自己的路由提供。
- **文字**：文档里的所有文字只以转义后的字符串出现在属性里，不写 JSX 文本、不写注释；屏幕和组件名只取字母数字（`lib/exportInjection.test.ts` 用敌意字符串走一遍网页和手机两种导出）。

## 给导出 v2 的接口

```ts
import { printRnApp, rnDependencies, rnAgentsSection } from "lib/export/rn/app";
import { readKitSources, readRnConfig } from "lib/export/rn/kitSources";

const { files, warnings, theme, screens } = await printRnApp(doc, widths, { kit: await readKitSources(), image: (data) => "assets/…" });
// files: { path: "src/generated/…" | "src/kit/…", text, kind: "generated" | "kit" }[]，路径相对 apps/mobile
// warnings: { kind, screen, part, detail }[]，导出时列给作者看
const { dependencies, devDependencies } = rnDependencies(); // 精确版本
const config = await readRnConfig(); // babel.config.js、metro.config.js、tailwind.config.js、global.css、tsconfig.json……
```

也可以只用 `printRnScreens(doc, widths, { kitImport })`（每个屏幕的源码）、`screensIndex(printed)`、`rnThemeOf(doc)`、`rnIconData(families, names)`。

## 主题

`rnThemeOf(doc)` 和画布用同一套规则：颜色先按种子色生成 M3 配色（`lib/m3e/color.ts`），风格有自己的颜色时按 `lib/styles/sheet.ts` 的展开盖上去，浅色和深色各一份，跟着系统切换（`ThemeProvider` 的 `dark` 可以指定）；字号阶梯用风格自己的（`type`、桌面软件的紧凑字号），没写的用 M3；圆角按形状比例；控件圆角（胶囊或某一级）；风格的配方；图标家族；风格自己的颜色（开关开着的颜色、导航选中色、栏的底色、强调文字色）。颜色只会是十六进制，`color-mix` 和 `var(--md-sys-color-…)` 在生成时就算好。

字体：网页上用风格的字体（画廊会从 Google Fonts 取），手机上用系统字体（iOS 是苹方/SF，Android 是 Roboto）；要用自己的字体得把字体文件打包进应用（`expo-font`），套件不带字体文件。

图标：按主题的图标家族从 `components/m3e/icon-sets` 取字形（和网页一样，家族没有的退回 Material Rounded），只带屏幕和套件用到的名字，离线可用；文档自己的图标（`svg:<编号>`）也一起带上。

## 检查

在 `rn/` 里：

```bash
npm ci
npm run typecheck   # tsc
npm run lint        # ESLint（eslint-config-expo），不许有警告
npm test            # jest-expo + React Native Testing Library：每个原子和组合组件、覆盖表、原子树、打印出来的屏幕、画廊
npm run export:web      # 画廊的网页构建（expo export --platform web）
npm run export:android  # Metro 打包 Android（expo export --platform android），不需要真机
```

`rn/src/printed/` 是打印器给两份样例文档写的应用（导出项目的验证文档用 Material，一屏组合件用 iOS），由 `bun run gen:rn` 写出，和真正导出的一样经过类型检查、lint、渲染测试和 Metro 打包。网页构建里 `?app=proof`、`?app=kits` 打开它们，`?style=ios&dark=1&part=button,switch` 打开画廊。

和编辑器的画廊并排对照：先在仓库根目录 `bun run dev`，再在 `rn/` 里 `npm run export:web` 后运行

```bash
node scripts/shots.cjs --web http://localhost:3000 --out shots
```

它对 Material、iOS、微信、Spotify（深色）四套风格，把编辑器 `/gallery` 和套件画廊里同一个组件的格子并排拼成 `shots/compare-<风格>.png`。CI 的 `rn` 任务安装 `rn/`，跑类型检查、lint、测试和两种导出。

## 已知限制

- 没开自动布局的屏幕按设计稿的坐标放，和网页导出一样不随屏幕宽度变；栏和自动布局里的内容会跟着屏幕宽度。
- 交互里只有跳转、浮层、返回、外链打印成代码；变量、显示隐藏、提示条、条件、指针移入和延迟触发、滚动到都还没有，打印成 `nav.todo` 或照常显示，并在 `warnings` 里列出。
- 绑定变量的设计字段按导出时的值写死，不跟着模式切换。
- 拆成原子树的组合组件，组件内部某个位置的点击（比如通知栏第二条）不保留，整个组件的点击保留。
- 动画只有加载圈和加载指示在转；画布上的动效、Lottie 之类不导出。
- 风格 CSS 里的细节只有 iOS、微信、Spotify 三套写进了 `EXTRAS`，游戏风格的厚边、切角、金边等只用配方近似（面板描边和硬阴影）。
- 字体在手机上是系统字体，要和设计一致需要自己打包字体。
