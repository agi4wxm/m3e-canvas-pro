# 数据绑定

屏幕连上[接口](接口.md)：一个屏幕声明它加载哪些数据、打开时收到哪些参数、要不要登录；组件的属性绑定到表达式；列表按返回的数据重复；容器做成某个接口请求体的表单，按 Schema 校验；点击调用接口，成功和失败各有去处；每个绑定了数据的区域都有加载中、空、出错、无权限四个状态的设计。这些全部写在文档里——作者不写代码，应用内的 AI 和 MCP 通过同一组操作做到同样的事；预览按真实的调用过程运行，完整产品的导出把同一份模型写成 Web、React Native 和小程序三个前端的代码。

代码在 `lib/bindings/`（纯 TypeScript，不依赖 DOM、Node 和 `fetch`），操作在 `lib/core/ops/bindings.ts`，读取工具在 `lib/tools/bindingsRead.ts`，编辑器在 `components/BindingsPanel.tsx`、`components/ExprField.tsx`，预览在 `components/Preview.tsx`，界面文字在 `lib/i18n/bindings.ts`。

```text
lib/bindings/
  expr.ts       表达式：读成语法树（从不 eval）、求值、{{模板}}、辅助函数，处处有上限
  format.ts     按语言写日期（绝对、相对）、数字、金额、百分比、文件大小（Intl）
  messages.ts   应用自己说的话（校验提示、默认状态设计的文字），中英日韩
  contract.ts   从契约读：成功响应和其中的列表、请求体的字段和规则、令牌放哪
  rules.ts      字段的校验、按类型转换、Problem、errors[].pointer 对应的字段、给人看的失败说明
  sources.ts    数据源的状态和分页、data.<名字> 读到的样子、乐观修改、区域显示哪个状态、屏幕参数
  form.ts       表单的请求体、校验结果、form. 读到的样子
  design.ts     把文档读到 lib/app 的运行时上：数据源的键和规格、表单的规则和值、会话需要的契约（AuthConfig）、调用的请求
  view.ts       一个屏幕此刻的样子：按数据展开重复、区域显示的状态、表单的值和错误
  scope.ts      表达式在某个组件上读到的作用域
  complete.ts   表达式能读什么（作用域的形状）和输入时的补全
  check.ts      操作写表达式前的检查：能不能解析、读的数据源和参数在不在
  clean.ts      读入文件时的清理
  transport.ts  页面自带的 Transport、没有模拟库时的替身，以及模拟库的会话是否一开始就登录
  fixture.ts    测试用的商店：接口、四个屏幕、全部绑定好，以及假后端
```

`expr.ts`、`format.ts`、`messages.ts`、`rules.ts`、`sources.ts`、`form.ts` 只依赖彼此和契约的类型，导出时原样复制进 `packages/app-runtime`（[导出](导出.md)的“前端共用的运行时”），所以导出的应用和预览按同一份代码求值、校验、分页、选状态。

预览和导出只有一个数据引擎：`lib/app` 的 Runtime（数据源缓存 `SourceCache`、表单控制器 `FormController`、会话 `SessionStore`
和带令牌的 Transport）。导出的屏幕由打印器把数据源、表单和契约写成代码交给它；预览（`components/preview/host.ts`）和无头截图
（`headless.ts`）由 `design.ts` 的 `DesignRuntime` 直接从文档读出同样的东西交给它。所以同一份契约、同一个模拟库下，预览和导出的应用
走过的状态一样（`design.test.ts` 的“the preview and an exported app, on one engine”并排比较）。预览自己的东西都在引擎外面：模拟库的
回答、场景和请求记录（交给 Runtime 的 Transport）、能力的模拟结果、演示、上传进度的估算（`tick`）。

## 模型

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Frame.data` | `DataSource[]` | 屏幕加载的数据，见下 |
| `Frame.params` | `{ name, type?, example? }[]` | 屏幕打开时收到的参数，读作 `params.<name>`；`example` 是画布和直接打开它的预览用的值 |
| `Frame.auth` | `"required" \| "login"` | `required`：要先登录；`login`：登录页（只有一个），401 和要登录的屏幕都去这里 |
| `Item.bind` | `{ 属性: "=表达式" }` | 原来的值是变量 id，以 `=` 开头的是表达式（`"=item.title"`）。两种可以混用 |
| `Item.field` | `string` | 表单里的输入框对应请求体的哪个字段，嵌套的用点：`address.city` |
| `Group.repeat` | `{ data, limit?, sample? }` | 除了集合（`{collection}`），还可以按表达式读到的列表重复第一个子项：`data.products.items`；每份副本读 `item` 和 `index`；`sample` 是画布上画几份（默认 3） |
| `Group.form` | `{ operationId, params?, values?, then?, catch? }` | 容器是这个接口请求体的表单；`values` 是没有输入框的字段（表达式） |
| `Group.states` | `{ source?, emptyWhen?, show? }` | 区域：显示 `source` 这个数据源的状态；`show` 是画布上显示哪个状态 |
| `ActionBody.params` | `{ 参数名: 表达式 }` | 打开的屏幕收到的参数：`{ productId: "item.id" }`；那个屏幕还没声明的参数在设置点击时（`set_action`、`add_tree`）自动声明，所以先做列表还是先做详情都行 |
| `Condition` | `{ expr }` | 条件可以是表达式（`showWhen`、`when`）；原来的 `{var, op, value}`、`{filled}` 照旧 |
| `Effect` | 见下 | 新增 `call`、`refresh`、`loadMore`、`submit`、`signOut`；`setVar` 可以带 `expr`；`snackbar` 的文字可以有 `{{表达式}}` |

**数据源**（`DataSource`）：

| 字段 | 说明 |
| --- | --- |
| `name` | 标识符，读作 `data.<name>`；默认从 operationId 来（`listProducts` → `products`，`getProduct` → `product`） |
| `operationId` | 接口 |
| `params` | 接口的 path、query、header 参数，每个是表达式；路径参数没给时读屏幕同名的参数（屏幕没有就声明一个），写成 `params.名字` 的也自动声明到屏幕上 |
| `body` | 用 POST 读数据（搜索）的接口的请求体，表达式 |
| `load` | `enter`（默认，进入屏幕时）或 `demand`（只在 `refresh` 时） |
| `pullToRefresh` | 下拉刷新 |
| `paging` | 分页接口的下一页：`scroll` 滚到底时，`button` 由带 `loadMore` 的点击（“加载更多”按钮） |
| `pageSize` | 每页条数（分页约定的 `limitParam`） |

**`data.<name>` 里有什么**：`value`（响应体；分页时列表字段里是到目前为止的所有条目）、`items`（列表：所有已加载的页，或者响应体本身就是列表）、`status`（`idle`、`loading`、`ready`、`error`）、`loading`（正在加载或重新加载）、`loadingMore`、`hasMore`、`empty`、`ready`、`error`（Problem：`status`、`title`、`detail`、`errors`）、`total`（偏移分页的总数）。

**效果**：

| 效果 | 说明 |
| --- | --- |
| `{do: "call", operationId, args?, body?, then?, catch?, optimistic?}` | 调用接口。`args` 按名字给参数，不是参数的名字放进 JSON 请求体；`body` 是整个请求体的表达式。2XX 时运行 `then`（读 `response`、`status`），否则运行 `catch`（读 `error`）。后面的效果和这次点击的跳转不等它返回——要等就写进 `then` |
| `{do: "invoke", capability, args?, then?, catch?}` | 调用平台能力（支付、第三方登录、定位、扫码……，见[平台能力](平台能力.md)）。`args` 的每个值是表达式；能力做到了时运行 `then`（读 `result`），没做到时运行 `catch`（读 `error`，`error.type` 是 `cancelled`、`failed`、`unavailable`、`not-implemented`、`denied`、`timeout`）。和 `call` 一样不等回答。`payment.pay` 的 `then` 只代表“已提交”：支付结果要按后端的订单状态显示 |
| `{do: "refresh", source}` | 重新加载当前屏幕的一个数据源 |
| `{do: "loadMore", source}` | 加载下一页 |
| `{do: "submit", form?}` | 提交表单：给了组的 id 就是那个，否则是被点的组件所在的表单 |
| `{do: "signOut"}` | 结束会话（有 logout 接口就顺便调用，不等它） |
| `optimistic: {source, remove: true}` 或 `{source, patch: {字段: 表达式}}` | 不等返回先把被点的那一行从列表里去掉（或改几个字段），失败时放回 |

`then` / `catch` 是普通的点击主体：可以跳转并带参数、设变量（`setVar {expr: "response.count"}`）、刷新数据源、弹提示条、再调用接口或能力（`call` 和 `invoke` 合起来最多嵌套 4 层，`lib/actions` 的 `MAX_CALL_DEPTH`）。嵌在调用回答里的 `invoke`，外层的 `response` 照样读得到：下单的 `then` 里 `{do: "invoke", capability: "payment.pay", args: {orderId: "response.id"}, then: {to: "result", params: {orderId: "response.id"}}}`。`then` / `catch` 可以按回答分支：带上 `when`（读 `response`、`status`、`error`）和 `else`，规则和点击的条件一样（[交互规则](交互规则.md)“回答上的条件”）；要在屏幕上分开显示，也可以把值写进变量（`setVar {expr: "error.type"}`），再用 `showWhen` 显示各自的设计。

`then` / `catch` 在点击所在的那一屏里运行，不管回答到达时显示的是哪一屏：读那一屏的 `params`、被点的那一行（`item`、`row`）和表单（表单提交的 `then` / `catch` 里 `form` 就是被提交的表单，提交按钮在表单外也一样），数据和会话读回答到达时的值。表单提交中再按一次不算新的提交，也不算失败。

效果的顺序、每一步读什么、嵌套上限、迟到的回答（重新开始后什么都不做；同一组件又调用了同一接口时旧回答让位；访客已经离开时效果照常运行、跳转不再发生）这些规则所有宿主共用一份，写在 [交互规则](交互规则.md)，由 `lib/actions` 实现，并有在预览、两种 Web 导出、手机端和小程序上各跑一遍的一致性表。今天预览在访客离开后整个丢弃 `then` / `catch`，`lib/app` 只在重新开始后丢弃回答，都记在那张表的已知分歧里。

## 表达式

绑定、条件、参数、请求体字段都用同一种小语言。它被读成语法树再求值，**从不交给 `eval` 或 `Function`**；只读普通数据（对象自己的属性、数组的元素、字符串的长度），不调用数据里的任何东西，只能调用下面列出的辅助函数。

| 读什么 | 写法 |
| --- | --- |
| 屏幕的数据 | `data.products.items`、`data.product.value.price`、`data.products.loading`、`data.cart.error.detail` |
| 屏幕的参数 | `params.productId` |
| 变量 | `vars.count`、`vars["购物车数量"]`（按名字，也可以按 key：变量的 id，永远不变；改名时按名字读的表达式跟着改，见[项目文件](项目文件.md)的“校验和引用”） |
| 重复里的元素 | `item.name`、`index`（从 0 开始）；集合的行仍是 `row.field` |
| 所在的表单 | `form.email`（也可以 `form.values.email`）、`form.errors.email`、`form.error`、`form.submitting`、`form.valid`、`form.progress` |
| 会话 | `auth.signedIn`、`auth.user.name` |
| 调用的结果 | `then` 里的 `response`、`status`；`catch` 里的 `error` |
| 平台能力的结果 | `invoke` 的 `then` 里的 `result`；`catch` 里的 `error`（`error.type`、`error.capability`、`error.message`） |
| 时间 | `now`（ISO 字符串） |
| 组件事件带的东西 | `on:<名字>` 动作里的 `event`：数字键盘确认时的 `event.value`，抽奖落定时的 `event.index`、`event.label`（每个组件发什么见 `describe_part`） |
| 槽位族里被点的那一个 | `tab:*` 动作里的 `slot.index`（第几个，从 0 开始）、`slot.key`（`tab:2`） |

- **字面量**：数字、`'文字'` 或 `"文字"`、`true`、`false`、`null`。
- **运算**：`+ - * / %`（任一边是文字时 `+` 拼接）、`== != === !==`（`==` 让 `3` 和 `"3"` 相等）、`< <= > >=`（数字比大小，文字按字典序，所以 ISO 日期能比较）、`&& || !`、`??`、`条件 ? 甲 : 乙`、括号、`a?.b`、`a[0]`、`a[-1]`（最后一个）。
- **真假**：`null`、`undefined`、`false`、`0`、`""`、`NaN` 和**空数组**为假（所以 `showWhen: data.cart.items` 就是“购物车不空”）。
- **读不到就是空**：路径中间断了、除以零、类型不对，结果都是“没有”，不会报错；绑定的文字显示为空，数字、开关、选项保持设计时的值。

**辅助函数**（按当前语言格式化，`zh` 用 `zh-CN`、`ja` 用 `ja-JP`、`ko` 用 `ko-KR`、`en` 用 `en-US`）：

| 函数 | 例子 |
| --- | --- |
| `date(v, 样式?)` | 样式 `date`（默认）、`time`、`datetime`、`short`、`long`、`weekday`、`month`、`relative`：`date(item.createdAt)` → `2026年11月6日` |
| `relative(v)` | `3 分钟前`、`2 days ago`、`2 時間前` |
| `number(v, 小数位?)` | `1,234,567.89` |
| `currency(v, 币种?, 小数位?)` | 不给币种时按语言：中文 CNY、日文 JPY、韩文 KRW、英文 USD：`¥12.50` |
| `percent(v, 小数位?)` | `percent(0.256, 1)` → `25.6%` |
| `fileSize(字节)` | `1.5 MB` |
| `plural(n, 单数, 复数?)` | `plural(n, "# item", "# items")`，`#` 换成格式化的数字；中日韩不区分单复数 |
| `truncate(s, 长度)` | 超出时截断加 `…` |
| `upper`、`lower`、`trim`、`len`、`join(列表, 分隔?)`、`pluck(列表, 字段)`、`sum(列表, 字段?)`、`first`、`last`、`contains`、`isEmpty`、`round(n, 位?)`、`floor`、`ceil`、`abs`、`min`、`max`、`string`、`num` | |

**文字里的表达式**：文字属性里的 `{{表达式}}` 在预览里被读出来写进去（`共 {{len(data.cart.items)}} 件`）。读不出来的 `{{...}}`（集合行的 `{{field}}`、打错的字）原样保留。

**上限**：一个表达式最多 4000 字符、2000 个记号、嵌套 64 层；一次求值最多 2 万步（辅助函数处理列表时按元素计步）；拼出来的文字最多 2 万字符；`__proto__`、`constructor`、`prototype` 之类的键一律读不到，函数和类实例也读不到。几千层括号、十万元素的列表、伪造原型的 JSON 都在毫秒内得到“没有”（`lib/bindings/expr.test.ts`）。辅助函数（`join` 的分隔符、`plural` 的 `#`）拼到上限就停，不会先拼出很长的文字再截断；文字里的 `{{` 后面跟着几万个空格而没有 `}}`，也是一遍读完（以前的模式会把空白的每种分法都试一遍，几千个空格就能让预览和导出停住几十秒）。

## 区域和状态

`set_region` 把一个有自动布局的容器做成区域：它的子项按状态分到不同的“页”上（借用 Dock 的 `Group.pane`：0 内容、1 加载中、2 空、3 出错、4 无权限），每个状态是一份普通的设计，像别的组件一样编辑。

- **默认设计**：区域缺哪个状态的设计就补上，按文档的风格组合：加载中是骨架屏（列表是三行头像加文字，单条数据是图片块加三行文字）；空、出错、无权限用“空状态”组合件（`empty-note`，风格选它的变体），换上相应的图标、标题、说明和按钮——空和出错的按钮重新加载数据源，无权限的按钮去登录页。出错的说明绑定到服务器给的 `error.detail ?? error.title`。所以没有哪个状态是没设计的。
- **画布**：选中区域或其中的组件时，区域上方（太靠屏幕顶时在区域内）出现状态切换条：内容、加载中、空、出错、无权限，像 Figma 切换变体；没有设计的状态显示为斜体，点它就补上。切换是 `set_region {show}`，一步撤销，存在文档里。
- **预览**：按数据源的状态选：还没有数据时“加载中”（按需加载、还没加载过时“空”）；失败且没有可显示的数据时 401/403 →“无权限”、404 →“空”、其他 →“出错”；成功但没有内容（列表为空、响应为空，或 `emptyWhen` 为真）→“空”；否则“内容”。重新加载时保留原来的内容，`data.x.loading` 为真。
- **只靠表达式显示的部分**（`showWhen: {expr}`：表单的错误行、“加载更多”按钮）在画布上画成半透明，表示它们是某个时刻的设计。

## 表单

`make_form` 把一个容器（或新建一个）做成某个接口请求体的表单，并为每个可写字段（不是 `readOnly` 的；对象字段展开一层）按文档的风格生成输入：

| Schema | 输入 |
| --- | --- |
| `string`（`email`、`password`、`uri`、电话类名字） | 带标签的输入框组合件（`labeled-field`，风格选变体），`type` 相应 |
| `number` / `integer` | 同上，`type: number` |
| `date` / `date-time` | 输入框，提示 `YYYY-MM-DD` |
| `enum` | 下拉选择（选项是枚举值） |
| `boolean` | 开关 |
| 很长的文字（`maxLength > 200`，或描述类名字） | 多行输入框 |
| `format: binary`、`contentMediaType` | 文件上传，下面是绑定 `form.progress` 的进度条 |

每个字段下面一行说明：平时写字段的描述或规则（“至少 8 个字符”“选填”），出错时换成错误并变红（`bind: {text: "=form.errors.email ?? …", color: "=form.errors.email ? 'error' : 'muted'"}`）；输入框本身在出错时显示错误态。最后是表单级的错误行（`showWhen: {expr: "form.error"}`）和提交按钮（`{do: "submit"}`）。

- **校验**来自 Schema：`required`、`minLength`/`maxLength`、`pattern`、`format`（email、uri、uuid、date、date-time）、`minimum`/`maximum`/`exclusive*`、`enum`、数字和整数。提交时先校验，有错就不发送；第一次提交之后随输入实时更新。值按 Schema 的类型转换（数字字段的文字变成数字）。
- **服务器的错误**：Problem 的 `errors[]`（`{pointer: "#/email", detail, in}`，和导出的后端一致）里 `in` 为 `body`（或没写）的按 `pointer` 落到对应字段上（`#/address/city` → `address.city`），其余的和 `title`/`detail` 显示在表单级的错误行。字段上服务器的错误在这个字段改动后消失（预览和导出的应用都是 `lib/app` 的表单控制器）。
- **提交中**表单里带 `submit` 的按钮被禁用；有文件时进度条按时间增长，返回后到 100。
- **登录**：`auth.login` 接口的表单（或调用）成功后，按 `authFields(auth)` 取出令牌，开始会话。

## 会话

- 登录接口返回的 `accessToken`、`refreshToken`（字段名按 `set_auth`）保存在这次预览里；`auth.user` 是响应的 `user`，没有就是去掉令牌后的响应。
- 之后的调用按接口实际生效的 `security` 带上令牌：Bearer 写进 `Authorization: Bearer …`，API Key 按 `in` 写进 header 或 query；`security: []` 的接口（登录）不带。
- 401：有刷新接口和刷新令牌时先刷新一次再重试；还是 401 就结束会话，应用去登录页（`Frame.auth = "login"`），登录成功后**回到原来的屏幕**并重新加载。没有登录页时区域显示“无权限”。
- 要登录的屏幕（`auth: "required"`）：没有会话时先去登录页，登录后直接去那个屏幕（登录表单 `then` 的跳转让位，效果照常运行）。
- `signOut` 结束会话。
- 预览由[模拟库](模拟库.md)回答时，`auth.signedIn` 一开始就是 true（模拟库的会话默认已登录：受保护的接口不带令牌也回答），要登录的屏幕直接打开；场景或模拟设置写了 `signedIn: false`（例如“未登录”场景）就从未登录开始。`signOut` 会告诉模拟库的登出接口，此后受保护的接口回答 401，应用去登录页；登录拿到的令牌之后照常带上。

## 预览

预览通过一个 `Transport`（`lib/api/transport.ts`）调用接口，和导出的 `packages/api` 同一形状。按顺序选：

1. 页面放在 `window.m3ePreviewTransport` 上的（嵌入编辑器的应用，端到端测试的假后端就是这样）；
2. 给 `Preview` 的 `transport`；
3. [模拟库](模拟库.md)：文档有接口时预览打开就加载（`components/MockPreview.tsx` 的 `usePreviewMocks`），屏幕显示按 Schema 生成的数据，表单的请求按契约校验（400/422 的 problem+json，`errors[].pointer` 落到字段上），登录、令牌和 401 都按模拟库的规则。模拟库加载好之前，绑定的区域显示“加载中”，不先显示一个马上要换掉的回答；
4. 文档没有接口时用契约示例的替身（`fallbackTransport`）。

预览栏的**场景**切换（正常、新用户、大量数据、网络错误、慢网、未登录，以及作者自己的场景）和请求记录里的“重新开始”都让模拟库开始一个新会话：数据重新生成、令牌清空。预览的绑定跟着从头开始——数据源、表单、会话清空，`auth.signedIn` 按新场景定，正在显示的屏幕（和叠加的屏幕）重新加载；之前发出、还没回答的请求作废，不会把旧场景的数据写回来。所以切到“新用户”列表显示空状态，切到“网络错误”显示出错状态，切到“未登录”受保护的列表回答 401、应用去登录页，登录后回来并带着令牌加载。

- 进入屏幕时加载 `load: enter` 的数据源；再进入时先显示已有的内容、在后面重新加载。参数读变量（搜索框绑定的变量）、别的数据源（只读排在它前面的）或会话时，求值结果一变就按新参数重新加载，和导出的应用一样以“接口 + 求值后的参数”为键（参数只取文字、数字、是否），回到以前的参数时先显示那时的结果；参数没变的数据源保持原样；绑定没有防抖设置，每次变化都请求，旧的回答让位给最新的。两个屏幕用同样的接口和参数时共用一份数据。
- 浮层（`overlay` 叠加的屏幕）里的点击读浮层自己的屏幕：它的参数、数据和表单，刷新的也是它的数据源。重复按数据展开，行读 `item`；滚到底加载下一页（`paging: scroll`），在顶部下拉（手指或滚轮）重新加载 `pullToRefresh` 的数据源并显示转圈。
- 加载数据的屏幕随内容变长，正文可以滚动，顶部的栏不动，底部的栏、悬浮按钮和站在屏幕下半部的按钮（“添加”“订单”这类）留在屏幕底部不动；正文滚到最后多出一段空白，最后一行停在它们上方 24 点处（`lib/foot.ts`，导出的三个应用用同一个规则）。
- 绑定了数据的文字（在自动布局里、高度没有写死的）按它在自己宽度里折成的行数排版，不超过最多行数：列表里的说明显示两行，详情的长说明把下面的部件往下推（`components/previewText.ts`）。画布仍按设计时的文字量尺寸，只有预览这样排。
- 行里没有自己的点击的组件（文字、图片、图标）点下去等于点它所在的那一行，和导出的应用里一样。
- **出错不会让预览停下**：传输层抛错是 status 0 的 Problem（“无法连接服务器”）；响应的形状不对（契约说返回列表却没有）是“出错”状态并说明原因；表达式读不出来就是空；某个屏幕的绑定算不出来时按设计原样显示。

## 操作和工具

都在 `OPS` 里，自动成为应用内 AI 和 MCP 的工具（分组 `data`，工具集 `bindings`），每个一步撤销。

| 操作 | 做什么 |
| --- | --- |
| `add_data_source {screen, operationId, name?, params?, body?, load?, pullToRefresh?, paging?, pageSize?}` | 加数据源；返回 `{name, addedParams}` |
| `update_data_source {screen, name, rename?, …}` | 改（`null` 清除）；`rename` 时屏幕上读 `data.旧名` 的表达式、文字和标签里的 `{{data.旧名…}}`、提示条、区域、刷新效果跟着改（按表达式的词法单元找，字符串字面量里的不算，`lib/refs.ts`） |
| `remove_data_source {screen, name}` | 删除（破坏性，先问） |
| `set_screen_params {screen, params}` | 声明参数 |
| `set_screen_auth {screen, auth}` | `required`、`login` 或 `null` |
| `bind_expression {id, prop, expr}` | 属性绑定表达式（`null` 解除）；检查能否解析、读的数据源和参数是否存在、`item` 是否在数据重复里 |
| `set_repeat {id, repeat: {data, limit?, sample?}}` | 按数据重复（原来的 `{collection}` 照旧） |
| `set_region {id, source?, emptyWhen?, show?, designs?}` | 做成区域并补上缺的状态设计；`show` 切换画布上的状态 |
| `remove_region {id, keepDesigns?}` | 变回普通容器，状态设计一起删掉（破坏性） |
| `set_form {id, form}` / `make_form {id? \| screen?, operationId, fields?, submitLabel?, then?, catch?, params?, values?}` | 表单；`make_form` 同时生成字段、错误行和提交按钮，返回 `{formId, fields, submitId}` |
| `bind_field {id, field}` | 输入框对应请求体字段 |
| `wire_screen {screen, operationId, name?, into?, detail?, paging?, params?}` | **一步把屏幕连上接口**（详情页还没有参数时，按列表的“取一条”接口给它声明，如 `productId`；标签用字段的 `title`）：数据源；列表接口是重复一行（按元素的字段挑标题、说明、图片、金额或时间并绑定好；`detail` 给了就点一行打开它并传 id）、下拉刷新、滚动或“加载更多”分页；单条数据是逐个字段显示；再加上四个状态的设计 |
| `set_action` | 新效果、`params`、`when: {expr}`、`setVar {expr}` |

读取工具 `describe_bindings {screen, expr?, at?}`：屏幕的参数、登录要求、每个数据源（接口、能读的路径）、区域和它有哪些状态设计、表单（每个字段的输入类型、是否必填、是否已绑定）、绑定了表达式的属性、可以重复的列表、辅助函数；给了 `expr` 就在那个位置检查它。

截图看绑定的效果：`screenshot {id, scenario, params?}` 按预览的方式画屏幕（模拟库在这个场景下回答，`""` 是正常回答；数据加载、按数据重复、文字读进去、区域显示数据所处的状态），结果的 `data` 列出每个数据源的状态、条数和错误、每个区域显示的状态和发出的请求；`screenshot {id, state, region?}` 让区域显示某个状态的设计。实现在 `lib/bindings/headless.ts`（`previewScreen`、`regionsShowing`），和预览同一套引擎。

工具集 `bindings` 的触发说法（`lib/agent/toolsets.ts`）：英文的 bind/wire … to the API、data source、loading/empty/error state、skeleton、pull to refresh、infinite scroll、load more、form validation、submit the form、call the API、expression……；中文的绑定接口、连接接口、数据源、加载状态、空状态、错误状态、骨架屏、下拉刷新、加载更多、表单校验、提交表单、调用接口、表达式……；日文的 APIにつなぐ、データソース、読み込み中、空の状態、スケルトン、フォームの検証、バリデーション……；韩文的 API에 연결、데이터 소스、로딩 상태、빈 상태、스켈레톤、양식 검증、API 호출、표현식……。

## 编辑器

- **屏幕面板 → 设计 →“数据”**：“连接接口”（选接口和“点一行打开”的屏幕，一步完成 `wire_screen`）；每个数据源一张卡片（名字、接口、参数的表达式、加载时机、下拉刷新、分页和每页条数、删除）；“添加数据源”；屏幕参数（名字、类型和示例值）；登录要求。
- **组件面板 → 设计 →“数据”**（文档有接口、屏幕有数据、文档有数据集合（表格和列表可以读 `collections.<名字>`）或组件已有表达式时出现）：由表达式决定的属性（每个一行，可以改或解除；表格属性也可以）和“绑定属性”；容器的“按数据重复”（列出能重复的列表路径，最多条数和画布上画几份）；“显示数据的状态”（选数据源、状态切换、视为空的条件、补上缺少的设计）；“表单”（选提交到的接口，“做成表单”自动生成字段；已是表单时改接口和参数、没有输入框的字段的表达式，以及“提交之后”的成功后、失败后：去哪一屏、带什么参数、运行哪些效果）；表单里的输入框选“表单字段”。
- **表达式输入框**：等宽字体，边输入边补全——开头是能读的根（`data`、`params`、`item`……）和辅助函数，`data.` 后是数据源，`data.products.` 后是 `items`、`value`、`loading`……，`data.products.items[0].` 和 `item.` 后是元素 Schema 的字段（带类型）；方向键选择，Enter / Tab 采用；不能解析时下面红字说明，并且不保存。
- **原型标签页**：效果多了“调用接口”（接口、参数和请求体字段、“不等返回先移除这一行”、成功后 / 失败后各自的去处、参数和效果，可以再嵌套）、“调用平台能力”（能力、参数、完成后 / 没做到时各自的去处和效果；选 `payment.pay` 时提示“完成只代表已提交”）、“重新加载数据”“加载下一页”“提交表单”“退出登录”；“设为变量”可以“用表达式取值”；条件多了“表达式”；跳转到有参数的屏幕时出现“传给屏幕的参数”。
- **画布**：状态切换条（见上），按数据重复的列表画 `sample` 份（副本半透明）。

新字段都写在屏幕和组件组的那一行里，加它们时格式版本没有升（当时是 2，现在是 3，见[项目文件](项目文件.md)的“版本和迁移”）。读入时（`openProject`）`lib/bindings/clean.ts` 清理：名字不合格、重复的数据源和参数丢掉，枚举值不对的字段去掉，表达式超长的不要，`call` 和 `invoke` 的 `then`/`catch` 最多嵌套 4 层，运行时才有的 `Item.scope` 从不保存。表达式写错了（解析不了）照样保留，预览里读成空，等作者改。没有绑定的文档写出的字节和以前完全一样。

## 导出

完整产品（[导出](导出.md)）把同一份模型写成三个前端的代码——Web 应用（[导出](导出.md)的“Web 应用：绑定接口的屏幕”）、手机应用（[手机端](手机端.md)）和小程序（[小程序](小程序.md)），行为和预览一致，都跑在共用的运行时 `packages/app-runtime` 上（它就是这里的 `expr.ts`、`format.ts`、`messages.ts`、`rules.ts`、`sources.ts`、`form.ts` 加上 `lib/app`，原样复制）。三个打印器各用自己平台的写法，写什么由同一个模块决定（`lib/export/bindCode.ts`：参数放在路径、查询、请求头还是请求体，列表和分页，表单字段的规则，区域的状态，绑定属性怎样读，哪些效果属于接口）：

- **表达式**：设计里的表达式原样作为字符串留在代码里，由复制过去的求值器在运行时求值（`$.text("item.name")`、`$.holds("form.error")`），从不 `eval`，读不到就是空、有上限，和预览一模一样。
- **数据源**：每个数据源一个以它命名的 hook（`useProducts`），调用 `packages/api` 的类型化客户端；缓存按参数，新请求取消旧的，再进入屏幕时在后台重新加载；分页用分页约定的字段；`refresh`、`loadMore`；下拉刷新（Web 的滚动正文、RN 的 `RefreshControl`、小程序的 `onPullDownRefresh`）、滚到底（RN `onEndReached`、小程序 `onReachBottom`）。
- **路由参数**：`Frame.params` 成为路由参数（Web `/product/:productId`，Expo Router `[productId].tsx`，Taro 的页面 query）；`ActionBody.params` 在跳转时求值。
- **重复**：`Group.repeat.data` 写成 `list.map((item, index) => …)`（RN 用 `FlatList`），key 是元素的 `id`，行读 `item`、`index`。
- **区域**：`Group.states` 写成按状态渲染的分支，状态由 `useRegion`（`regionOf`，和预览的 `regionState` 同一份代码）选出。
- **表单**：`useForm`：受控的输入，字段规则由契约的 Schema 生成，Problem 的 `errors[]` 按 `pointer` 落到字段上（`in: body`），提交中禁用按钮；`date` 字段在 Web 上是浏览器的日期选择器；文件字段走上传，进度条接平台报告的真实进度（Web 用 `XMLHttpRequest`）。
- **点击**：`call` 效果调用客户端，`then` / `catch` 是同样的动作；`optimistic` 先改缓存、失败回滚。`invoke` 效果经运行时的能力注册表交给产品自己写的适配（`src/custom/capabilities.ts`），没写的回答 `not-implemented`，开发版在控制台提示（[平台能力](平台能力.md)）。
- **会话**：运行时保存令牌（Web `sessionStorage`、RN `SecureStore`、小程序 Taro 的存储），按 `security` 加到请求上，401 时刷新一次，再失败就去登录页并在登录后返回；`auth: required` 的屏幕有守卫。
- **模拟**：开发时用模拟库的 transport（或 MSW），`auth.signedIn` 的起点和预览一样跟随模拟库的会话（场景的 `signedIn`，默认已登录），切换场景时数据缓存和会话清空；生产构建里没有模拟库，只看有没有令牌。

## 已知限制

- 表单的字段只展开对象的一层；数组字段（除了文件列表）和 `oneOf` 结构不生成输入（用 AI 或手工绑定）。
- 预览里日期字段是带格式提示的输入框（导出的 Web 应用里是日期选择器）。
- 上传进度在预览里按时间估算（模拟库的 Transport 没有进度事件）；导出的 Web 应用报告真实进度。
- 实时通道（AsyncAPI）还没有绑定到屏幕：订阅和发送消息是后续工作。
- 导出的原型项目（`exportProject`，只有一个应用、没有接口）按变量求表达式条件，数据、表单的值和会话在那里都读成空；数据源、表单和调用只在完整产品里生成。
