# M3E Canvas Pro

在浏览器里用现成组件拖拽搭出可交互的应用，定义好它和后端之间的接口，用模拟库看到完整运行的产品，再导出成一个完整的产品仓库（Web、手机应用、小程序、接口契约、后端骨架），后端交给 AI 编程助手去写；也可以只导出可运行的 React 原型或给 AI 的提示词。基于 [m3e-canvas](https://github.com/lnkiai/m3e-canvas) 和 [shadcn M3E](https://github.com/Crysta1221/shadcn-m3e)，把各分支和组件库的组件全部按同一种方式重新实现。这是一个重构后的独立项目，只打开自己保存的文件，不兼容其他分支的文件格式。

## 能做什么

| 方面 | 功能 |
| --- | --- |
| 组件 | 215 个组件，分两层：**原子组件**（盒子、文字、图标、矢量图形、图片、按钮、输入框、开关……不能再拆）和**组合组件**。原子放进嵌套的自动布局盒子就能拼出任何组件，比如 Claude 或 Codex 风格的输入框。74 个组合件（216 种组合方式）拖进来就是可编辑的原子树，换风格时没改过的组合件按新风格重新组合；53 个常用组合组件可以一键拆成原子，拆出来外观不变 |
| 风格 | 27 套对照真实产品的风格：微信、iOS、抖音、Claude、Codex、Windows、VS Code、原神、黑神话、赛博朋克 2077 等。每套都是一份规范：配色和字体、控件造型和组合方式（返回文字、居中标题、分组列表、分栏弹窗、游戏描边……）、产品自己的图标集（SF 风格、Fluent、VS Code、Phosphor、Lucide、游戏图标、彩色图标等 16 套，离线打包）、边距和导航位置一键换掉，之后手动修改、AI 和自动排版都被约束在规范内。组件和风格解耦，同一个组件在不同风格下呈现不同；风格画廊可以把全部组件按某套风格画出来核对，见 [风格清单](docs/风格清单.md) |
| 效果 | 填充色和文字色可用主题角色、角色加透明度或任意颜色；多层纯色和线性、径向、角向渐变；内外侧和居中描边、虚线点线、四边分别设置；多重外阴影和内阴影；图层模糊、毛玻璃、混合模式、滤镜、缩放倾斜翻转；文字的字号字重、字距行高、大小写、阴影、描边和渐变；噪点、纸张、网点、扫描线等纹理；光泽按钮、玻璃、霓虹、立体按钮、游戏标题、金色边框等 14 个预设，可复制粘贴到别的组件。严格遵守风格时改用风格自己的高度层级 |
| 模板 | 98 个屏幕和流程模板：登录、购物、社交、内容、工具、桌面和 32 个游戏模板。所有文字和结构都是通用的，不绑定任何产品，加到哪份文档就用哪份文档的手机尺寸 |
| 排版 | 自动布局（横排、竖排、网格，间距和行距、四边内边距、对齐含基线、两端/环绕/均分分布、换行；子项各自固定/随内容/占满，单独对齐，最小最大尺寸，跨列，脱离布局叠放；可嵌套）。整理会读出屏幕的行列结构，统一间距、对齐边缘和基线、识别网格，结果稳定；整理所选把选中的排成整齐的行、列或网格；转为自动布局把选中的或整屏变成嵌套的盒子。拖动时有智能参考线、等间距提示和距离标注，按住 Alt 测量；4dp 网格，按数字设位置 |
| 屏幕 | 手机（常见型号可选，一份文档统一一个型号）、平板、桌面和自定义尺寸，长屏滚动，状态栏和安全区，可垫一张设计稿描图，同一屏幕可建多个尺寸的变体 |
| 复用 | 可复用组件（一处定义，多处实例，实例可覆盖文字、图标、图片）；变体集（变体属性和取值）、组件属性（文字、显示隐藏、实例替换）、实例替换，转到主组件再回到实例 |
| 数据 | 数据集合驱动的重复列表，点一行把这行数据带到详情页 |
| 接口 | 前后端之间的约定：数据模型（JSON Schema）、HTTP 接口（OpenAPI 3.1，含分页、上传、RFC 9457 错误）、鉴权（Bearer JWT、API 密钥、OAuth2）、实时通道（AsyncAPI 3.0）和各环境的服务器；左侧“接口”标签页编辑，导入别人的 OpenAPI / AsyncAPI 文件，导出 `openapi.yaml`、`asyncapi.yaml` 和类型，AI 和 MCP 用同一组操作改，见 [接口](docs/接口.md) |
| 模拟库 | 没有后端也能看到完整的应用：接口由模拟库回答，数据按数据模型生成（人名、头像、邮箱、地址、价格、日期，中英日韩，种子确定），会话里能增删改查，分页、校验、上传下载、登录和令牌过期都是真的；命名场景（新用户、大量数据、网络错误、慢网、未登录）在预览里一键切换，请求记录面板列出每个请求；文件库放图片、PDF、音频、视频，也能用 AI 生成图片；实时消息按脚本推送。左侧“模拟”标签页编辑，导出的 `packages/mocks` 是同一个模拟库（传输层模拟和 MSW，只在开发时），见 [模拟库](docs/模拟库.md) |
| 数据绑定 | 屏幕连上接口：数据源、屏幕参数、要不要登录；属性绑定到表达式（日期、金额、复数按语言格式化）；按返回的列表重复，滚动或“加载更多”分页、下拉刷新；表单按请求体的 Schema 生成和校验，服务器的字段错误落到字段上；点击调用接口，成功和失败各有去处；登录、带令牌、401 回登录页；每个区域都有加载中、空、出错、无权限的设计，画布上切换；“连接接口”一步完成，见 [数据绑定](docs/数据绑定.md) |
| 交互 | 跳转、返回、外链、浮层、滚动到；点击、指针移入、延迟后触发；立即、溶解、移入、推入、滑入的动画；显示隐藏、开关弹层、设变量、改属性、提示条；按变量或输入内容走不同分支；输入框写入变量，属性可绑定变量；Dock 按标签切换内容；在画布上拖出连线，流程起点 |
| 变量 | 像 Figma 的变量面板：颜色、数字、字符串、布尔变量分集合存放，每个集合有模式（浅色、深色……），文档和屏幕各自选模式；设计面板的填充、描边、文字颜色、不透明度、圆角、旋转可以绑定变量 |
| 图层 | 和 Figma 一样的图层树：屏幕 → 盒子 → 原子，标出自动布局方向、组合件和实例；原地重命名、搜索、隐藏、锁定；拖动行排序或放进别的盒子；与画布选区同步 |
| 编辑 | 右侧设计面板按 Figma 的顺序分节（属性、位置、布局、外观、文字、填充、描边、效果、导出），数字框可拖动标签调值、方向键步进、输入算式，多选显示“多个值”；画布上点选最外层、双击或 Enter 进入、Esc 退出，Shift/Alt 改尺寸，直接拖动自动布局的间距和内边距；右键菜单、多选一起拖动、与父级对齐、约束、双击就地改文字；`?` 打开快捷键表。见下面的“编辑” |
| 项目 | 一个浏览器里可以有多个项目，存在 IndexedDB：项目主页可以搜索、按最近排序、新建、重命名、创建副本、删除（可撤销），每个项目有第一屏的缩略图；不同项目可以在不同标签页同时编辑。保存失败时工具栏会说明原因（空间已满、存储被关闭、不允许、被别的标签页保存过等）并自动重试，切换项目前先确认都已保存；关闭页面时没保存完的修改，下次打开项目会询问是否恢复（见 [项目文件](docs/项目文件.md)）。在 Chromium 里可以把项目绑定到电脑上的 `.json` 文件或文件夹，之后每次修改自动保存过去（原子写入，重新打开后一键重新连接，文件在外面被改过会先询问），清掉网站数据也不会丢；文件的排版适合放进 git，图片可以作为单独的文件放在旁边。打开或拖入文件默认作为新项目。别人的文件或分享链接里来自其他网站的图片、视频和网页，要你在画布上方点“加载外部图片”才会加载（像邮件客户端一样，每个项目记住这个选择）；项目自己的图片不受影响。旧版保存在浏览器里的文档第一次打开时自动成为第一个项目 |
| 输出 | 两种导出：**原型项目**（一个可运行的 React 应用，zip）和**完整产品（monorepo）**（npm workspaces 单仓库：Web 应用、手机应用（Expo / React Native）、微信和抖音小程序（Taro，同一份代码也构建 H5）、接口契约和与平台无关的客户端、三个前端共用的运行时、模拟库、Fastify 后端骨架、契约测试，ESLint、Prettier、类型检查、测试和构建都配好，见下面的“完整产品”）。完整产品可以写进电脑上的文件夹（Chromium）、用命令行 `bun scripts/export.ts` 或 MCP 的 `export_product` 导出，之后再导出到同一个文件夹：生成的文件按清单 `.m3e/manifest.json` 更新，自定义代码（人或 AI 写，`server/src/handlers`、`custom/`）从不覆盖，被手改过的生成文件不覆盖、新版本写成 `.m3e-new` 并报告，见 [导出](docs/导出.md)。还有项目文件、复制代码、给 AI 的提示词、分享链接（先选“仅外观 / 含示例数据 / 完整契约”，列出并可排除每一项，可预览）、导出屏幕图片。原型项目和预览一样运行原型：指针移入和延迟的触发、浮层、滚动到、各种动画、流程起点，绑定变量的字段跟着模式、深色模式和点击设的值变化 |
| AI | 应用内的智能体用编辑器自己的操作改画布：按当前风格加屏幕、改组件、加变量和交互、画 SVG 图标和图片，自己截图检查再修改；一次请求是一步撤销，可以中途停止。见下面的“AI” |
| MCP | Claude Desktop、Codex 等 MCP 客户端通过 `m3e-canvas-mcp` 操作设计：连上打开的编辑器实时修改（输入客户端给的配对码，可以记住客户端、服务器重启后不再询问；可只读、删除要在编辑器里允许、每次调用一步撤销），或不开编辑器直接改项目文件（可撤销、重做）并在无头浏览器里截图，见 [MCP](docs/MCP.md) |

## 编辑

编辑方式对照 Figma（UI3），外观仍是 Material 3 Expressive。

- **图层**：左侧“图层”是整棵树：每个屏幕下是放在上面的组件，盒子里是它排的组件，一直到原子。行首的图标说明是什么：盒子按自动布局方向（竖排、横排、网格、换行）显示，组合件带一个小标记，组件实例是菱形。点击选中，Shift 连选，Ctrl/Cmd 加选或取消；双击名字或按 F2 重命名；悬停显示隐藏和锁定。拖动一行可以在同一个盒子里排序，拖到盒子那一行的中间放进去（自动布局的盒子按位置插入，没有布局的盒子会把它移到盒子里面），拖到屏幕的第一层就离开所在的盒子。画布上选中的组件会展开到它所在的那一层并滚到可见。搜索时保留匹配的图层和包含它们的盒子。
- **设计面板**：右侧“设计”从上到下是：组件自己的属性、位置（X、Y、旋转、翻转、在屏幕上的位置、脱离自动布局）、布局（宽高和固定/随内容/填充、最小最大值、按屏幕的宽度、自动布局的方向、对齐格、间距、内边距、分布方式）、外观（不透明度、圆角、混合模式、裁切、开始时隐藏）、文字、填充、描边、效果（阴影、模糊、滤镜、纹理、缩放倾斜）、外观预设、导出 PNG。“原型”标签页是点击后做什么、显示条件和说明。
- **数字框**：按住前面的标签左右拖动调值（Shift 一次十），方向键加减一（Shift 十），可以输入 `12*2`、`100/3+8`，或以运算符开头在原值上改（`+8`、`*2`）。选中多个组件时，不同的值显示“多个值”，输入后每个都改成这个值。
- **选中**：点一下选中最外层的组件（比如组合件的外框），在已选组件的范围内再点选它的兄弟；双击或 Enter 进入一层，Shift+Enter 或 Esc 回到上一层，Tab/Shift+Tab 选下一个或上一个兄弟；Ctrl/Cmd+点击直接选中最里面的组件。指针停在组件上会描出点击会选中的范围；在空白处或屏幕的底面上拖动框选最外层的组件（按住 Ctrl/Cmd 框选里面的每一个），在屏幕底面上单击选中屏幕，拖屏幕的名字或边框移动它。
- **尺寸和间距**：拖手柄改尺寸时按住 Shift 保持比例，按住 Alt 从中心缩放。选中自动布局的盒子后，画布上内边距和间距的中间有粉色小手柄，拖动即可修改（内边距按 Alt 两边一起、Shift+Alt 四边一起，Shift 按 8 取整）。
- **视图**：Shift+1 显示全部，Shift+2 缩放到所选，Ctrl/Cmd 加 +、-、0 放大、缩小、100%；按住空格拖动平移，触控板捏合缩放。`?` 或右下角的键盘按钮打开快捷键表。
- **选择框和菜单**：选择框、下拉菜单、菜单栏、搜索建议和日期选择器在画布上展开画，方便看到样子，但排版、测量和对齐都按收起的尺寸，展开的部分悬在后面的组件上；预览里点一下才展开。
- **右键菜单**：在组件上按右键，先像单击一样选中它（已经选中的不变），菜单里有复制、粘贴到这里、创建副本、删除，上移下移一层、移到最上最下，编组和取消编组，添加自动布局，创建组件，实例的“转到主组件”，有文字的组件的“编辑文字”，以及“选择图层”：列出它外面的每一层，点一层就选中它。在空白处按右键可以粘贴、全选。
- **一起拖动**：选中几个组件后，拖动其中任何一个，所有选中的连同它们装着的组件一起移动，保持彼此的距离（自动布局排着的组件除非它的布局也被选中，否则不跟着拖）。图层树里拖动属于选区的一行，选中的各行一起放到新位置。
- **与父级对齐和约束**：只选一个组件时，“位置”一节有六个对齐按钮，把它对齐到装着它的盒子（没有自动布局的盒子），没有这样的盒子就对齐到屏幕。放在没有自动布局的盒子里的组件，下面有“约束”：水平方向左、右、左右、居中、缩放，垂直方向上、下、上下、居中、缩放。盒子改尺寸时（拖手柄、输入宽高、AI 改属性），组件按约束保持到边的距离、居中、跟着拉伸或按比例缩放；没设约束的仍然固定在左上。
- **就地改文字**：双击文字原子（已经选中、里面没有更深的一层时；按钮这类有文字属性的组件也一样）或选中后按 Enter，组件上出现一个同字体的输入框，Enter 确定（多行文字用 Shift+Enter 换行），Esc 放弃，点别处也确定；一次是一步撤销。
- **单选时的操作**：只选一个组件时，设计面板最后的“操作”一节有“建议自动布局”（容器自己打开布局，普通组件放进一个横排）和“存为组件”，组合组件还有“拆成原子”；选中一个手工组时，“建议自动布局”和“取消编组”也在。

### 组件、变体和组件属性

- **变体**：左侧“组件”标签页里，每个组件下面有“添加变体”。组件第一次添加变体时成为一个变体集的第一个变体（变体属性先叫“属性 1”，取值“默认”），新变体是它的副本：零件和 id 都一样，所以实例在变体之间切换时，覆盖跟着走。变体集的卡片里可以改集合的名字、每个变体属性的名字和取值（用逗号分隔，在原来的位置改一个值就是把它改名，变体跟着改名），添加或删除属性；每个变体下面按属性选自己的取值，两个变体不会取同一组值。
- **实例替换**：实例的设计面板里，变体属性各是一个下拉框，选一个值就换到最接近这组取值的变体；“替换实例”可以换成文档里任何组件。覆盖按路径保留，路径对不上的按零件的类型和名字找同一个零件，找不到的去掉；组件属性的值按属性名保留。
- **组件属性**：在组件卡片的“组件属性”里（滑杆图标）给主组件加属性：文字属性改某个零件的某段文字，布尔属性显示或隐藏某个图层（连同它排着的组件），实例替换属性把嵌套的实例换成别的组件。实例在面板的“组件属性”一节设值，没设的跟着组件；手工覆盖优先于文字属性。
- **转到主组件**：实例面板顶上的“转到主组件”（右键菜单里也有）打开它的定义，底部的按钮变成“回到实例”，点它回到原来的视图，实例仍然选中。“重置全部覆盖”去掉实例的所有覆盖和属性值。

### 变量

- **集合和模式**：左侧“变量”标签页一次显示一个集合：选集合、新建或删除集合、改名；“模式”一节列出这个集合的模式，可以改名、添加、删除（删除的模式连同各变量在它下面的值一起删掉）。新建的集合默认有“浅色”“深色”两个模式。没有放进任何集合的变量（包括以前的文档里的变量）在默认集合里，它只有一个模式，值就是变量原来的值。
- **变量**：添加颜色、数字、字符串或布尔变量，每个模式下各有一个值；颜色可以是主题角色或任意颜色。布尔变量可以打开“切换应用的深色模式”（就是 `drives: "dark"`），预览和导出的项目里设置或切换它就切换深浅色。
- **显示哪个模式**：集合可以指定“深色模式下用的模式”，应用处于深色模式时用它；“整份文档的变量模式”选整份文档用哪个模式；屏幕面板的“原型”标签页里“这个屏幕的变量模式”给单个屏幕选，优先于文档的选择。
- **绑定字段**：设计面板里填充、文字（颜色）、描边三节标题旁，以及不透明度、圆角、旋转数字框旁，都有一个变量按钮，点开选同类型的变量（颜色或数字），已绑定的显示变量名，可以“解除变量”。组件属性的绑定仍在各属性旁边。绑定的字段在画布上按屏幕的模式画，预览里按当时的模式和点击设的值画，截图、导出的项目也一样：导出的项目里每块屏幕按自己的模式给出变量的值，应用切到深色时跟随深色模式的集合换成深色模式，点击设了变量后，绑定它的填充、文字颜色、描边、不透明度、圆角、旋转在每块屏幕上都马上变。

### 原型

- **连线**：选中组件、打开右侧的“原型”标签页，组件右边缘中间出现一个带加号的圆形手柄，拖动时画出一条线，拖到哪个屏幕上就连到哪个屏幕（目标屏幕描边提示）。点画布上的连线，线旁弹出交互框：触发（点击、指针移入、延迟后多少毫秒）、跳转还是打开浮层、目标屏幕、动画（立即、溶解、移入、推入、滑入，四个方向、缓动、时长），右上角的按钮删除这条连线。
- **原型标签页**：目标除了屏幕、返回、外链，还有“滚动到”（选屏幕上的一个组件，预览里把它滚到可见处）；目标是屏幕时可以“打开浮层”；下面是触发和动画，“同时执行”里可以设变量、显示隐藏等。
- **流程起点**：屏幕面板的“原型”标签页里打开“设为流程起点”并起名，屏幕名字旁出现带播放图标的标记；预览的屏幕菜单最上面列出各个流程，从没有选中屏幕时打开预览，从第一个流程开始。导出的项目也从第一个流程开始，在地址后面加 `?flow=名字`（项目的 README 列出各个流程）就从那个流程开始。
- **预览和导出的项目**：按触发运行（指针移入、进入屏幕后延迟），浮层放在当前屏幕中间、下面压暗，点外面、返回或 Esc 关闭它，滚动到把组件平滑地滚到可见处，动画按设定的方向、缓动和时长播放，返回时倒放。导出的项目播放的是和预览同一份动画（`lib/screenMotion.ts` 复制进项目），系统设置了“减少动态效果”时，屏幕的移动直接到位、滚动不再平滑。

## AI

在左侧的 “AI” 标签页里，先在“设置”中选服务商、填 API 密钥。密钥只存在这个浏览器里，浏览器直接请求服务商，中间没有服务器。默认文本模型是 OpenAI 的 `gpt-6.1-sol`（工具调用走 Responses API），图片模型是 `gpt-image-2.6-sunburst`；也可以选 Claude、Gemini、DeepSeek。推理强度（低、中、高）在同一页调，做整个应用时建议选高。

- **对话**：直接说要改什么，比如“按当前风格做一个登录页”“把这个列表改成卡片”“加一个深色模式开关变量并绑定”“画一个叶子图标放进标签栏”。智能体用编辑器自己的操作在画布上改，过程实时显示：它的计划、每一步用了什么工具、它截图看过的屏幕、花了多少 token 和时间。
- **一次请求一步撤销**：完成后显示改了什么（屏幕、组件的增删改），可以保留、撤销或重试。中途按停止，画布恢复到请求之前，这一步也不能再重做。
- **删之前先问**：请求没有明确要删，智能体却要清空画布、删屏幕或删很多组件时，对话里先弹出“允许 / 不要”，说明会删掉什么；选“不要”就保留你的内容，智能体改为先问你想要什么。像“都不好看，全删了重做”这样的请求，它会先问一句。
- **图片只用文档里的**：智能体放的图片要么是图片模型画的，要么是项目自己的图片，不引用外链（外链可能失效、截图和导出都带不走）；截图时遇到加载不了的旧外链，画成灰块并告诉智能体。
- **Cmd/Ctrl+K**：在画布上打开提示栏，针对选中的组件或屏幕提要求。
- **快捷操作**：起草整个应用、打磨这个屏幕、写屏幕说明、写组件的行为、给场景画图。
- **风格**：文档严格遵守风格时，智能体只用风格允许的外观；不严格时可以用全部效果。选择框、下拉菜单、日期选择器在画布上展开画，但自动布局按收起的尺寸排，展开的菜单悬在后面的组件上，不留空位。
- **SVG 和图片**：画布上没有的图标或插图，智能体可以让图片模型画出再描成 SVG，或让文本模型直接写 SVG；内容图片用图片模型画，也可以画成整个屏幕的背景。每个请求最多两次，都会经过 SVG 清理。画出的图标可以存成文档自己的图标（`svg:<编号>`），像普通图标名一样用在导航栏的标签、按钮、列表行上，画布、预览和导出的项目里都画得出来；图标选择器的“本文档”一栏可以直接选。
- **用原子拼组件**：目录里没有的东西（Claude、Codex 那样的输入框，游戏的 HUD，自定义卡片），智能体用一次 `add_tree` 搭出整棵嵌套的盒子和原子树，一步撤销；说“存成组件”就存成可复用组件。
- **复刻截图**：在对话框或 Cmd/Ctrl+K 提示栏里粘贴、拖入或点图片按钮添加截图，说“照着做”。智能体先量图里的颜色（`sample_colors`），用原子搭出来，再把自己的截图和参考图并排对照（`compare_to_reference`），按差别修改布局、间距、颜色、字体、圆角和阴影。请用自己有权使用的截图。
- **生成风格**：说“生成一个暖色纸张笔记本风格并穿上”，或附一张图说“照这张图做风格”。描述里提到材质（纸张、皮革、霓虹、像素……）时，风格会用纹理、描边和阴影把它画出来，而不只是换颜色。智能体写出自定义风格，经过和风格文件一样的校验（颜色对比度、配方、安全的 CSS），加进文档并穿上，再截图检查、修改一次。每个请求最多让模型写两次风格（修改也算一次），之后智能体直接改风格的字段。
- **深色模式开关**：说“加一个深色模式开关”，智能体加一个驱动深色模式的变量，开关绑定它；在预览里点开关就切换深浅色，导出的项目里也一样。
- **做成能用的产品**：说“把商品列表连上接口，用模拟数据显示”“加登录，订单页要登录才能看”“做一个记账小应用，三个页面，要有接口和模拟数据”，智能体按顺序做完：从屏幕推出数据模型和 REST 接口（分页、鉴权、problem+json 错误；给了 OpenAPI 文件就导入），把屏幕绑定上去（数据源、按数据重复的行、点一行带着 id 打开详情、表单按 Schema 校验并显示服务器的错误、调用接口的按钮、登录页和要登录的屏幕），按文档的风格设计加载中、空、出错、无权限四个状态并用产品自己的话写，再填好模拟库和场景。最后用截图检查：截图可以带一个模拟场景（屏幕按模拟数据画出来，并说明每个数据源拿到了什么），也可以让区域显示某个状态。全程不写代码，导出的完整产品照样能类型检查和构建。
- **省 token**：一段对话开始时只给智能体读取和搭建的工具，请求里提到风格、数据、绘图等时再加对应的工具集，模型也可以自己加载；工具只增不减，提示缓存能持续命中。截图只保留最近几张。
- **对话跟着项目**：每个项目有自己的 AI 对话，刷新页面或重新打开项目后还在；“新对话”清空它。

同一套工具（`lib/tools`）也通过 MCP 提供给 Codex、Claude Desktop 等外部客户端，见 [MCP](docs/MCP.md)。给外部智能体一次写出整份文档用的说明在 `public/agent.md`。

## 完整产品

一个产品就是前端和后端，中间是接口。在编辑器里把三样都定下来：“接口”标签页写契约（数据模型、接口、鉴权、实时通道，按 OpenAPI 3.1 / AsyncAPI 3.0 存），“模拟”标签页决定没有后端时接口怎样回答（按 Schema 生成的数据、场景、文件），屏幕连上接口（数据源、表单、点击调用、加载中/空/出错/无权限的设计）。预览里整个应用跑在模拟库上，场景一键切换。导出“完整产品（monorepo）”得到一个可以直接开发和上线的仓库：

```text
apps/web               Web 应用（React + Vite）：屏幕、路由、表单、多语言，全部由设计生成
apps/mobile            手机应用（Expo / React Native），同一份设计
apps/miniapp           微信、抖音小程序和 H5（Taro），同一份设计
packages/api           接口契约 openapi.yaml、asyncapi.yaml，类型，与平台无关的客户端
packages/app-runtime   三个前端共用的运行时：数据源、表单、调用、会话、表达式（和编辑器预览同一份代码）
packages/mocks         模拟库：传输层模拟和 MSW，只在开发时，生产构建里没有
server                 后端骨架（Node + TypeScript + Fastify）：路由、校验、鉴权、分页、上传、实时通道都已生成，
                       业务逻辑写在 server/src/handlers（每个接口一个文件，先回答 501）
contract-tests         对照契约检查运行中的后端
AGENTS.md              给 Codex、Claude Code 等 AI 编程助手的规则：哪里能写、哪里不能写、怎样检查
.m3e/manifest.json     生成的文件和它们的哈希：再导出一次只更新生成的文件
```

**开发时用模拟库**（在导出的文件夹里）：

```bash
npm install
npm run dev                        # 后端（3001）和 Web 应用；Web 应用的接口由模拟库回答，地址里加 ?scenario=new-user 换场景
npm run start -w apps/mobile       # 手机应用（Expo Go、模拟器或网页），开发版同样由模拟库回答，角落的开发菜单切换场景
npm run dev:h5 -w apps/miniapp     # 小程序的 H5；dev:weapp、dev:tt 构建给微信、抖音开发者工具
VITE_API_MOCKS=off npm run dev     # Web 应用改为请求本地后端（手机应用 EXPO_PUBLIC_API_MOCKS=off，小程序 TARO_APP_API_MOCKS=off）
```

**后端交给 AI 编程助手**：在导出的文件夹里打开 Codex 或 Claude Code，让它“按契约实现后端”。`AGENTS.md` 告诉它只在 `server/src/handlers/`（处理函数，类型来自契约，返回契约以外的东西过不了类型检查）和 `server/src/custom/`（鉴权、数据层、插件）里写，不碰生成的代码，用 `npm run contract -w contract-tests -- --strict` 确认每个接口都按契约实现；契约本身要改时，回到设计里改（接口标签页、应用内 AI 或 MCP）再导出。设计表达不了的前端集成（支付、地图、推送等第三方 SDK）写在各前端的 `src/custom/`。这些自定义代码（人或 AI 写）再导出时原样保留：契约多了接口只多一个处理函数桩，去掉的接口留下的文件报告为孤儿，被手改过的生成文件不覆盖、新版本写在旁边的 `.m3e-new`。

细节见 [导出](docs/导出.md)、[后端](docs/后端.md)、[手机端](docs/手机端.md)、[小程序](docs/小程序.md)、[数据绑定](docs/数据绑定.md)、[模拟库](docs/模拟库.md)、[接口](docs/接口.md)。

## 启动

需要 [Node](https://nodejs.org/) 22 以上和 [bun](https://bun.sh/) 1.4。

```bash
bun install
```

```bash
bun run dev
```

然后打开 http://localhost:3000。

| 命令 | 作用 |
| --- | --- |
| `bun run build` | 生产构建，输出到 `dist/` |
| `bun run preview` | 预览生产构建 |
| `bun run typecheck` | 类型检查 |
| `bun run test` | 运行测试 |
| `bun run lint` | 代码检查，有警告也算失败 |
| `bun run test:e2e` | 端到端测试：构建后在无头 Chromium 里用编辑器自己的控件操作（Playwright 需另装，见 `e2e/run.ts`） |
| `bun run gen:parts` | 重新生成组件索引（每个组件模块一个按需加载的分块） |
| `bun run gen:versions` | 依赖升级后，按 `package.json` 和 `bun.lock` 重写导出项目用的版本表 `lib/versions.generated.ts`（`check:versions` 只检查，测试也会检查） |
| `bun run gen:agent` | 把组件清单写进 `public/agent.md` |
| `bun run gen:icon-sets` | 按图标对照表重新打包各风格的图标集（`check:icon-sets` 只检查） |
| `bun run gen:rn` | 重新生成手机端组件套件（`rn/`）用的数据和打印器的样例输出（`check:rn` 只检查），见 [手机端](docs/手机端.md) |
| `bun run gen:miniapp` | 重新生成小程序组件套件（`miniapp-kit/`）用的数据、画廊的主题和图标，以及打印器的样例页面（`check:miniapp` 只检查），见 [小程序](docs/小程序.md) |
| `bun run mcp:build` | 把 MCP 服务器打包成 `mcp/dist/m3e-canvas-mcp.js`（先 `bun run build`，编辑器的构建会一起复制过去给截图用）；`mcp:dev` 直接运行源码，`mcp:docs` 按注册表重写 [MCP](docs/MCP.md) 里的工具表 |
| `bun scripts/style-shots.ts --base <地址> --out <文件夹>` | 把风格画廊按风格、分类截图，用来核对每套风格（先另开 `bun run dev`） |
| `bun scripts/export.ts <项目文件> <输出文件夹>` | 把项目导出成完整产品（monorepo），再次导出到同一个文件夹时保留自定义代码、报告冲突，见 [导出](docs/导出.md) |
| `bun run check:product <空文件夹> [shop]` | 导出一个带接口契约的示例产品，真的 `npm install`、类型检查、lint、构建、测试，启动后端跑契约测试，在 Chromium 里打开应用，再导出一次检查合并规则；`shop` 是屏幕绑定了接口的商店，在模拟库和真实后端上驱动 Web 应用、手机应用和小程序 H5，截图放在 `<文件夹>/shots-shop` |
| `bun run check:export <空文件夹>` | 生成项目，真的安装、构建，再用无头 Edge（不是 Windows 时用 Playwright 的 Chromium）点一遍；`… systems` 只跑原型和变量的项目，用 Playwright 检查触发、浮层、动画和变量 |

在 Windows 上，项目路径要尽量短。依赖目录层级很深，放在超长路径下安装可能失败。
